## §3 方法陷阱：`git ls-files` 默认的 quote-path 会**静默跳过**那 55 个非 ASCII 名

**陷阱复现（现算，`%TEMP%\t84_readings.md` §陷阱）**：

* `git ls-files`（默认 `core.quotepath=true`）输出 369 行，其中**带引号、八进制转义**的 = **55** 行，例如 `"docs/design/01-\345\244\247\346\226\271\345\220\221.md"`；
* 按「逐行 `Test-Path` / `Path.exists()`」逐条判 ⇒ **只能判到 314 条**（369 − 55 = 314）—— 那 55 条被当成**不存在**，**整份文件**漏出所有判据；
* 正确姿势只有两条：**`git ls-files -z`**（本页用的就是它）或 `git -c core.quotepath=false ls-files`；闸门 `_受控文件()` 两者都用了（`-z` + `-c core.quotepath=false`），并且注释里写明了原因。

⇒ 于是「CRLF 0」这个读数**必须**由覆盖 369 条的方法给出；PowerShell 逐文件那一版只能覆盖 314 条，**不构成全量读数**（这正是 t4 当时那次读数的缺陷，本卡把它写成方法而不是改判据）。

## §4 新增两条判据 + 三次**真实判红**的阴性对照

判据落地在 `tools/tests/test_repo_hygiene.py`（in-scope）：

* `_孤立CR违规`：落单的 `0D`（后面不接 `0A`）—— 与 CRLF 分开的理由写在模块 docstring 第 4 条：`0D 0A` 是"换行风格错了"，落单 `0D` 是"混进了控制字符"，后者在 `git diff` 里看不见；

* **TAB（`09`）刻意不判**：`_实例` 里有两例带 TAB 的判绿用例（`仓库侧无控制字符_判绿`、`无NUL_判绿`），全量读数里 101 条含 TAB 的文件也全绿。

## §5 顺带修掉的一处**静默漏判**（本卡最值钱的一条）

写新判据时撞出来的：**分块扫描（`_CHUNK` = 8192 字节）在块边界上会漏判 CRLF**。

* 旧写法每块各自 `chunk.find(b"\r\n")`、总量也是 `sum(chunk.count(b"\r\n") for …)` ⇒ `0D` 落在前一块最后一字节、`0A` 落在后一块第一字节时，**一处都查不出来、也数成 0 处**；
* 复现（新用例 `test_分块扫描跨块边界也判得出`）：把 `_CHUNK` 压到 4、`_READ_WHOLE_MAX` 压到 1，写 `b"abc\r\ndef\r"` ⇒ 第一版**当场红**，报的是 `共 0 处`（"报了第几行"与"共几处"互相矛盾）—— 这就是它暴露计数那一半也是按块数的；
* 修法：新增 `_第一处(source, needle)` 与 `_计数对(source, needle)`，都 carry 一个 `len(needle)-1` 字节的重叠窗口（每个命中至少含当前块一个字节 ⇒ 不会重复计数）；孤立 CR 的扫描同样带 carry，并单独处理**文件末尾**那个没有后继的 `0D`；
* 修后：该用例判绿，且既有 `test_大文件走分块扫描也判得出CRLF` 的期望值（`第 41 行（共 1 处）`）**逐字未变** ⇒ 口径没被改动，只是把漏掉的那一类补上。

为什么要紧：现场只有两份 6.36 MiB 的入库快照走分块那条路；漏判的代价是「闸门一声不吭」——与本卡要修的 NUL 盲区同族。

## 二、门禁今天怎么判这两类引用（实测，照抄输出）

**A. 官方原版那一类** —— `citations mod/data/ru_defeat.toml mod/data/sp_empire_remnant.toml`：

```
exit=0
218 条引用全部指得到唯一一行 ✅
```

**B. 本仓文件那一类** —— 用临时探针（已删）验证「本仓路径能不能被判定、越界怎么报」：

```
4 条引用（2 条指得到）
│ out_of_range │ tools/pdx/modgen.py:999999   │ "文件只有 2266 行"        │
│ out_of_range │ common/…/03_political…:999999│ "文件只有 1395 行"        │
│ unsupported  │ common/…/03_political…:1178  │ "第 1178 行没被记进支撑域" │
```

⇒ **门禁能做三件事**：① 文件找不找得到（`missing`）；② 行号越不越界（`out_of_range`）；
③ **那一行的内容指纹对不对**（`unsupported`，见 §三）。
**它不做语义判断**（`v3 citations --help` 明说：「它不做语义判断：『那一行真的支持这条 why 吗』仍然要人看」）。

**⚠️ 一个必须写下来的操作性事实**：**新写一条官方引用，在 `snapshot create --compact` 之前一定报
`unsupported`**（"第 1178 行没被记进支撑域"）。支撑域是**入库快照的一部分**，不是从当前盘上现算的
（`support_domain()` 的文档：键是**引用写法**、值为 `["lines=N", "<行号>:<指纹>"]`）。
⇒ 这就是「新引用先红、刷新快照才绿」的**反馈回路**，也是门禁给的下一步命令
（`v3 snapshot create --compact`）的由来。

## 三、漂移是怎么被判出来的（我在 worktree 里复现了两态）

**做法**：`git worktree add <临时目录> HEAD`（detached，`542c914`）→ 在里面造一处引用
（`tools/pdx/modgen.py:185-189`）→ **手工构造支持域**（用仓库自己的 `line_digest` 算真指纹）
→ 先验"漂移前"→ 再在 `modgen.py` 顶部**人为插入 5 行注释**（只改 worktree）→ 看 `unsupported()`
在两种模式下的差异。**工作区一个字节都没动**（见 §六）。

| 状态 | `unsupported(live=False)`（CI 口径） | `unsupported(live=True)`（本机口径） |
|---|---|---|
| 漂移前 | **0 条** | **0 条** |
| 漂移后（内容整体下移 5 行） | **0 条**（不报！） | **1 条**：`第 185 行的内容变了（原版更新？）—— 核对后刷新快照` |

**⇒ 判决**：判定**漂移**的那一步是 **`live=True` 的内容指纹核对**，不是行号存在性
—— 行号 185 在漂移后依然「存在」，所以纯行号检查永远是绿的。
**今天那条红走的正是这条**：`sp_empire_remnant.toml` 记的支持域指纹是**旧 `ab_probe.py:852-867` 的内容**；
`ab_probe.py` 被 t18 加了两族行后整体下移 ⇒ `live` 核对时第 852 行的文本指纹对不上 ⇒ `unsupported`。
**修复形态也可复制**：把引用改成新行号（`t16` 改成 `:1017-1031`）+ `v3 snapshot create --compact` 刷新
⇒ 两态我都实测过：**修完 `v3 citations` 连续两次 `exit 0`（878 条全部指得到）**。

## 四、处置建议（两条路都写清利弊，不替队长选）

### 路线 A：继续用**行号锚 + 门禁兜底**（现状），但把边界补全

* **要不要改实现**：**不用**。门禁已经能**自动发现**漂移并给出**可执行**的下一步
  （`第 N 行的内容变了` + `改完引用行号后重跑本命令；改的是数据源就再接 v3 modgen --write，最后
  v3 snapshot create --compact`）。今天从红到绿，**人工改动只有 2 处**（1 行引用 + 1 次快照刷新）。
* **要补的三件（都不大）**：
  1. **把 `docs/**` 显式排除或显式纳入**：今天 `docs/**` 的 1 146 条（含 49 条本仓引用）**完全没被判**。
     要么在 `v3 citations --help` 与文档里写明「本门禁只管 `mod/data`；`docs/**` 的引用由人工/别的手段守」，
     要么另加一条低频检查（`docs/**` 引用随文档重排而漂移，风险更高）；
  2. **给 `v3 citations` 加一个「把新行号打出来」的输出**（现在只说"内容变了"，新行号要人自己找；
     今天那条是命令自己推断出 `:852 → :926` 才那么好修 —— 把它变成**每条都给的默认输出**）；
  3. **在数据源里把「会漂的指针」压到最少**：已知靶子只有 `modgen.py`/`ab_probe.py` 两个
     —— 引用它们时**尽量引稳定块**（如类定义、`def` 行），少引"中间那一小段"。
* **不改的代价（实测）**：每次改 `tools/pdx/modgen.py` / `ab_probe.py` 的**行数**，就会让
  `mod/data` 里指向它的引用进入 `unsupported`，直到有人重排引用 + 刷快照。
  今天这次的实际代价：**1 条红 + 2 处人工改动 + 约 4 分钟**（01:35 红 → 01:39 修好 → 01:40 快照已刷新）。
  **而门禁把"哪一条、为什么、怎么修"全说清了** ⇒ 这是"被看住的成本"，不是"静默腐烂的成本"。

### 路线 B：行号锚 → **内容锚**（引用里带一段原文）

* **最小可行改动**（我按现有机制推的，**没有实现**）：
  1. `CITATION_RE`（`citations.py:46-51`）加**可选**的锚段，例如把
     `mod/data/ru_defeat.toml:148-150` 写成 `…:148-150@<该行/首行的 8-16 字原文>`；
  2. `line_digest` 已有（去首尾空白取 sha16）⇒ 内容锚直接复用同一套规范化；
  3. `_resolve`/`unsupported` 增加一条**重定位**分支：行号对不上时，在**该文件内按锚文本搜索**，
     唯一命中 ⇒ 自动判 ok（并输出"建议把行号改成 :N"）；多处命中/找不到 ⇒ 仍报红。
  4. 数据源侧：**只需给已经存在的 25 条本仓引用加锚**（2 个文件、9 份数据源里 6 份），
     不必一次改完 `docs/**` 的 49 条。
* **好处**：① 改 `modgen.py` 的行数**不再需要编辑 `mod/data`**（门禁自己缩放到新行号）；
  ② 内容真被改写时仍然红（这正是我们要的"内容变了要人看"）。
* **代价与风险**：① 引用串变长、`why` 可读性略降；② **两套格式并存**（带锚/不带锚）会有一段时间的
  混乱；③ **锚文本自己也可能被编辑**（那就退化成今天的形态）；④ 要动 `citations.py` 与 6 份数据源
  —— 而这两处的写权都**不在本卡**，属实现任务。

## 五、一条可立即执行的结论

> **继续用「行号锚 + 门禁兜底」，不必换内容锚。判据有三条，都有实测支撑：**

1. **门禁真的看得住漂移**：我在 worktree 里复现了「内容下移 5 行」⇒ `live=True` 立刻报
   `第 185 行的内容变了`，且给出可执行处置；而**离线通道（CI）压根不查这一层**（`live=False` 报 0 条）。
   ⇒ 结论：**这一层的守护只在本机（有游戏树）生效**，`--offline` 那一条守的是"与入库快照一致"。
   **这就是为什么它必须在 `v3 citations`（本机）里跑，而不是只靠 CI**。
2. **漂移的成本是被看住的、且很小**：今天实测 **1 条红 → 2 处人工改动 → 4 分钟内转绿**，
   而且换新行号是**机械动作**（`modgen --write` + `snapshot create --compact`）。
   与"内容锚"相比，收益是"省掉那 2 处编辑"，代价是改 `citations.py` + 6 份数据源 + 两套格式并存
   —— **性价比不划算**。
3. **真正的缺口不是格式，是范围**：`docs/**` 的 1 146 条引用（含 49 条本仓引用）**今天一条都不判**。
   若担心引用腐烂，**优先做的是把范围说清或补一条检查**，而不是换成内容锚
   —— 换成内容锚之后，`docs/**` 仍然不在范围内。

**⇒ 建议的下一张卡（如果队长要开）**：不是"换内容锚"，而是
**「让 `v3 citations` 默认把每条漂移的『新行号建议』打出来，并把 `docs/**` 的处置写进 `--help` 与文档」**
—— 两件都是小改动，直接消掉今天暴露的两个真实缺口。

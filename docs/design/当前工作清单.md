## T0 计划落地结果

T0 只更新当前计划和文档入口，不宣称新增 Mod 行为：

1. 冻结 1.2.0 源、标准包、SHA-256 和 Victoria 3 1.14.5 底本；
2. 将“事实 → 有限状态 → 领域评估 → 协调 → 原版消费者”固定为终极架构；
3. 建立 T0–T13 阶段、阶段出口、统一门禁和证据边界；
4. 把全量能力审计、国家状态、预算、机会成本、路线惯性、冷却和有限记忆列为明确交付物；
5. 将 U0–U14 保留为历史工程基线，不再作为当前待办；
6. 保持当前标准包和生产源不变。

## 观察和反馈

用户提供的日志和存档可用于辅助归因。报告必须标记 `runtime`、`snapshot` 和 `inference` 边界，存档差异不能单独证明 AI 决策因果。
用户反馈应包括游戏版本、Mod 版本、标准包 SHA-256、启用的 Mod 集、存档或新局条件、复现步骤、相关日志原件、预期和实际行为。

问题按工程错误、运行语义、数值平衡、性能、本地化和体验分类。工程改动必须回到受影响的 T 阶段并重新经过对应门禁；已发布标签不移动。

## 目标架构摘要

```text
原版事实
  → 证据/未知
  → 能力、压力、机会、承诺
  → 目标组合
  → 行动卡
  → 有限互补/替代/冲突关系

  → 原版消费者的有界倾向
  → 原版资格、成本、概率和执行
```

计划要求 19 个产品子域逐项登记 D0–D4 深度、事实、协调、消费者、未知回退、质量等级、性能预算、确定性和静态证据；不能接入的面明确保留原版或仅作解释。

## 证据边界

- `static_check`：字段、作用域、生成、未知回退、玩家边界、编码、包结构和 Git 交付。
- `snapshot`：原版或仓库快照的结构差异。
- `simulation`：Python 参考求值、PDX 子集解释器和属性/反例测试。
- `runtime`：用户提供的游戏日志、存档或实际运行材料。
- `inference`：基于上述材料的有限推断。

测试、CI、脚本加载、根 hook、评分变化和存档差分都不能单独证明长期 AI 行为质量、平衡或玩家体验；长期游戏验证仍由用户完成。

缓存、测试输出、临时部署和可再生产物按贡献流程清理；用户存档、日志、截图、设置、启动器数据库和冻结证据按原有契约保留。历史计划和旧执行结果不作为当前入口，原始内容留在 Git 历史或明确的历史收据中。

## 当前架构

```text
原版事实
  → facts.toml / EvidenceSpec / 未知回退
  → 能力、压力、机会、承诺
  → 目标与有限行动卡
  → 互补/替代/冲突关系（最多两级）
  → 参考仲裁和消费者预算
  → 原版策略字段的有限 PDX 条件块
  → 原版资格、成本、概率、执行和失败
```

生产源由 `mod/decisions/*.toml` 维护；`src/pdx/situated/` 只在生成期解析和编译。行动条件使用 `is_ai` 根边界，未满足、未知或不支持时保留原版消费者。

## 证据边界

- `static_check`：字段、作用域、生成、玩家边界、编码、包结构和 Git 交付。
- `snapshot`：锁定原版或仓库快照的结构差异。
- `simulation`：Python 仲裁、关系图和 PDX AST 解析。
- `runtime`：用户提供的游戏日志、存档或实机材料。
- `inference`：基于可复核材料的有限推断。

脚本加载、工程测试、根 hook、评分变化或存档差分不能单独证明长期 AI 行为质量。用户的固定包游玩和反馈是 K12 之后的产品验收来源。

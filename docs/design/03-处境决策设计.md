# 处境决策设计

## 目标

Situated AI 读取锁定版本中可发现、可由脚本访问的国家和世界信息，把它们转成原版 AI 消费者可接受的
有限增量。政治、社会、财政、经济、市场、贸易、外交、宗属、军事、战争、殖民、地理、身份和时间因素
先按单位和作用域形成事实，再用声明式规则与显式优先级决定每个原版字段的唯一贡献。

设计追求可解释、可回退和可维护，不追求替代引擎规划器或计算全局最优。没有可靠 getter 或合法消费者的
信息登记为 `unknown`/`unsupported`，保留原版行为。

## 架构

```text
原版快照/目录
      │
      ▼
information_catalog + vanilla_index
      │  发现、版本、字段、作用域、来源指纹
      ▼
mod/decisions/*.toml
      │  Reader / Predicate / Rule / Intent / Adapter
      ▼
decisions.py + decision_rules.py + decision_adapters.py
      │  单字段作者、预算、玩家边界、原版底本最小补丁
      ▼
distribution.py
      │  11 种本地化、BOM/LF、manifest、确定性 ZIP
      ▼
Victoria 3 原版消费者
```

游戏运行时不调用 Python，不启动外部服务，不全世界扫描。财政风险是唯一带 TTL 的持久状态；其它规则沿
原版消费者的刷新时机直接读取当前事实。禁用或卸载会停止新增规则，但不会回滚已发生的世界变化。

## 信息与消费者

| 域 | 典型事实 | 原版消费者 |
|---|---|---|
| 政治/社会 | 合法性、利益集团、阶层、生活水平、激进化、改革条件 | `change_law_chance`、政府与协商策略 |
| 财政/行政 | 借贷、信用、违约、债务、收入、行政能力 | 财政风险生命周期、外交中立和进取倾向 |
| 经济/产业 | 建筑、生产方式、投入/产出、就业、基础设施、科技 | 建设、生产、研发和支出权重 |
| 市场/贸易 | 商品供需、价格、贸易依赖、港口、护航和封锁 | 外交支持、商品立场和军需权重 |
| 外交/宗属 | 关系、条约、博弈双方、宗主/属国、自治和威胁 | 支持、目标、保护、独立和退出倾向 |
| 军事/战争 | 战争、前线、装备、补给、兵种、舰类和战争目标 | 军费、军力结构、目标和防御倾向 |
| 地理/身份/时间 | 本土、邻接、战略位置、国家身份、日期和世界冲突 | 资格、目标范围、重评估时机和长期路线 |

信息目录的状态不等于行为验证：`consumer_mapped` 只表示生成器有合法消费者，`behavior_verified` 需要用户
的实际游戏证据，本仓库当前不把它自动升级。

## 规则组合

1. 先检查 `is_ai = yes`、作用域、资格、已知值和原版条件。
2. 每个字段按 TOML 声明的优先级使用第一条匹配规则；同一字段不得由旧模块和全域适配器重复写入。
3. 多个领域只能在同单位、同作用域和有明确理由时组合；未知值保持 unknown，不用零猜测。
4. 贡献只改变原版默认策略或权重；原版仍负责最终概率、花费、随机性、行动和失败。
5. 关闭模块、缺少事实、版本漂移或字段不合法时回退原版并让生成失败可见。

## 兼容性和性能

目标只覆盖锁定的原版 `1.14.5`。生成器从原版底本复制并最小化补丁，保留其余字节；游戏更新后旧包不会
自动恢复，必须重新分析、更新源指纹并生成新包。静态预算限制候选、谓词、路径和依赖深度；游戏内性能仍需
用户在新包上观察。

标准包为 `Situated AI 1.0.1`，metadata ID 为 `situated-ai`。其行为质量、语言显示、玩家体验、长期运行、
后期性能和创意工坊兼容由用户验收；问题以带版本和日志的最小复现回流为 `1.0.2` 等修复版本。

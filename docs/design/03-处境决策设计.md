# 处境决策设计

## 目标和边界

Situated AI 让每个国家基于自身处境和可观测信息，在 Victoria 3 原版机制内持续做出符合自身约束与利益的相对最优决策。
“相对最优”是受信息、能力、政治阻力、财政成本、外部威胁和原版规则限制的情境最优，不是全知全局规划器，也不是固定国家剧本。

Python 只负责信息登记、规则校验、生成、解释、打包和工程检查。游戏运行时只加载标准 PDX 脚本和本地化，不调用 Python、
外部常驻服务或全世界扫描。没有可靠 getter 或合法消费者的信息登记为 `unknown`/`unsupported`，保留原版行为。

## 决策管线

```text
原版目录、快照和日志证据
          │
          ▼
information_catalog + vanilla_index
          │  来源、版本、作用域、单位、更新和可见性
          ▼
国家状态画像（能力、压力、结构、机会、冲击）
          │  仅由可证实事实组合，不创建资源或资格
          ▼
mod/decisions/*.toml
          │  Reader / Predicate / Rule / Intent / Adapter
          ▼
decision_rules + decision_adapters + decision_report
          │  硬约束、优先级、唯一作者、解释和未知回退
          ▼
原版策略、法律、建筑、科技、贸易、外交和军事消费者
          │  原版资格、成本、概率、政治博弈和行动执行
          ▼
distribution.py → 本地化、manifest、确定性 ZIP 和安装树
```

## 信息域和画像

| 域 | 画像问题 | 原版消费者示例 |
|---|---|---|
| 政治/社会 | 政府是否稳定、改革是否可行、社会是否接近危机 | 法律候选、政府组合、协商和革命规避 |
| 人口/能力 | 人口、识字率、生活水平、行政和教育基础 | 学校、医疗、建设和研发倾向 |
| 财政/行政 | 能否承担承诺、债务和行政容量是否健康 | 建设、军费、国有化和外交冒险 |
| 经济/产业 | 产业结构、就业、投入短缺和生产机会 | 建筑、生产方式、补贴和工业策略 |
| 市场/贸易 | 商品依赖、价格、港口、路线和封锁风险 | 商品立场、贸易和外交机会成本 |
| 外交/宗属 | 关系、条约、联盟、宗主/属国和威胁 | 支持、保护、独立、宗属和外交目标 |
| 军事/战争 | 军力、军需、补给、前线和战争负担 | 军费、舰队、目标、护航和防御 |
| 地理/殖民/身份 | 本土、邻接、资源、港口、殖民机会和位置 | 州价值、殖民、海军、战略地区和路线资格 |
| 时间/冲击 | 战争失败、危机、改革结果和路线惯性 | 重评估时机、冷却、切换成本和长期方向 |

信息目录的 `consumer_mapped` 只表示存在合法静态消费者合同；`behavior_verified` 必须来自用户实际游戏证据，本仓库不会自动升级。

## 组合规则

1. 先检查 `is_ai = yes`、作用域、原版资格、能力和已知值。
2. 先应用硬约束，再按同单位、同作用域的显式优先级选择候选；同一生产字段只能有一个作者。
3. 综合生存与稳定、财政经济、军事安全、外交收益、长期结构、政治可行性和机会，扣除成本、风险、行政负担和路线冲突。
4. 未知输入不等于零；不能证明某条件为假时保留原版并阻止低优先级猜测。
5. 贡献只改变原版默认策略或权重；原版仍负责资格、费用、随机性、意识形态、协商、行动、失败和终止。
6. 关闭模块、底本漂移或字段不合法时生成失败或回退原版，不静默修复。

## 历史合理性的实现方式

国家差异由结构和环境推导，而不是国家名称分支。例如人口大、财政弱、保守集团强的国家可能先改善行政和军制，
战争失败后改革收益上升但仍受政治阻力约束；港口、金融、海运强而陆军和人口有限的国家可能优先贸易、金融、海军和殖民。
重大冲击改变评分输入，不能直接强制历史结果；普通波动只平滑调整，防止 AI 摇摆。

## 性能和证据

游戏内不做全世界扫描，不新增无界缓存或常驻服务；规则沿原版消费者刷新时机计算。静态复杂度预算限制候选数、谓词数、
作用域深度和战略依赖深度。`v3 decision-audit` 默认复用一次生产构建的 engineering metadata，`--offline` 从锁定源构造同一份
规则合同；两者都报告域连接、信息与消费者读取器、规则输入、原版消费者、解释和未知回退。`modguard --offline`、快照和
candidate coverage 继续核对冻结合同。

这些工具只能证明静态合同、快照、脚本语法、包结构和有限日志事实，不能证明 AI 行为、平衡、长期性能、语言体验或工坊结果。

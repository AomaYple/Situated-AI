# 处境行动决策内核设计

> 设计版本：27.2（2026-10-30）。本文定义 Situated AI 的目标架构和机制，不表示代码已经实现。当前生产基线为 `Situated AI 1.5.0`；新架构在计划完成前均属于设计目标。
>
> 当前实施顺序、勾选状态和交付出口只维护在[处境行动决策内核实施计划](exec/mod重设计-实施计划.md)；当前事实见[当前工作清单](当前工作清单.md)，工程合同见[工程基线](exec/工程基线-1.0.md)。

## 目标

**Situated AI 让每个国家基于自身处境和可观测信息，在原版机制内持续做出符合自身约束与利益的相对最优决策。**

相对最优不是全知的全局最优，也不是按国家名称复刻历史。它表示：在可观察事实、当前能力、政治阻力、财政成本、外部威胁、既有承诺和原版规则约束下，国家持续选择当前较合理、较可承担、可由原版执行的行动倾向。结构相似的国家可以出现相似路线；同一国家在事实改变后应能转向。

## 核心机制

```text
原版事实
  → 证据和未知语义
  → 能力 / 压力 / 机会 / 承诺
  → 目标组合和时间尺度
  → 具体行动卡
  → 互补 / 替代 / 冲突的有限关系
  → 合法性、瓶颈、政治、承诺和机会成本仲裁
  → 路线惯性、TTL、冷却、迟滞和冲击反馈
  → 原版 AI 消费者的单项有界倾向
  → 原版资格、成本、前置、随机、执行和失败
```

### 为什么不是一个万能总分

财政余额、识字率、军力、商品价格、外交关系和政治支持的单位、方向和用途不同。把它们相加成一个“国家健康分”会隐藏未知、重复计算并制造不可解释的路线。设计采用四种状态：

- **能力**回答当前能承担什么；
- **压力**回答什么问题必须优先缓解；
- **机会**回答哪些窗口值得利用；
- **承诺**回答现有体系已经占用了多少财政、行政、政治和人力空间。

仲裁器使用固定顺序和离散 rank tuple，而不是跨单位加法：先保护玩家/原版边界和生存，再处理确认瓶颈，再建立能力，再利用机会；每一步都核对可行替代、政治成本、既有承诺和退出条件，最后只输出一个有界倾向增量。

## 决策周期和职责边界

运行期决策分为六个有限阶段：

```text
Observe → Assess → Prioritize → Select → Adapt → Exit
```

观察只读取事实，评估只派生能力/压力/机会/承诺，优先级只形成目标组合，选择只比较有限行动卡，适配只写入原版消费者允许的有界倾向，退出只处理 TTL、冷却、迟滞和有限状态。任何领域不能直接改写其它领域；跨域影响必须经过关系图和仲裁器。

路线是当前姿态的有限记忆，不是一个包办所有目标的国家人格。目标是时间尺度，行动卡是可执行消费者映射，二者不能混为一层。

## 编译降低和职责边界

高层语义模型可以在 Python 中表达类型化状态、有限关系、替代行动和解释链，但游戏运行期只加载预编译的有限 PDX 分支。关系图不会在游戏里动态遍历，Python 不作为常驻进程，运行期不会执行全局规划器。

架构把原版硬约束、Mod 软倾向和安全不变量分开：原版继续负责资格、成本、前置、政治支持、随机、执行和失败；Mod 只在原版候选已经存在时改变有限相对权重；未知、漂移、玩家、关闭和越界条件回退或硬失败。

## 证据层

每个事实都有：

- 原版来源和版本指纹；
- actor/target 作用域；
- 类型、单位、范围和合法求值时机；
- 刷新成本和性能预算；
- 可以服务的状态、压力、机会、承诺或消费者；
- `known`、`stale` 和 `unknown` 的区别；
- 核心未知回退原版、高档辅助未知降到已证实低档的策略。

“没有正面证据”不等于“事实为假”；未知不会被静默转换为零、健康或可用机会。每个事实还记录有效性、新鲜度、作用域可信度、运行成本和底本版本可信度；质量不足只能减少 Mod 影响，不能提高倾向。无法读取或没有合法消费者的内容明确标为 `unsupported`、`discovered_only`、`explanation_only` 或 `retained_vanilla`。

## 状态和分层

四层承受能力仍然保留，但只回答承诺能力：

| 层 | 允许的方向 |
|---|---|
| `recovery` | 先恢复偿付、行政和安全；限制新增昂贵长期承诺，保留低成本能力建设。 |
| `foundation` | 补基础瓶颈；不要求财政、政治、行政、产业和教育全部同时良好。 |
| `stable` | 允许更稳健的制度、教育、产业和安全投入；法律仍看具体政治可行性。 |
| `expansion` | 在已证实承受力和机会匹配时增加长期扩张；仍受局部资格、承诺和原版成本约束。 |

每个领域还拥有自己的压力和机会信号。低识字、小国、行政欠缺或正常低债融资不能成为所有发展的全局禁止条件；严重违约、战争和承诺过重也不能被一个正向机会信号抵消。

## 目标、行动和反事实

目标不是直接执行动作，而是给行动提供时间尺度和优先级。一个国家可以同时拥有“避免违约”“修复军需”“扩大教育”“利用资源窗口”等目标；危机目标短期抢占，普通目标保持惯性，目标解除后有迟滞退出。

行动卡是架构的最小决策单元。每张卡明确：

- 真实原版消费者和作用域；
- 需要的证据、可改善的压力或可利用的机会；
- 会消耗的财政、行政、政治、人力或外交承诺；
- 互补、替代、冲突和退出条件；
- 未知回退、最大倾向增量和 reason code。

行动卡不创建资源、不绕过资格、不接管玩家、不强制原版没有的行动。它只改变原版 AI 在已有候选中的相对倾向。每次选择都必须能说明至少一个替代行动，或者明确写出没有合法替代；每个消费者周期最多应用一个主行动增量和一个受控互补信号。同一行动不能在本周期内凭自己的输出伪造自己的前置条件。

## 有限关系和瓶颈逃生

领域之间通过有限关系连接：

- **互补**：铁路与发动机、军队与军需、大学与识字/行政；
- **替代**：国内生产与贸易、外交保障与军备、补给改善与扩大军队；
- **冲突**：高额海外承诺与财政整固、战争扩张与战后恢复；
- **使能**：某项能力建立后，另一项行动获得更高可行性。

关系最多展开两级并做循环检测，不能成为全世界规划器。每个主要压力尽量有低依赖的逃生路径：短缺可以在本地生产、合法贸易或生产方式替代之间选择；行政不足可以先补行政、选择低行政成本建设或放缓新增制度；战后可以先恢复军需和基础设施，再重新评估扩张。所有路径仍由原版资格和成本决定。

## 双时钟、单调性和数值校准

运行期使用安全时钟和结构时钟：战争、违约、重大战败和关键短缺等已核实冲击可以快速重评估；教育、产业、行政、贸易、法律和海外等慢变量按月度或路线 TTL 更新。两种时钟共享事实和预算，不保存无限历史。

安全信号需要满足可测试的不变量：压力缓解不能提高同一危机优先级，承诺增加不能无条件提高扩张，替代路径出现不能让行动依赖变得更严格，删除普通事实不能提高非安全扩张。例外必须属于明确的安全回退并有独立证据。

数值不固定为全局激进或全局保守，而是按条件调节：基础倾向、已确认压力、可行机会、承诺成本、政治/外交风险和消费者限幅共同决定最终增量。参数按领域和消费者校准，不按国家名称写死；工程校准只证明范围、方向、单调性和回退，不预测具体 GDP、战争或改革年份。

## 时间和反馈

运行期只保留有限的当前路线、进入/过期日、冷却、必要摘要和固定大小缓存。月度刷新处理普通变化，重大冲击 hook 触发重新评估；TTL、冷却和退出迟滞防止每个小波动都切换路线。新增时间记忆必须证明存档默认、禁用停止、国家消失和版本迁移行为。

## 广度和深度

19 个产品子域逐项登记：政治/法律、人口/劳动力、社会/健康/福利、财政/债务、行政/国家能力、产业/生产方式、农业/资源、市场/商品/贸易、科技、教育/知识、外交/条约、宗主/属国、陆军/动员、战争/军需、海军/海上投射、殖民/海外、地理/目标州、身份/文化、时间/冲击。

每个子域的深度等级为：

- D0：保留原版；
- D1：能观测并登记事实；
- D2：事实进入状态/压力/机会/承诺并可解释；
- D3：具体原版消费者获得有界调整；
- D4：具有有限时间反馈和退出机制。

最终目标是对所有可合法接入的面达到 D3，能安全表达时间语义的面达到 D4；引擎不暴露或没有消费者的面要如实保留低等级，不用文档和数量掩盖边界。

## 原版兼容性

Mod 不替换整个 Victoria 3 AI，也不直接执行国家行为。它通过原版已经存在的建筑、生产方式、科技、教育、法律、政府/利益集团、市场/贸易、外交/宗属、陆军、海军、战争、战后、殖民和目标州等消费者提供有限倾向增量。原版的实际成本、资格、前置、政治支持、随机、谈判、拒绝、执行、失败和终结零分保留原职责。

活跃原版策略对同名字段的合并或覆盖语义如果无法从底本和运行证据确定，只能报告静态接线，不得宣称所有策略状态下都生效。玩家、关闭开关、未知和不可用路径必须回退原版。

## 兼容性协商、确定性构建和交付物

Mod 按底本版本、字段、作用域、消费者和策略遮蔽建立能力矩阵。能力完整时使用 `full`，只有部分证据时使用 `degraded`，无法安全接入时使用 `vanilla`，底本漂移且无法判断时使用 `unsupported` 并硬失败。不能用旧生成物掩盖新底本的变化。

固定源、底本、Python、依赖和配置时，生成结果、manifest 和解释排序必须稳定。最终交付分为运行时 Mod 包、开发/分析 Python 工具和证据包。运行时包不带 Python、探针、日志、快照和原版资源；工具不作为游戏依赖；证据包记录源、底本、包、检查和限制的对应关系。

## 性能和证据

生成期共享解析、底本指纹和关系图；运行期按月/冲击刷新，复用已求值事实，限制候选数、关系深度、状态数量和解释历史。禁止世界级扫描、后台服务和无界缓存。

静态检查证明字段、作用域、生成、未知回退、玩家边界、包合同和编码；模拟证明 Python 参考与 PDX 子集在覆盖范围内一致；日志和存档证明实际记录到的变化；它们都不能单独证明长期 AI 行为质量、历史合理性、平衡、后期性能或 Workshop 体验。运行期事实读取数、候选数、关系深度、持久变量、解释记录和 hook 频率必须有预算。长期验收由用户在固定标准包上完成。

# 处境行动决策内核设计

> 设计版本：30.0（2026-10-31）；状态：目标设计，尚未完整实现。已发布的 2.0.0 是迁移基线，不能据发布、目录齐全或既有检查通过推断本设计完成。
>
> 顺序和任务见[实施计划](exec/mod重设计-实施计划.md)，逐域范围与场景见[行动覆盖与验收](04-行动覆盖与验收.md)，实际进度见[当前工作清单](当前工作清单.md)。生成与证据遵循[工程基线](exec/工程基线-1.0.md)。

## 1. 不变的目标与完成含义

**Situated AI 让每个国家基于自身处境和可观测信息，在原版机制内持续做出符合自身约束与利益的相对最优决策。**

“最优秀的机制和架构，极致广度和极致深度”按以下可检验合同落实：

- **机制**：具体行动是最小决策单元；事实、状态、目标、行动、关系、仲裁、适配、时间退出各司其职，使用同一个语义模型生成游戏脚本。
- **广度**：锁定原版所有已发现的可观察面和 AI 决策消费者均有处置；已有生产写入无遗漏迁移，19 子域及目录新增子面无未分类项。九粗域、卡数、字段数不能替代覆盖。
- **深度**：接入行动具有处境敏感、成本敏感、替代/互补、局部未知回退、必要时间退出和可追溯消费者；每个声明参与判断的因素有改变生产输出的见证。
- **架构质量**：拒绝重复作者、装饰性配置、隐藏旁路、万能健康分、无限叠加、同名误接、循环前置和无界世界扫描；同等语义下选更简单、运行成本更低的表示。
- **边界**：验证功能确实实现、参考语义与生成脚本一致及工程可交付性；长期行为、平衡和游戏内性能由用户验收。未实现功能不能归入用户长期验证。

完成证明针对锁定底本、冻结范围和本文语义，不声称数学上的全局最优或真实历史必然重演。新版本和反馈可以产生后续改进，不能反向抹去本轮未实现项。

## 2. 架构选择与实际运行

选择**行动中心、类型化证据、有限关系图、按消费者仲裁、语义编译到原版**。独立条件补丁只作迁移输入，不能继续成为第二套业务系统；外部 Python 常驻规划和替换整个原版 AI 不进入方案。

```text
原版事实 + actor/target 上下文 + 有限路线记忆
  → Observe：事实可用性、作用域、单位和未知
  → Assess：能力 / 压力 / 机会 / 承诺及来源
  → Prioritize：危机、恢复、能力、结构、安全、政治、外交、海外目标
  → Propose：该消费者的具体候选和低依赖替代
  → Coordinate：局部互补、替代、冲突、使能与机会成本
  → Select：可行候选的有界、确定性仲裁
  → Adapt：单一作者对消费者应用一次有界倾向
  → Exit：保持、退出、抢占、TTL、冷却和失效清理
  → 原版资格、成本、支持、随机、执行、拒绝和失败
  → 下一次合法求值重新观察
```

Python 定义语义、构建关系、分析、编译和参考求值；游戏只加载有限 PDX 分支及合法生命周期脚本。动态事实不得在生成期冻结；图可以生成期展开，但条件、动态 rank 和输出仍须在游戏求值点保留等价意义。

同一国家可在建筑、科技、法律和外交等不同消费者上并行产生倾向，没有一个全局主行动锁住所有行为。主路线仅表达姿态和惯性。影子预算表达机会成本，不声称跨消费者实际扣财政或预留建设队列。

## 3. 类型化数据与单一来源

生产配置在 `mod/decisions/`，实现位于 `src/pdx/situated/`。下列合同不可被占位字段替代：

| 对象 | 必须包含的内容 |
|---|---|
| `EvidenceSpec` | ID、底本指纹、源文件和 AST 路径、actor/target 作用域、参数、类型、单位、范围、合法求值点、刷新成本、未知策略 |
| `EvidenceValue` | 事实 ID、原始值、known/stale/unsupported、来源；未知不是 false、0 或健康 |
| `SignalSpec` | 能力/压力/机会/承诺命名空间、输入、类型化派生表达式、方向、分档、未知传播和可用时机 |
| `GoalSpec` | ID、激活和解除、时间尺度、危机等级、允许行动族；优先级不是国家标签 |
| `ActionSpec` | ID、族、具体消费者、actor/target、证据、硬边界、软档位、消耗、rank、效果、关系、退出和解释 |
| `RelationSpec` | 源/目标、类型、条件、共享证据身份、作用域、上限和失效条件 |
| `ConsumerSpec` | 源文件、定义 ID、字段 AST 路径、作用域、add/multiply 及单位、原版资格和终结尾部、限幅、策略遮蔽 |
| `TemporalSpec` | 刷新、进入/保持/退出、抢占、TTL、冷却、存档默认、玩家/关闭清理和变量上限 |
| `DecisionIR` | 类型化条件、候选、动态 rank、选中/拒绝原因、去重证据、单次输出和回退；参考器和 PDX 共用语义 |
| `CoverageRow` | 原版决策面、子域、事实、信号、目标、行动、消费者、生命周期、证据、处置和未完成原因 |

事实身份使用 `(source, engine, scope_path, argument, unit)`，禁止只按短 key 合并。原版 getter 与 `sitai_` 派生触发器分开登记。声明了压力、机会、承诺、关系或退出字段却无生产使用者，视为死配置并失败。

## 4. 行动卡是唯一的最小决策单元

一张生产卡对应**一个具体行动在一个具体消费者上的倾向**。行动族可以展开到多个建筑、科技、法律、商品和目标；每个实例有稳定 ID、真实目标和证据。族名、模板、普通 if 和库存不计为已实现卡。

“修复产业瓶颈”是族；工具、铁、煤、发动机、铁路等要按各自商品、州、技术、投入和消费者展开。把旧规则机械改名为卡，或让一张总卡拥有所有领域，均不满足要求。

一张卡可包含多个强度档和反例；条件规则是卡内部实现，不能绕过关系与仲裁直接写生产字段。只有消费者适配器能写 PDX，owner 为 `situated_kernel`；旧模块不再贡献独立业务增量。

### 4.1 硬条件与软证据

- **原版资格**：保留前置、成本、政治支持、随机、拒绝、零分和失败；不加资源、不改玩家路径、不强制执行。
- **Mod 安全边界**：`is_ai`、开关、核心输入已知、作用域合法、输出有限、目标有效。额外硬条件必须解释为何不能作为软证据。
- **软证据**：财政、行政、政治、市场、科技和教育按独立局部档位参与；不把全部健康条件作为发展通行证。
- **低依赖恢复**：每种生产压力有一个只依赖该压力及必要资格的修复候选，或有原版无法接入的字段级证据。

基础发展不要求盈余、行政正值和高合法性同时成立；战时不一概关闭教育、研究、军需和恢复。债务可抑制昂贵新增承诺，不能无差别否决修复危机的行动；研究倾向不被误当成大学维护费或新增军费。

### 4.2 状态与目标

四层 `recovery/foundation/stable/expansion` 只表达承受能力；八需求 `fiscal/administrative/political/education/industry/security/reconstruction/overseas` 可以并存。
目标至少有 survival、recovery、capacity、structure、security、political、diplomatic、overseas，各自定义激活、解除和时限。
观察不到的建设承诺、政治支持细节或战争历史不得凭常识补值；代理量必须标注来源和局限，不冒充真实预算。

## 5. 有限关系与联合决策

关系必须带条件，不能只是永久给行动优先级加一。

| 关系 | 语义 | 反例要求 |
|---|---|---|
| complements | 已证实可实现的局部条件提高另一行动边际价值 | 未知/不成立无奖励；同事实不重复计算 |
| substitutes | 主路径不适合时，合法替代获得机会；同时可行时比较成本 | 高成本、封闭市场或原版不允许的替代不伪造资格 |
| conflicts | 竞争同类承诺时提高成本或降低倾向 | 不形成互相惩罚环；跨消费者不冒充真实互斥锁 |
| enables | 已建立、可观察的能力提高后续路径档位 | 选中候选不等于能力建立；禁止本周期自我使能 |

最多展开两级依赖；有向依赖/使能必须无环。对称替代、互补、冲突按配对记录，不能误判成有向前置循环。端点必须是生产行动；缺合法替代时记录原因，不虚构卡。作用域不能越过消费者实际可观察上下文。

必验联合链：原料—工具—能源—运输—工业；教育—大学—科研—生产率—财政；行政—制度—民生—稳定—改革；战争—军需—财政—恢复；海军—补给—贸易—海外；外交保障—军备；宗主关系—自治—财政/安全；身份—政治可行性—迁移/劳动力。
每条链要求正面、断链、成本增加、未知四种生产见证，不能用注释或共享同一事实代替因果接线。

## 6. 仲裁及数值语义

在消费者可观察上下文内先过滤安全边界，再比较有限的、同尺度分档 rank：

```text
(危机缓解, 目标紧迫性, 已确认瓶颈缓解, 可行性,
 能力建设收益, 机会档位, -新增承诺成本, -政治外交风险,
 路线惯性, 稳定行动ID)
```

各普通分量取0–3档，惯性取0–1，行动ID只作稳定决胜；各档的原版阈值在消费者合同中明确。货币、识字率和军力不能直接相加。不可行候选不能靠高危机分获胜。政治约束局部作用于政治行动，不能全局阻断经济。
成本不能只放在词典序末尾、仅同分时起作用：先用该行动实际消耗的承诺/风险档位调整本地可行档和效果强度，再作rank比较。每个消费者必须给出完整的收益档×成本档决策表；成本增加至少在一个非同分场景降低强度或切换替代。零成本修复不依赖无关预算，不能把全财政条件重新变成硬门。
可作同消费者内的语义支配消除：只有一候选在全部适用维度不劣且至少一项更优、效果和资格可比较时才消除被支配候选，并保留理由与等价证据；不能按固定top-N静默截断。
每个“参与 rank”的配置都有只改变该因素就改变主行动或强度的见证；无见证不得声称参与。

每个消费者一次最多一个主行动及一个受控互补信号。二者在同一个表达式中合成并只限幅一次，不是两次独立写入。方向与幅度来自消费者合同，不由压力总分推导；鼓励和抑制都须可表达。

- `multiply` 以 1 为中性，初始区间沿用 `[0.5, 1.5]`；零、负基值和终结零分独立核验，不把不可选项变成可选。
- `add` 以 0 为中性；逐字段登记原版尺度、上下界和插入位置，不统一套用“10 分”；工程外层保护范围仍为 `[-50, 50]`。
- 强度至少有中性、温和、明确档，危机限幅独立登记；不能对所有字段复制同一倍率或统一激进开关。
- 现有健康阈值、TTL 100 日、冷却 62 日先作基线；改阈值须有边界、方向、局部可达和差异收据。

## 7. 参考语义到 PDX 的降低

类型化 `DecisionIR` 为生产权威语义；Python 参考器和 PDX 发射器读取它。测试另有手写期望和独立 PDX AST 求值器，防止共享错误自证。
IR 只含类型化比较、三值 all/any/not、局部档位、有限词典序选择、证据去重、限幅、固定加乘和有限状态转移。
无法等价降低时构建硬失败并列出行动/事实/消费者，不能丢弃因素、退回固定排序或以注释宣称完成。

允许常量折叠、共同子表达式、互斥分区和决策 DAG，前提是行动、增量、回退、解释和未知传播保持一致。不能只给旧优先级乘常数/加固定偏移就宣布动态仲裁完成。
逐卡比较候选、rank、主/替代、合成值、原版尾部和状态转移；source map 从配置 ID 追到 IR、PDX AST 和 witness case。
冻结 2.0.0 写入逐项标 migrate/merge/remove/retain_vanilla；不得隐藏未迁移规则。

## 8. 时间与反馈

安全条件在已有消费者求值时实时检查，已核实违约事件用于危机刷新；结构姿态沿用月度国家 hook。不承诺不存在的“每日安全 hook”；无事件则在消费者时机读取。
仅对确有独立价值的族复用六路线记忆；即时建筑/科技不因无变量而被错误要求 D4。需要记忆的行为必须实现进入、保持、退出、抢占、恢复、TTL、冷却、禁用/玩家清理、存档缺失默认。
战败来自真实原版状态；反馈表示观察实际处境变化后重评估，不将“选中卡”当成“行动已成功”，不声称在线学习。

## 9. 广度、深度与合法降级

按[行动覆盖与验收](04-行动覆盖与验收.md)登记 19 子域；原版发现新增面须加入范围。深度分为事实、处境、成本、关系、消费者、时间（适用时）、未知、安全、编译等价和复杂度。D0–D4 是每个具体实例的可验收等级，不是子域平均分：

| 等级 | 实例必须具备 | 不能用来替代的证据 |
|---|---|---|
| D0 发现 | 原版来源、定义、字段、actor/target、作用域、单位和 source hash | 目录存在、旧库存计数、文件名或报告提及 |
| D1 证据与处境 | 可观察事实、三值/新鲜度、能力/压力/机会/承诺及局部目标的真实派生 | 变量命名、固定国家画像、单一总分 |
| D2 行动与关系 | 具体行动卡、消费者、硬资格、软档位、成本、效果、关系、替代和去重 | 行动族模板、旧规则改名、永久 priority |
| D3 生产与反事实 | source→IR→PDX、原版尾部、选中/回退/未知/负例、动态反事实和唯一 owner | Python 参考器、文本哈希、schema/报告存在 |
| D4 时间与运行合同 | 适用的进入/保持/退出/TTL/冷却/抢占/清理、预算、确定性、包和恢复收据 | 所有卡统一标 N/A、声明不存在的 hook、用户未来游玩 |

完成要求所有合法接入面至少 D3，适用时间语义达到 D4；D0–D2 只能说明调查或局部设计完成，不能计入生产实现。一个实例缺任何适用层都保持 pending/blocked；不能用同一族或同一消费者的高等级见证覆盖其他实例。
不能用某子域一个 D3 字段掩盖其他可接入面未实现。

| 状态 | 条件 | 完成口径 |
|---|---|---|
| implemented | 生产卡、IR、PDX、正反见证和审计齐全 | 计入实现 |
| engine_unexposed | 底本、官方接口、相关作用域/消费者遍历无合法接口；列出替代审查和原版保留 | 计入已审计，不计入 Mod 已实现 |
| pending | 字段存在未接入、测试不足、编译缺失或语义不等价 | 阻止完成 |
| blocked | 缺底本、语义冲突、无法合法降低，列恢复条件 | 阻止完成 |

实施困难、时间不足和卡未扩展不得标 engine_unexposed；不能缩小范围或去掉成本/关系以便通过。
保存 discovered、legally_addressable、implemented、engine_unexposed、pending、blocked 的分母和数量，逐项证据优先。

## 10. 兼容、性能、交付和证明边界

固定 Victoria 3 `1.14.5`；生成和正式包读取真实底本，缺失/漂移硬失败。离线 CI 只验证冻结合同。策略遮蔽逐定义登记，不能把默认策略接线说成所有策略生效。
不改玩家、不赠资源、不覆盖整套 AI、不世界扫描；第三方 Mod 不在兼容承诺内。性能按计划静态上限和同口径测量，不能为预算删卡、丢状态、固定 rank 或缩测试集。
源码 UTF-8 无 BOM、LF；游戏 BOM 仅在交付边界；11 种本体语言键集、占位符与路径完整。
目标交付为架构性大版本 `3.0.0`，这是计划目标；实现完成和授权交付前生产保持 `2.0.0`，既有标签不移动。

静态验收先证明承诺功能完整进入生产，再核对字段、包和工程质量。长期用户验收单列，不要求计划长期跑游戏，也不能让用户承担实现缺口。

## 11. 与当前基线的差距

2.0.0 有 7 张显式卡、4 个直接行动字段、广域规则、六路线和工具链。状态、关系和仲裁部分仍是辅助模型，不能认定全域运行语义完整。
本设计是重开后的目标；旧 K0–K13 完成声明不再作为本目标验收依据。既有检查和交付事实仍保留，但按新合同重新评价。

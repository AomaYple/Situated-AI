# Situated AI 架构子计划

> 对应[架构主计划 A1.0](架构主计划.md)，2026-11-02。P0–P11 **全部未开始**。
> 本页集中维护 12 个有独立交付物和出口的子计划，避免 12 份空壳文件。每个子计划实现主计划的一部分，不另建竞争架构。
> 本轮只落盘与复核设计；已有旧候选代码不能自动计入新子计划进度。执行仍待用户后续指令。

## 1. 原子项、状态和证据

下表每一行是可独立审查的交付任务。涉及多目标的任务必须在 P0 独立发现范围确定后展开为原子项，不能以一行打勾代替全目标完成。
展开键为 `P阶段.任务 / surface_id / action_instance_id / binding_id / context_variant / witness_id`；无动作的基础合同项使用明确的合同 ID。

统一记录：

```text
task_id、requirement_ids、depends_on、scope_hash、source_hashes
输入与对象身份、预期与理由、生产落点、参考输出、实际PDX输出
证据类别、结果文件、状态、失败原因、下一动作
```

状态为 `not_started → in_progress → implemented → verified`；失败保留 failed，依赖或证据不足保留 blocked/pending。
“implemented”要求生产入口可达；“verified”要求全部适用见证通过。报告存在、字段合法、测试绿或计划勾选均不能跳过此区分。
`not_applicable` 必须列精确理由、证据和影响，并在独立范围审查中复核；不能因实现困难使用它。

所有子计划都遵守主计划 A01–A20。下述产物是未来实现要求，不是本轮已生成的文件或现成命令。
P0 先冻结机器记录格式、来源索引与输出路径；再生报告写入忽略的 `tools/out/`，版本化合同放在生产源或 `research/situated/`。
每个子计划只保留一份必要结果收据；不得把所有原子输出复制成大批手写 Markdown。

## 2. P0：原版能力、范围与失败基线

**依赖**：主计划评审与执行授权。**职责**：先知道能够做什么、完整范围是什么，保留真实起点。
**落点**：`vanilla_inventory.py`、证据模块、`research/situated/`、收口检查器的范围与追踪入口。
**接口**：产出 `SurfaceContract`、`ContextContract` 的底本依据与独立范围 manifest，供 P1/P2 使用。

| 任务 | 交付与通过边界 | 必须拒绝的情况 |
|---|---|---|
| P0.01 基线冻结 | 记录原版/源码/生成器哈希、旧 writer 与入口、旧包身份；已知失败各有可定位复现输入或明确缺失原因 | 用历史全绿替代当前状态 |
| P0.02 独立发现 | 遍历原版脚本目录、定义、字段与事实接口；发现分母不依赖现有行动，解析失败逐项可见 | 从已有 ActionInstance 反推“全部原版” |
| P0.03 能力分类 | 每面记录读/写能力、类别、actor/target/auxiliary、操作、时机与精确来源；未知保持 pending | 同名字段猜作用域、未知改名不可控 |
| P0.04 外连接 | 独立范围与旧 writer、候选新行动全外连接；孤立原版面、孤立 writer 和重复 owner 均输出错误 | 只检查生产清单内部自洽 |
| P0.05 验收记录 | 建立 A01–A20 与原子项、源、见证、状态的记录格式；删除或漏项检查失败 | 新主计划仍只由旧 D 门自证完成 |
| P0.06 迁移处置 | 每项旧失败/能力有修复、迁移、保留边界或退役路径；退役需证明无必要调用与功能损失 | 删除失败测试消红，或将全部旧失败推给长期验证 |

**出口**：全部发现项已登记；P1/P2 使用的合同已证实；未解决面继续占范围并阻止最终完成，不能为等它们而制造假证据。
P0 可以完成范围登记，不代表所有能力调查都已解决；结果需分别标明“范围建立”和“能力闭合”，后者由最终门重新检查。

## 3. P1：事实、处境和因果依赖

**依赖**：P0 对应能力证据。**落点**：事实 schema、reader 与处境求值模块、领域声明。
**接口**：`observe(context, FactSpec) → Observation`；`derive(observations, dependency_graph) → Situation`。
两者为目标接口合同，实际函数签名由此子计划固定，不能同时保留含义不同的同名接口。

| 任务 | 交付与通过边界 | 关键见证 |
|---|---|---|
| P1.01 reader 身份 | reader 全参数、actor/target/auxiliary 与定义常量类型化 | 同名不同商品/法律/州/国家不得命中同一观察 |
| P1.02 单位和取值 | 每个事实有单位、有效区间、符号方向与合法转换 | 比例与百分数、库存与流量、国家与州量混用均拒绝 |
| P1.03 未知与新鲜度 | known/unknown/unavailable 原因显式；持久来源有新鲜度与失效合同 | 缺对象不变零，旧观察不当本次已完成 |
| P1.04 独立处境 | 需求、能力、风险、机会与真实承诺独立派生 | 低识字不降低无关产业资格；借款与违约不同 |
| P1.05 有向依赖图 | 事实/派生节点有向无环，拓扑序与来源完整；跨 scope 映射合法 | 当次循环、自我贡献和串对象拒绝 |
| P1.06 用途与裁剪 | 每个生产 reader 有可改变输出的使用方；消费者只取可达依赖 | 无用途全量读取、未绑定只为凑广度的 reader 拒绝 |

**出口**：受本批使用的全部事实有合法输入、未知/越界、单位和身份反例；后续新事实必须满足同一合同再接入。

## 4. P2：最小行动、消费者合同与纵向骨架

**依赖**：P0；P1 可按已证实输入接口配合。**落点**：`schema.py`、`decision_ir.py`、编译入口、消费者适配模块。
**接口**：声明 `ActionSpec/Binding/ConsumerContract` → 类型化 IR → 参考结果、PDX AST、`DecisionTrace`。

| 任务 | 交付与通过边界 | 关键见证 |
|---|---|---|
| P2.01 对象分层 | domain/objective/action/instance/variant/binding/opportunity 分开；实例 ID 完整 | 仅换阈值不增加卡数，定义目标不冒充运行期对象 |
| P2.02 行动 schema | 具体目的、对象、资格、事实、收益、成本、风险、关系、退出与消费者完整 | 空收益、装饰关系、无生产落点拒绝 |
| P2.03 消费者类别 | 数值、布尔、姿态、静态参数分别适配；固定单位、方向和合并操作 | 公司资格当浮点、建设目标当直接队列指令拒绝 |
| P2.04 唯一 owner | writer key 唯一；同字段所有贡献进入一个组合器 | 规则旁路与显式卡双写、默认/活跃定义混接拒绝 |
| P2.05 垂直样本 | 一个已证实消费者从声明到实际生成、独立 PDX 求值、追踪全部打通 | 只有抽象类型和报告不算出口 |
| P2.06 原版保护 | 原版尾部、拒绝、零分、资格和玩家/关闭同一上下文等价 | 加分复活不可行目标、玩家路径变化拒绝 |
| P2.07 新门接线 | 收口工具识别新要求、源哈希和功能见证，缺任一项拒收；旧 D 合同保持历史身份 | 运行旧检查器后声明 A1.0 完成 |

**出口**：可运行纵向骨架与所有适配类别的合同具备真实正反例。P3 在该路径上扩展联合权衡，不另建演示内核。

## 5. P3：联合多目标评估与数值机制

**依赖**：P1、P2。**落点**：行动评估、数值 schema、参考器、PDX lowering、对应测试。
**接口**：`evaluate(ActionIR, Situation) → ActionEvaluation`；`combine(ConsumerContract, evaluations) → ConsumerDecision`。

| 任务 | 交付与通过边界 | 关键见证 |
|---|---|---|
| P3.01 归一曲线 | 明确单位→贡献、分段点、上下限、单调方向和实际定点舍入 | 每个拐点前/等/后，零值负值和溢出；误差不能隐藏变号 |
| P3.02 净贡献 | 收益、成本、风险同时参与，不能由规则先后屏蔽 | 固定收益时成本升高净支持不升；关键成本未知不额外鼓励承诺 |
| P3.03 因果去重 | 因果组、主证据与权重上限进入生产；缺项不重新归一 | 增加同义短缺信号不重复获奖，少知道信息不更乐观 |
| P3.04 同字段组合 | 互斥变体、因果组与独立目标分别处理，合并后限幅一次 | 同字段正负项并存；目标换序不改变非优先语义 |
| P3.05 基础可达 | 删除无关全满足门；高强度只增加适用成本，基础合理行动仍可评估 | 低教育/行政/正常借款组合不全局封锁发展 |
| P3.06 三方核验 | 手写预期、独立参考器和实际 PDX AST 对同输入一致 | 人为倒置成本符号或换 target 应产生失败 |
| P3.07 展开预算 | 固定纵向样本，量化分支、谓词、深度、字节及 Python 内存 | 发现组合爆炸先分解语义；不能删成本或隐藏分支 |

必须独立写入的最小算法预期：

| 归一化输入（其他项为零） | 预期净贡献 |
|---|---:|
| 需求 0.60、能力收益 0.15、成本 0.35、风险 0.10 | 0.30 |
| 相同收益、成本升至 0.65 | 0.00 |
| 需求降低到 0.10、其他同第一行 | -0.20 |
| 增加一项属于同因果组的重复价格信号 | 仍为原组合同结果，不重复加 0.60 |
| 必需成本未知 | 本行动额外调整为中性，其他独立行动保持其结果 |
| 消费者原版终结零分＋正贡献 | 仍为原版终结零分 |

以上是内核算法样本，不是虚构的游戏 getter；字段转换后的数值另按真实消费者单位验收。
**出口**：适用边界、定点语义、输出方向和反例全部通过；没有合法 PDX 表达的机制不得先在参考器中宣布支持。

## 6. P4：跨域协调、反馈与有限记忆

**依赖**：P1–P3。**落点**：关系 schema、协调模块、既有生命周期入口及迁移合同。
**接口**：`RelationSpec` 只引用已验证事实/实例；记忆刷新产生有限状态，纯评估只读取。

| 任务 | 交付与通过边界 | 关键见证 |
|---|---|---|
| P4.01 六类关系 | 使能、互补、替代、冲突、机会成本、饱和/退出各有两端与条件 | 每关系适用/不适用、未知、不同对象反例 |
| P4.02 实际结果反馈 | 条件基于真实完成或变化，前后输出可追溯 | 提高研究分不使能生产；实际研发后才改变 |
| P4.03 跨接口边界 | 只传播可观察压力和偏好，多个领域可并存 | 建设高分不关闭外交或教育；不预留真实资源 |
| P4.04 记忆必要性 | 每轴有独立价值证据；最多 3 轴、每轴最多 4 模式、总计最多 9 持久值 | 没有价值不创建；不按卡增加变量 |
| P4.05 生命周期 | 进入/退出迟滞、TTL、冷却、紧急退出、关闭/玩家接管清除合法且有边界 | 到期前/等/后、切换临界、小波动、危机、旧存档、重启 |
| P4.06 有界影响 | 同一行动各轴记忆偏差绝对值之和≤0.15；无副作用评估、旧路线不双写 | 记忆不得绕过资格、危机风险或全局锁死基础行动 |

**出口**：运行可表达、状态有限、关系无当次循环。不能证明合法生命周期的需求保持未完成，不能藏入永不过期变量。

## 7. P5：经济、社会与知识行动

**依赖**：P1–P4。**落点**：领域声明、真实消费者适配、逐目标见证。
**范围**：主计划 7.2 中 P5 各面及 P0 新发现的同类面；每个目标使用共同机制，不新建经济专用旁路。

| 任务 | 通过边界 | 必须区分的反事实 |
|---|---|---|
| P5.01 财政融资 | 财政压力进入相关行动成本，流量/存量/偿付分开 | 正常借款 vs 违约；低成本修复 vs 新大规模承诺 |
| P5.02 建设投资 | 基础建设、容量与扩张按具体对象评估；保留原版私人投资边界 | 小国、低教育、行政不足仍有合理基础支持；容量饱和退出 |
| P5.03 资源农业工业 | 全合法目标展开，投入、劳动力、产出用途、地区差异进入评估 | 同价不同配方/缺工/资源；投入恶化不能被产出奖励掩盖 |
| P5.04 生产升级 | 科技、配方投入、产出需求和劳动替代联动 | 未研发、已研发但投入不足、投入充足分别不同 |
| P5.05 市场运输 | 真实连接与容量瓶颈影响局部行动 | 铁路/港口改善前后、无合法运输接口时诚实限制控制精度 |
| P5.06 科技教育 | 每个合法科技/教育落点有用途、前置、成本和边际价值 | 低识字保持研究需求；不可研究不被权重解锁；饱和不无限奖励 |
| P5.07 人口就业 | 工作与劳动力状态影响相关行动，社会风险不当全局禁令 | 失业/缺工、迁移条件变化、不同州不串线 |
| P5.08 粮食健康福利 | 民生需求、可负担与制度容量联合；短期救济与生产修复分别投影 | 高需求低财政仍比较低成本修复，不全盘归零 |
| P5.09 公司组织 | 资格、意愿、候选权重与建设目标分别有合法合同 | attainable 与 available 区别、空州条件无效、不伪造直接公司行为 |

**出口**：P0 属于本域的全部合法绑定达到主计划 7.3 深度合同；至少形成“投入—建设—运输—研究—产业升级”和
“人口—就业—粮食—健康—财政”两组实际事实反馈链。每链同时有成立、不成立、未知、成本恶化、目标变化与改善退出见证。

## 8. P6：内政、治理与身份行动

**依赖**：P1–P4。**落点**：政治、行政、制度与身份声明及对应原版消费者。

| 任务 | 通过边界 | 必须区分的反事实 |
|---|---|---|
| P6.01 行政税收制度 | 缺口修复、税基与新增制度负担分别评估 | 缺行政提高修复需求，同时限制过度新增承诺 |
| P6.02 政府与利益集团 | 合法性、支持、利益阻力与联盟作用于对应选择 | 同改革不同支持；目标集团与行为国不混读；不得固定意识形态 |
| P6.03 法律与运动 | 具体法律后果、可行性、风险与机会进入联合评估 | 平稳时阻力大 vs 危机改变权衡；不保证改革成功 |
| P6.04 身份人物等级 | 按合法接口处置国家形成、等级、地区与人物因素 | 国家名变更不改变同条件决策；不可控人物行为不冒称实现 |

**出口**：全部合法目标与具体上下文闭合，法律证据缺失等旧问题有实际处置；“危机—支持/阻力—改革—治理/财政”的
条件链有真实两端、局部未知和不适用反例。任何政治模式不得成为无关经济行动的总资格门。

## 9. P7：贸易、外交、宗属与海外行动

**依赖**：P1–P4。**落点**：外部领域声明、条约/博弈/贸易/宗属/地区消费者。

| 任务 | 通过边界 | 必须区分的反事实 |
|---|---|---|
| P7.01 外部供给 | 进出口用途、路线负担、依赖风险与国内替代各有实际落点 | 可进口 vs 封锁/运输不足；不假装脚本控制完整贸易队列 |
| P7.02 关系条约 | 双方具体利益、承诺与机会成本有角色绑定 | actor/target 互换不同，条约名相同不等于利益相同 |
| P7.03 博弈与战争目标 | 安全、实力、收益和升级风险联合影响对应字段 | 小收益大风险、可信支持、退出替代与不同目标 |
| P7.04 宗属自主 | 保护价值、自主收益与外部支持分开，全部合法面处置 | 无支持弱国与有支持强国；自治变化不虚构独立成功 |
| P7.05 殖民海外 | 投射、运输、财政、资源与安全约束局部作用 | 同海外利益不同保障能力；过度承诺回落 |
| P7.06 集团与地区 | 成员/领导/地区角色利益及控制精度明确 | 合作互利与支配冲突；静态 stance 不冒称实时模式切换 |

**出口**：全部合法外部消费者目标闭合；“供给—贸易—运输—安全”和“海外利益—承诺—海军保障—财政”有完整反事实链。
跨消费者只声明协同倾向，不宣称一次全局最优外交组合或已支付共同预算。

## 10. P8：军事、安全与恢复行动

**依赖**：P1–P4。**落点**：军备、编成、装备、动员与安全姿态消费者。

| 任务 | 通过边界 | 必须区分的反事实 |
|---|---|---|
| P8.01 军事结构装备 | 陆军编成、装备/改装与技术需求按具体合法目标展开 | 科技有无、供给成本、无用升级、原版资格 |
| P8.02 动员与恢复 | 威胁、持续负担、损耗与战后修复联合影响倾向 | 威胁升高不自动无限动员；财政恶化约束承诺；恢复区别扩张 |
| P8.03 海军与物流 | 舰队、运输、海外保障与实际能力相连 | 相同贸易利益不同海军保障；缺合法战术接口不冒称直接指挥 |

**出口**：全部合法军事面和具体目标闭合；“威胁—承诺—军需—工业—财政—恢复”形成实际事实联动。
没有合法接口的战术、战线控制或内部作战状态保留原版，能力证据必须具体。

## 11. P9：全迁移、结构整合与旧逻辑退役

**依赖**：P5–P8 全部出口。**落点**：`mod/decisions/`、编译/适配入口、旧规则模块、CLI、生成锁、测试和导航。

| 任务 | 交付与通过边界 | 拒收条件 |
|---|---|---|
| P9.01 旧新映射 | 每个旧 writer 有新实例/适配设施或带依据的退役记录，设计变化有手写预期 | 简单重命名旧 rule_action；遗失目标 |
| P9.02 单内核切换 | 所有生产 writer 使用同一语义，旧路径不再可达，新增旁路为零 | 保留两套决策法长期相加 |
| P9.03 策略覆盖 | 全部默认/活跃定义按字段合并合同验证 | 只检查默认策略或漏掉同名覆盖 |
| P9.04 状态迁移 | 新旧记忆不会并存写入；玩家/关闭/旧存档失效规则可证 | 永久变量、过期状态继续获奖 |
| P9.05 内容整合 | 重复参数、无效行动、孤立事实、无用途关系和过时模块删除；调用/测试/文档同步 | 无证据删除历史原字节，或仍有装饰配置 |
| P9.06 重生成 | 读取锁定原版确定性生成，重复构建逐字节一致，全部变化可追溯 | 手改产物、静默旧冻结数据代替原版 |

**出口**：完整生产源进入单内核，无无效/重复业务路径；功能变化、保留与退役可逐项审查。

## 12. P10：全 Mod 复核、性能和最终工程门

**依赖**：P9。**范围**：整个 Mod，包含未改动的结构与内容，不仅审差异。

| 任务 | 交付与通过边界 | 拒收条件 |
|---|---|---|
| P10.01 独立范围复核 | 重新从底本发现并 join，全部合法面接线，unknown/pending 无遗漏 | 用卡数、writer 数或历史范围替代独立分母 |
| P10.02 全实例深度 | 主计划 7.3 各适用维度、关系两端、原子见证齐全 | 族级样例代替全部目标；无变化配置算实现 |
| P10.03 全语义复核 | 手写预期、参考器、实际 PDX AST 一致；全部策略尾部与回退核对 | 放宽断言、重写预期来掩盖差异 |
| P10.04 预算与测量 | 复核全部消费者静态预算、记忆上限；同口径测生成/测试时间与树/worker 内存 | 局部基准当整体提速；抬高看门狗掩盖异常 |
| P10.05 完整工程回归 | 稳定候选一次跑完贡献流程所需检查和全量验收；结果完整、无未解释失败 | 内存终止、缺 JUnit/coverage/collection/资源收据仍报通过 |
| P10.06 要求闭环 | A01–A20 与子计划、所有原子项、生产源、见证全关联，旧失败全部处置 | 孤立要求、未实现项、pending 或无依据不可控项 |

**出口**：完整功能静态语义验收与工程门通过。用户长期行为未验收仍明示，不阻塞此出口，也不被写成已通过。

## 13. P11：标准交付与用户长期验证交接

**依赖**：P10。**落点**：版本源、包生成、全语言本地化、说明/Workshop 文案、交付收据。
**外部动作**：只有执行时用户授权包含 Git/发布/部署才执行；本轮计划编写不触发这些动作。

| 任务 | 交付与通过边界 | 拒收条件 |
|---|---|---|
| P11.01 完整包 | 唯一标准生产包、合法 metadata/ID、全部本体语言、自有键/占位符/编码/封面/manifest 正确 | 探针、Python、日志、缓存、原版资源或历史实验进包 |
| P11.02 版本与发布 | 依据实际变更确定版本；固定源构建 ZIP/SHA；授权后 CI/中文 PR 合并与不可移动 tag/Release | 计划完成先于功能；新版本从旧候选包直接改名 |
| P11.03 安装与回滚 | 授权后部署同哈希包到标准 Mod 目录，核对路径与旧文件；回滚包和存档边界清楚 | 覆盖本体、误删用户存档/日志、未核对目标便递归清理 |
| P11.04 文档文案 | 规则/设计/状态/结果各单一来源；Workshop 按目标、内容、兼容、语言与链接描述实际交付 | 计划目标当已证实行为，原样沿用过时能力声称 |
| P11.05 反馈工具交接 | 保留用户使用的只读日志/存档分析与归档能力，记录版本/包哈希/来源/缺失信息 | 长跑工具成发布前必跑项，或不完整日志推出行为结论 |

**出口**：工程可交付与授权范围内的实际交付完成；仓库无缓存/运行态残留，当前入口不再指向已结束的执行计划。
计划完工收据保留在必要结果入口，旧细节可从 Git 历史追溯；不能为了整洁删除唯一失败或原始证据。

## 14. 验证节奏与接手方式

1. 每个任务先固定输入、手写预期、生产落点和失败标准，再实现与跑受影响检查；无关缓存不混入受控树。
2. 同一消费者链批量完成事实、行动、成本、适配和反事实；不要反复为未稳定候选跑全量，也不把所有验证拖到最后。
3. 独立子计划可以交错准备，但不能越过依赖认领出口；P5–P8 共享的内核变更统一整合，禁止各域复制一套算法。
4. 发现未预见的合法面，加入独立范围与所属子计划；只有新证据允许变更接口结论。影响架构时同步主计划要求与失效收据。
5. P9 冻结完整候选后做 P10 全域复核和一次完整验收；正确性通过后，才接受速度与内存优化结论。
6. 接手读取[当前工作清单](当前工作清单.md)；恢复点记录原子项、失败、来源哈希与下一可执行动作，不只记“推进一轮”。

本页不预报虚构工时或百分比。执行后按 verified 原子项及剩余未知范围报告进度，范围未闭合时不得给出“全部完成”的百分比。

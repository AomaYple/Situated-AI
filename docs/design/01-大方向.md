## 0. 目标

> **让维多利亚 3 里的每个 AI 国家，按「内部因素 + 外部因素」推出自身的最优解，
> 并让这个推导随玩家改变的世界一起重算** —— 世界由此自己运转，而不是照着剧本走。
>
> **实现方式：在官方基础上做增强（纯追加）。** 原版 AI 照常运行，我们只补它缺的能力 ——
> 不替换、不并行第二套 AI、不关任何原版子系统。**目标是"原版 + 我们 > 原版"。**

### 0.1 「最优」的定义与判据

> **最优 = 约束下的可行最优（feasible optimum）**
>
> * **目标函数** = 利益项（存续、财政、合法性、军力、市场依赖）× 身份项（历史使命、意识形态、威望诉求）；
> * **约束集** = 禀赋 · 位置 · 摩擦 · 外部结构（**含玩家**）· **以及它不知道的东西**（不做全知假设）；
> * **含义** = 在这个约束集内、按它自己的目标函数排序后，**可行集中最好的那条路**；
> * **不宣称**：全局最优、全知全能、永远算对。

**三条判据**：① **差分**——同处境下与基线行为不同，且方向符合它的目标函数；
② **自陈一致**——面板三行与它的实际行为一致；③ **反事实**——换掉一个输入，它的最优跟着变。

**派生义务**：必须把每个国家的**目标函数表**写下来（谁在乎什么、在乎多少），它让身份项显式、可审、可测。

**验收纪律**：每条推导都要能指出它**在修哪个具体毛病**（战败不改革 / 被围殴还硬扩张 / 破产还大兴土木…）。
写不出"修什么"的推导，一律不进实现。

### 0.2 反目标（明确不做）

不做**全局**最优；不让 AI 学玩家打法或钻机制漏洞；不让 AI 获得任何数值作弊（凭空收入、免费部队）；
不做不可解释的随机；不以「AI 更凶 / 更难」为卖点（卖点是**世界有意志**）。

## 1. 贯穿始终的原则

> 原则分三类：**兼容与性能**（P1–P2）、**工程与质量**（P3–P8）、**协作与可维护**（P9–P14）。
> 每条都写明**检查方式** —— 没有检查方式的原则不算原则。

### 兼容与性能

| # | 原则 | 检查方式 |
|---|---|---|
| **P1** | **兼容性做到最佳实践**：兼容目标**只有官方原版**；**纯追加**（不碰原版文件与键、不关原版子系统）；R3 禁用、R4 封存；命名空间 `sitai_`、文件平铺；三层检查（官方 / 存档 / 版本）；五道自动闸门；官方每次更新跑一次版本演练 | 五道闸门 + 版本演练（自动，见 §5） |
| **P2** | **性能做到最佳实践**：结构像原版 · **频率自己负责** · 热路径只读预存值 · **最坏情况实测**；量化世界不用连续曲线；事件驱动 + 分片；三条红线（不月度全扫 / UI 帧字段不放表达式链 / `weight` 块不写循环） | `gametimer_*.tsv` 平均值 + 压力场景；基准测试；预算见 §2 F9 |

### 工程与质量

| # | 原则 | 检查方式 |
|---|---|---|
| **P3** | **能 Python 化的都 Python 化**：工具链、生成器、校验器、测量脚本一律 Python；**引擎脚本由 Python 生成**，人只改数据源 | 仓库里不存在手写的生成物（生成物带头注释 + 重新生成无 diff） |
| **P4** | **能用成熟库的用成熟库**：不重复造轮子（解析、模板、校验、测试、基准都走现成库）；**依赖锁定**，新增依赖必须写明理由 | `requirements.lock` + 依赖审查（新增即记录理由） |
| **P5** | **正确性优先于速度**：任何提速都不得牺牲准确率；每一项优化都要有**前后对照**才允许合入 | 优化提交必须附对照数据（基准或 gametimer） |
| **P6** | **测试优先、覆盖率只升不降**：新功能/生成器/闸门/判据都要带测试；性质类逻辑用假设检验（hypothesis）；覆盖率门禁不得下调 | `pytest` + 覆盖率门禁（`v3 cov` 的分模块下限）；新增模块必须带用例 |
| **P7** | **性能测试与回归**：Python 侧跑基准（pytest-benchmark），游戏内跑 `gametimer`；**性能回归即红** | 基准套件 + 游戏内对照表 |
| **P8** | **可复现**：同样的输入 → 同样的产出；生成过程确定性（固定顺序、固定种子）；环境与版本记录在案 | 两次生成 diff 为空；`v3 lock` 指纹 |

### 协作与可维护

| # | 原则 | 检查方式 |
|---|---|---|
| **P9** | **单一数据源**：阈值/权重/文案集中在一份结构化数据里，脚本 + 本地化 + 文档同步生成 | 改一处 → 三处同步；重复定义即红 |
| **P10** | **每个数字有依据**：权重与阈值必须带 `why`，引到官方文件行号 / 探针日志 / 知识库章节 | CI 检查空 `why` |
| **P11** | **可观测**：面板三行（当前目标 / 最大压力与阻力 / 上次改主意的原因）+ 完整推导日志（可关） | 试玩者能复述"目标 + 主因"；日志可定位决策 |
| **P12** | **幂等与可回滚**：每阶段产出可安装、可卸载；卸载后回到原版基线；重复安装结果一致 | 装 → 卸 → 黄金回归；重复安装 diff 为空 |
| **P13** | **失败要出声**：版本不符、引用缺失、闸门不过时必须报错，**不许静默降级** | 失败路径有用例；缺引用即红 |
| **P14** | **小步、风险优先、不做无判据的工作**：先证生死门（H1）再做功能；每阶段有出口判据；新问题进 `backlog` 不展开 | 阶段出口判据 + `backlog` 记录 |

> **工具服务于 mod（P3 的推论）**：工具链不是独立项目 —— 任何工具化都必须能指到一个 mod 需求，否则不做。

## 3. 路线图

> 每阶段只写三行：**目标 / 出口判据 / 失败处理**。细节在执行时想，且只允许一页。

### 阶段 0 · 方向定稿 ✅（本文件即产物）

* **目标**：目标、原则、冻结项、验收口径定稿；文档入库。
* **出口判据**：`01 / 01a / backlog` 入库；无 TODO；本节之后不再修订方向。
* **失败处理**：个别契约谈不拢 → 只冻结 F1–F5，其余进 `backlog`。

### 阶段 1 · 可执行面盘点（**不写任何 mod 代码**）✅（`exec/阶段1-结果.md`）

* **目标**：盘清「能读 / 只能改 / 读不到 / 数据可驱动 or C++ 决定」；产出**粒度可行性表**（候选因子 → 读法 → 成本 → 是否代理 → 是否进第一版）、**失败模式清单**（症状 + 动哪个输入 + 判据）、**H1 实验设计**。
* **出口判据**：清单由**脚本生成**（不手抄）；"数据可驱动"比例足以支撑第一版。
* **失败处理**：关键能力多为 C++ 决定 → 收窄 §0 的承诺范围（并记进 §7）。

### 阶段 2 · H1 生死门（**一次游戏会话**）✅ **G1 通过**（`exec/阶段2-结果.md`）

> 只加了进度标记，三行判据未动 —— 方向没变，所以 §7 不新增行。

* **目标**：证明"改一处权重能在引擎重掷时改变落点"；顺带测重掷频率、权重块成本、新增策略的 loc/icon 需求、第四槽是否可能。
* **出口判据（G1）**：同开局两次、只差一处权重 → **UI 上 AI 策略不同**。
* **失败处理**：换挂载点（`possible` 门 → 世界状态引导）；连续两轮失败 → 触发 §4 承认失败流程。

### 阶段 3 · 最小闭环「战败求存」（1–2 次会话）

* **目标**：**俄罗斯单国**；**A 级为主**（战败记忆变量、改革窗口 JE、真实的贵族/合法性/财政变化）+ 三槽分布位移；产出第一份**生成物**（数据源 → 脚本 + 本地化 + 文档）。
* **出口判据**：G2 差分可复现 + G3 三行说得通 + **和平期占槽率 ≈ 0**。
* **失败处理**：差分不出现 → 换失败模式或换挂载点，**不加代码**。

### 阶段 4 · 框架化

* **目标**：数据源 schema 定稿 + 生成器完整化 + **五道闸门全绿** + 性能压力场景（大战 + 连锁破产 + 革命潮）。
* **出口判据**：**加一行数据 = 加一个处境**，不改逻辑；闸门与基准进 CI；`gametimer` 对照不超预算。
* **失败处理**：生成器撑不住 → 允许"手写一版再看抽象"**一次**，之后必须回到生成。

### 阶段 5 · 档案扩张（每批 2–3 个）

* **目标**：按失败模式清单扩张处境档案库；每批跑闸门 + 基准 + `gametimer` + 一次 A/B 会话。
* **出口判据**：每个档案带判据与 `why`；占槽率和平期≈0、危机期上升；G4 不退化。
* **失败处理**：档案加不进去 → 说明**抽象不对**（改抽象，不是加特例）。

### 阶段 6 · 可见性与难度

* **目标**：三行解释上屏（JE/tooltip → 必要时 scripted GUI）、难度三档 `game_rules`、中英本地化。
* **出口判据（G3/G4）**：试玩者能复述"目标 + 主因"；反馈关键词是"**世界活了**"。
* **失败处理**：解释不清 → 加第四行（身份项来源）。

### 阶段 7 · 长期维护（决定能不能活过下次官方更新）

* **目标**：版本演练固化、闸门与基准进 CI、每个数字带 `why`、维护预算、发布流程（changelog 对应到档案）。
* **出口判据**：官方更新后一次演练全绿；任意一个"为什么这么定"都能在文档里查到答案。
* **失败处理**：演练失败 → 修引用 + 更新生成器输入清单，并把这次失败写进 §7。

### 并行轨（不等主线，第一天起步）

`v3 modgen`（数据源 → 脚本/本地化/文档）、`v3 modguard`（五道闸门）、基准与性能测量脚本 ——
**它们是 mod 的构建系统**，按 P3/P4/P6/P7 用 Python + 成熟库实现，并自带测试。

### 四条纪律

1. **阶段 2 不过，3–7 一律不做**；
2. **A 级优先**：能改世界表达的绝不占槽；
3. **验收看分布**：单槽位移产生可复现差分即算达成；
4. **只生成不手写**；**不做第三方 mod 兼容**。

## 4. 验收

| 门 | 要证明 | 判据 |
|---|---|---|
| **G1 能操纵** | 权重改动能在引擎重掷时改变意图 | 同开局两次、只差一处权重 → AI 策略在 UI 上不同 |
| **G2 有因果** | 外部冲击 → 压力 → 意图变化，可重复 | A/B（战败组 vs 战胜组）差分稳定出现 |
| **G3 可读** | 玩家看得懂它为什么这么选 | 试玩者能复述"当前目标 + 主因" |
| **G4 不退化** | 世界像有意志，而不是"更凶 / 更随机" | 观测改革时机、结盟偏向、宣战克制；反馈关键词是"世界活了" |

**承重假设**：**H1** 权重能推动重掷落点（**生死门**，阶段 2）；H2 冲击→压力→意图可复现；
H3 摩擦能进权重并有效否决"最优"；H4 事件驱动 + 稀疏更新开销可控；H5 三行解释够用。

**承认失败的条件**：G1 连续两轮改挂载点都不成立 → 核心主张（冲击 → 意图）不成立，按 §7 流程修订本文件。

## 5. 实现期纪律（何时必须跑什么，不过怎么办）

> `01a` 管"标准是什么"，本节管"什么时候跑、跑不过就别往前走"。

| 时机 | 必须做的事 | 不过怎么办 |
|---|---|---|
| **每次生成后** | 闸门 ① 键/路径不相交、② 引用完整性、⑤ 生成可复现 + `why` 非空 | **不许提交** |
| **每次改 Python** | `ruff` + `mypy` + 相关用例；新逻辑带用例（P6） | 不许合入 |
| **每个阶段结束** | 闸门 ③ 稀释预算、④ 往返净度；`gametimer` **平均值**对照；补一份"结果"文档 | **阶段不算结束** |
| **阶段 4 起** | 性能**压力场景**（大战 + 连锁破产 + 革命潮 + 玩家大动作） | 不进入下一阶段 |
| **官方每次更新** | 版本演练：指纹 → 五道闸门 → 一次常规开局 → 重新生成比对 diff → 写 §7 | 修完引用再继续 |
| **每次加牌 / 加档案** | 命名空间与平铺检查；**占槽率**对照（和平期 ≈ 0） | 回退该档案 |
| **每写一个数字**（权重/阈值） | `why` 非空，且引到官方行号 / 探针日志 / 知识库章节 | 不许合入 |

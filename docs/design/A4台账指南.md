# A4 机器台账

唯一当前机器台账为 [A4实施台账.json](A4实施台账.json)。字段、枚举与严格嵌套结构的唯一来源是
[`a4_schema.py`](../../tools/ci/a4_schema.py)，引导器与校验器共用同一 schema；未知字段、缺字段和旧计划状态不会被静默接受。
目标与终态合同仍由[架构深化计划](架构深化计划.md)定义。本指南只解释机器入口，不签发产品完成。

从仓库根使用现有 `.venv`，不需要安装额外依赖：

```text
.venv\Scripts\python.exe -B -X utf8 -m tools.ci.a4_scope validate --stage A4-0
.venv\Scripts\python.exe -B -X utf8 -m tools.ci.a4_scope validate --stage all
```

CLI 验证总是重新读取本机安装版本、EXE、Steam buildid/manifest 和声明目录输入树哈希。未安装游戏的环境可通过
`validate(data, root, stage=..., check_installation=False)` 测试冻结机器合同；这不构成本机安装身份验收。
离线构造可显式调用 `bootstrap(root, frozen_installation=identity)`，输入必须满足同一安装身份schema；
合成夹具明确标为synthetic，不读取游戏目录。该注入仅供Python合同接口，CLI没有绕过真实安装采集的开关。
真实安装采集与重查由单独的`integration`用例验证；离线反例集保留正常CI选择。
生产生成锁保持历史身份，A4-0 的输入哈希不授予新版生产兼容权。

`bootstrap` 在目标不存在时创建初始台账，拒绝覆盖已有台账：

```text
.venv\Scripts\python.exe -B -X utf8 -m tools.ci.a4_scope bootstrap --ledger tools/out/a4-review/initial.json
```

初始发现分母独立来自当前 G/B/R/U/C 计划表、A3 原始 gzip 台账、e140287 的逐文件候选变动、正式 3.2.0
至当前生产源差异、1.15 结构快照全部 section 和受控生产输入。发现行与产品义务行分开映射。
A3 迁移保留 96 个原 ID、旧状态、完整原件哈希和每个 `[[obligations]]` 原始字节块哈希，`reverify`
只表示接收待重验；旧 17 项实现不会变成 A4 完成。候选差异分别记录检查点字节、当前字节及整个差异身份。

快照 section 和文件是 **A4-0 初始发现单元**。它们不是消费者全集，也不证明目录已经完成语义解析。
A4-1 独立全量盘点保持 `pending`；须按 `INVESTIGATION` schema 生成独立调查文件，将其身份登记到独立的
[A4发现源.json](A4发现源.json)，再将同一身份加入 `inventory.investigation_sources`，追加其全部发现并与义务关联。
校验从独立发现源索引读取分母；仅从台账删掉一个报告及其发现会被拒绝。索引变化也使冻结输入身份失效，须记录范围变更与重验。
独立调查须记录实际输入、扫描目录、解析失败、
未识别结构、重复、DLC、writer、消费者与交叉复核收据；不能将 ledger 内 ID 集合作为分母。
阶段门只允许未来阶段保持 pending；全计划门要求全部义务和依赖形成终态。
产品义务的`stage`只允许A4-1至A4-7；A4-8专门承担外部交付，不接受被后移的产品缺口。
A4-7机器门无条件选择全部产品义务，盘点consumer/writer映射也要求全部产品终态。
调查报告的消费者/writer必须全部映射到稳定义务身份；A4-1要求现有生产迁移项及本阶段义务完成，未来阶段新增扩展可保持pending，
不能因未来消费者尚未实现而阻止已完成的迁移阶段。A4-7再要求所有产品义务终态。

`interface_status` 与 `obligation_status` 分别表示接口与产品状态，行结论由状态组合计算。
终态需要当前源身份、实际生产 writer/对象/消费者/事实/端口/见证映射、全部适用配置和用例。
保留与不支持另需精确原版 source、父结构、引用闭包、关闭路径，不支持还需接口边界证据。
`boundary_proofs` 引用独立原版研究 JSON 中的具体身份；JSON 路径每个 token 使用 `~1` 表示 `/`、`~0` 表示 `~`。
理由、文件存在、整文件哈希或 Python 报告自身均不能替代边界证明与实际独立测试。

事实、端口和同因 ID 分别进入 `facts`、`ports` 和 `causes` 注册表并绑定实际源码身份。
未适用字段用 `status=not_applicable` 和具体 `reason`；未调查保持 `pending`，不填伪零或伪证据。
DLC、关闭、未知、对象、角色、阈值、生命周期和 U01–U10 分别登记适用性、具体配置与用例，完成见证覆盖各项。

实际见证使用 `tests/...py::test_name` 的 pytest node ID；参数化节点须包含完整参数 ID。
批量运行请求 JSON 只有 `selection` 与 `bindings` 两个字段。`bindings` 是全部受验输入、生产与见证引用的并集，
每个引用有 `path`、`sha256`、`identity`、`kind`；执行入口：

```text
.venv\Scripts\python.exe -B -X utf8 -m tools.ci.a4_scope witness --request tools/out/a4-review/witness-request.json --output tools/out/a4-review/witness-run
```

执行器复用仓库`run_check.interpreter`：优先仓库`.venv`，缺失时使用当前`sys.executable`，兼容setup-python提供解释器的CI。
实际解释器路径、pytest命令和选择集写入收据，校验时核对当前受控解释器身份，不能以任意命令替代。
输出 JUnit、日志和 `receipt.json`；失败/错误/跳过均不能签收。
长选择集超过安全命令行长度时，执行器使用 pytest 官方 `@selection.args` 参数文件，文件逐行保存完整 node ID，
其原始 bytes/SHA 进入同一收据绑定。校验仍要求与 `selection` 的顺序和完整节点逐一相等；换行注入、额外 CLI 参数、
缺失或篡改文件均拒绝。短选择集保持原有直接 argv 合同。
将收据 ID、相对路径和 SHA 登记到台账 `receipts`，各义务的 `witnesses` 关联该收据、节点与用例。
校验器重新核对命令、选择集、JUnit 实际身份、输入/生产/见证哈希并实际重放。单次门内同一选择集与绑定并集只重放一次，
多个义务共享批量运行，不逐行重复启动 pytest。任何绑定漂移、失败测试或未闭依赖都使验收失败。

初始台账建立时没有产品终态或产品见证收据；A4-0只证明机器合同与接收映射建立。
后续独立全量盘点、生产迁移、原版语义闭包、实际功能和发布仍须分别验收，最新事实见工作清单；用户游戏行为验收保持独立边界。
A4-8的实际Git/CI/tag/Release/部署独立验收器已接入，入口为 `validate --stage A4-8` 或 `--stage all`。
产品义务全部通过后，还必须提供 `--delivery-request` 的严格live请求，以及 `--delivery-output` 指定的、预先创建且为空的
`tools/out/`读回目录；该目录须与不可变发布运行目录分离。验收器核对GitHub、当前Git生产树、固定ZIP、本地部署、恢复材料和全部语言正文，
并在外部读取前后重新读取全部受验输入。离线夹具、缺失请求、输入漂移或 `delivery=pending` 均不能签发全计划完成。
这些工具不会自动执行发布；当前实际交付状态见[工作清单](当前工作清单.md)，实现和复核记录见[工程维护结果](exec/A4工程维护-结果.md)。


## 完整发现投影与保进度登记

Task7 的原始输入为固定 Task4 捕获，SHA-256 `51343911008b9b1dd62c53d31c1d118175d049b6346f18022acf515143e8537e`。
`research/vanilla-ai/1.15.0/discovery/capture.json` 记录原始字节长度、顺序与分片闭包；8 MiB 原始块使用确定性 gzip 保存，
重组后必须重新得到同一完整原始捕获 SHA。catalog 记录全部 source/definition/surface/reference/slot/未知观察及精确 syntax source membership。
完整 AST 与所有原始字段在分片内保持原字节，可离线读取；本机 ignored JSON 与游戏目录均不作为冻结投影的必需输入。
原生候选没有 writer/scope/getter 权限；物理重复事实永久保存，unresolved 状态与其分离。登记后所有混合分类组仍 pending，
不能通过整体 retain_native/unsupported 或删除重复数组获得终态。投影存在不关闭 A4-1；初始无 crosscheck 也明确保持 pending。

机器台账 schema 2 保留完整 `rows`，新增 `pending_rows` 和 `stale_history`。紧凑 pending 记录只有 domain、discovery_ids、goal_ids、source，
展开时复用唯一 `pending_row` 合同，并以 `O:<domain>` 为稳定 ID；它不能编码终态，后续实现须显式物化为完整 ROW。
不生成百万个空义务。原 653 ID 与全部 96 A3 映射保留，失效的行状态和证据在 `stale_history` 留档。
CHANGE 的两端使用 `presence=present|absent` 与 hashes 列表；present 恰一实际 SHA，absent 没有 hash。
空文件是 present，不能充当 absence。历史生产对象由固定 Git 树及登记后实际生产提交边重建，保存在受控 production-history manifest 与 gzip objects 中。
退出路径保留稳定发现/墓碑，产品目标仍需独立处置；rename 可表达为 D+A。未登记的 untracked 生产候选在门内明确拒绝。

已有台账使用 reconcile，不调用 bootstrap 覆盖：

```text
.venv\Scripts\python.exe -B -X utf8 -m tools.ci.a4_scope reconcile
.venv\Scripts\python.exe -B -X utf8 -m tools.ci.a4_scope reconcile --execute
```

默认预览写 `tools/out/a4-reconcile-preview.json`；执行前验证完整候选 overlay，再切换 index/ledger；根不一致的中间状态拒绝验收。
reconcile 保留未失效行的原状态、decision 和 predecessor 映射，仅按 direct/transitive 输入与依赖漂移使受影响状态 pending，旧证据入档。
有新的实际生产提交边时，先使用 `tools.ci.a4_history.write_history` 从真实 Git 对象更新受控历史，再预览/复核 reconcile；历史文件变化期间旧冻结门失败是预期保护。
此函数及 `tools.ci.a4_discovery.import_capture` 是明确的生成 API，不运行原版 scanner；登记器不执行 Git 状态写入、生成 Mod、发布或部署。

新 gate、projector 和所有新 witness 文件均加入冻结输入。A4-0 也检查所有 consumer/writer 的存在映射；crosscheck 的独立 expected bindings 来自实际报告、完整 source_inputs 与受控 witness 身份，不能由 receipt 自述决定。
no-game/no-.venv 的标准库冻结投影检查与真实 installation identity 核对分开记录。

## 分类、当前迁移与产品阶段

`research/vanilla-ai/1.15.0/classification/` 追加当前分类、完整父结构、逐物理责任、G/B/R/U 映射和原96目标接收映射。
`target-inputs.json` 是人工审查的选择规则输入；`targets.json` 是从固定捕获实际展开的输出，两者不是同一文件。
分类器仅复用已捕获 AST 与当前生产 ConsumerIR，不运行另一套扫描器。语法分类、原生合同适用性、现有迁移和新产品完成分别记录。

`migration-acceptance.json` 绑定原17已实施目标的当前精确 actor/reader/writer、完整原版父结构、生成 AST、固定迁移包和实际见证。
当前包和当前锁使用各自固定身份，并保留 Task6 旧 ZIP 与旧锁作为历史比较；旧包不能冒充当前证明来源。
`current_native_boundaries.json` 记录现有11个建筑初始化器的正式 selector/source/parent/lifecycle 闭包；
它由生产 `building_defaults` 路径自动核验，不扩大到铜矿或动态 HQ 对象的本地 writer。
`stage-assignments.json` 给出每个稳定行的原阶段、当前责任、阶段与完整发现集合。原 A3 C5/C6/C9 的编号含义与当前 C 页不同，
按冻结原目标分别保留联合评价、联动与静态资源预算责任。原 ID、旧状态、原始目标和剩余增强不因迁移而删除。

A4-1 启用门重新计算完整分类与物理归属、原始观察绑定、当前全部6193个IR writer的source/IR/AST/包闭环和17项实际迁移见证。
通过后只把明确的索引或当前迁移子责任计算为 `indexed`，不会写成产品 ROW 的 `verified`/`retained`，也不授予字段、getter 或 writer 权限。
71条原始未展开观察、34个重复字段和8个显示名歧义永久保留；未分类、物理归属缺失和错误 resolution 另行计算并阻塞启用。
当前生产的承重未知仍阻塞 A4-1；未来接口未知保留精确问题、owner、物理身份与待实现产品责任。

新增 B/R/U 与原待实施产品按其实际阶段保留 pending。A4-2 还需要真实公共接口及独立纵切，分类通过不代签它。
A4-7/all 仍无条件选择全部产品义务，`indexed` 不签署任何这些义务的终态。
本静态索引与迁移验收不表示实际启动18种DLC配置；产品终态的DLC、关闭和其他适用状态仍须各自独立证明。

# Situated AI 分层联动深化计划

计划代号：**A3**；制定日期：2026-11-04；复核日期：2026-11-05；状态：**已授权，待实施**。

**目标：**基于当前决策内核，把原版脚本允许的国家决策面尽可能扩展为内部细致分层、通过真实处境联动、具有明确成本与退出条件的行动系统。

**架构：**保留统一语义 IR、具体行动实例、同因分档、独立贡献联合、消费者末端限幅和原版适配；
在同一生产链上深化类型化事实、领域判断、行动组合、跨域关系及时间反馈。Python 负责开发、生成和静态验证，游戏内仍运行合法 PDX。

**规划依据：**[Mod 开发原则](../principles/Mod开发原则.md)、[工程原则](../principles/工程原则.md)、
[工程交付基线](exec/工程基线-1.0.md)及[当前生成 Mod 架构复核](exec/生成Mod架构复核-结果.md)。

本页维护目标架构、公共合同和完整性出口；[主计划](架构主计划.md)维护顺序与依赖；
[子计划](架构子计划.md)维护领域与联动目标；[工作清单](当前工作清单.md)维护实际状态。
实施时按 `executing-plans` 的逐项核对方式推进；具体代码拆分、字段和参数依据当时原版证据决定。
这些文档不预先证明任何新功能已实现；实际实施、检查和交付由工作清单与结果收据记录。用户已授权执行整套计划和标准发布流程。

## 一、起点与不改变的边界

当前生产版本为 3.2.0，锁定 Victoria 3 1.14.5。真实生产链和限制以工程基线、架构复核及版本收据为准。
显式行动卡、规则行动和对象变体尚不是同一种作者表示；当前显式关系表仅有教育与产业的两条互补边，
其他联动分散在具体 reader 和消费者合同中。这是本计划要整合、深化的基础，不能当作全域目标已经完成。

本计划不通过叠加第二套评分器、恢复全国排他路线或新建全域月度扫描器来扩展架构。
保留原版资格、实际成本、政治支持、执行、随机、拒绝和终结零分；不赠送资源，不强制建设、研究、转法或战争。
同时存在多个领域需求、多个具体行动；不同原版消费者仍在各自合法时机比较与执行。
“协调”不表示 Mod 有一个能统一分配真实预算或接管全部国家行为的中央执行器。

正确性第一、速度第二、内存第三。广度由独立盘点的决策面衡量，深度由可追溯的判断和反例衡量，
不以卡片、条件、文件、reader 或关系边的数量替代质量；不为追求数量制造无效联动。

## 二、八个逻辑层及其边界

这些是职责分层，不要求恰好八个文件、八次运行期遍历或八套持久变量。
纯派生判断尽量在生成时组合、在原版消费者中按需读取，复用当前内核。

| 层 | 输入与职责 | 对外输出 | 禁止事项 |
|---|---|---|---|
| L0 原版接口 | 盘点实际声明、读取权限、精确候选对象、消费者及调用作用域 | 可读事实、可写字段与保护合同 | 把字段存在等同于可写，推断未知引擎合并行为 |
| L1 事实证据 | 读取真实国家、州、市场、建筑、候选行动及双边对象；核对来源、单位与时效 | 带身份和未知策略的观测 | 用国名、候选评分或未执行意图代替事实 |
| L2 领域判断 | 在本领域内归纳需求、能力、机会、风险、成本、已观察承诺 | 类型明确的领域端口 | 合成无单位的国家万能总分、把所有短板做成共同门槛 |
| L3 最小行动 | 对具体对象、具体原版行动评估适用收益、成本、替代项与失败风险 | 可解释的贡献及行动身份 | 只创建名称而不接生产 writer；把倾向当成已执行 |
| L4 领域协调 | 对同消费者内的竞争、替代、同因与边际饱和协调；表达有限机会成本 | 去重且方向明确的联合贡献 | 假装分配真实资源、让一个全国路线排除其他合理行动 |
| L5 跨域联动 | 通过有类型端口消费其他领域的真实状态与必要关系 | 有界的互补、约束、替代或恢复贡献 | 隐式依赖他域内部变量、同周期递归评分、重复奖励同因 |
| L6 原版投影 | 统一 IR 编译、精确适配、唯一 writer 和末端限幅 | 可加载的 PDX 与可核查包 | 绕过资格或执行；不同单位和数值方向未经解释直接相加 |
| L7 时间反馈 | 下一次合法求值重读世界；必要时使用受控迟滞和已观察冲击 | 更新的真实事实与局部惯性 | 自学习假象、虚构行动完成、无生命周期的永久状态 |

领域内部可以细分，但只能通过明确端口发生依赖；端口既可以直接映射原版读取，也可以是已证实事实的纯派生值。
不要求把派生值全部写入存档。领域关闭、数据缺失和单项失败时，退出范围应局限于真正依赖该项的判断。

## 三、公共合同与最小工作项

### C1 覆盖台账与范围冻结

以锁定原版的独立盘点建立全集，覆盖现有来源目录及新发现的 AI 评估入口，不能只从现有绑定反推分母。
采用两个独立维度：接口能力状态，以及产品义务的实现状态。原版来源保护通过不等于产品能力完成。

每条记录至少具备：稳定 ID、领域/子方向、原版来源及身份、读取/影响权限、候选对象和消费者、已有能力、
真实缺口、关联工作项、接口证据、生产差异、参考/PDX见证、状态和限制。原版更新时先重新建立差异，不静默继承授权。
复用现有原版审计与绑定索引关联产品义务，不另写一套重复扫描器；义务集随代码受版本控制，机械索引由生成入口维护。
完成状态核对实际源、绑定、生成物和见证身份，遗漏 ID、空证据、过期身份或只有手填的“通过”必须失败。

所有子计划列出的方向都必须盘点。对具有合法消费者、有效信息且有实质决策价值的缺口，拆成计划内工作项实现；
一个方向不能用“一条样例接线”代替其余可实现目标。对边际无效、重复、非 AI 或未暴露接口的条目，
给出逐项事实依据和保留原版理由；它们只关闭盘点责任，不计作新增能力。
“无决策价值”须能具体证明属于重复原因、原版已完整处理或不参与该类 AI 判断，不能仅以实现繁琐或没有先例为由排除。
`unknown`、待确认和已知可实现但未实现分别保留；不能改名为不支持或交给用户长期验证来获得完成。

执行 A3-0 时冻结第一版义务集。后续可扩展，修改须保留新增/删除/重分类差异、依据和受影响验收；
不得为了收尾删掉尚未完成的目标。未暴露接口可以形成有证据的边界结论，不能把仅缺调查的项如此处理。
仍有影响目标可实现性的待确认项时，对应方向保持未完成。

联动调查同样建立有限且可核查的分母：从全部已确认的领域输出端口、实际消费需要和共享因果出发，
逐项记录需接线、原版已处理、重复/无独立价值、无合法接口或待确认，并赋予稳定的 R 工作项 ID。
R01–R12 是重点链，不是联动全集；不枚举无意义的领域两两配对，但每项实际依赖都要有去向和证据。
方向覆盖、联动调查及产品实现状态分别统计，不能以标签数量或手填状态关闭责任。

### C2 类型化事实和领域端口

每项事实/端口注明来源、实体、作用域、单位/量纲、方向、有效时机、未知语义、求值成本和消费方。
国家缺口不能伪装为候选州缺口，市场总供给不能等同于同州可达投入，外交目标与本国不可混用。
复合端口保留原始因果来源集合；同一风险换个端口名仍属于同一原因。

缺失不等于零、否定或健康。核心身份或必要事实未知时局部回原版；高档辅助未知只降到已证实档。
收益未知退出相应增量；成本未知使用声明且有依据的保守分支，不能无成本地保留最高收益。
已知成本不因无关收益未知而消失。不可比较的单位只能通过有解释的原版字段映射参与，不直接求和。

端口须有已知正例、否例、未知、边界和对象替换见证；切换不相关实体不得改变该端口。
禁止未声明跨域引用；拆模块后不以互相导入或复制规则掩盖循环。

### C3 最小行动及逐项完成凭据

最小行动是“某一原版消费者对具体对象评估的具体选择”，不是宏观国家路线、UI 决议卡或一条阈值规则。
同一行动可包含多个分档；同一模板可有多个合法对象实例；这些数量分别报告，不混作独立能力。
行动卡、规则行动和生成绑定使用同一语义合同与追踪身份，逐步消除绕过内核的旁路及重复作者。
不要求为了形式一致手写数千份等价卡片；允许有可审计的参数化生成。

每个最小工作项使用 `领域ID.方向序号.工作项序号`；若规模仍过大，再向下细分。每项交付记录以下内容：

1. **问题与反事实**：原版在哪个具体处境下缺少判断；只改变哪项事实应改变哪项倾向。
2. **输入与资格**：精确对象、可读事实、必要原版资格，以及不会成为全局门槛的辅助信息。
3. **行动与权衡**：基础需求、适用的高低档、成本、风险、替代、机会和约束；不适用项给出理由，不虚构准备阶段。
4. **联动与退出**：端口、因果组、触发与退出、未知、领域关闭、状态过期及重新进入。
5. **生产接线**：唯一作者、IR、实际生成字段、原版尾部和标准包文件；只有数据模型或报告不算完成。
6. **独立见证**：预期来自原版语义与明确计算，核对生成 PDX；不从同一个生成结果抄出预期再互证。
7. **收口**：定向检查、生产差异、影响范围及限制，按贡献流程提交；任一必需证据缺失仍为未完成。

“已有能力核对通过”“新增功能实现通过”“仅盘点边界闭合”分别记录。
领域最终完成要求其全部计划内工作项通过，且所有方向盘点闭合；不以首个纵切、旧测试或文件存在代替。

### C4 无全满足陷阱的分层判断

把必要资格与软条件分开。只有原版确实要求的技术、法律、目标、位置等是硬门；财政、教育、行政或军力短板
应分别改变相关行动的档位、成本、可行路径或恢复优先级，不能无依据地共同封死全部发展。

每个适用行动分别评估：可独立成立的基础需要、单项改善、多个已知改善、风险/成本、真实危机及恢复退出。
高档的必要组合可以使用 AND，但不得把高档组合冒充全部行动的唯一入口；同因档位取强，独立项联合。
低识字、正常低债融资、小国规模、行政短板、缺一个辅助事实时，仍需有原版可行的基础路径或准确解释原版必要限制。
资本不足可以提高相关融资代价；不能据此假称所有有价值投资永远不应开始。

要求“单一已知需求 + 其余辅助中性/未知”的见证，及“独立成本叠加”“高档缺一项”“危机恢复”见证。
当原版自带不可行条件时保留其拒绝；不能为了证明可达性绕过原版。

### C5 联合评估、数值与有限资源

每个数值注明消费者语义、方向、单位、适用区间、独立原因和限幅；提高数值不一定意味着更愿意行动。
优先级体现危机、基础维护、现实机会和长期收益的处境差异，不使用统一“所有领域激进”倍率。

同一因果的重复代理、分档和经关系传来的副本去重；独立需求与成本共同参与。
同一消费者内的共享成本只计一次，替代行动分别承担自己的真实风险；不同消费者对同一现实稀缺的反应不机械删除，
但必须说明各自语义，不能把这些字段求和声称真实预算已平衡。
机会成本、承诺负担与边际收益只使用可观察或明确的有界代理；不虚构未来利润、执行概率或引擎内部预算。

增加有效需求应产生方向合理的非递减贡献，增加相关成本应产生非递增贡献，必要资格与原版拒绝优先保留。
同因重复不增益、关系组合不放大成无界回路、饱和后不继续叠高、末端一次限幅，均须有独立数值见证。
测试上下边界、阈值两侧、多个正负项同时成立、替代路径及极端值，不能让常态普遍顶格而失去处境差异。

### C6 类型化联动与反馈

每条联动声明来源/目标、真实条件、实体映射、因果身份、适用行动、消费者、方向、强度、未知和退出。
互补、瓶颈、替代、共享负担、外部冲击和恢复是语义分类，执行时选用现有关系表示或扩展统一 IR，
不为每个类别另造互不相容的评分器。

有条件联动不等于多加全局前置：教育欠缺可降低高技能扩张收益并增加补教育需求，不能顺便封死所有基础工业。
候选行动、偏好、准备和评分不是行动完成证据；只有实际法律、制度、建筑、配方、投入和战争等可观察状态能产生现实反馈。
“某事实有利于某行动”不宣称该事实由上一个行动造成。

当前求值内的纯依赖必须是可终止的 DAG；经济与教育等跨时间循环通过下一次重读真实世界闭合，不能递归相加评分。
链路展开深度、对象数和计算量按资源证据设上限；确需扩容时先提供合法性和成本依据，不能靠硬剪掉必要语义过门。
联动须有逐边正反例、断边、未知、重复路径、反向对象和完整链路见证；其中一域关闭不拖垮不依赖它的行动。

### C7 时间、惯性、冲击与适应

区分本次观测、原版已暴露的短期冲击、可证实的中期承诺和长期结构条件。
优先重读原版状态并复用既有财政迟滞和战败事实；仅在无状态判断确有反复摇摆问题且接口允许时加入必要的局部记忆。
不把“有惯性”扩大成全国路线锁定，不把一项失败解释为该类行动永远禁用。

新增持久状态必须说明 writer、读者、刷新、进入/退出阈值、TTL、冷却、关闭、玩家切换、读档、升级和卸载边界；
缺合法更新时机不得生成。过期或未知不能留下永久奖励/惩罚，危机恢复应撤销危机偏好。
没有可观察行动结果时不承诺失败学习；以当前新证据调整，解释哪些反馈仍不可见。

### C8 静态完成与用户验收

本计划出口要求完整生产语义、原版接口正确性、生成一致性和标准包合同；长期游戏运行不是计划必跑阶段。
日志、存档和用户反馈用于后续辅助分析，不新建长期挂机体系，也不以用户未来观察替代缺失的生产实现。

默认/活跃策略同名字段合并等未知引擎行为单独列明，不据静态声明推断运行效果。
所有新写入都须证明源保护、作用域、适配与回退；必要的语义授权无法建立时，相关写入与目标保持未完成，
不能因为“不要求长期实机”就把猜测当作合法接口。

正式交付明确区分静态功能完整、工程检查通过、Git/Release/部署状态和用户未验收项。
计划版本与产品版本分别维护；现在不预先增加产品版本，不重建已发布历史包。

### C9 静态资源预算

A3-0 记录当前生成物和 Python 生成路径的基线，A3-1 冻结可执行的静态预算：每消费者候选/谓词与表达式规模、
对象扫描范围、关系展开深度和数量、重复读取、持久 writer/变量规模。优先沿用现有 STATIC_BUDGET 和资源门；
新增维度须说明计数方法、基线、阈值依据及失败语义。超限必须硬失败，不以已写成本报告代替通过。
确需扩大预算时单独记录原版合法性、受影响消费者、资源成本和优化比较，不靠压掉功能或改分母过门。
这些门只证明静态规模受控，不宣称游戏运行时间或内存已经实测通过。

## 四、实现路由和职责

以下指定调查与修改入口，不预先规定缺乏原版证据的新 API、数据类型或字段名。
现有模块适用时扩展；确需拆分时按单一职责拆，并同步消费者、测试、CLI 与文档，禁止复制生产逻辑。

| 职责 | 现有首选入口 | 需要同时核对 |
|---|---|---|
| 接口全集与能力边界 | `situated/vanilla_inventory.py`、`inventory.py`、`native_treatments.py`、`information_catalog.py` | 原版独立分母、权限和来源保护；既有审计状态不替代产品义务集 |
| 事实和领域端口 | `mod/decisions/facts.toml`、`information.toml`、`country_state.toml`、`observation_queries.py`、`country_state.py` | 精确作用域、单位、未知及端口依赖 |
| 行动及统一合同 | `mod/decisions/actions.toml`、`action_families.toml`、`action_layers.toml`、`action_bindings.toml` | `situated/actions.py`、`action_instances.py`、`decision_ir.py`、`bindings.py` |
| 联合数值与跨域关系 | `mod/decisions/relations.toml`、`capacities.toml`、`commitments.toml`、`goals.toml` | `situated/programs.py`、`relations.py`、`joint_chain_contract.py`；因果去重与时间边界 |
| 领域策略与原版投影 | 各 `*_opportunities.toml`、`economy.toml`、`strategic.toml`、`diplomatic_goals.toml` 及对应规则模块 | `situated/compiler.py`、`lowering.py`、`decision_adapters.py`；唯一 writer、原版尾部 |
| 参考器和真实脚本见证 | `situated/pdx_eval.py`、既有 `test_situated_*`、`test_architecture_*` 与各领域测试 | 独立期望、正反例、具体消费者和所有工作项映射；不以自证快照替代 |
| 包与全语言交付 | `distribution.py`、`publishing.py`、`deployment.py`、`mod/decisions/localization.toml` | 生成锁、manifest、11语键与占位符、固定包身份；复用发布工具 |

表中 Python 文件位于 `src/pdx/`，测试位于 `tests/`。不以预先创建空模块或大批空行动卡作为阶段交付。
每个领域可以形成独立子模块，但共享的事实、因果和消费者合同只维护一份。

## 五、共同场景和反事实矩阵

每个工作项按 C3–C7 选择适用边界；每个领域的全部义务均需覆盖，以下场景只补充组合覆盖，不能替代逐项验收。
固定输入、预期方向和具体消费者；代表场景不得靠国名触发。

| 场景 | 必须证明的静态语义 |
|---|---|
| 低识字、正常融资、基础工业不足 | 基础建设需要可独立参与，教育改善可另获倾向，高技能溢价分档；不要求先补完教育和行政 |
| 教育与行政不足同时存在 | 可并行增加相关需求；真实财政、纸等投入成本共同参与，不由首个奖励分支遮蔽 |
| 农业人口多、工资低、粮食紧张 | 区分生存供给、就业与长期升级，不把低工资自动等同于无限扩产利润 |
| 岛国依赖进口、运输紧张、海上威胁上升 | 贸易、港口、舰队与外交只在可观察关联下联动，不能把市场总量当同州可达供给 |
| 保守政治结构下战败、财政受损 | 重建、政治可行性和改革机会分别评估，战败不直接获得转法资格或强制现代化 |
| 工业成熟、财政健康、但新增收益已饱和 | 边际价值降低，研究和服务等现实机会可竞争；不持续满幅奖励同一产业 |
| 小国、宗主市场与有限海外能力 | 自身利益、市场收益、依赖与安全分开；不凭小国或宗属身份封死合理发展 |
| 多线战争与已有外交承诺 | 新承诺成本独立参与，军事与外交方案可并存，预算代理不谎称已分配军费 |
| 危机消退、和平恢复、辅助事实转未知 | 危机贡献退出，合法惯性按合同衰减，已知独立项保留，没有永久负反馈锁 |
| 目标州/目标国替换、领域关闭、玩家国家 | 作用域和对象隔离正确，关闭及未知局部回退，玩家路径不受新增 AI 权重影响 |

俄罗斯、英国、荷兰等可用作解释场景，正式见证以实际结构条件定义。
跨域链路的所有最小边还须分别验证，不能只检查整条链的最终倍率。

## 六、实施节奏与提速方法

1. **先找真实缺口**：A3-0 用一次锁定底本盘点建立义务集和既有能力基线，避免重复实现、重复调查。
2. **先稳公共合同，再批量纵切**：A3-1 统一端口、行动和见证要求；各领域按小工作项把源、生成和验收一次接全。
   先行纵切用于验证公共合同，不能关闭整个领域；其余义务继续在同阶段完成。
3. **按共享依赖批次处理**：同一 reader、原版父结构或适配家族的相关项一起调查和实现，单个工作项仍保留独立状态。
   已有健康路径保持可交付；共享契约改变后复验所有受影响域。
4. **定向检查持续反馈**：每批运行相关静态、参考/PDX和生成测试，语义变化后只复用输入身份仍一致的证据。
   不在每改一段文档或每个纯数据项后重复完整回归，不通过缩减选择集或忽略失败提速。
5. **候选冻结后集中全检**：全域与组合出口均闭合后重生成、整 Mod 复核和完整回归；
   后续源码变化、修复或新增疑点使证据失效时，按影响范围重验，必要时重新完整回归。
6. **控制资源**：先复用原版解析与索引，再考虑缓存和并行；key 含源/底本身份，禁止无界全量驻留。
   依据现有资源门选择 worker，不用开发期提速牺牲未知、失败、覆盖或内存合同。
7. **每项阶段性收口**：实现、定向验证、更新状态和中文提交构成一个闭环；失败先定位，不能只更新计划和报告。
   提交频率跟随可独立复核的功能目的，不机械地每个函数提交。

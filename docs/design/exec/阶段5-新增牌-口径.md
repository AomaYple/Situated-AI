## 1. test 0：`set_strategy` 直置受不受 `possible` 门约束

### 1.1 先交代：它为什么必须最先做，以及本轮为什么没有结论

**为什么必须最先做**：`possible` 门只有两种可能的作用 ——
(a) **它挡直置**（脚本递一张门外牌，引擎拒绝或忽略）；
(b) **它不挡直置**（牌照样挂上，与标志无关，**零报错**）。
若是 (b)，"由处境标志驱动牌选择"这句话在**直置**这条通道上就是假的：只要脚本递了，牌就在，
门形同虚设；而失效是**沉默的** —— 没有日志、没有红、读数上还"看起来正常"。这正是 P13 要拦的形态。

**本轮（t15）没跑它的原因，如实写在这里**：t15 的 inScope 只有本文件；而 test 0 要往探针里加一张
`possible = { always = no }` 的牌 + 一个直置效果 + 一条自报行 —— 那是探针侧产物（`tools/probe/*`、
`tools/pdx/*_probe.py`），属 t18。并且本轮执行期间 captain 开了**独占测量窗口**（禁止任何起游戏的操作）。
⇒ 本页把它定成 **t18 的第一道门**：**不跑出结论，不许往真档案里写牌**。

### 1.2 离线先排掉两个假说（其中一个是我自己先提出的）

**【实测·未获支持】"引擎侧也绕过门"**：我一度拿 `h1-natural-v1`（2026-09-20 的 H1 会话）的
11,143 条 `ZZPROBE H1;CARD;<牌>;<国名>` 读数当证据 —— 其中 `reactionary` 出现 **265** 次，
落在 9 个国家上（夏威夷 41 / 东印度 41 / 两西西里 41 / 波罗的总督区 41 / 开普殖民地 38 / 瑞士 29 /
上加拿大 22 / 南澳大利亚 11 / 俄罗斯 1）。而 `ai_strategy_reactionary_agenda` 的 `possible`
要 `has_technology_researched = egalitarianism`（`ps:296-299`），开局科技档 1–2 才发这门科技
（`00_starting_inventions.txt:23`、`:35`），看起来"门为假却挂着"。**逐国去查之后，这条假说没有拿到支持**：

| 国家 | 为什么门其实为真 | 出处 |
|---|---|---|

按 P13 它们**不作依据** —— 也就是说：**"引擎侧绕过门"这条假说既没被证实、也还没被彻底关掉**，
但它对本文的结论没有影响（本文的结论只需要"门的可靠性未证"这一点，见 §1.3）。

`set_variable` 分组 + 自报链，`tools/pdx/h1_probe.py:194-364`）⇒ 那个会话里出现的任何牌都不是我们写的。

### 1.3 剩下那一条可疑线索（这就是 test 0 要钉的东西）

原版自己用**直置**给两个"门在地图上为假"的国家分配了牌：

* `common/history/ai/00_strategy.txt:87-91` 的 `c:RUS` 块，`:90` = `set_strategy = ai_strategy_reactionary_agenda`；
* 同文件 `:52-55` 的 `c:SIC` 块，`:55` = 同一张牌。

而这两个国家**开局都没有** `egalitarianism`（上表），也就是 `possible` 为**假**。
`common/history/ai/` 只有 3 个文件，`00_strategy.txt` 只覆盖 **27 个 tag**
（SWE SAR PAP TUS BRZ ARG SIC FIN AUS HUN CRO FRA PRU RUS TUR GBR BIC DEI USA EGY CHI JAP CAM SER MOL WAL MON）；
`history/ai/` 的 `set_strategy` = 脚本效果（`docs/victoria3-modding/11-历史初始状态与AI策略分配.md` §3、
`backlog.md:104` 的 B58）；那次会话只装了探针（`v3 h1-probe --deploy`「同步进用户 mod 目录并**只启用它**」，
`阶段2-结果.md:180-181`），我们的真 mod（含 JE 的 `set_strategy`）**不在场**。

⇒ **可判定的部分**：原版**自己**就把一张 `possible` 为假的牌直置进了局势里 ——
所以"`possible` 门保证牌不会出现在门外"这句话，**在原版数据里就有一个反例**。
⇒ **判不了的部分**：反例发生在**开局分配**上，它**不能区分**两个机制 ——
① 脚本效果 `set_strategy` 无视门；② 引擎的开局抽牌无视门（历史分配先写、开局抽牌随后覆盖，
`阶段2-结果.md:118` 已实测"开局抽牌早于 `on_game_started`"）。**要区分它们，只能专测。**

现在这 8 个行号由 `tools/tests/test_ai_surface.py::test_真实原版_反IG块8处行号与归属` 守着）。

**数据源怎么表达（能力边界是**事实**，本设计**落在边界内**）**：`tools/pdx/modgen.py` 的 `Card`
已经有 `possible`（`modgen.py:427-436`），解析在 `:983-998`（`[[cards.items.possible]]`），
渲染在 `card_text`（`:1394-1416`）；其余字段走 `fields`，数据源键是 `key` + **`amount`（数值）
或 `arg`（标识符，二选一）** + `why`（`modgen.py:162-174`、`:667-688`）。
**现有生成器能发的就这四样**：`type`（由 `slot` 推出）、可选 `possible`、`weight = { value = N }`
（`Card.weight` 是**单个 float**：`:432`、`:991`、`:1403`）、以及**数值标量**字段 `key = <数字>`
（`:1404-1406`）。

⇒ **本设计只用其中的三样**（`type` / `possible` / 单值 `weight`）加可选数值字段 —— 也就是 §3.3 的
**单值权重要求**，它**正好落在边界内**。因此：

* **不许改生成器**（不改 `modgen.py`、不加 schema、不开档案专用分支）；
* **不许用 `arg` 绕过** —— 牌面字段的 `arg`（标识符形式）会被渲染成 `key = 0` 而**静默落盘**，
  且闸门 ⑤ 那边同样用 `num(p.amount)`、看不见这件事（本页 §7 的"静默"族）。
* **生成器发不出的字段，第一版一律不写**：`icon`（字符串）、`pro_interest_groups` /
  `anti_interest_groups` / `pro_movements` / `anti_movements`（标识符列表）、`institution_scores`（映射）
  ⇒ §2 表里这些行的取值**只作为"这张牌若能在原版形状里写全，该写什么"的记录**，
  第一版产物里**一个都不出现**。**这不改变承重件**：门与权重照发（§3），它们的取值理由照旧按 §2 复核。
* ⚠️ **未测（留给 t18 的第一眼）**：原版这 14 个字段全都写作**块**（例 `revolution_aversion = { value = 50 }`，
  `ps:6-8`），而生成器对 `fields` 发的是**裸标量** `key = <数字>`（`:1406`）。引擎是否接受裸标量当
  script value，本页**没有依据**（P13：不当依据）⇒ 开局时按 §7 的"三种跑不成"处理：引擎会自己报解析错，
  **报错就是结论**，不许当成"牌没被选中"。
**闸门 ③ 已强制**：没有 `possible` 的牌直接红（`modguard.py:659-663`）。

## 3. `possible` 门的写法：走「处境标志」路线

### 3.1 门读什么：**既有的处境压力修正**，不新造标志

```
possible = {
	has_modifier = sitai_<档案>_pressure
}
```

* **为什么是修正而不是变量**：`has_modifier = <名字>` 是**同一份文件里**读"处境旗"的原版写法 ——
  `ps:355`（反动牌）、`ps:548`（进步牌）、`ps:738`（民族牌）、`ps:927`（天命牌）四处都读同一个旗
  `forced_regime_change`，而它的本体是一个静态修正
  （`common/static_modifiers/00_code_static_modifiers.txt:976-981`）。
  ⚠️ **这四个先例全在 `weight` 块内**（`forced_regime_change` 在 `ps:` 全文件只出现在这四行，
  每条都是 `weight` 里的 `if = { limit = { has_modifier = … } }`）。
  机械复算（2026-09-24；**现在由用例守**：`test_真实原版_牌面门与权重复算`，本文 §8 给了命令与铁律）：把口径放大到**整个 `common/ai_strategies/`**（5 份文件）
  —— 带 `possible` 的牌 **34 张**、带 `weight` 的牌 **35 张**，其中 **`possible` 内读 `has_modifier`
  的牌 = 0 张**、**`weight` 内读 `has_modifier` 的牌 = 4 张**（就是上面四处）。⇒ 下面那张门用的是**修正**这条路线（原版完整存在），
  但「在 `possible` 里读修正」是**对原版写法的外推，不是原版直引**（详见下一条）。
* **同类先例（修正当"处境旗"的完整一生）**：`sick_man_of_europe` / `dead_man_of_europe`
  （`common/static_modifiers/content_3_modifiers.txt:245-251`、`:253-260`）——
  **开局挂上**（`common/history/countries/tur - ottoman empire.txt:33`）、
  **被别的系统读**（`common/company_types/00_companies_asia.txt:186` 等 6 处用 `has_modifier` 读它）、
  **处境结束时由 JE 摘掉**（`common/journal_entries/00_sick_man.txt:17`、`:26`）。
  也就是说"名字即处境"的修正这条路线在原版是**完整存在**的；
  另一条路线是**拿 JE 当旗**（坦志麦特牌的 `possible = { has_journal_entry = je_sick_man_main }`，`ps:1178-1180`）。
  ⚠️ **但两件事要分开**：原版证明的是「修正能当旗、能被读」，**没有**证明「`has_modifier` 能写在
  `possible` 里」—— 整个 `common/ai_strategies/` 里 34 张带 `possible` 的牌，**零张**在 `possible`
  内读修正（§8 复算）。
  所以 `possible = { has_modifier = … }` 是外推。**风险形态是沉默**：引擎若在 `possible` 里不吃这个
  触发器，门就恒为假（或恒为真），而**没有任何日志**——本仓已有同型的静默先例（`ab_probe.py:233-241`
  的 B87：手写清单少一张牌 ⇒ 那个月一行都不记）。
  ⇒ 这条风险**只由实机读数判决**（§1.4 的 test 0 + §5.2 的 A/B 两臂），§7 已为它单列一行失败判据与降级路径。
  **我们选修正那条**：本档案的处境压力修正已经存在（`mod/common/static_modifiers/sitai_ru_defeat_pressure.txt`）、
  时长与处境一致（`[pressure.params].years`），而 JE 是"窗口"的载体、它的 `possible` 另有语义
  （`legitimacy <= 75`），拿它当牌的门会把两件事绑死。
* **为什么不读记忆变量**：`sitai_<档案>_memory`（10 年，`mod/common/scripted_effects/sitai_ru_defeat_effects.txt:9-13`）
  是"**战败过**"这件事，它**故意比处境活得久**；门要跟**处境**走（压力修正同样 10 年，
  但语义是"窗口开着"）。这条正是 t9 的门 5「不假真」（`阶段5-目标牌口径.md:20`）在牌上的应用：
  开局即为真的判据不许当门。
* **门的形状要求**：`possible` 只写**一层平铺子句**（`key = value`），与 JE 判据同一套 `Clause`
  （`modgen.py:187-188`）—— 需要块形式的判据（如 `ig:… ?= { … }`）现在的 schema **表达不了**，
  第一版不写（要写先扩 schema，别开特例）。

### 3.2 门开/门关各自的期望（这就是 G-EXIT-5.2 / 5.3 的结构保证）

| 状态 | 修正在不在 | 牌在不在池里 | 期望占槽率 |
|---|---|---|---|
| **和平期**（不施加冲击） | 不在 | **不在**（`possible` 假） | 0 —— ⚠️ **简化后这是唯一依据**：门外没有权重那道防线（§3.3） |
| **危机期**（施加冲击后） | 在（10 年） | 在 | 显著 > 0（目标：门开时 54.8%） |
| 处境结束（修正到期） | 不在 | 退回不在 | 回到 0 |

### 3.3 权重：**单值 40**（落在生成器能力内；**不设"门外 0"第二道防线**）

```
weight = {
	value = 40
}
```

* **门内 40 的依据**：政治槽的等效竞争权重 `S ≈ 33`（【实测】`阶段2-结果.md:68`；闸门 ③ 的价格表
  `modguard.py:51`），份额 `p = W/(W+S)`（`modguard.py:617-622`）。稀释预算 **`MAX_CARD_SHARE = 0.60`**
  且**有下界口径**：低于三成"推不动落点"（`modguard.py:53-59`：区间 `[0.3, 0.6]`）⇒
  `W = 40` 时 `p = 40/73 = **54.8%**`，落在区间里；上限换算过来是 `W ≤ 49`（`0.6·33/0.4`）。
* **为什么不做"门外 0"**：那一段权重是给 `set_strategy` **直置**准备的保险（门被直置绕过时兜底），
  而本设计的牌子**只在门内进池**（§3.2）⇒ 门外根本不存在这张牌，保险没有对象；
  而且两段式权重（`value = 0` + 门内 `add = 40`）**不在生成器能力边界内**（§2 数据源段：
  `Card.weight` 是单个 float，`modgen.py:432`/`:991`/`:1403`）。**砍掉它不是妥协，是去掉了外部复杂度**
  —— 不再需要"门外 0 = 永不选中"这条原版未定义的语义。
* **代价（必须写清，否则留窟窿）**：和平期 ≈ 0 的**证据从"双保险"变成只有 A 臂一条**。
  门在**引擎重掷路径**上是否真生效，只能由 A 臂（不施加冲击那 12 个月，§1.4 / §5.2）判；
  不过的处置写在 §7（**换门或撤牌**，不是改权重）—— 这是 P13「不许静默降级」在简化设计里的落点。
* **旁证（先验，不是实测）**：原版有**三张 `weight = 10000`** 的牌，门都是国家专属 JE ——
  坦志麦特（门 `ps:1178-1180` = `possible = { has_journal_entry = je_sick_man_main }`，`weight = 10000` `:1182-1183`）、
  明治（`ps:1288-1290` 门 / `:1292-1293` weight）、大改革（`ps:1388-1390` 门 / `:1392-1393` weight）。
  若引擎在重掷路径上**不看 `possible`**，这三张会把每个国家的政治槽按 `10000 : (5–100)` 吞掉
  （另外六张政治牌的权重：保守 20 `ps:118`、反动 5 `:303`、进步 5 `:498`、平等 10 `:693`、
  民族 7.5 `:878`、天命 100 `:1065` —— 即权重比 100:1 到 2000:1），而探针实测的**主态**是
  `conservative` / `progressive` / `reactionary`（`阶段2-结果.md:122` 事实 5 的读数基础）
  ⇒ 这是**反证「门在重掷路径上很可能生效」**。
  ⚠️ **必须与实测分开读**：以上是**旁证/先验**，它只降低"门整体失效"的怀疑；**判决仍归 A 臂**（§1.4 / §5.2）。
* **字段语义的官方依据（比剂量反应倒推强）**：`common/ai_strategies/00_default_strategy.txt`
  的两行原版注释就是官方对这两个字段的定义 ——
  `:9473` = `# Trigger for whether this strategy can be randomly allocated to a country`（`possible`）、
  `:9478` = `# Chance that this strategy will be randomly allocated to a country`（`weight`）。
  **关键在"随机分配"四个字**：它给**引擎那一侧**的门上了官方背书，而**一个字没提 `set_strategy`**
  ⇒ 与 §1.3「判不了的那一环」完全一致：门对**引擎重掷**的作用有依据，门对**脚本直置**的作用
  仍只能靠 test 0 专测（§1.4）。
* **同型直引（写准，别写成"某处碰巧出现"）**：`:9473-9481` 是 `ai_strategy_default` **本体**的收尾
  —— 该卡片块从 `:4`（`ai_strategy_default = {`）起、一直到文件末 `:9482`，所以
  `possible = { always = no }` + `weight = { value = 0 }` 这一对就是**官方给「永不被随机分配」写的标准写法**。
  （原版按块扫，这是**唯一一处** weight 基值为 0 的牌；现在由
  `tools/tests/test_ai_surface.py::test_真实原版_权重为0的牌只有默认牌` 守着，§8。）
  **勘误（2026-09-25）**：本节早先写过「原版**没有** `weight = 0` 的先例…未测项」——
  这句现在是**错的**，反例就是上面这条成对出现的直引。本设计已不再用两段式权重，
  那条"`0 = 永不选中`"的未测项**随之作废**（不再有依赖它的设计）。
* **为什么不取 100/250**：`阶段2-结果.md:29-36` 的剂量反应表给的是 10→23.0%、50→64.6%、100→80.1%、
  250→92.5%。92.5% 等于"我们替原版决定"（F2 的底线：原版自己的牌必须还有发言权，
  `modguard.py:55-56`），而 54.8% 既高于剂量反应可辨的下限（23%），又留出原版的发言权。
* **这是可调参数**：第一版取 40，跑完 A/B 用**实测份额**回填（§5.2 的同一口径），不许靠公式当成结论。
  ⚠️ 但**可调的只有这一个数**（单值权重）；"门外 0"那条路已经删除，**不许**以"调权重"代替 §7 的失败处置。

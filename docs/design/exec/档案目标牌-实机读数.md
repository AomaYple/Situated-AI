## 五、`bv_alignment` 的「改抽象」：最小范围与为什么不是加特例

`bv_alignment` 的处境（倒向谁）决定它该走**外交槽**，而 schema v1 **表达不了**（四条断点，各自带行号）：

| # | 断在哪 | 具体 |
|---|---|---|
| 1 | 写不了 | `[pressure].effects` 渲出来的是**静态修正的数值字段**（`tools/pdx/modgen.py:1239`）；"与谁的关系"要 `set_relations`、"在谁的集团里"要 power bloc 的 `member =`、"支持谁"要 `is_supporting_unification_candidate` —— 没有一个是修正字段 |
| 2 | 读不了 | JE 判据只支持**平铺一行**（`Clause.render`，`tools/pdx/modgen.py:187-188`），而原版读"你站哪边"一律带**作用域操作数** |
| 3 | 钩子挂不上 | schema 里**没有 `on_action` 这一格**（产物清单里没有 `common/on_actions/`） |
| 4 | 意图递不出去 | 原版的"统一德意志"意图挂**外交槽**，而递牌白名单只有四张**政治**议程牌（`tools/pdx/modgen.py:697-704`） |

**处置**：按 §3 阶段 5 的失败处理走「**改抽象**」（`01-大方向.md:144`），**最小范围三件**（缺一不可）：

1. **读**：`Clause.render` 支持**一层块**（`key = { 子句 }`）—— 带作用域操作数的判据唯一写法（顺带解开 B69 的块形式与 B81 的布尔值）；
2. **写**：`[pressure].effects` 从"只渲染修正字段"扩成**可渲染 effects**（`set_relations` / power bloc `member =` / 变量）；
3. **分叉**：数据源要有"**一个处境、两种取值**"的表达（一个变量 + 每个取值一套 effects/判据）—— 这是"选了哪一边"与"选边的代价"之间的分界。

**为什么不是加特例**：上面三条都改**抽象**（`Clause` / `effects` / 处境取值），改完全部档案一起受益；
而"给 bv 写一段专用分支"只让一份档案能跑，正好是 `01-大方向.md:144` 与 `阶段5-档案扩张.md:41` 明令禁止的那条路。
本轮**没有**改 `tools/pdx/`（不在 t16 范围内），也没有为 bv 加任何特例；`bv` 的 `reform_card` 留空 + `[probe].why` 写明缺口。

### 七.1 `cn_intervention`：杠杆与目标牌**反向是有意的**（两层分工 + 可证伪）

**先承认前提**：`[reform_inputs]` 抬的工业家/知识界，确实是目标牌 `maintain_mandate_of_heaven` 的
`anti_interest_groups`（`common/ai_strategies/03_political_strategies.txt:1006-1010`）。**这不是两处互相拆台，是两层分工**：

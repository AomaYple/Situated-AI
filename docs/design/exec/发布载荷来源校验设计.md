# 发布载荷来源校验设计

适用基线为 `9b2ad70e`。工程原则 EP-30、EP-39 约束公开包的载荷来源。现有归档结构校验和发布恢复需要保留。 [工程原则](../../principles/工程原则.md)

## 当前候选校验

现有 3.4.0 ZIP 中的 `common/ai_strategies/00_default_strategy.txt` 为 394,727 字节，SHA-256 为 `64435666ed847f0308d791a9fae211263fa341a0f681e9ced383a007cf6ebcf3`。锁定底本对应文件的 SHA-256 为 `7fa4e018a796b1f1c04275e7fbc712ac39a4376e86db311f31079b12a8337760`。底本第 6,672 行与归档成员第 7,611 行起连续 1,854 行逐字节一致，共 38,295 字节，区段 SHA-256 为 `efdb6206558f95f143d6114e011055e62305aae813ac0ff1ef3b72c6ef85180c`。比较含原始行尾，证据只保存位置和摘要。

独立复核对 77 个已登记的 3.4.0 归档成员逐个比对，各自找到连续 20–1,854 行、460–38,295 字节的原版区段。逐成员原件、区段及归档成员的定位与摘要见本机复核证据 `tools/out/publication-origin-independent-review/retained-members.tsv`，其 SHA-256 为 `37abd956c8f9ab23773ef94450e8053bbe9430de79117355257c6171bcc41c60`。发布器从这份证据登记 77 个互异的归档成员 SHA-256，无需携带原件、归档成员或比对区段。

公开渠道执行在打开同一冻结包后比对所有成员的 SHA-256。改动版本元数据、归档容器或成员名称后，只要仍携带任一已证实的精确成员字节，GitHub 和 Workshop 执行均会阻塞。只读预检、历史包验证和单独本地安装继续走各自入口。同名的独立原创文件沿现有检查校验。修改后的旧成员或新来源需要下述完整来源合同逐项证明。本防护位于正式单命令发布器，原生 Steamworks 辅助程序负责 Steam 渠道操作，由发布器统一执行正式发布合同。 [执行入口](../../../src/pdx/publishing/runner.py)

## 现有入口和可复用证据

`distribution.package()` 调用 `package_inputs()` 和 `decisions.build()`，再由 `_release_files()` 投影发布载荷。后者仅从元数据移除工程字段。现有归档校验覆盖成员路径、完整性、摘要、编码、包身份和元数据。`generation_lock()` 将生成器输入与工作树生成产物逐路径绑定到 SHA-256。发布器会从当前源构建包，或复用收据目录中的冻结 ZIP。基线 `9b2ad70e` 的两条路径均缺少完整载荷来源判定。 [打包实现](../../../src/pdx/distribution.py) · [发布实现](../../../src/pdx/publishing/runner.py)

原版清单及锁定底本哈希用于确定原件身份；部分生产改写已有原件到生成器的显式映射，可从接线收集实际保留的内容范围。就地重写、完整复制与移入其他位置都可能带入原文。源码指纹及原件路径查重各只能证明相应身份和路径事实。位置相同的独立原创实现可经分类通过，位置不同的原文复制仍应拒绝。 [独立文件清单](../../../src/pdx/input_inventory.py) · [R2 原件映射](../../../src/pdx/situated/r2_native.py)

## 拟定判据

在生成时登记最终归档中每个载荷的规范路径、归档编码后的 SHA-256、生成入口与来源处置。原创载荷绑定受审的原创文件或原创生成入口及其输入；只有对控制语义的读取且输出独立构造的入口可据此登记原创。保留原文的生成入口附原件规范路径、原件 SHA-256 和保留区段证明，全部经本地比对，持久证据仅记定位、摘要和处置。混合载荷包含已证实保留的原版字节即拒绝；来源未知、缺项、重复或身份变化也拒绝。确切字节匹配可作拒绝证据；没有匹配不足以确认原创。

复用 generation lock 核定运行代码和工作树产物身份。由发布审查独立固定完整来源清单的摘要，绑定正式源提交、锁摘要、最终 ZIP 摘要及其逐成员集合。游戏脚本的发布编码、README 和元数据投影在归档层发生，校验以最终归档字节为准。清单在包外留存；随包提供的自述和历史收据状态均无权授信。manifest 是内部计算的索引，应通过现有全量验证覆盖，对实际载荷的每条来源记录仍须逐项核对。

已知保留原文的路径应由独审证据生成来源记录，绑定对应的实际产物摘要和原件证据。完成分类前公开发布保持阻塞。生产集成需要接线侧发出分类事实，并对照完整载荷集合审核，由受版本控制的来源及证据身份得出授权结论，无路径例外名单。

阶段 3 首轮迁移闭包在 `9b2ad70e` 计数为 77 个文件和 981 个物理写点。证据目录 `situated-ai/subplan-readiness/stage3-first-round/projection/` 的 `file-closure.tsv` 与 `writer-closure.tsv` 分别绑定文件与实际写点，SHA-256 分别为 `3ad5187214fd646024641ed195d0014a5669a156a83702735f821c2c77159b70` 和 `593bc3ef324ce915ef57f93df94c3d80bd3c4e3642ac73eb6270e76fcc42788d`。表格提供原件和产物定位。判定已知载荷保留原文时，需把实际原件区段比较、成员摘要和 ZIP 身份一起纳入证据，表中路径不能单独作为拒绝谓词。3.4.0 的正式源为 `e14d5bd1085e5727274f74c5f82876608df148f0`，ZIP SHA-256 为 `a5ccf61255338ade0bdd6d71eaf9e22cbdb90a71c6090d9bd3ff3e706c25507e`。 [3.4.0 交付结果](3.4.0-交付结果.md)

## 入口与恢复

新公开包在 `package()` 生成完整文件集合并投影到发行格式后、写 ZIP 前拒绝已知原文或未知来源。新发布在 runner 的冻结包读取后、选择渠道写入前，对同一内存字节快照重新核对独立清单。这里覆盖冻结包首次执行和已有收据重试，启动单个 GitHub 或 Workshop 写入前已经取得同一包的通过证据。原包、身份、来源清单和 generation lock 的摘要在续跑时必须一致。若历史发布缺少证明，保留原收据的阶段，新增写入停在预检。纯只读查询与历史归档的结构、哈希、收据复核仍使用既有入口。只有已取得独立证据且可保证没有写入的渠道读取才可脱离该新发布门执行。

标准包目前只接受 ZIP。沿用 `distribution._validate_paths()` 和归档读取器对成员名称、重复、可移植路径冲突及实际文件集合的校验，来源清单复用同一规范路径判据，任何额外成员皆须处置。后续若接受 tar，还需要在传递文件集合前独立拒绝硬链接、软链接、特殊文件、稀疏条目，校验有效名称（包含 pax 覆盖结果）、重复及路径冲突，按规范路径和实际普通文件内容生成来源清单。当前无需增加 tar 写入或解包。

合成证明使用独立构造的 ZIP 覆盖同路径原创、异路径保留原文、续跑身份变化、变更与缺失的分类、规范路径和清单可信绑定。在候选工作树将 `src` 加入 `PYTHONPATH` 后运行 `python -B -X utf8 -m pytest tests/test_candidate_publication_origin_gate.py`。下一步是把生成器的来源事实补齐并独立审核，再接到公开渠道和归档构建边界，使用合成包证明失败没有到达任何渠道写入。现有 3.4.0 归档可按其收据只读校验。后续新包另行按这些检查取证。 [合成证明](../../../tests/test_candidate_publication_origin_gate.py)

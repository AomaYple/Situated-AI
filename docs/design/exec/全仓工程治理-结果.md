## 范围与基准

这是规则、目录结构、代码、工具、配置与文档的工程治理，不是 Mod 功能开发。
基准提交为 `46c7348`，开始时工作树干净；用户授权提交、推送、PR 合并和可再生残留清理，
未要求恢复 A4、补完 Mod、启动游戏、部署、发布版本或更新创意工坊。

规则复核覆盖全局及项目 `AGENTS.md`、`CONTRIBUTING.md`、工程与 Mod 原则、工程基线、
安全政策、发布指南、编辑器/Git/依赖/测试/CI 配置；Claude 专属说明与代理定义仍只适用于 Claude。
全局文件不纳入项目提交，也不把客户端模型配置复制到项目规则。

## 工程修正

1. wheel 构建在临时源码副本中运行，构建后自动回收，嵌套 Python 禁止写入字节码。
   逐项比较模块集合和源码字节，拒绝缺失、额外、陈旧模块及重复 ZIP 条目，核对 ZIP CRC。
   既有 `source_modules`、`wheel_modules`、`missing_modules` API 保留，历史校验方不迁移身份。
2. 卫生工具拒绝不存在或非目录根；Windows 目录联接等重解析点与符号链接均不跟随。
   路径读取失败仍为违规，不扩大忽略目录或删除历史材料。
3. 资源前置门禁即使没有其他重型进程，也检查可用物理内存；显式并发模式保留原有行为，但记录低内存。
   不降低 4096 MB 起跑预算、700 MB 运行保护线、覆盖率或超时门禁。
4. 源码编码审计先识别符号链接，再处理已删除文件，避免损坏链接被当作普通删除而静默漏查。

新增回归先复现 wheel 与资源门禁缺陷，再实现修正；使用真实 wheel 构建检查临时隔离路径及全部模块字节。
未更改 Mod 行动、数值、生成器业务规则、生产本地化、包版本或用户游戏目录。

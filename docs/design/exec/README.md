## 命名说明

现存结果页有四种命名写法：`X-结果`（如 `D3-结果.md`）、`X-执行结果`（如 `分层联动-执行结果.md`）、`版本号-交付结果`（如 `3.2.0-交付结果.md`）
以及区间写法（如 `D11-D13-结果.md`、`K6-K13-结果.md`）。历史收据不改名，以免破坏哈希、manifest 与其他文档对原路径的引用；新增页面沿用与其同类的既有写法。

## 维护规则

- 计划目标不等于已实现能力；只有生产源、生成物、检查结果和收据相互对应时，才能标记静态出口完成。
- 结果页只记录可核查证据，并明确区分 `static_check`、`snapshot`、`simulation`、`runtime` 和 `inference`。
- 已退役的执行页从 Git 历史追溯；仍需迁移的旧计划与必要原始收据按合同保留，不作为新计划完成证据，也不进入标准 Mod 包。
- 版本标签不可移动或覆盖；标准包只能从对应标签的源和生成器重建。

命令、验证、文档维护和 Git 流程统一见根目录 [CONTRIBUTING.md](../../../CONTRIBUTING.md)。

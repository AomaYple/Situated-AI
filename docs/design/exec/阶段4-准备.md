## 三、G-EXIT-1：加一行数据 = 加一个处境

### 3.1 现在为什么做不到（三条机器证据，本轮实跑）

1. **第二份档案直接生成不出来**：`modgen.build_all([A, B])` → `DataError: 档案 zz_test 与前面的档案写了同一个产物路径：['.metadata/metadata.json'] —— 产物路径由 sitai_<档案 id>_* 派生`。
   根因：`modgen.py:984` 把 `METADATA_REL` 放进**每一份**档案的产物集，而 metadata 是 **mod 级**产物；`build_all` 的冲突检查（`modgen.py:1006-1011`）于是必然报红。
2. **闸门 ④ 的比对是全产物并集**：人工绕开 metadata 冲突后模拟 `gate_roundtrip`（`modguard.py:542-553` 的 `extra = [i for i in back if i not in want]`）得到——
   `gate4 sim ru_defeat: want 35 / back 67 / missing 0 / extra 30`、`gate4 sim zz_test: want 35 / back 67 / missing 1 / extra 31`。
   即：两份档案会**互相把对方的事实报成"多出"**；B 的 `missing 1` 正是 `metadata.id` 被 A 的那一份覆盖。
3. **自家产物内重复定义不报红**：让两份档案写**同一个** `je_sitai_ru_reform_window`，`modguard.definition_names()`（`modguard.py:227-238`，用 `set` 收集名字）只剩 1 个名字，闸门 ① 只把名字与原版取交集（`modguard.py:320-326`）→ **零问题**；而反解出来的是 2 条事实（`journal_entry.je_sitai_ru_reform_window.icon` ×2）。这是"加一行数据"最可能的静默失败方式。

## 五、G-EXIT-3：`gametimer` 对照不超预算（**需要真实游戏**）

### 5.1 未知一：gametimer 怎么开（未跑，必须先解决）

已实测的事实：

* 用户目录 `logs\` 里有 **12 份** `gametimer_20260913_*.tsv`（99,271–315,366 B，最新一份 2026-09-13 22:02），此后（含 09-20 全部探针局）**再没有新文件**；
* 格式（读原文）：首行 `Game Date \t Time Unit \t Seconds`，行如 `1836_05_01\tMonth\t8.836418`、`1838_01_01\tYear\t119.141134`；
* 扫 `binaries\victoria3.exe`（97,292,920 B）：`gametimer` 出现 **1 次**（就是文件名格式 `gametimer_%04d%02d%02d_%02d%02d%02d`），`-gametimer` 出现 **0 次** → **没有**这个启动开关；
* `console_history.txt`（49 行）里**没有** `gametimer`，但有 `measure_frame_time` / `log_ticktask_performance` / `TickTask.List` / `clear` —— 历史被 `clear` 过，**不能**据此反证"它是控制台命令"；
* 合成键盘已被否定（`自动化范式.md:204-206`）。

三条候选路线（都要游戏，判据统一）：**①** 启动参数穷举（含 `-debug_mode` 组合）；**②** mod 侧 `.gui` 的 `ExecuteConsoleCommand('…')`（`自动化范式.md:212-236` 的待测线索）；**③** 人手动在控制台敲一次点火，之后由脚本接管（一次性人工，代价最低）。
**统一判据**：跑完一局后 `logs\` 里出现**新的** `gametimer_<时间戳>.tsv`，且其行数随游戏时间增长（不是空文件）。**没有这条，G-EXIT-3 一行数据都取不到。**

### 5.2 未知二：单帧与"每国每月"的口径（实测限制）

* 「单帧 ≤0.5ms」（F9）**不能**由现有 tsv 给出：12 份文件里只有 `Year` / `Month` 两档，**没有帧行**；`logs\ui_animation_stats.log` 实测 **0 字节**。
* 可用的**代理**（F6：代理必须标注）：`logs\dedicated_server.log` 的逐 tick 行带**秒级**时间戳（实测 314 行，如 `[23:50:17][jominiapplication.cpp:539]: Processing Tick: 1836.1.1.6`）→ 只能识别"秒级卡顿"，**判不了 0.5ms**。
* 「每月每国 ≤2ms」需要两个量：每月秒数（tsv 有）与**当月 AI 国家数**（tsv 没有）→ 由压力场景驱动 mod 每月自报一行（照 `ZZPROBE` 的既有做法）取国家数。
* **结论**：`阶段4-结果.md` 里必须把三档预算逐条写成「实测值 / 代理值 / 未测」三态之一，**不许**用月度均值冒充单帧。

### 5.3 压力场景装置（`tools/probe/zz_stress/`，照 `zz_probe_ab` 的既有范式）

* **固定开局**：官方 `-scripted_tests` 从 bookmark 自己生成（`自动化范式.md:1.3` 实测：`custom_automated_stats.log` 里能看到 generate-from-bookmark → save-initial-save → load-initial-save → ingame-idler）；**不许**用"随机跑一局"当基准。
  ⚠️ 「固定存档」仍是**未实测**（`自动化范式.md:143-178`：exe 里没有 `-load*`，`continue_game.json` / 点「继续」三条都待实测）→ 本阶段**先做一条小实验**判定"固定开局到底有多固定"：同参数跑两遍，比 `dedicated_server.log` 起始 tick 与前 12 个月的 `gametimer` 均值；两遍不一致就记为"非确定开局"，并把它写进结果文档（P13）。

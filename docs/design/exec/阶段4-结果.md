## 三、G-EXIT-1 的实机自检：**被阻断**（如实记录，不当作通过）

按 `阶段4-准备.md` §3.5，实机步是"装进用户 mod 目录跑一局、看 `error.log` 里我们命名空间的
错误条数、看两条 JE 能否被条件解析"。这一步**尝试过、没跑成**，过程与证据：

```
1) 备份 content_load.json（2166 B / enabledMods 23 条）
2) 把仓库 mod/ 拷进 …\mod\sitai_ru_defeat（18 个文件）
3) content_load.json 追加我们的 path ⇒ enabledMods 变成 24 条（读回确认 has ours = True）
4) python -m pdx.game_auto run
   → 启动成功、进大厅成功，但在最后一步失败：
     TemplateNotFoundError: 点了「观察」(btn_observe @ (864,1055) score=0.860) 后 30 秒按钮仍在
     ⇒ 点击没生效（前台被抢或这一局大厅状态不同）—— 游戏进程还活着（PID 27504）
5) 查日志：error.log 里 sitai / tr_defeat / ru_defeat **0 命中**……
   但 debug.log 里**也没有任何 "Mounted Data" 行**，整个 logs/ 目录（含 debug.1–5 / error.1–5）
   对 `sitai` **0 命中** ⇒ **引擎这一局根本没加载我们的 mod**。
```

**结论**：`error.log` 的 0 命中是**空的**——mod 没被加载，0 错误不构成"脚本干净"的证据。

`-gdpr-compliant -debug_mode -scripted_tests`）；阶段 3 那些**确实挂上了探针 mod** 的局走的是
`v3 experiment launch`。两者差在哪（启动器 playset / 另一个命令行开关 / 元数据字段）**未查**。
判据建议：先用已知能挂载的路径（`v3 experiment`）跑一局，确认 `Mounted Data` 里出现

## 四、G-EXIT-4：无手写产物（达成，且补了一个实测存在的洞）

原先 `v3 modgen --check` 与 `v3 modguard` **都只认本档案命名空间**（`sitai_` 前缀）。实测：

```
mod/common/scripted_effects/zz_stray_handwritten.txt        （别的前缀）
  → v3 modgen --check  exit 0   盘上 9 个产物与数据源逐字节一致 ✅
  → v3 modguard        exit 0   五道闸门全过 ✅
mod/common/scripted_effects/sitai_stray_handwritten.txt     （本档案前缀）
  → 两道门禁都 exit 1
```

⇒ 换一个前缀手写一个游戏侧文件，**两道门禁都看不见**；而它会被照样打进 mod、可能与原版或
第三方撞名（正是闸门 ① / F7 存在的理由）。补的判据是 `tools/tests/test_mod_hygiene.py`：
**盘上 `mod/` 文件集 == 生成结果 ∪ 数据源**，带阳性对照（换前缀也一样抓得住）。

## 四、G-EXIT-4：无手写产物（达成，且补了一个实测存在的洞）

原先 `v3 modgen --check` 与 `v3 modguard` **都只认本档案命名空间**（`sitai_` 前缀）。实测：

```
mod/common/scripted_effects/zz_stray_handwritten.txt        （别的前缀）
  → v3 modgen --check  exit 0   盘上 9 个产物与数据源逐字节一致 ✅
  → v3 modguard        exit 0   五道闸门全过 ✅
mod/common/scripted_effects/sitai_stray_handwritten.txt     （本档案前缀）
  → 两道门禁都 exit 1
```

⇒ 换一个前缀手写一个游戏侧文件，**两道门禁都看不见**；而它会被照样打进 mod、可能与原版或
第三方撞名（正是闸门 ① / F7 存在的理由）。补的判据是 `tools/tests/test_mod_hygiene.py`：
**盘上 `mod/` 文件集 == 生成结果 ∪ 数据源**，带阳性对照（换前缀也一样抓得住）。

## 六、G-EXIT-3：**仪器已入库并实测出数；对照表未跑**

**先纠正一条此前的结论**：`gametimer_*.tsv` 的 `FRAME_GRANULARITY_AVAILABLE = False`
**只对那个文件成立**，不代表引擎没有帧级能力 —— 同一个 exe 里自带一套**逐帧逐任务**的计时：

* `dump_ticktask_timings [<file>]` → `ticktask_timings.csv`，表头
  `frame,task,milliseconds,calls,longest_lock`（exe 明文，逐串复核过计数与上下文）；
* `clear_ticktask_timings`：*"so the next dump covers only what follows"* ⇒ 可做**有界窗口**测量；
* `run_console_action`：命令行能发控制台命令（绕开 B31 的合成键盘问题），但**跑完即退** ⇒
  拿不到"跑到目标日期之后"的 dump，所以主路是 **debug 常驻 gui 按钮 + 鼠标点击**（实测走通）。

**第一份真实读数**（1,220,280 字节，`tools/pdx/gametimer.py` 已入库解析器）：

```
数据行 31458；坏行 0
帧 502 个；任务 257 个
每帧各任务合计：min=3ms 中位=14.0ms 均值=34.153ms max=472ms
最贵的任务：RecalculateModifierNodes  帧数=502 合计=3035ms 均值=6.0458ms 最坏=74ms 最长锁=46ms
```

两条对设计有直接影响的观察：**最贵的任务正是 `RecalculateModifierNodes`**，而我们的档案加的
就是 static modifier ⇒ 这是"我们让引擎多花了多少"的**直接观测点**；另外**毫秒是整数**
（单帧分辨率 1ms）⇒ F9 的「单帧 ≤0.5ms」不可能靠单帧读数证明，**必须窗口聚合**。

**未达成**：对照表（原版一局 vs 装 mod 一局、同开局同日期、每局 clear→跑 N 月→dump）**未跑**；
`阶段4-框架化.md` §④ 的标准压力剧本（大战 + 连锁破产 + 革命潮）**未构造**；`profiling.log` 那条
**未实测**。细节与复算命令见 `exec/阶段4-性能仪表侦察.md`。

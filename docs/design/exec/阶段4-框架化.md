# exec · 阶段 4：框架化（一页执行文档）

> 依据：`01-大方向.md` §3「阶段 4」三行。**写完即执行**；本阶段不做三行之外的事。
> 前置：阶段 3 收口（实验判定 + 归档清点 + 收口清单 A→E 全绿）；自动化范式已定（`exec/自动化范式.md`）。

## 三行判据（原文照抄，逐条落实）

* **目标**：数据源 schema 定稿 + 生成器完整化 + **五道闸门全绿** + 性能压力场景（大战 + 连锁破产 + 革命潮）。
* **出口判据**：**加一行数据 = 加一个处境**，不改逻辑；闸门与基准进 CI；`gametimer` 对照不超预算。
* **失败处理**：生成器撑不住 → 允许"手写一版再看抽象"**一次**，之后必须回到生成。

## 要做什么（对应三行的四件事）

### ① 数据源 schema 定稿（`mod/data/*.toml`）

* 冻结 schema v1：每个条目**必须**有 `why`（P10）与命名空间合法（F7）；`modgen` 校验失败即拒生成（P13）；
* **单一数据源**（P9）：脚本 / 本地化 / 文档 / metadata 全部由同一份数据生成，禁止任何手写产物（P3）；
* schema 一旦定稿，**加处境 = 加数据行**，生成器与闸门代码不改。

### ② 生成器完整化（`v3 modgen`）

补齐目前缺的产物类型（按需，不做无用抽象）：

| 类型 | 现状 | 阶段 4 要求 |
|---|---|---|
| `scripted_effects` / `static_modifiers` / `journal_entries` / `defines` / `localization` / 说明文档 / metadata | ✅ 已有 | 保持 |
| `ai_strategy_*` 牌（C 级手段） | 生成器已支持（用例覆盖过/红两路），档案里 **0 张牌**（F5） | 需要时**只加数据行** |
| 事件 / 决议（若某个处境需要） | ❌ 无 | 先问"能不能用 A 级/JE 表达"，不能再加，且**只加数据行** |

### ③ 五道闸门全绿 + 进 CI

* `v3 modguard` 五道闸门（键/路径不相交、引用完整性、稀释预算、往返净度、生成可复现 + `why` 非空）；
* **进 CI** 的口径：无游戏环境下必须能跑的闸门走 `--offline`（阶段 1–2 已给离线核验通道），有游戏时跑全量；
* 闸门与基准**一条命令可复算**，写进 `exec/收口清单.md` 的 C 段。

### ④ 性能压力场景（大战 + 连锁破产 + 革命潮）

* 剧本（对应 `backlog` B20）：**固定存档 + 固定指令序列**，做成可重放脚本；
* 测法：`gametimer_*.tsv` **平均值 + 最坏帧**，对照"原版同场景"与"装 mod 后同场景"；
* 预算（F9）：≤ 引擎自身 AI 开销 5% 量级；每月每国 ≤2ms；单帧 ≤0.5ms；
* 顺带把 `backlog` B27（节奏杠杆的开销）在这里测掉。

## 出口验收（怎么算过）

| # | 判据 | 验证方式 |
|---|---|---|
| G-EXIT-1 | **加一行数据 = 加一个处境** | 实测：往数据源加一个新处境（例如第二个国家的一份档案骨架），**只改数据**，生成 → 五道闸门 → 游戏内自检全绿；文档记录改动行数（应为"只加数据行"） |
| G-EXIT-2 | 闸门进 CI | 一条命令跑完五道闸门 + 全量门禁；写进收口清单；无游戏环境可跑离线部分 |
| G-EXIT-3 | `gametimer` 对照不超预算 | 压力场景下 mod 版 vs 原版版的均值/最坏帧对照表，落在 `exec/阶段4-结果.md` |
| G-EXIT-4 | 无手写产物 | `v3 modgen --check` 与 `ai-surface --check` 一致；仓库里不存在手写的游戏侧文件 |

## 失败长相与处置

| 现象 | 含义 | 处理 |
|---|---|---|
| 加数据行必须改生成器代码 | schema 抽象错了 | 改 schema（**不是**加特例）；改完重跑 G-EXIT-1 |
| 生成器撑不住某类产物 | 抽象不足 | **允许手写一版再看抽象一次**（照三行原文），之后**必须回到生成**，并在结果文档写明这次豁免 |
| `gametimer` 超预算 | 频率/结构问题 | 按 P2 三条红线回退：减频率、把热路径改成读预存值、把 `weight` 块里的表达式挪到预计算 |
| 压力场景不可复现 | 剧本没钉住 | 用固定存档 + 固定指令序列重做；不可以用"随机跑一局"当基准 |

## 依赖与回滚

* 依赖阶段 3 的**自动化范式**（压力场景要能反复重放）：若自动化只到"一次点击换一整套数据"，则剧本按"一次点击 + 自动跑到目标日期"设计；
* 所有产物可安装、可卸载、可回滚（P12）：装 → 卸 → 黄金回归；
* 本阶段**不做**：档案扩张（阶段 5）、可见性与难度（阶段 6）。

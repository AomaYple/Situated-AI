   ```text
   .venv/Scripts/v3.exe modgen --check
   .venv/Scripts/v3.exe verify
   .venv/Scripts/v3.exe citations --offline
   .venv/Scripts/v3.exe objectives --check
   .venv/Scripts/python.exe -m pytest -q -n auto            # 单文件用 -n0
   .venv/Scripts/python.exe -m ruff check .
   .venv/Scripts/python.exe -m ruff format --check .
   .venv/Scripts/python.exe -m mypy --no-incremental
   .venv/Scripts/v3.exe cov
   ```
4. 标准 `acceptance` 模式：**功能做到** + **不破坏**（门禁全绿）+ **有牙**（注入反例必须变红）+ **记录**（改前/改后 sha256 + 行号 + 命令 + 读数）+ **报告落盘路径**。
5. **依赖只能指向已存在的卡**；`inScope` 重叠的卡必须串行（分波）。

### 5.2 怎么盯（省 token、不误事）

- **不要轮询**：成员报告会唤醒队长。归档/停队后不要在无授权时重建工作。
- `update_task` 的 `output` **≤600 字**（摘要 + 交付件路径 + sha256），长内容写进报告文件；**大块写入拆成多次小 `edit`**（否则可能 `MALFORMED_RESPONSE` 掐断整轮）。
- 成员报「未达成 / 阻断」时**照实记账**，别为凑绿放松判据；判据要改就显式改并留痕。
- 队长**不要替成员干活**（除明确的接管授权）；也不要替用户按「停」。

### 5.3 收尾顺序

`INT1 集成收口`（8 条逐条对照 + 一页人读总结 + 下一轮候选清单 + 全门禁现跑）→ `VFinal 独立验证` → `RVFinal 最终评审` → `C1 按主题分块提交`（**不 push**）。

## 6. 铁律

1. **正确性第一、速度第二**；**「未达成」不许写成「达成」** —— 无法在本机验证的（macOS/Linux 实跑、CI 是否触发）**单列一栏**。
2. **所有文件 UTF-8 无 BOM + LF**（游戏侧生成物按白名单保留 BOM）。
3. **删除三条件**：无引用 + 有替代 + 可复算；已明确废弃可例外；**删除必须可逆且可复算**。
4. **不得打断上一轮 mod 的恢复路径**（§3·B 的清单）；移动/改名必须同步改文档并给「旧→新」清单。
5. **`v3 modgen --check` 必须始终 EXIT 0**（69 产物逐字节一致）。
6. **`inScope` 互斥是创建时的静态检查** ⇒ 重叠路径分波建卡（§3）。
7. 实机活走机器锁协议（§2.5）：取锁 → 冷启动闸 → 收尾三件。
8. 大块工具写入拆小步，避免 `MALFORMED_RESPONSE`。

## 7. 已知的坑（按主题，能省几小时）

**A. harness 与团队**
1. 质量类卡（implementation/review/…）的 `inScope` 必须互斥，报错形如 `inScope overlaps tX`；**传递依赖不算串行**，要直接串行或拆精确文件路径。
2. `changedPaths` 与 `inScope` **精确匹配**（照 inScope 原文写）；inScope 写目录条目时 changedPaths 也只能原样写目录名 ⇒ **尽量写文件级**。
3. 报告路径必须写进 `inScope`/`deliverables`，否则 `changedPaths` 被判 `<path> is undeclared`。
4. `MALFORMED_RESPONSE` 与「单次超长工具入参」相关 ⇒ 摘要 ≤600 字、长文入文件、大块写入拆小。
5. 长时批处理**不能**「起后台 job 后结束 turn」（turn 一结束进程树被杀）⇒ 必须在 turn 内等待。
6. 杀进程**不许**按命令行正则宽匹配（曾误杀 DSH 自己的 node.exe）⇒ 精确「可执行名 + 参数特征」并先打印命中清单。
7. `review` 卡必须给 `reviewedTaskId` 与 `round`，完成时 verdict = `pass` 才算过；`repair` 要 `sourceTaskId`（+ findings）。

**B. 实机仪器（Windows）**
8. **`.venv\Scripts\v3.exe` 与 `python.exe` 必须是 Medium 完整性标签**（否则写 `Documents\…\Victoria 3\` 三处同时 `WinError 5`，而 PowerShell 手工操作却成功）：
   `icacls "…\.venv\Scripts\v3.exe" /setintegritylevel Medium`（**字节不变、可逆**）。**每次实机跑前复验**（重启/策略会重新贴 Low）。
9. 冷启动：重启后第一局 `wait_for_boot_settle` 的 20 s 安静判据会落在加载停顿里 ⇒ **任何实机批前先跑一次不计入样本的热身**（冷启动到按钮实测 205.8 s，热启动 0.2 s）。
10. **游戏起局后是暂停态**：暂停期完全不写 `Processing Tick` ⇒ 「零 tick」不等于点击没生效，先按空格解暂停再判。
11. `btn_start_game` 模板在**禁用态与启用态都是 1.0** ⇒ 「选中国家了吗」要用按钮内芯 RGB（`(58.7,60.0,60.1)` 禁用 → `(61.0,66.2,46.8)` 启用）。
12. **难度档位跨会话粘滞**（某遍没点 ▶，`tier_harsh_name` 已命中）⇒ 复现遍别当成「翻档成功」。
13. **模板互锁**：收料遍里「缺模板的步不点」⇒ 规则窗不关 ⇒ 后续步骤无处可找 ⇒ **Pass B 至少要两遍**（先点 `btn_rule_next` 把档翻到「无情」裁 `tier_harsh_*`）。
14. **JE 面板在左侧**（x≈60–640），入口 = 左侧竖排图标列 journal 按钮 ≈(30,706)；条目在**「日志条目」页「国内事务」组**；`je_panel` 常量 = `(0.0276,0.0676,0.3188,0.9204)`。
15. **硬编码几何不可靠**（一晚三次不符）⇒ 改成由模板/行 box 推导，或加启动期几何自检（`t40`）；驱动自带的 `require_row_arrows` 会拦错，别绕过它。
16. `rule_card_title_sitai` 是**历史名字**（从没落盘过）；L7 的定位物是 `rule_row_sitai`。
17. 光标停在北大西洋会让省份 tooltip 遮住底部条 ⇒ **起局前把光标停到不遮底部条处**（只移不点）。
18. Windows 前台锁：shell 岛持焦点时我们的进程链**没有置前权** ⇒ 已验解法 = **Alt 轻敲**取得置前权后照原样调 `_route_to_foreground(force=True)`；**别**自造「不抢前台点击」的新机制。
19. 前置权丢失的表现是 `ForegroundLostError`；最小化窗口上的「假成功」已被改成抛异常。
20. `crosscheck` 的实机口径是 **EXIT 3（不可核对）**（Workshop 覆盖 `gui/*.gui` 时 token 行号不可比）；别把「行号不可比」当「真错配」。

**C. 仓库、编码与文档**
21. **`.gitignore` 已管住 `tools/out/*`**（只 carve-out `tools/out/snapshots/*.compact.json`）—— 别说「会被 `git add -A` 扫进去」。
22. **快照时序**：`v3 snapshot create --compact` 必须在**所有**文档/数据源改动后重刷并 `git add`；**禁止**照 `v3 tables --offline` 的提示跑 `--write`（会把陈旧值写死）。
23. `.gitignore:130` 与 `src/pdx/cli.py:909-910` 写「92 篇官方文档仍在 git 历史里」是**错的**（`git log -- research/official-docs` 0 提交）⇒ 要改文，别当包袱。
24. **`tools/design` 目录不存在**（仓库与 git 历史都没有）⇒ 建卡引用路径前先 `Test-Path` / `git ls-files`。
25. `ruff format --check` **会格式化 Markdown 里的 python 代码块**（`.py.frozen` 只躲 lint/mypy，**不躲 format**）。
26. 多人并行改仓时别人在飞的编辑会让整树门禁变红 ⇒ 先 `git status` + 归因到具体文件，再判断是不是自己的。
27. 覆盖率/性能分母**不含仪器层**：635 个 `tools/out/**/*.py`（163,914 行）单独报。

**D. 性能与内存**
28. 本机 RAM 15.8 GB：全量 pytest 会把空闲内存压到 ~2.6 GB ⇒ 同一时刻只跑一个重活；要并行先压 worker 数。
29. **全仓 pytest 别用 `-n0`**（串行 600 s 才 43%）；默认 `-n auto --dist loadscope`。
30. 跑基准必须显式 `--benchmark-only`（`-n0 --benchmark-only` 也能出表）。
31. 本机 **pytest 峰值 RSS 测量不可靠**（psapi `ok=False`、`Win32_Process` 出 0.1 MB 坏读数）⇒ 拿不到就如实记「未取得可信峰值」。

**E. 内容与设计**
32. 建图时必须把「大方向文档的义务/欠账清单」**逐条映射到卡或显式延期 + 理由**（否则会像我一样只追阶段出口，漏掉 §0 派生义务与 `阶段5-9国目标函数表.md` §六 的四条）。
33. mod 内容改动只许「删无用 + 合并重复 + 统一命名」，**数值/条件/触发链/权重零改动**（y1）。
34. `on_complete` 里的 `set_strategy` 裸写会被引擎拼成 `BUG: …` 文本（`effect_localization/00_country_effects_loc.txt:40-42` 只登记 `global`、那格要 `first`）⇒ 可见块必须包 `custom_tooltip`，生成器对四类错法直接 `DataError`。

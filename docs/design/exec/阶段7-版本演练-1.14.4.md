## 三、`v3 refresh` **不是**一条命令就能变绿的 —— 这一点要写清

`refresh` 做的是「**表按新原版重算** + **正文按归属标记改写**」。它**不改断言表里的期望值**
（那是 `tools/pdx/verify.py` 的 `CLAIMS` 常量）。所以官方更新后的正确顺序是：

```text
① v3 refresh                       # 表重算 + 正文可机械修的部分
② v3 verify --fix-claims           # 把**实测值**写回 CLAIMS（本轮新加，41/44 自动）
   手工改 3 条非整数指纹（caligula_rev / caligula_branch / 版本号）
③ v3 verify                        # 应回到 234/234
④ v3 ai-surface --write            # 原版 AI 面变了，对照面要重写
⑤ v3 mirror write --sync           # 官方 .md 清单与镜像（篇数会变！）
  v3 snapshot create --compact     # 刷新入库快照（版本/表/AI 面/引用支撑）
⑥ v3 analyze                       # 产物重算（check-outputs 与黄金回归都读它）
  pytest tools/tests/test_golden.py --force-regen + 全量套件
⑦ 一次常规开局（python -m pdx.game_auto run）—— 引擎侧实证
```

**② 是本轮新补上的自动化**（`v3 verify --fix-claims`，见 `阶段7-长期维护.md` §四）：
它按 `ast` 的精确偏移只换期望值那个字面量，并在表里提示「描述里还写着旧值」。
它**不**代改描述 —— 有些旧数字是故意留的历史对照（如 `chr.tech_definitions` 的
"178 是 1.14.2 旧值"）。本轮 18 条描述里的旧数字是手工改的。

> ⚠️ **快照 diff 的口径陷阱**（本轮实测）：`v3 snapshot diff release-1.14.3 release-1.14.4`
> 会报出「删除 1,162,183 条」，而真正的原版变化只有几百处 —— 因为入库的 1.14.3 快照是
> **上一轮的域集合**（6 个域，`localization` 存明细），而 1.14.4 是 14 个域
> （`localization_digest` + `ai_surface` / `vocabulary` / `citation_support` 等）。
> 差异里混着格式变化。现在命令会**显式点明**域集合不同、并列出可比的那几个域；
> 真正可比的口径是两侧都有的 `common_entries` / `defines` / `fields` / `dlc` / `config`。

## 四、这次更新的性质：**不是**破坏性变化

`01-大方向.md` §7 只允许两种情况新增变更记录行：G1 失败回炉、**官方破坏性更新**。
本次**不属于**后者，理由（全部实测）：

1. `v3 modguard` **五道闸门全过** —— 我们引用的原版键、图标、修正字段、JE 分组**一个都没失效**；
2. `v3 citations` **850 条全部还指得到唯一一行** —— 我们引用的行号**没有被挪动**；
3. `v3 modgen --check` 通过、**67 个产物与数据源逐字节一致**；黄金回归里 **mod 侧 4 个产物逐字节不变**
   （变大的 4 个全是游戏侧 JSON/报告）；
4. 43 条红全是**数量漂移**，没有一条是"引用不到"或"字段消失"。

⇒ **大方向文件不动**（它仍然是冻结的）。顺带把 mod 声明的
`supported_game_version` 从 `1.14.3` 提到 **`1.14.4`**（9 份档案的 `game_version` 同步），
`v3 release` 三边一致 ✅。

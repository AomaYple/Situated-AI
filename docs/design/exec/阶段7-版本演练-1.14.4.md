## 三、`v3 refresh` **不是**一条命令就能变绿的 —— 这一点要写清

`refresh` 做的是「**表按新原版重算** + **正文按归属标记改写**」。它**不改断言表里的期望值**
（那是 `tools/pdx/verify.py` 的 `CLAIMS` 常量）。所以官方更新后的正确顺序是：

```text
① v3 refresh                 # 表重算 + 正文可机械修的部分
② **人改 CLAIMS 的期望值**    # 48 处；每一条都要按"新原版实测值"改，并留痕
③ v3 verify                  # 应回到 234/234
④ v3 ai-surface --check --write   # 原版 AI 面变了，对照面要重写
⑤ v3 snapshot create --compact    # 刷新入库快照（版本/表/AI 面/引用支撑）
⑥ 黄金回归重新生成 + 全量套件
⑦ 一次常规开局（`python -m pdx.game_auto run`）—— 引擎侧实证：mod 还挂得上、没有新错误
```

**第 ② 步是本轮没做完的那一步**（48 处），也是"官方更新"这件事真正的固定成本。
第 ⑦ 步也还没做。

## 四、这次更新的性质：**不是**破坏性变化

`01-大方向.md` §7 只允许两种情况新增变更记录行：G1 失败回炉、**官方破坏性更新**。
本次**不属于**后者，理由有三条实测：

1. `v3 modguard` **五道闸门全过** —— 我们引用的原版键、图标、修正字段、JE 分组**一个都没失效**；
2. `v3 citations` **850 条全部还指得到唯一一行** —— 我们引用的行号**没有被挪动**；
3. `v3 modgen` 编译通过、67 个产物与数据源逐字节一致。

⇒ **大方向文件不动**（它仍然是冻结的），本次演练记在这里与 `阶段7-长期维护.md` 的演练记录里。

# 并行测试内存基线：2026-10-03 复测

本记录补充 `并行测试内存基线.md` 中的历史读数。历史文档保留旧口径和优化过程；本记录冻结词法器优化后的当前运行门槛与实测结果。

## 结果

本轮首先运行 `mem_baseline.py one biggest`，逐文件解析全部 6,254 个真实语料文件。最大文件是 `european_dynamic_forestry_objects_generator_2.txt`，大小约 2.47 MiB，内部有一个跨 26,829 行的长字符串。

| 指标 | 优化前记录 | 优化后复测 |
|---|---:|---:|
| 该单文件造成的峰值 | 约 1,193.2 MiB | 122.9 MiB |
| 首次超过 512 MiB 的文件 | 1 个 | 0 个 |
| 全部 6,254 文件的逐文件步骤 | 约 26 秒 | 约 12 秒 |

原因是 `src/pdx/lexer.py` 的字符串正则使用贪婪回溯。Python 3.11 起使用 possessive quantifier（`*+`）后，重复段不会在闭引号处逐字符回溯；未转义引号仍然是唯一的结束标记，差分测试在真实语料和合成样例上保持通过。

随后用仓库 `.venv` 运行：

```text
.venv\Scripts\python.exe tools\probe\mem_baseline.py run --groups auto --tag memfix-auto --index tools\out\mem\memfix-auto-index.json --wait-quiet-s 0
```

结果为：3 个 worker，2,204 passed，10 skipped，1,501 个 subtests，退出码 0，墙钟 912.3 秒，整套峰值 2,593.7 MiB，每 worker 峰值 1,353.1 MiB。`peak_total_mb` 小于旧的 3,072 MiB 总量上限。

无磁盘缓存的 `n4-nocache` 对照为 4 个 worker、2,179 passed、25 个缓存契约失败、10 skipped、1,501 个 subtests，墙钟 838.0 秒，整套峰值 3,110.8 MiB，每 worker 1,364.3 MiB。失败集中在明确要求磁盘缓存存在的测试，属于实验臂预期结论；内存读数仍低于新的 1,536 MiB/worker 门槛和 4 worker 的总量上限。

## 门槛口径

旧文档的 512 MiB 每 worker 目标适合作为单文件异常峰值探测线，但不适合作为完整测试 worker 的运行预算：一个 worker 会同时保留 `ga`（单点实测峰值 504.8 MiB）、`ma`（257.9 MiB）以及有界解析缓存和 pytest/xdist 开销。继续把完整 worker 与单文件异常使用同一数值，会把必需的分析数据误判为异常。

当前运行门槛统一采用 `src/pdx/parallel.py` 已使用的 `DEFAULT_WORKER_MIB = 1536`：

```text
整套上限 = 1024 MiB 车头 + 实际 worker 数 × 1536 MiB
每 worker 峰值 ≤ 1536 MiB
```

这个调整有两个前提：长字符串的异常回溯已经消除；`n auto` 的实际读数 1,353.1 MiB 留有约 12% 余量。`tools/probe/mem_baseline.py check` 现在读取同一门槛，避免并行度计算和内存门禁各自使用不同预算。

## 正确性与边界

`tests/test_lexer.py`、`tests/test_lexer_differential.py`、`tests/test_parser.py` 和内存探针测试通过；差分测试继续逐 token 比较真实语料，优化没有改变 AST、行号、引号标记或错误恢复。

macOS 没有等价的进程高水位 API，探针会把 `peak_source` 标成 `sampled`；Windows/Linux 使用 OS 高水位。不同平台的绝对 MiB 读数只能在相同测试集合、缓存状态和 worker 数下比较。

单 worker 的完整测试仍会因为 `ga`、`ma` 和分析中间结构叠加而高于 1.5 GiB；如果机器可用内存不足，`tests/conftest.py` 的 `-n auto` 护栏会自动降到更少的 worker。正确性门禁不因内存紧张而静默跳过测试。

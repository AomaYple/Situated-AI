## 一、版本演练（官方更新后跑一次；步骤固化在这里）

按顺序跑，**每一步都要留下实际输出**（不是"应该没问题"）：

```powershell
# 0) 版本指纹：确认"现在面对的是哪个版本"
.venv\Scripts\v3.exe refresh                     # 重算依赖原版的统计（会写 tools/out/）
.venv\Scripts\v3.exe verify                      # 234 条断言：文档里的数字还对不对
.venv\Scripts\v3.exe tables                      # 171 张生成表：还与游戏一致吗（**不带 --write 就是核对**；没有 --check 这个选项）

# 1) 生成器输入清单：官方动了哪些目录/键 → 生成物是否还合法
.venv\Scripts\v3.exe modgen                      # 编译（不写盘）：schema 与数据源自洽
.venv\Scripts\v3.exe citations                   # 850 条 文件:行号 引用：还指得到吗
.venv\Scripts\v3.exe modguard                    # 五道闸门（① 键与原版不相交最容易被更新打破）

# 2) 代码与测试
.venv\Scripts\ruff.exe check .
.venv\Scripts\ruff.exe format --check .
.venv\Scripts\mypy.exe
.venv\Scripts\python.exe -m pytest -q -n auto    # 默认并行

# 3) 一次常规开局（引擎侧实证：mod 真的挂上、没有新错误）
.venv\Scripts\python.exe -m pdx.game_auto run    # 起游戏 → 观察 → 5 档 → 空格 → 切后台
#   然后看日志：Mounted Data 里有我们的 mod、error.log 里没有我们的键名真值
Get-ChildItem "$env:USERPROFILE\Documents\Paradox Interactive\Victoria 3\logs\*.log" |
  Select-String -Pattern "sitai","错误","Error" | Select-Object -First 20
```

**"全绿"的定义**：上面每一步退出码 0（`pytest` 0 失败、`modguard` 五道全过、`verify`
234/234、`tables`（不带 `--write`）一致、`citations` 全部指得到），**并且**第 3 步的两条实测
判据成立（`Mounted Data` 有我们、`error.log` 里没有我们的标识符）。

**失败了怎么办**（照 §3 阶段 7 的"失败处理"）：修引用 + 更新生成器输入清单，
并把**这次失败**记进 `backlog.md`（新条目）与本节末尾的"演练记录"。

> ⚠️ **一处必须说明的口径冲突**：冻结文档写的是"把这次失败写进 §7"，而 §7 在
> `01-大方向.md` **内部**，那份文件是**冻结的**（本仓库的纪律：方向文档不许改）。

## 二、闸门与基准进 CI（现状矩阵，逐条写清"在哪跑、为什么"）

CI 配置：`.github/workflows/ci.yml`（两个 job：`check` 跑 3.11/3.14 矩阵，`lock` 固定
Windows 跑依赖锁）。

| 检查 | CI | 本机 | 为什么 |
|---|---|---|---|
| `ruff check` / `ruff format --check` / `mypy` | ✅ | ✅ | 不需要游戏 |
| `pytest -m "not integration"` | ✅ | ✅（全量） | 无游戏时 conftest 自动 skip 集成用例 |
| `v3 verify --from-snapshot`（43/234 条） | ✅ | ✅（234/234） | 入库精简快照带着当时的真值 |
| `v3 tables --offline`（171 张） | ✅ | ✅ | 快照里带着每张表当时的数据行 |
| `v3 modgen --check`（32 产物） | ✅ | ✅ | 只比对数据源与盘上产物 |
| `v3 modguard --offline` | ✅ | ✅（在线版） | ①② 的原版真值走快照 |
| `v3 ai-surface --check --offline` | ✅ | ✅ | 同上，且复用同一个 `render()` |
| `v3 lock` | ✅（Windows job） | ✅ | 锁是本机解析出来的闭包，必须同平台 |
| `v3 citations`（850 条引用） | ✅（`--offline`） | ✅ | 快照里的 `citation_support` 域记着每条引用的**文件行数 + 被引那一行的文本指纹**（B77 闭环）；离线核的是"与入库快照一致" |
| `v3 tables`（不带 `--write`，171 张） / `v3 verify`（全量） | ❌ | ✅ | 要读游戏本体重算 |
| `v3 cov`（覆盖率门禁） | ❌ | ✅ | 无游戏时集成用例被 skip，覆盖率必然低于下限（CI 上判它是**误报**） |
| 基准（`pytest-benchmark`） | ❌ | ✅（`-n0`） | 基准数字与机器相关；CI 上跑出来的数不能与本地对照 |

## 三、维护预算（一次改动的固定成本，实测口径）

| 动作 | 实测耗时 | 说明 |
|---|---|---|
| `pytest -q -n auto`（1434 条，全量） | **≈3.5 分钟** | 本机 16 核；这是每次改动的下限成本 |
| `v3 modgen` + `--check` + `modguard` | ≈40 秒 | 生成 + 五道闸门 |
| `v3 verify` + `tables` | ≈1.5 分钟 | 234 条断言 + 171 张表 |
| `v3 citations` | ≈10 秒 | 850 条引用（含一次原版目录索引） |
| **一次完整门禁** | **≈6 分钟** | 上面四项之和 |
| 一次游戏会话（起→观察→5 档→空格→切后台→收尾） | **≈4–5 分钟** | 加载 ≈3 分钟 + 会话 ≈1.5 分钟（`性能仪表侦察.md` 的实测口径） |
| 一次 A/B 对照（12 个月 × 2 局，`perf_compare.py`） | **≈22 分钟** | 每局 ≈11 分钟；`--repeat 3` 约 1 小时 |

**预算口径**：改一个档案的常规成本 = **6 分钟门禁**；要动世界状态的改动 **+ 一次游戏会话**；
要声称性能没退化的改动 **+ 一次 A/B**。这三档写在这里，是为了让"要不要跑"这件事
有依据，而不是凭感觉。

## 四、还欠的三件事（照实列）

1. ~~**`v3 citations` 进 CI**~~ ✅ **已做（2026-09-23，B77 闭环）**：精简快照新增
   `citation_support` 域（每条引用记着**文件行数 + 被引那一行的文本指纹**），
   `v3 citations --offline` 在 CI 上核「与入库快照一致」，CI 加了这一步（check job 现 13 步）。
   口径与其它离线通道一致：**它证明的是"与入库快照一致"，不是"与现在的游戏一致"** ——
   后者是本机门禁的活，而且有游戏时 `v3 citations` 会顺手核「被引那一行还是不是那句话」，
   那正是官方更新挪走我们依据的信号（也正是 §5 版本演练要的第一手证据）。
   **维护动作**：改过引用（加档案 / 改 why 的行号）之后跑一次
   `v3 snapshot create --compact` —— 快照是入库的，本次刷新只多了这一个域。
2. **标准压力剧本**（大战 + 连锁破产 + 革命潮）：阶段 4 §④ 要的受控对照，仍未构造
   （`阶段4-结果.md` §六·补 已说明它决定"0.5ms 能不能分辨出来"）。
3. **发布流程的机械部分**：changelog ↔ 档案的对应关系目前只有人工纪律
   （`mod/data/<id>.toml` 的 `id` 必须出现在 changelog 条目里），还没有工具检查。
4. **覆盖率的 CI 口径**：现在 CI 完全不跑 `cov`（无游戏必误报）。要么做一个
   "只算非集成用例"的**独立下限**并入库，要么维持现状并在文档里写清 —— 现在选的是后者。

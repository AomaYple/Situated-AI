## 3. 帧级测量口径（B40 的裁决）

### 3.1 两个硬事实（决定公式长什么样）

1. **毫秒是整数**【实测】：`ticktask_timings.csv` 的 `milliseconds` 列是整数（`src/pdx/gametimer.py:497`、
   `:507`；`阶段4-性能仪表侦察.md:40`）⇒ **单帧/单任务读数的分辨率是 1 ms**；
2. **有 `frame` 列**【实测】：引擎每 6 帧落一组（`TICKTASK_FRAME_STEP = 6`，`src/pdx/gametimer.py:119`；
   实测 12 个月 ≈ **1500 帧**，`阶段4-结果.md:179`），且 `clear_ticktask_timings` 能给**有界窗口**
   （"so the next dump covers only what follows"，`阶段4-性能仪表侦察.md:12`）⇒ 窗口内的帧数**是可实测的**，
   **不需要假设**（这一点正好满足 B40 的警告）。

### 3.2 公式（写死；t22 与后续闸门照这个实现）

设窗口 `W` = 两次 `clear`/`dump` 之间的全部帧（`frame` 列的**实测**集合），`|W|` = 帧数。

```
① 每帧合计            T_f  = Σ_task ms(frame=f, task)        # gametimer.ticktask_frame_stats() 的 total_ms
② 主量（窗口均值）    M(W) = ( Σ_{f∈W} T_f ) / |W|           # 单位 ms/帧；= summarize_ticktask()['per_frame_total_ms']['mean']
③ 任务均值            M_t(W) = ( Σ_{f∈W} ms(f, t) ) / |W|     # t 取 §3.3 的名单；= ticktask_task_stats() 的 mean_ms
④ 两臂增量（配对）    Δ_arm  = M_ours(W) − M_vanilla(W)       # 同一 repeat 序号的两局相减
⑤ 归因增量            Δ_attr = 对 §3.3 名单逐任务算 ③ 的差，求和
⑥ 噪声带            U(n)  = t_{0.975, n−1} · s_d / √n        # s_d = 配对差 ④ 的样本标准差；n = 配对局数
```

**判决规则（配对的 Student-t，两条）**：`Δ̂ = mean(Δ_arm)`；
* **达标**：`|Δ̂| + U(n) ≤ 阈值`；
* **未判决**：`U(n) > 阈值`（此时**只能**报 `Δ̂ ± U(n)`，**不许**写"达标"或"超预算"）。

### 3.4 窗口长度怎么定、为什么

* **下界**：必须覆盖**三波压力的全部释出** —— 大战 1837.1、破产 1837.7、革命潮到 **1838.7** ⇒ 从 1836.1 开局
  起算 **≥ 33 个月**；取整 **`--months 36`**（≈ 4500 帧，按实测 12 月 ≈ 1500 帧换算）。
* **上界与理由**：窗口越长，**均值分辨率越高**（`1/|W|` ms，4500 帧 ⇒ 0.0002 ms），但**不降低**
  run-to-run 噪声（§3.5）⇒ 加长窗口买的是分辨率，不是判决力。
* **两臂必须同起止**：`clear` 都在进局后、压力释出前；`dump` 都在同一 `--months`（用 §2.1 ④ 的日期自报背书）。

### 3.5 判决力：**今天 0.5 ms 判不出来**（这是本页最重要的一条）

用 §六·补 的 6 局实测（`阶段4-结果.md:182-192`）算：配对差 = −1.32 / +0.10 / −0.31 ms ⇒ `s_d ≈ 0.73 ms`。

| n（配对局） | `U(n) = t_{0.975,n−1}·s_d/√n` | 能判 0.5 ms 吗 |
|---|---|---|
| 3（已跑过） | **1.815 ms** | ❌ 不能（噪声带是预算的 3.6 倍） |
| 10 | 0.523 ms | ❌ 刚好够不着（差 0.023） |
| 11 | **0.491 ms** | ✅ **最小的可判 n**（`|Δ̂| + 0.491 ≤ 0.5`） |
| 20 | 0.342 ms | ✅ 有余量 |

**要判 0.5 ms 需要什么（条件清单）**：
1. **先量 s_d，再按本页自己的判据定 n（不是估）**：跑 **3 对 pilot**（受控剧本 + 固定协议）算 s_d，
   然后**从 n = 3 起逐个试，取第一个满足 `U(n) = t_{0.975,n−1}·s_d/√n ≤ 0.5` 的 n**：

   | s_d | **最小 n** | 边界证据（两个 U 值，缺一不可） |
   |---|---|---|
   | **0.7308**（今天实测） | **11** | `U(11) = 0.491` ✓ ／ `U(10) = 0.523` ✗ |
   | 0.3654（= 0.7308 的一半） | **5** | `U(5) = 0.454` ✓ ／ `U(4) = 0.581` ✗ |
   | 0.30 | **4** | `U(4) = 0.477` ✓ ／ `U(3) = 0.745` ✗ |
   | 0.20 | **3** | `U(3) = 0.497` ✓ ／ `U(2) = 1.797` ✗ |

   ⇒ **对 `t22` 的机器时间影响（要按这个排实验）**：按 **11** 排而不是更保守的 17–19 排，**省 ≈35%**；
   s_d 若降到 0.30，按 **4** 排而不是 7–8，**省 ≈50%**（每局都是一次完整实机会话，这是本轮最稀缺的资源）。
2. **"降噪比加局数便宜"这句话要说准**：`n` 只在 t 变化可忽略的区间里近似 ∝ `s_d²`；
   小 n 时 t 变大 ⇒ 缩得**更温和**（实测：s_d 减半 0.7308 → 0.3654 只把 n 从 **11 降到 5**，不是 11→2.75）。
   ⚠️ 表里的 n 是**最小值（不含余量）**：要余量必须**先定目标再算**——同一 `s_d = 0.7308` 下
   目标 `U ≤ 0.4` ⇒ **n = 16**、目标 `U ≤ 0.333` ⇒ **n = 21**。**不许**拿"17–19"这种没有对应目标的数排实验。
   ⚠️ 闭式 `n ≈ (t·s_d/0.5)²` **只是粗估，不是判据**：同一 s_d=0.7308，按 t=4.303 算得 40、按 t=2.228 算得 10，
   **两头都不是 11**（t 随 n 变，只有对 `U(n) ≤ 0.5` 迭代不动点才是对的）。
3. **降 s_d 的手段（按性价比排）**：① 受控剧本（§2 的三条压力 + 固定日期 ⇒ 世界演化对齐）；
   ② 固定存档（§1.5，进一步消掉开局分叉）；③ 同机同时段交替跑（runner 已经是交替顺序，`:315-318`）；
   ④ 关后台、锁频、同温（本机实测已被外部进程污染过一次：`阶段3重做-结果.md` 记录过"同时跑着别的项目"）。
4. **不许**把"最坏帧"拿来凑：原版自己的最坏帧就是 **316–472 ms**（`阶段4-性能仪表侦察.md:38`、`:141`），
   任何实现都过不了"某帧 ≤0.5 ms"这种读法 ⇒ **F9-3 只能读作"归因增量的窗口均值"**（§5 的解释边界）。

**整数毫秒**在这里**不是**限制：窗口均值的分辨率是 `1/|W| ms`（4500 帧 ⇒ 0.0002 ms）；整数化限制的是
**单帧/单任务读数**。⇒ 真正的限制是 **run-to-run 噪声**，不是毫秒取整（这一条要写进口径，免得后人以为
"多跑几个月就解决了"）。

## 5. G-EXIT-3 的三条判据谓词（**分开写**，不许合成一句）

> F9 原文（`01-大方向.md:97`）：**"≤ 引擎自身 AI 开销 5% 量级；每月每国 ≤2ms、单帧 ≤0.5ms；三条红线"**。
> **F9 文本不动**；下面是**口径层的解释**，边界写在 P3 的注里。

### P1 · ≤ 引擎自身 AI 开销 5% 量级
* **判什么量**：`R = Δ_attr / B_AI`，其中 `Δ_attr` = §3.2⑤（归因集的配对增量之和，按窗口总 ms 折算：
  `Δ_attr × |W|`），`B_AI` = **基线臂**窗口内 `UpdateAI` 的合计 ms（`M_{UpdateAI}(vanilla) × |W|`）。
* **阈值**：`R ≤ 5%`。
* **今天能不能测**：**不能**（剧本与**序列自报已有**（`t50`：45 条；读数口 `scan_stress_lines`），但**固定存档仍缺**、且"两臂序列逐行相等"的**读数还没跑** ⇒ `Δ_attr` 里混着世界分叉；
  且 `U(n=3) ≈ 1.8 ms` 远大于 5% 折算出的阈值 —— 以实测 21.4 ms/帧、`UpdateAI` 5.85 ms/帧估算，
  5% ⇒ ≈0.29 ms/帧）。
* **测不到怎么写**：`未判决（P1）：Δ_attr̂ = X ± Y ms/帧，n=3 ⇒ U=1.815 ms > 阈值 0.29 ms；需要 §3.5 的 n（按 s_d 算）或降 s_d`，
  并附 P1 的两个输入（`Δ_attr`、`B_AI`）与本文档链接。**不许**写"看起来没问题"。

### P2 · 每月每国 ≤2 ms
* **判什么量（两种读法，分开写）**：
  * **读法 A（总量分摊，今天可算）**：`C = Δ_attr × |W| / (C̄ × M)`，`M` = 窗口月数，`C̄` = 窗口内**每月活跃国家数**均值。
  * **读法 B（每国自身开销，今天测不到）**：需要**按国家**的耗时 ⇒ `ticktask_timings.csv` **没有国家维度**
    （表头只有 `frame,task,milliseconds,calls,longest_lock`，`src/pdx/gametimer.py:115`）⇒ **今天测不到**。
* **阈值**：`≤ 2 ms`（读法 A）。
* **今天能不能测**：读法 A **部分能**（公式齐，但 `C̄` 没有引擎读数 ⇒ 见下）；读法 B **不能**。
* **测不到怎么写 + 分母怎么办**：`C̄` 今天用**静态替代 `C₀`**（开局国家定义数，**可复算**：
  `common/country_definitions/*.txt` 的顶层 `TAG = {` 合计 **830**，其中 `99_dynamic.txt` **100** 个是动态/可释放
  ⇒ `C₀ = 730`【实测】2026-09-25 本页作者数过），并**必须**写明两点：① 它是静态替代、不是窗口内读数
  （缺口：需要一个"每月活跃国家数"读数口）；② **方向**：`C₀` 偏小 ⇒ 分母偏小 ⇒ 判据**偏保守**（宁可报超）。
* ⚠️ **顺带记一条对裁决有用的事实**：读法 A 在 `C₀ = 730` 下允许的月度总量 ≈ **1.46 s/月**，
  而引擎整帧合计 ≈ 21.4 ms/帧 × 125 帧/月 ≈ **2.7 s/月** ⇒ **P2 的允许量级已经到了整机总量的一半**，
  **它几乎不可能成为约束**。⇒ 建议（留给裁决）：P2 若要有判别力，应按**读法 B**（每国自身开销）理解，
  而那需要新读数口；这一条写进 backlog，不在本页改 F9。

### P3 · 单帧 ≤0.5 ms
* **判什么量**：`M_attr(W)`（归因集的窗口均值，§3.2②③ 的归因部分），**配对增量** `Δ̂ ± U(n)`。
* **阈值**：`|Δ̂| + U(n) ≤ 0.5 ms/帧` 才算达标；`U(n) > 0.5` ⇒ **未判决**。
* **今天能不能测**：**不能**（`U(3) = 1.815 ms`；§3.5 给了 s_d=0.7308 ⇒ **n = 11** 的条件）。
* **测不到怎么写**：`未判决（P3）：Δ̂ = −0.51 ms，U(3) = 1.82 ms（s_d = 0.73，n=3）⇒ 分辨率不足以判 0.5 ms；
  下一步：3 对 pilot 定 s_d → n = 11（s_d=0.7308 时；§3.5）或降噪`（`阶段4-结果.md:198-203` 的原文就是这一形态）。
* **注（口径的边界）**：F9-3 的"单帧"**read 作平均单帧**（窗口均值），**不**读作"某一帧的瞬时值"——
  后一种读法在原版自己身上就是 316–472 ms（`阶段4-性能仪表侦察.md:38`、`:141`）⇒ 不可能是 F9 的原意。
  **最坏帧**因此**不判 0.5 ms**，只作**异常检测**：报两臂各自的 `max`（`summarize_ticktask()['worst_frame']`
  现成）、最坏帧的最重任务名，并要求"处理臂最坏帧不高于基线臂最坏帧 + 噪声带"这一条**单独登记**（§2.2 的
  四成分缺口未清之前，这条只能标注为"未覆盖"）。

# 工程交付基线 1.0

本页定义标准包的生成、包结构、编码、验收、证据和恢复合同。持续约束见[工程原则](../../principles/工程原则.md)与
[Mod 开发原则](../../principles/Mod开发原则.md)。计划、工作清单和交付收据的入口见本页“当前状态与历史边界”。
环境准备、日常验证、文档维护、Git 和发布步骤统一见根目录 [CONTRIBUTING.md](../../../CONTRIBUTING.md)。

## 范围和身份

- 工程只维护原则所定义的唯一当前游戏基线；本页不复制具体版本号、历史 profile 或易变发布状态。
- Mod 展示名与用户安装目录均为 `Situated AI`，包身份为 `situated-ai`，自有 PDX 资源使用 `sitai_` 前缀。版本、不可移动标签、包哈希和实际发布与部署状态见[版本交付索引](版本交付-结果.md)与[当前工作清单](../当前工作清单.md)。
- 支持 Windows、macOS、Linux 的 Python 生成和离线检查；游戏 GUI 与长期运行由用户验收。
- 生产源位于 `mod/decisions/*.toml`；策略和本地化由 Python 生成，历史实验不进入发布 ZIP。

## 生成与包合同

1. 生成器从生产源生成仓库产物；检查必须逐字节核对生成结果。具体命令和参数只在 [CONTRIBUTING.md](../../../CONTRIBUTING.md) 维护。
2. 标准包按当前版本和显式构建配置生成确定性 ZIP，并写入 `DISTRIBUTION-MANIFEST.json`；生成、检查和打包使用相同配置。
3. 生成器核对原版字段、触发器、效果、作用域、路径、底本 SHA、源 SHA、玩家边界和本地化键集合；任何漂移硬失败。
4. manifest 列出除其自身外全部载荷文件的 POSIX 路径和 SHA-256；ZIP 不含重复路径、路径穿越、Windows 保留名、反斜杠或大小写冲突。
5. `mod/generation-lock.json` 只供仓库离线审计，记录生产源码、TOML、底本和产物的原始字节 SHA，不进入游戏包。无游戏环境可核对冻结合同与快照，但生产重生成和打包仍须读取锁定原版；缺失或漂移时拒绝。
6. `thumbnail.png` 是标准包必需的二进制资源，必须是 256–4096 像素的方形 PNG 且小于 1 MB；其 SHA-256 必须出现在 manifest 中。
7. 标准包只包含 Mod 安装所需的 PDX、本地化、元数据和封面等内容，不含 Python、探针、日志、缓存、本体资源、第三方资源、历史实验或历史文档。
8. 包内游戏 `.txt`/`.yml` 使用 UTF-8 BOM、LF；仓库源、JSON、TOML、Markdown 和 Python 使用 UTF-8 无 BOM、LF。
9. manifest 分别记录包状态 `status`、预定渠道 `publication_channel`、行为质量状态 `behavior_quality` 和声明的存档适用范围 `save_compatibility`。实际发布、行为质量与存档兼容各自取证。

标准包的自有文本覆盖当前游戏版本支持的全部正式语言，核对各语言文件的语言头、路径和交付编码，以及自有文本键与占位符的一致性。按实际状态登记缺译和待校对内容，分别核对键的完整性与译文质量。

## 验收职责

- **工程验收（E）**核对工具、生成和标准包交付合同。
- **Mod 静态语义验收（M）**以独立证据核对交付的 Mod 如何接入并影响所声明的原版决策，确认合法信息的使用符合所声明的决策语义。可检验的预期须明确候选、比较基准、偏好变化和保持原版的条件。正反证据按适用范围覆盖对象与单位、方向与成本反转、组合、资格、原版随机及未知回退。
- **运行验收（R）**以固定交付包与游戏条件下的引擎证据核对实际行为。加载、求值、原版执行、结果、后续观察和重评各自取证，未观察的环节保持未知。
- **长期体验验收（U）**由用户在版本与哈希固定的交付包上实机验收，范围包括长期国家行为、数值平衡、本地化呈现和玩家体验。

开发侧补齐 E、M 的实现与验证缺口，并保留实际失败及未覆盖的范围。E 和 M 具备充分证据后可签署相应的静态验收。R 和 U 依据各自取得的实机结果签署。

按 MP-10 和 MP-47 核对改动对象是否为 AI 作为国家操控者作出的国家层面选择。记录控制权、角色和资格条件，核对玩家原有操作、国家内部独立主体和自动管理判断的原版路径，以及新增选项默认向合资格玩家和 AI 国家开放的路径。改进一项原版判断时，记录当时决策国无法获知的已确认输入、官方接口能否单独移除该输入，以及移除后的可获知依据或保留原版的条件。分别以正反见证核对相关输入与其余判断。按 MP-45 记录接口证据覆盖的用法，登记与官方说明的冲突、同构建的可重复实测及复验条件。

## 证据口径

报告必须标明 `static_check`、`snapshot`、`simulation`、`runtime` 或 `inference`（中文类别名见工程原则 EP-36）。

| 证据类别 | 可以证明 | 不能代替 |
|---|---|---|
| `static_check` | 源码、生成物、包结构、语法、链接或指定静态合同满足检查 | 引擎运行期语义、长期行为、平衡或玩家体验 |
| `snapshot` | 受控快照中记录的文件、字段和原始字节事实 | 当前安装以外的运行期状态或生产接线 |
| `simulation` | 明确输入和模型范围内的模拟结果 | 真实引擎调度、长期国家行为或渠道发布 |
| `runtime` | 固定版本、包身份和条件下取得的实际运行观察 | 未观察的国家、时点、版本或长期结论 |
| `inference` | 基于已声明前提的推断，并保留不确定性 | 静态、快照或运行证据本身 |

加载成功、脚本解析、评分变化、根 hook、一次短跑和 Python 基准不能升级为行为质量结论。访问或解析失败按 EP-43 如实登记；不把外部阻塞、模拟结果或旧收据升级为生产许可。结果页记录可核查的输入身份、实际结果与证据边界。

效果与兼容声明绑定对应的版本、配置及证据。区分已证、未知、实现缺口和已证实不支持。

评估 MP-47 的成效时，登记决策国在判断时可获知的信息及其对选择合理性的依据，并按预定指标记录条件可比的多局对照。报告绑定游戏构建、包、启用组合、初始条件、观察期及相同条件下的原版或原包对照，列出样本、受益范围、实际得失、退步处境及其损失和是否持续。判断改善与实际成效分别登记，尚无稳定收益证据时实际成效待证。

兼容证据按 MP-41 和 MP-66 绑定固定的游戏构建（含同版本号热修身份）、Mod 版本和包 SHA-256、完整官方玩法 DLC 组合及单人或多人联机模式。记录 DLC 内容存在、权益、实际启用、联机主机共享及适用的开局检查。逐模式记录加载、新开局、开局后原版与官方 DLC 功能、存档适用范围及同条件保存与读档结果。维护记录可另记控制权切换、停用、卸载与恢复。适用纯原版已知问题的例外时，记录同构建、同 DLC 组合和同模式的原版复现、本 Mod 未引入或加重问题的对照，以及发布说明的位置。有意调整 AI 决策时，记录相关玩家操作及原版与官方 DLC 功能的实测结果。

声明国家覆盖范围时，逐国列出有据的观察和受影响的原版决策，分别标明保留原版、待研究、未知和已证实不支持的部分。样本的证明范围限于被观察的国家和条件。

## 发布与恢复合同

发布前冻结同一已验收合并源、版本身份、当前游戏底本、构建配置、生成锁、唯一 ZIP 和 SHA-256；确认包可解压、manifest 可复核、源树干净。发布和部署按当轮授权分别记录目标身份、执行状态、独立回读和恢复状态。

| 发布或部署对象 | 必需的真实验证 |
|---|---|
| 正式标签 | 回读远端正式标签，确认指向已验收交付合并提交；既有公开标签不移动 |
| GitHub Release | 核对正式发布状态，重新取得 ZIP 与 SHA-256 附件，独立核对原始字节、包身份及 manifest |
| 本地用户 Mod 目录 | 从同一 ZIP 部署到明确的用户目录，核对完整文件树、额外文件、metadata 与 manifest；记录备份、恢复点及启用状态 |
| Steam Workshop | 核对 app/item/owner、上传结果、远端身份与订阅内容；平台允许的变换单独登记，不能跳过差异后声称全字节一致 |

按 MP-41、MP-66 为每个正式发布渠道分别记录核对时间、玩家实际可取得的包及对应游戏构建、玩法 DLC 组合、单人和多人联机的验证与正式支持状态。记录过渡期结束、切换或恢复的触发事实、受影响的版本和模式、回读及证据来源。包的公开状态与配套构建可获取性分别取证。

渠道缺认证、响应丢失或能力不足时，保留失败、阻塞或未核验项，回查实际状态后再决定是否重试。dry-run、fake 客户端、进程退出码或其他渠道成功不能替代真实证据，也不能把发布工具合同通过写成全链发布完成。恢复分别覆盖 GitHub、文件系统和 Workshop 的实际阶段，不声称跨服务原子回滚；重试不得重造同版本异字节包、重复新建 Workshop item、移动已发布标签或覆盖用户后续修改。

本地文件部署、launcher 启用、playset 与 Workshop 订阅选择分别记录；未授权时不改变用户选择。用户应在独立 playset、新游戏和保留原存档的条件下进行长期验收；卸载不会撤回已发生的世界变化，恢复对应存档和原挂载才是回退方式。发布、部署和恢复记录按对应输入身份留存。

# Situated AI 1.15 架构实施计划

状态：未来实施计划，A0–A6均未开始。本轮只完成设计与计划，不修改生产代码或生成产物。
规范见[1.15架构设计](../1.15架构设计.md)，阶段状态只由[架构主计划](../架构主计划.md)维护；
[领域子计划](../架构子计划.md)仅目标，实施架构时不提前开展领域调参或全域优化。

## 执行与职责

每阶段先确认输入、已有改动与相关进程，再实现、定向验证、独立复核和记录出口；后阶段只消费已通过合同。
可并行开展互不写同文件的盘点、见证及审查；共享语义、生成事务和底本切换顺序执行。安装、Git和外部动作由主代理统筹。
阶段结果写入少量新的结果页，标明输入身份、生产差异、实际命令、失败、跳过及证据类别，不修改历史收据。

A0–A3在隔离候选分支开发，允许解析器、盘点与核心源码的未完成阶段提交（WIP），按阶段运行定向检查并保留失败。
源码变化导致旧1.14.5生成锁失配时，明确记录该门未通过；不得刷新旧锁、缩小哈希集合或跳过失败来宣称baseline/完整验收通过。
这些提交不合入主线、不交付，也不改现用部署。A4以完整1.15生成/交付合同、完整底本重生成和新锁关闭迁移缺口；
A6全部工程门通过后才形成主线审查候选，仍按贡献流程办理后续合并与发布。阶段提交不等于满足生产交付门禁。

预期代码职责如下，是迁移路由而非现在创建空目录：

| 边界 | 现有入口与预期处理 |
|---|---|
| 原版发现 | `src/pdx/`分析器与能力目录：复用解析和遍历，建立独立原版分母 |
| 核心合同与纯语义 | `src/pdx/situated/`：分离类型、事实、处境、行动、关系、组合和参考语义；核心不导入领域 |
| 领域声明 | `mod/decisions/`：版本化严格模式；政策只在声明中拥有一个来源 |
| 适配与编译 | `decision_adapters.py`、`decision_rules.py`及compiler：公开合同消费、精确原版位置和降低证明 |
| 生成交付 | `decisions.py`、`distribution.py`与锁：版本适配身份、事务、确定性包和恢复 |
| 验证 | `tests/`、`tools/ci/`：独立参考、PDX见证、原版保护与工程门禁 |

最终模块名在A1按依赖拆分；避免按七层机械创建七个单例服务。优先复用成熟组件，不预设新增依赖。

## A0：固定底本、分母与迁移范围

输入：设计、[现场勘察](../1.15底本勘察.md)、完整本机1.15安装、旧3.2.0源码与历史证据。

1. 只读记录版本文件、launcher、内容根、DLC条件、逐文件原始哈希、扫描器身份和解析失败。先修复相关解析缺口或明确其受影响范围，不静默跳过。
2. 定义可作为 AI 行动主体的国家 Universe、排除条件和 `ActorCoverage`；独立盘点消费者、事实、对象、作用域、操作、零值、合并、尾部和求值时机，追踪非ai_字段及间接引用。区分静态发现、文档证实与引擎未知。
3. 对旧reader、行动、关系、写点与策略逐项登记重证迁移、原版保留、退役、待研究，给出处置理由；不继承旧数量或完成率。
4. 选定真实地方经济、制度政治、双边外部三类最小纵切的合法消费者，冻结具体对象/写点清单和增减审批依据；覆盖默认及非默认策略风险。
5. 记录旧生成、原版样本和预期新链的同口径静态规模/构建成本基线，冻结允许的查询形态、相对预算依据及测量办法。A5据同口径数据校准门限，不按已实现规模倒定通过线。
6. 独立核实1.15支持语言及配置入口，记录来源、能力边界和旧配置/自有键迁移范围，不继承旧版语言数量或假定入口可用。
7. 建立 `ObservationCoverageMatrix` 初版，按国家 actor、目标对象、消费者和评估时点登记来源、合法读取、作用域、新鲜度、性能预算及完整/局部回退/原版保留状态；登记每国可观察利益目标的来源和待研究项。

出口：可再生的版本/能力目录及失败明细、国家 Universe 与逐国处置、独立分母、观测覆盖矩阵、利益目标来源、迁移矩阵、受控纵切范围和成本口径。若所选消费者不合法，先依据证据调整形态并记录，不假造可执行性。
验证：同输入重复盘点一致；改字节/缺内容/解析失败均可发现；重复字段不丢失；旧新来源不混用；抽样回到原始位置人工核查。

## A1：冻结核心与扩展合同

输入：A0能力与消费者语义。输出：设计第5节的严格模式、不可变IR及公开接口。

1. 定义精确实体键、上下文绑定、单位、时点、已知性和来源；区分事实、目标、评估、贡献、程序及原版消费者。目标项明确稳定ID、适用对象、期限与现状比较基准。
2. 定义领域注册、能力要求、依赖DAG、稳定ID、单写者和模式演进。公开边界设类型，错误包含声明路径及依赖链。
3. 每种消费者绑定其组合代数、neutral、终结值和尾部；在A4生成前确定适用的1.15生成/交付合同。定义支持矩阵：哪些关系/算子能在何种上下文合法降低，不能只验证字段存在。
4. 明确旧state.py规则副本的迁移方案：从唯一声明派生，消除参考器手写政策副本；兼容层必须有退役条件。
5. 固化配置类型、默认值、有效组合、模块/能力依赖与局部关闭回退；非法值和组合显式失败，玩家资格和执行路径保持原版。固化语言分母、自有键/头/占位符/路径与编码合同，不预设新增UI或探针。
6. 固化 `SituationSnapshot`、`EvaluationSchedule` 和 `ActorObjectiveSpec` / `InterestSpec`：声明 actor/target/时间身份、国家与地方聚合、合法触发、刷新、TTL、失效、幂等、目标来源、期限、基准和冲突关系。

出口：可供至少两个独立领域声明使用的合同，无核心对领域反向依赖；每个消费者有持续评估合同，每个国家目标有来源/接线状态；接口签名和变更政策固化。
验证：错误单位、对象串接、未知字段、非有限值、重复ID/写者、循环、模式不匹配、能力不足均拒绝；非法配置值/组合与本地化合同错误有反例，合法重排结果不变。

## A2：事实、处境、行动与参考语义

1. 实现事实reader绑定、三值逻辑、时效和局部未知传播；把invalid错误与unknown回退分开。
2. 实现需求/能力/机会/风险/已观察承诺的纯派生，再对具体候选形成多目标收益成本；资格由原版保持，候选不能视作结果。
3. 只保留已证实低档；未知成本不得免费；期限、单位和目标映射显式声明。
4. 参考语义消费同一IR；另外编写手算期望与变形性质，避免参考与生成共享错误自证。
5. 以 `SituationSnapshot` 和 `EvaluationSchedule` 实现合法时机的重评；同输入重复求值幂等，相关事实变化只更新依赖候选，无关事实不触发无关项；无法证明持续触发时保留 runtime-unknown。

出口：事实到行动链可解释、无第二份政策来源；尚未生成生产行为时如实标记。
验证：逐国观测覆盖可追溯；同国不同州不串接；缺辅助绑定局部降档；unknown/stale/unsupported分别保留；低能力不抹去真实需求；短期收益与长期负担保留各自期限/基准并共同参与；多轮时间序列证明事实变化更新相关候选、无关事实保持、stale/unknown 局部回退；玩家/关闭分支回原版。

## A3：因果联动与消费者组合

1. 实现规范因果身份、同因分档取强、独立相反贡献共同参与、一次末端限幅；说明同因正负是否为独立权衡。
2. 实现有条件关系、对象映射、时间边界与DAG检查；软机会成本不宣称真实资源预留。
3. 对变体选择、跨卡共享成本和去重要求生成合法性证明。现有compiler会拒绝variant与跨卡cause/evidence/shared cost组合；新架构不得仅改schema解除限制。
4. 无运行期选中候选可读能力时，仅允许已证明的同消费者有限联合程序；跨消费者强互斥不能保证，必须诊断拒绝相应强约束或明确改为有依据的软语义，不能静默降级。
5. 为每个原版消费者建立 `SelectionWitness`：记录候选集合、硬资格、原版比较器、可比较目标、未知/成本回退、非支配或排序规则、neutral、平局、随机、零分、全零和原版基线；跨消费者只保留并行倾向。

出口：每个生产算子、关系类型和消费者选择都有参考、正反/未知/重复/顺序见证，且能证明可降低；注册关系不等于执行。
验证：教育需求与财政成本并存、地方恢复与扩张需求、战时军需与偿付成本、候选贸易与真实供给分离；别名重复不加分；变体强弱与共享成本不同、成本未知时仍正确选择/去重或显式拒绝；合法顺序重排不变；无界循环失败。

## A4：1.15适配、降低与中立路径

1. 按A0逐消费者语义实现公开适配，保护精确原版结构、活跃策略合并、特殊零分、拒绝、资格和随机执行尾部。
2. 从验证IR降低至PDX，建立声明→IR→物理写点来源映射；不允许领域私自拼接脚本。
3. 建立独立生成AST解释见证，并对保留部分执行原始字节或规范AST比较；比较口径预先固定。
4. 生成完整关闭/不可用时的中立回退候选包，将配置声明接通实际生成分支；验证无自有持久状态依赖、玩家资格/执行边界、DLC缺失与最小合法覆盖结构。
5. 按A1确定的合同显式修订1.15生成/交付基线，用完整底本重生成并建立新锁；接通自有本地化的键/头/占位符/路径和包编码校验。旧1.14.5保留可追溯身份，禁止旧摘录回填、静默底本更新或缩小源码哈希集合绕过保护。

出口：中立包可由真实1.15底本确定性重建；所有启用算子有合法PDX和独立见证。游戏加载与行为未实测时不得写成已通过。
验证：篡改底本、改变scope/尾部、漏活跃策略、重复定义、局部生成失败、事务中断均显式失败且不污染旧完整产物；两次包字节一致。

## A5：代表性纵切、扩展与迁移

1. 将A0冻结的三类真实纵切接通生产；最小示范政策只为检验合同，不展开25领域优化。至少实际覆盖地方对象、多目标相反贡献、已观察跨域关系、非默认策略保护。
2. 扩展第二领域或消费者时复用公开合同；验证有效配置组合、非法值/组合拒绝、核心及模块局部关闭、加入/删除、顺序变化、DLC缺失、玩家路径不变和第三方同写点诊断；自有键随模块增减仍满足语言合同。必要的新适配器不等于核心增加领域特例。
3. 消除确认的政策副本与绕过路径；逐项回收兼容层，迁移矩阵对每项缺口保持公开。当前阶段不要求旧所有领域全部深化。
4. 测量构建时间、进程树RSS、生成规模、求值嵌套与对象查询上界，依据A0查询形态和相对预算校准数值门限；超限先改算法/合同，预算变更须记录依据，不隐瞒或静默放宽。
5. 核对新游戏/现存存档/升级/卸载的声明与恢复边界；如未来启用记忆，必须另有合法生命周期见证。默认不新增持久状态。

出口：生产纵切的完整链及独立参考/PDX见证，而非只有合成fixture；逐国处置、未支持形态/待研究缺口和静态性能限制有清单；静态语义兼容与运行时执行证据分开记账。
验证：三类真实fixture与反例、至少一个跨国家差异和相反目标序列、模块隔离、迁移回归、原版保护；连续冲击/恢复序列证明重评与无关项稳定；性能测量串行，不以Python速度代替游戏内性能。无游戏运行证据的纵切标为runtime-unknown/未验收。

## A6：集中复核与候选交付

1. 由独立于实现者的审查检查：设计合同、国家 Universe/逐国覆盖、观测矩阵、国家利益来源与接线、生产接线、分母处置、每算子/选择见证、每写点作者、未知/玩家/关闭/原版尾部、配置组合、全部1.15支持语言的自有键/头/占位符/包编码及兼容边界。
2. 修复缺口后冻结候选，按贡献流程执行定向集成、完整回归、静态门禁、wheel及标准包验证。新底本不允许依赖旧版本跳过项伪造完整验收。
3. 集中核对并冻结A1/A4已确定的1.15生成/交付合同、支持版本和新锁；关闭此前候选开发的锁失配及其余门禁缺口，全部工程门通过后才形成主线审查候选。更新当前清单和新结果页，记录实际源码/底本/工具/包身份与命令输出。旧收据仍解释旧版本。
4. 提供候选包路径、哈希、安装与回滚说明；本地候选准备不包含自动部署、推送、合并或正式发布授权。

出口：A0–A5证据逐项闭合、实际1.15生产候选与完整工程收据；静态语义兼容和运行时执行证据分别签发，逐国持续决策缺少运行证据时保留 `runtime-unknown`，保留所有真实失败和未验证项。
长期行为、数值平衡、游戏内性能与玩家体验由用户另行实机验收；这些事项不代替静态实现完整性，也不由静态验收代签。
架构出口后，用户再选择领域目标启动后续有界子计划；领域数量或目标条目数不作为完成率。

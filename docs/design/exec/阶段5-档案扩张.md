# exec · 阶段 5：档案扩张（一页执行文档）

> 依据：`01-大方向.md` §3「阶段 5」三行。**写完即执行**（等阶段 4 收口后进入）。
> 前置：阶段 4 出口全绿（schema 定稿、生成器完整、五道闸门进 CI、性能预算达标）。

## 三行判据（原文照抄，逐条落实）

* **目标**：按失败模式清单扩张处境档案库；每批跑闸门 + 基准 + `gametimer` + 一次 A/B 会话。
* **出口判据**：每个档案带判据与 `why`；占槽率和平期≈0、危机期上升；G4 不退化。
* **失败处理**：档案加不进去 → 说明**抽象不对**（改抽象，不是加特例）。

## 一、扩张的"清单"从哪来（不另造）

失败模式清单 = `01a` A 节的输入因子 × K 节示例表 × 已记录的失败模式（战败、破产、革命、
被包围、失去市场、列强干涉…）。**每个档案 = 一种失败模式 + 一个主角国家**，条目化写进
数据源；**禁止**为了好看而造处境（P14：不做无判据的工作）。

## 二、每批（2–3 个档案）的标准流程

1. **数据源只加行**：新档案 = `mod/data/<tag>_<mode>.toml`（照 schema，不改生成器与闸门代码）；
2. **生成 + 五道闸门**：`v3 modgen --write` → `v3 modguard`（含稀释预算：新档案若递牌，必须报占用）；
3. **基准 + `gametimer`**：跑阶段 4 定下来的压力场景脚本，出**均值 + 最坏帧**对照；
4. **一次 A/B 会话**：按 `exec/自动化范式.md` 跑（一次点击开局机制 + 引擎侧套件判定），
   验 **G2 差分**（行为层优先，策略层次之）与 **G3 三行说得通**；
5. **收口**：按 `exec/收口清单.md` A→E 走一遍（每批都要），记录归档与偏差。

## 三、出口验收（怎么算过）

| # | 判据 | 验证方式 |
|---|---|---|
| G-EXIT-5.1 | 每档案带**判据与 `why`** | `v3 modgen` 校验（空 `why` 即拒）+ 人工抽查每条 `why` 是否引到官方行号 / 探针日志 / KB 章节 |
| G-EXIT-5.2 | **和平期占槽率 ≈ 0** | A 组（不施加冲击）会话里我们的牌几乎不出现；用 `v3 ab` 的策略层读数报出占槽率 |
| G-EXIT-5.3 | **危机期上升** | 冲击组的占槽率 / JE 开启率显著高于对照组（同一档案的 A/B 对照） |
| G-EXIT-5.4 | **G4 不退化** | 与上一版对照：世界不是"AI 更凶"，而是**行为分布随处境移动**；试玩者能复述"目标 + 主因"（G3） |
| G-EXIT-5.5 | 抽象没被特例污染 | 统计每批改动：**只加数据行**；若改了生成器/闸门代码，必须在结果文档说明是否属于"抽象改进" |

## 四、失败长相与处置

| 现象 | 含义 | 处理 |
|---|---|---|
| 新档案加不进去、必须写特例 | **抽象不对** | 改 schema / 生成器抽象（照三行原文），**不是**加特例分支 |
| 危机期占槽率不升 | 冲击没被牌读到 | 回到手段阶梯：先用 A 级（世界状态 / JE），再考虑递牌 |
| G4 退化（世界更乱/更凶） | 意图层压过了世界层 | 回退该档案；检查是否把"该由世界变化表达的东西"塞进了牌 |
| `gametimer` 超预算 | 频率/结构问题 | 按 P2 三条红线回退（减频率 / 热路径读预存值 / `weight` 块去表达式） |

## 五、边界

* 本阶段**不做**：可见性 GUI 与难度三档（阶段 6）、长期维护流程（阶段 7）；
* 每批都要留**可安装、可卸载、可回滚**的版本（P12），并写进结果文档；
* 档案数量不设硬上限，但**筛选标准只有一个**：该档案能否挂上判据（`backlog` B21）。

## PR #112 工程整合实测

以下候选证据取代历史段落中“候选完整门及 ZIP 待验”的状态，不覆盖历史清退结果：`acceptance.log` 指向本地 Windows CPython 3.15.2 的完整验收运行 `20261120T185446-bb0d05eb1b33`。`pytest.log` 记录 12,601 passed、14 skipped、1,580 subtests passed、4 warnings，历时 2,265.12 秒，覆盖率 89.32%；`test-summary.json` 记录 0 failures、0 errors、0 unknown skip reasons。13 项平台跳过涉及 Windows 无符号链接权限或 POSIX 专属路径操作，另 1 项因本地文档镜像不存在；它们不是运行覆盖证据。该运行只证明对应候选及输入身份。

同一候选收据记录生产 wheel 构建、安装与 100 个生产文件核对；`package-compare.json` 记录 ZIP payload 101 项、changed payloads 为空，manifest 差异仅含源码指纹。ZIP 哈希与旧归档不同，故不得写成整个 ZIP 字节相同。`modgen-check.log`、`modguard-forced-offline.log` 分别证明冻结源码/产物、脚本语法和快照接口检查通过，以及入库快照离线检查；不能证明新的游戏运行行为。PR #112 的检查结论为 `MERGED`，静态、Windows、macOS、Ubuntu、bench、lock 与两项 CodeQL 检查均成功。当前基线的分支保护另经 GitHub API 回读，required contexts 与 main 上实际检查名一致，`allow_force_pushes.enabled` 为 false。本轮没有生产/部署渠道操作，因而不更新渠道状态。

文档写入核对预览时读入的原字节，发现内容漂移时报告冲突。文件替换使用 `Path.replace`，外部写入者应与生成过程协调，检查与替换之间仍存在竞争窗口。

实装 Victoria 3 1.15.2 的紧凑和完整快照各含 121 个域、30,452 个来源身份和 184 张生成表。两种快照的非本地化域逐项一致，从完整键列表重算的本地化计数和指纹与紧凑版一致。新紧凑快照相对于旧基线仅新增 16 项部分解析记录，全部来自 `game` 内容根。离线验证通过 43 项断言，占登记的 234 项断言中的 43 项。真实生成及校验的 100 个生产文件与清退提交逐字节一致。

本地正式版 CPython 3.15.2 环境的 50 项依赖与锁一致，`pip check` 通过。调度对比 B 的完整验收使用三个 worker，墙钟 2,481.23 秒，整套峰值 RSS 2,968.2 MB，单 worker 峰值 1,158.8 MB。此前清退运行分别为 2,456.42 秒、3,291.8 MB、1,215.8 MB。B 测试的是调度初稿，后续的 worker 恢复和优先顺序调整另有定向验证。最终整合候选的完整验收与托管检查以本轮运行和 PR 收据为准。

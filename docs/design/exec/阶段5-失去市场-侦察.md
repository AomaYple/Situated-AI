## 三、⚠️ 一处必须先解决的判据陷阱（B80 那一类）

**巴西的初始政治牌里已经有 `ai_strategy_progressive_agenda`。**
而探针的通用判据写的是「**进步牌挂上过** = 日志里出现过 `ai_strategy_progressive_agenda`」
（`tools/probe/stage3_rerun.py` 的 `analyze()`）—— 在巴西身上这条**开局即为真**，
于是 G-EXIT-5.3 会报一个**假的**"行为层动了"。

这正是 `收口清单.md` 反复强调的那句：**任何"跨档案通用"的判据都要问"它对别的档案是不是立刻为真"**。

两条候选修法（**都不许**靠"这次先手工放过"）：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 本档案声明该盯哪张牌** | 给 `[probe]` 加一格 `reform_card`（与 `reform_law` 同款：每份档案显式声明 + `why`），套件与分析器都按声明判 | 要给八份既有档案都补一格（可留空 = 不判，与 `reform_law` 同口径）—— **已做**（2026-09-23，九份都补了；八份声明 `progressive_agenda`，巴西留空并写明为什么） |
| **B. 改成相对判据** | 判「**牌换过没有**」：观测到的政治牌集合与**开局那张**不同 | 需要套件/分析器知道开局牌（可从 `00_strategy.txt` 读，或由探针在 A 臂记一次） |

**倾向 A**：与 `reform_law` 完全同构（P9：一处声明、三处同步），而且空值语义已经验证过
（tr/eg 就是留空的）。B 更"聪明"但引入了"开局牌从哪来"的新依赖。

## 四、字段侧侦察：「市场」本身**表达不出来**，能表达的是它的后果

`[pressure].effects` 渲出来的是**国家静态修正的数值字段**（`tools/pdx/modgen.py`），所以先问：
原版有没有一个**国家作用域**的"市场/贸易"字段？

**答案是没有。** 实测原版自己的贸易类修正用的都是 **`state_` 作用域**：

| 字段 | 出现次数 | 例子 |
|---|---:|---|
| `state_trade_advantage_mult` | 16 | `opium_wars_export_modifier`（`common/static_modifiers/content_1_modifiers.txt:33`，`:35` 是该字段，+0.10） |
| `state_trade_capacity_mult` | 8 | |
| `state_market_access_price_impact` | 4 | |
| `state_import_advantage_mult` | 3 | |

`state_*` 字段放进**国家**修正里不是同一回事（作用域不对）—— 与 `bv_alignment` 里
`power_bloc_leverage_generation_mult` 那条是同一类让步。

### 4.1 可用的**国家侧代理**：出口部门的产能

原版有一条现成的路：`building_group_bg_plantations_throughput_add`（`bg_plantations` 定义在
`common/building_groups/00_building_groups.txt:184`）。对巴西（咖啡/糖＝种植园）语义贴，
而且原版自己就给了**负档**：

| 档位 | 谁在用 |
|---|---|
| **−0.2** | `temporary_switch_to_food_crops`（`common/static_modifiers/00_ip2_02_modifiers.txt:149` 是块首、`:153` 是该字段） |
| **−0.1** | `food_crop_system_modifier`（同文件 `:181` / `:185`） |
| +0.05 / +0.04 / +0.10 | `modifier_agricultural_development_trade`（`content_204_modifiers.txt:282` / `:284`）等 |

⚠️ **写档案时必须写清楚的让步**：这是「**出口部门产能**」而不是「市场通道本身」。
正式版应当走真实的贸易路线/关税/市场准入位移，那条与既有档案的 B35 是同一族。

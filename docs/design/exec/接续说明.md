## 4. 怎么跑（确切命令）

```powershell
# 环境（已建好；换机器才需要）
.venv\Scripts\python.exe -m pip install -r requirements.lock

# 生成：数据源 → 产物
.venv\Scripts\v3.exe modgen                      # 只编译，不写盘
.venv\Scripts\v3.exe modgen --write              # 写盘（生成物一律由它产出）
.venv\Scripts\v3.exe modgen --check              # 盘上产物与数据源逐字节一致？→ CI 门禁
.venv\Scripts\v3.exe modgen --why                # 把每个数字的依据展开

# 门禁（完整一轮 ≈6 分钟；分项耗时见 阶段7-长期维护.md §三）
.venv\Scripts\v3.exe verify                      # 234 条断言：文档里的数字还对不对
.venv\Scripts\v3.exe tables                      # 171 张生成表还与游戏一致吗（不带 --write 就是核对）
.venv\Scripts\v3.exe modguard                    # 五道闸门
.venv\Scripts\v3.exe ai-surface --check          # 与原版 ai_strategies / defines 的对照面
.venv\Scripts\v3.exe citations                   # 850 条 文件:行号 引用还指得到吗
.venv\Scripts\ruff.exe check . ; .venv\Scripts\ruff.exe format --check . ; .venv\Scripts\mypy.exe
.venv\Scripts\python.exe -m pytest tools/tests -q -n auto
.venv\Scripts\v3.exe cov                         # 覆盖率门禁
```

**五条会咬人的口径**：

1. **并行是默认**（`addopts` 带 `-n auto --dist loadscope`）；**基准必须 `-n0`** ——
   `pytest-benchmark` 在 xdist 开启时会**静默禁用自己**，不带 `-n0` 时基准根本不会跑。
2. **`v3 cov` 固定 `-n 4`**（不是 `auto`）：16 核下 `-n auto` + 覆盖率会 376 秒且偶发假红，
   `-n 4` 是 185 秒全绿（`../backlog.md` **B28**）。
3. **`v3 analyze` 之后必须 `v3 check-outputs`**：前者刷新 `tools/out/*` 与 `tools/reports/*`，
   后者核"落盘产物有没有把断言写对"。改了现场数字却忘了刷新产物 ⇒ `test_check_outputs` 红。
4. **跑过仪器 / 探针之后 `test_engine_crosscheck` 会红**：那是"引擎日志是探针会话"这条按条件跳过
   在起作用（正常），但 `test_cli.py::test_crosscheck_与引擎日志一致` 会因为 mod 集合不同而红 ——
   跑一次 `.venv\Scripts\python.exe -m pdx.game_auto run` 即可恢复。
5. **离线通道证明的是"与入库快照一致"，不是"与现在的游戏一致"**：后者永远是本机门禁
   （`verify` / `tables` 不带 `--offline`）。**exit 2 不是"闸门不过"，是"这台机器上跑不了"**，
   CI 里把 2 当通过是错的（`../../tools/README.md` 的环境矩阵）。

**实机**（一次 ≈4–5 分钟）：

```powershell
.venv\Scripts\python.exe -m pdx.game_auto run    # 点火四步：起游戏 → 前台 → 加载期不碰窗口 → 点「观察」→ 5 档速度 → 空格 → 切回后台
.venv\Scripts\python.exe -m pdx.game_auto run --wait-tests 900   # **完整闭环**：再验后台仍在跑 → 等官方套件判定 → 读产物；不通过退 1
.venv\Scripts\python.exe tools\probe\stage3_rerun.py --months 12 [--archive <id>] [--no-probe] [--fresh-logs]
.venv\Scripts\python.exe tools\probe\perf_compare.py 12 --repeat 3     # 性能 A/B（≈1 小时）
```

**开游戏前必须先看 `收口清单.md` §B.0** —— 那一段是"清零残留"的一条命令版，
用来确认：游戏进程 0 个、用户 `content_load.json` 是**原样**的、仓库里没有垃圾文件。

## 6. 踩过的雷（读一遍能省几小时）

| 症状 | 真相 / 纪律 |
|---|---|
| 提交了但工作树还是脏的 | 先 `git status --short` **逐项**看；`.gitignore` 里 `tools/out/` 是产物、`tools/reports/` 是**入库**的人读报告 |
| 控制台敲了命令没反应 | 反引号开控制台后，**必须按两次回车**才提交（自动补全吃掉了第一次）。判据走画面 ROI —— `../../tools/README.md` 那张 `game_auto.py` 行 · backlog **B66** |
| 脚本崩了，用户的 mod 配置却已经被改 | **崩在 `finally` 之前**：`finally` 根本不会执行。任何"改用户环境"的脚本，**第一次改动之前不许有会抛的操作**（挪日志→再改配置）。backlog **B79** |
| 改了 A，B 却 `NameError` | "从 A 到 B 整段替换"的手术把**夹在中间的函数**一起切掉了；静态检查全绿（探针脚本没有用例守着）。**整段替换前先把那一段打出来确认**。backlog **B78** |
| `.yml` 被写坏、`_reason` 的值被拆成几行 | 生成器里拼文本时换行必须是**字面量** `\n\n`（两个字符），不是真换行。backlog **B75** |
| 产物改了，`test_golden` 红 | 金标准指纹要**重新生成**（`test_artifact_digests.yml`），它不是"自动跟随"的 |
| 一条判据在另一份档案上**立刻为真** | 任何"跨档案通用"的判据都要问这句话。硬编码 `law_serfdom` 就是这么暴露的。backlog **B80** |
| `modguard` 的合成夹具又红了 | 夹具"按需列出原版有什么"，每加一份档案都要补词（tag / 图标 / 分组 / 触发器 / 修正字段）。**闸门没错，夹具的设计有代价**。backlog **B82** |
| **`v3 verify` 报"用户订阅的 mod 数变了"** | **先查是不是我们自己**：跑 A/B 时部署进用户 `mod/` 的那份真 mod，如果没清掉就会被数成一个订阅项（`mod.total` 23→24、`mod.files` 跟着涨），而报错指向"文档过期"，方向完全错。同一个坑踩过两次（第二次还把它判成了"用户新订阅了一份"）。现在 `mods.discover_mods()` 按 `.metadata/metadata.json` 的 `id` 前缀认自己的 mod（**不看目录名** —— 档案集合一变旧名字就匹配不上），`stage3_rerun.restore()` 也会清掉所有我们的本地目录。backlog **B83** |
| 文档里"本机现场"的数字过期 | 现场类断言（订阅了几个 mod、共几个文件）会随**用户自己**订阅变化而漂移。改了**要留痕**，而且**分布数必须重新测量、不能按比例换算**。backlog **B83** |
| **实机读数"看着对、其实是切片"** | `debug.log` 到 512 KB 就轮转成 `debug.1.log`…。分析器若用 `sorted()` 读，**字典序是错的**（当前那份排最后、次新的排最前），再叠上按 `RUN` 行切片，就会拼出一段**不连续的切片**：实测**盘上 1,401 行只读了 402 行**，还报出一个假的「窗口 inactive→active」。**纪律**：① 轮转日志按**时间**排（`debug.N` 递减，`debug.log` 最后）；② 跑了 `--fresh-logs` 就**不该再按 `RUN` 剪**（观察者局里那把剪刀会剪掉这一局自己的前 37 个月）；③ 读数必须同时报**盘上自报行数**与**算进读数的行数**。backlog **B85** |
| **用 PowerShell 批量改仓库里的中文文件，整份变成乱码 + 带 BOM** | 实测踩过（2026-09-23）：`Get-Content -Raw` + `Set-Content -Encoding utf8` 改 `README.md` / `tools/README.md` 的两个数字 —— 文件被按 GBK 读、按 UTF-8 写，中文**双重编码**（`鐨?…`），而且写进了 BOM（`239,187,191`），`git diff` 显示 338 / 760 行全变。**纪律**：改仓库里的文本一律用编辑工具（按 UTF-8 读写），**不要**用 `Get-Content`/`Set-Content` 往返；真要用 PowerShell，先 `[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)`。改完立刻验三件事：**前三字节不是 `239,187,191`**、**CRLF 计数为 0**、`git diff --stat` 的行数与你改的处数一致。**恢复**：`git checkout -- <文件>` 然后重做 |
| **`git commit -m` 的提交信息里带 ASCII 双引号 ⇒ 提交直接失败** | 实测踩过**两次**（2026-09-23）：PowerShell 把消息里的 `"` 当成参数边界，`git` 收到的是被拆开的碎片，报 `error: pathspec '…' did not match any file(s) known to git`（看着像"文件没加进暂存区"，其实是消息被切了）。**纪律**：提交信息里的引号一律用 `「」` 或 `『』`，**不要**写 ASCII `"`；用 `@'…'@` 字面量 here-string 传（`$` 不会被展开，但 `"` 照样会被拆）。失败后暂存区是**完好的**，改掉引号重跑 `git commit` 即可 |
| 本地 mod 装上了却没挂载 | 本地 mod 的挂载条件与 Workshop 不同；`-scripted_tests` 套件格式里**没有**存/读档指令。backlog **B32 / B39 / B47** |

此处用完整目录的摘要名称选择候选。它提供可复用的安装树和 ZIP 冻结边界，后续受审原创写者可加入同一成员清册。默认标准 `modgen`、正常发行 `package`、正式 `validate_package` 及 `publish` 的生产范围仍由原合同决定。把候选接成新的正式基线，还需完成 955 项处置与财政决策、正式语言路径和 Mod 身份、逐方面 M/R/U 及发布验证。后续正式基线每次改变生成源或产物时，均需复核对应的生成锁。旧树退役必须核实 Git 索引和工作树实际所有权，覆盖意向暂存的空文件与 NTFS 短路径别名。候选构建本身不读取这些条目作为退役授权，固定输出根核查物理拼写。[工程基线](工程基线-1.0.md) · [正式载荷准入](发布载荷来源校验设计.md)

## 冻结生产锁与历史包回读

以 CPython 3.15.2 读取前序 `68d3f169` 的工程锁。对其 100 个产物逐项核实当前物理文件、前序与候选提交的 Git blob、前序锁 SHA-256。将核实的仓库字节交给现有 `distribution.generation_lock(files)`，再由 `distribution.check_generation_lock(files)` 校验。旧树仅在已有检出中读取，稀疏候选树只写工程锁。[生成锁代码](../../../src/pdx/distribution.py)

锁中 100 个输出和原 SHA-256 全部一致。源码从 235 项变为 237 项，新增 `company_injection.py` 和 `original_candidate.py`，更新 `distribution.py` 与 `cli_commands/release.py`。237 项均通过候选提交的 Git 字节复算。工程锁 SHA-256 为 `26a9615185d0f8dfd916b807c60355bc86c26db0595e2c841dc7901f990f6224`。在另一主线整合时，其他来源可能已变化，应使用实际整合源码和经核对的输出再生成锁。[当前锁](../../../mod/generation-lock.json)

从已保全的 GitHub 下载件只读打开 3.4.0 ZIP，其 SHA-256 为 `a5ccf61255338ade0bdd6d71eaf9e22cbdb90a71c6090d9bd3ff3e706c25507e`。102 个成员通过 CRC，101 个载荷逐项符合旧 manifest。候选分支的默认 manifest 构造函数以这些现存载荷和历史 generation 重算，结果与旧 manifest 相等，旧 manifest 原始 SHA-256 为 `b240f151706e4b81ceeb8f5c15f665a48aea5cdb362915a2b93dc9bb07ea96f7`。对原创候选采用其独立身份执行相同检查，16 个成员通过，15 项载荷与候选 manifest 一致。两次比较分别确认固定档案的可追溯性和候选 manifest 的适配。自当前源码完整重建旧标准发行包仍未运行。[3.4.0 正式交付](3.4.0-交付结果.md)

`distribution.write_zip` 复用确定性编码、路径与 manifest 校验。新载荷的全部最终摘要须匹配独立固定的清册。安装文件与收据先经 `GenerationTransaction` 写进空的本机临时目录，随后将完整目录以无覆盖重命名冻结到 ZIP 摘要名。旧生成树、先前的冻结目录、未知的兄弟文件均保留在原位置。目标已有同名冻结目录时核对完整文件、目录和字节，遇到篡改或未知项会失败。目录冻结前失败可撤销本次写入，进程异常终止可能留下本次的私有暂存目录。[生成事务](../../../src/pdx/generation_transaction.py) · [非覆盖重命名](../../../src/pdx/publishing/local.py) · [合成回归](../../../tests/test_original_candidate_freeze.py)

此处用完整目录的摘要名称选择候选。它提供可复用的安装树和 ZIP 冻结边界，后续受审原创写者可加入同一成员清册。默认标准 `modgen`、正常发行 `package`、正式 `validate_package` 及 `publish` 的生产范围仍由原合同决定。把候选接成新的正式基线，还需完成 955 项处置与财政决策、正式语言路径和 Mod 身份、逐方面 M/R/U 及发布验证。另外，生产源码发生变化后，旧 `mod/generation-lock.json` 的源码指纹需要在正式迁移时一并更新。旧树退役必须核实 Git 索引和工作树实际所有权，覆盖意向暂存的空文件与 NTFS 短路径别名。候选构建本身不读取这些条目作为退役授权，固定输出根核查物理拼写。[工程基线](工程基线-1.0.md) · [正式载荷准入](发布载荷来源校验设计.md)

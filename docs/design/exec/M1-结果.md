# M1 结果：外交策略接口与实机行为观测

> 实验日期：2026-10-04  
> 游戏：Victoria 3 1.14.5（Windows 实机）  
> 探针：tools/probe/zz_probe_m1_diplomacy，由 src/pdx/m1_probe.py 生成  
> 原始摘要：tools/out/m1/latest.json（最后一次为 6 个月干净启动；24 个月完整窗口的摘要也在本轮日志中）

## 1. 问题与对照

M1 只验证外交策略接口是否能进入真实游戏流程，不把策略牌名称、变量变化或
debug_log 单独当成行为因果证据。探针让俄罗斯在观察者局中按固定阶段切换两张
极端外交策略：

| 阶段 | 游戏月 | 策略 | 目的 |
|---|---:|---|---|
| cautious | 1–6 | 保守外交 | 高中立、低大胆、低侵略、低支持 |
| assertive | 7–12 | 进取外交 | 低中立、高大胆、高侵略、高支持 |
| cautious_reentry | 13 起 | 重新保守 | 验证运行时再次切换 |

第 4 月由俄罗斯脚本创建一场固定的 dp_humiliation、目标为普鲁士的受控外交博弈。
自然外交博弈同时保留，用来确认观测器不会只对受控样本有效。

## 2. 静态与加载结果

- 两张 type = diplomatic 策略牌均能加载；set_strategy 在月度脉冲中切换成功。
- 变量首次触发前先用 set_variable ... value = 0 初始化，再递增和比较；受控博弈闩锁明确写入数值 1。
- 外交博弈命名 on_action 使用 play 的 initiator/target，活动博弈迭代也使用同名 event target，避免依赖未传递的 scope:*。
- metadata 使用游戏实际字段 supported_game_version、short_description 等完整结构。
- 生成文本 UTF-8 无 BOM、LF；M1 单元测试 7 项通过；探针引用/形状检查 4 项均为 ok=True。

修复后的干净 6 个月启动和 24 个月完整窗口中，error.log 对以下标记检索均为 0：

    zz_probe_m1 / sitai_m1
    Undefined event target
    Variable 'sitai_m1
    Invalid left side
    Unknown effect
    Unexpected token
    Mod metadata read error

## 3. 实机证据

自动化阶段完整通过：

    created → foreground_ready → boot_settled → observe_selected
    → speed_set → running → background → verified → complete

修正 metadata 后的 24 个月完整窗口观测到 241 行 M1 日志：

    strategies: cautious, assertive
    phases: cautious, assertive, cautious_reentry
    control_play_observed: true
    control_play_targets: c:PRU
    play_start_observed: true
    play_active_observed: true
    play_roles: initiator, committed, undecided
    play_types: dp_annex_war, dp_return_state, dp_humiliation, dp_conquer_state
    play_goals: annex_country, return_state, humiliation, conquer_state
    strategy_counts: cautious=20, assertive=6
    play_type_counts: dp_annex_war=8, dp_conquer_state=6, dp_humiliation=17, dp_return_state=6

受控样本的日志顺序包含：

    PLAY_START_INIT;yes;俄罗斯
    PLAY_START_TARGET;yes;普鲁士
    PLAY_TYPE;dp_humiliation;play
    PLAY_GOAL;humiliation;play
    CONTROL_PLAY;c:PRU;俄罗斯

这证明脚本创建的博弈确实进入 on_diplomatic_play_started，发起方、目标方、博弈
类型和战争目标可被引擎日志读取；PLAY_ACTIVE_* 还证明运行中的外交博弈可以按
参与关系反查。6 个月干净窗口同样记录了俄罗斯→普鲁士的受控博弈和保守策略。

## 4. 结论边界

M1 的接口与观测链通过：

1. 策略定义能被游戏加载；
2. set_strategy 能在运行时切换；
3. AI 确实持有两张探针策略；
4. 受控外交博弈能创建；
5. 发起方、目标方、角色、博弈类型和战争目标可观测。

M1 尚未证明“同一机会下只改变策略字段就必然造成可重复的行为差异”。当前窗口
是单个观察者局，策略切换和自然世界状态同时推进，未固定随机种子、未做同局反事实
双臂，也没有足够样本估计每个策略阶段的发起率或目标选择效应。因此不能把
cautious 阶段与 assertive 阶段的行数差异直接解释成策略的因果效果。

后续 M2 应把这条已验证的接口链接入最小正式实现；行为因果差分应在 M3 用固定输入、
重复窗口、机会分母和失败分布单独验证。

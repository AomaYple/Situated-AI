# 全链路速度优化实施计划 · 正确性优先

> **版本**：1.1（复核稿）；日期：2026-10-09。  
> **状态**：2026-10-09 用户已授权执行；第一批组件验证通过，T03/T04 进行中，完成速度计划后继续 Mod 主计划。  
> **执行者须知**：评估通过后使用 superpowers:executing-plans 逐任务执行，复选框用于记录进度。子代理只做只读审查，文件修改和跨模块决策由主线负责。

**目标**：在保留正确性、证据完整性和行为验收标准的前提下，减少重复计算、无效实机运行和失败重跑，提高端到端开发与验证效率。

**架构**：在现有 Python 工具链和游戏自动化入口上补充计时、输入索引、任务账本和条件调度，复用已有解析缓存、快照、日志归档、资源采样和恢复机制。先优化能证明等价的离线工作，再验证采样、启动、存档和并发等条件性优化。

**技术栈**：仓库 .venv 的 Python、标准库 hashlib/json/sqlite3/pathlib、已有 psutil/filelock/pytest/xdist/coverage、现有 Windows 自动化。成熟库优先；新增依赖须有已测瓶颈、语义对照和三平台支持依据。

**依据**：[最终执行纲领](mod重设计-实施计划.md)、[工程基线](工程基线-1.0.md)、[M3 可测性清单](M3-可测性清单.md)、[自动化范式](自动化范式.md)和用户“正确性第一、速度第二”的要求。

## 1. 范围和效力

本计划是执行效率的专项附件，不替代唯一的 Mod 执行纲领。覆盖实验设计、输入选择、游戏启动与后台运行、观测、恢复、Python 分析、快照、生成、测试、CI、内存、磁盘及条件性多机扩展。

财政与外交最小闭环继续优先，这是主计划已有顺序，不是删掉政治、市场或其他最终目标的提速手段。M3-B 的机会分母为 null 时记为无法判定，不无限重跑旧窗口；独立接口研究和 M4 安全验证可以继续。

用户评估通过前，不实现优化、不启动新实机批次、不修改生产参数。生产开关和 aggression 沿用主计划与对应结果页。

## 2. 全局约束

- 项目文本 UTF-8 无 BOM、LF；游戏要求的 BOM 只在安装或打包边界添加。
- 工具链支持 Windows、macOS、Linux；GUI 能力逐平台取证，不假定 Windows 自动化能直接用于其他平台。
- 正确性第一，速度第二；尽可能 Python 化、成熟库优先，避免平行工具和死代码。
- 版本、完整挂载、源/部署指纹、存档完整性、进程身份、引擎错误、恢复和原件保护门禁保持严格。
- 自然机会、受控机会、评分差分、实际行为差分和质量改善分别记录。
- 缺失、零值、未采样、无合法机会、预算截断和运行失败分别表示。
- 不用强制行动、暴力 debuff、免费资源、伪造存档、事后挑选有利样本或放宽筛选制造成功。
- 每项优化保留基线、针对反例的测试、速度和内存对照及回退办法；提交消息使用中文。
- 快速反馈不能替代完整回归；基准、覆盖率、剖析与实机行为验收分别标注。
- 原始证据沿用已有备份、归档和恢复契约；格式化视图不得覆盖取证原件。

## 4. 怎样衡量提速

分别记录准备、预检、启动、加载、机会等待、正式推进、采集、保存、解析、恢复与重试时间。重叠阶段记录起止，不能相加冒充总墙钟。

主要指标：

- 合格配对数 / 总墙钟小时，同时报告机会数、失败数和全部拒绝原因；
- 从排队到首份合格证据的耗时，以及固定任务集完成时间；
- 预检拒绝、机会未知、无机会窗口、工具失败、引擎错误分别计数；
- CPU、RSS、私有内存、磁盘读写、进程数、缓存命中与失效、恢复成本。

快速反馈、完整覆盖率回归、组件基准和实机实验各有独立基线。pytest 内存不能当游戏内存，tracemalloc 不能当整机 RSS。

目前合格配对基线为 0，不能计算“提高几倍”。此前聊天中的 3～5 倍、5～8 倍及各项百分比缺少端到端对照依据，本计划不把它们写成承诺或验收标准。

先测阶段占比再排序。某部分只占总耗时 5%，即使全部消除，总体加速最多约 1.053 倍。每项用实测报告，不将各项倍数直接相乘。

## 6. 正确性边界

### 6.1 不把机会未知当作没有机会

检查点索引输出四态：可做仪器验证、可做正式配对、明确拒绝、机会未知。未解析字段、尚未发生的自然机会和缺实机验证都记未知，允许有预算的侦察，不直接拒绝后声称“没有机会”。

候选、落选项与理由全部留档；只依据处理前状态选择，不能看候选臂结果再挑样本。受控和自然机会分开验收。

### 6.2 配对和提前结束

两臂从同一检查点、同一阶段和相同激活 tick 开始，不能各自等到不同机会后再配对。多国共享一场博弈不等于多个独立世界样本。

等待上限到期属于预算截断或无法判定，不能写成永久无机会。截断规则事前登记、两臂对称，不因看到有利结果提前停。M4 固定窗口和至少 24 月正式长期要求保持原样。

### 6.3 缓冲不能补回引擎未记录的事件

Python 缓冲只能保存已经产生的事件。引擎按月输出的状态不能靠高频轮询恢复月内未记录的角色变化。先核验 hook/getter 真实分辨率，再决定采样。

错误日志、轮转捕获和关键行为通道保持完整；优先减少冗余截图。降低频率若改变行为分辨率或 RSS 峰值精度，必须单独报告，不能与原基线直接宣称等价。

### 6.4 统一采集不能增加不可控扰动

先定义必需最小观测包，其他模块按目的选配。两臂使用相同包，测量探针本身的 CPU、内存、脚本和日志开销；探针改变时不能自动合并旧证据。

不为“一局采齐”始终启用最重政治矩阵或高频全世界扫描。共享解析事件和时间轴，比盲加 getter 更优先。

### 6.5 恢复账本不等于续接游戏世界

可以复用已完成生成物、不可变日志解析、预检记录和完整单臂。崩溃、进程身份丢失、缺日志或恢复失败的片段隔离，不能拼成完整合格运行。

从存档重启作为新 run_id，重新核对版本、挂载、激活和窗口。反事实需要时重跑对应臂；不能把重载前后随机状态当连续无中断实验。

数据库事务不能与文件移动、部署或配置替换一起原子提交。外部操作前先持久化意图、原件与目标路径、操作前指纹和备份位置；重启先核对磁盘实际状态，再恢复或幂等续做。状态有歧义时阻断自动重试，保留备份和诊断，不因账本显示“未完成”再次移动或删除原件。

### 6.6 缓存与复制不能省略内容证明

路径、大小和时间戳仅作变更线索，不省略正式验收的当前内容 SHA。严格模式在会话内复用经内容验证的不可变输入；输入可能变动或失效不明就重读。

输入读取途中变化必须失败或重新审计，不能输出前后不同代的数据。worker 只读已有缓存，不声称共享 Python 堆中 AST。保留类身份、格式、损坏回退与原子发布，不读取不可信 pickle。

大存档流式化保留源摘要、目标重读摘要、版本校验、原子替换和失败备份，不删目标验证。不得硬链接可变存档绕过复制，避免修改原件。

### 6.7 进程和环境复用

重载存档不证明脚本重新加载。不同 vanilla/candidate 脚本挂载仍独立启动，除非官方支持和实机证据证明可以切换。

同用户目录保留运行锁。用户目录、启动器、窗口、日志、存档和退出身份完全隔离后才评估双实例；不通过就保留单实例，不能绕锁。

多实例测吞吐，不能让资源争抢污染正式 M4 性能配对。硬件、分辨率、渲染和后台设置两臂一致，不改 tick、AI defines、国家数、DLC 或世界状态制造速度。

### 8.2 逐热点预登记预算

T01 为每个入选方向保存以下登记，候选测量开始前冻结并附内容指纹；既有 worker 估算常数和组件比较器的默认 10% 不能自动成为所有任务的验收预算。

| 登记项 | 必填内容 |
|---|---|
| 输入与环境 | 任务集、内容指纹、两臂源指纹、解释器/依赖/平台、硬件、覆盖率模式、观测包与缓存状态 |
| 主指标 | 阶段或总墙钟/首份合格证据耗时/吞吐之一，单位、计时边界和是否包含预检、准备、失败、恢复 |
| 资源预算 | 进程/进程树范围、RSS/私有内存/Python 分配峰值/CPU/磁盘指标的适用集合，各自上限或允许相对回退；采样间隔和平台不可测项 |
| 重复与噪声 | 预热是否计入、固定轮数和交错顺序、主统计量、噪声计算方法、最小有用改善量、超时和异常样本处理 |
| 正确性与停止 | 字节或结构语义对照范围、实机门禁、失败预算、回退开关和原件恢复检查 |

可重复离线任务默认至少三组交错基线/候选，固定 AB/BA 顺序后运行；不根据途中收益追加轮数。默认主统计量为各臂中位数，保守噪声取各臂样本相对其中位数的最大偏离值中较大者；候选改善须超过该噪声和预登记的最小有用改善量，并满足其他速度/资源预算。计时中位数为零或输入不相等时不计算比例。要换方法，必须在候选测量前登记，不能测完后选择更有利统计量；少量重复只支持本工作负载的工程判断。

超时、OOM、引擎错误和恢复失败不作为“离群值”删除；全部计入端到端成本与失败记录。单独诊断环境异常的运行保留原件，重测须按登记规则处理完整配对。资源无法可靠测量时填写 null 和原因，不能写零或声称相应预算通过。预算未定、收益低于噪声或重要资源超限时只报告，不默认启用；必要正确性修复单列，不包装为提速收益。

### 8.3 批次与停止

T01 后按占比调整同阶段顺序；每批最多选三个已测热点。低占比、无输入、已有能力或收益低于噪声的方向保留结论，不连续重构。第一批优先评估阶段计时、perf_compare 重复 IO/大存档内存和缓存正确性。

实机沿用主计划有限探索预算：先一组仪器验证，正式行为场景不因本计划自动扩样或延长；M4 固定窗口按原出口。修改预算要在新一轮开始前登记，不能看结果追认。

同类原版错误达到主计划阈值停止该场景；恢复、指纹或进程身份失败停止受影响队列。条件性优化不通过就关闭，继续独立任务。

为避免工程取代 Mod 制作，每批只实现有测量依据的收益或必要正确性修复；测量不足时回到合法机会/接口研究，不为列齐方向构建通用调度平台。

## 9. 验证与收益报告

### 9.1 缓存状态和可比范围

| 状态 | 操作定义 |
|---|---|
| 应用冷缓存 | 新进程、空 memo、独立且初始为空的应用磁盘缓存；明确记录缓存是否允许写入 |
| 热磁盘、空 memo | 用相同源与输入预建完整磁盘缓存，在新进程读取；记录预建成本，不混入正式读取计时 |
| 热 memo | 同进程先完成同一输入预热，计时内只执行声明的复用工作；记录 LRU 上限与命中率 |
| 禁用磁盘层 | V3_PARSE_CACHE=0 只关闭磁盘层；memo 仍存在，须另行声明进程与 memo 状态 |

cache.clear() 只清内存层；不把它当冷磁盘测量。基准通过子进程隔离的临时目录控制应用缓存位置并先断言实际路径，不能清掉用户或其他任务共享缓存。应用冷缓存不等于操作系统页缓存、磁盘控制器或硬件冷启动；这些状态未知时明确标记，不使用“磁盘冷读”的结论。计时、tracemalloc、profiler 和进程树采样分别登记开销，前后采用同一测量方式。

### 9.2 结果契约

确定性工具要求同输入下字节或规定结构语义一致；运行 ID 和耗时可以不同，样本、资格、角色、拒绝理由和结论不得变化。

游戏有随机性和机器噪声，不能要求两次独立运行逐字相等，也不能用三次运行证明总体显著。必须保证输入、挂载、观测、激活和窗口契约一致，报告所有差异和不确定性。

离线重复按第 8.2 节冻结规则执行；实机先一组仪器验证，再按主计划预注册预算重复。正式 M4 仍先做三次 vanilla 噪声测量，再评估冻结候选。冷/热与 profiler 单列；噪声大于收益就记为未证实。

复用现有报告和消费者；已有性能报告使用 schema=1，不将其直接改名为 schema_version。汇总侧增加版本化附加字段，旧格式通过明确适配读取；下表是待实施字段契约，不是本轮测量结果：

| 字段 | 类型和含义 |
|---|---|
| schema / speed_plan_schema | 保留原报告 schema；汇总附加契约版本为整数 1 |
| optimization_ids / task_id / status | 方向列表、任务和实测状态；未证实、回退、不可用、待输入不能写通过 |
| input_manifest_sha256 / baseline_source / candidate_source | 实际输入清单与两臂源内容 SHA；dirty 工作树还需内容清单，不能只报 commit |
| preregistration_sha256 / evidence_paths | 冻结登记文件的 SHA 与原始输出路径；证据缺失时不能判通过 |
| measurement_scope / environment / cache_mode | 进程范围、环境及第 9.1 节缓存状态，覆盖率和 profiler 模式显式记录 |
| primary_metric / unit / sample_order | 主指标、单位和实际测量顺序，不能把组件时间代替端到端时间 |
| baseline_samples / candidate_samples / stage_intervals | 全部逐轮测量、运行身份、阶段起止、失败与恢复成本；重叠不重复相加 |
| resources / budgets / noise / decision_rule | 逐项资源读数、采样间隔、冻结预算、噪声方法/读数和是否满足启用规则 |
| correctness | 离线的对照范围、equivalent 和差异；实机填写 contract_valid、门禁明细与结论边界，不用 equivalent=true 暗示两个随机世界逐字相同 |
| qualified_pairs / opportunity_count / failures | 两臂分别列数量、机会范围和全部失败；机会不可观测为 null，不变成零 |
| speedup_metric / speedup_ratio / incomparable_reason | 时间比为 baseline/candidate，吞吐比为 candidate/baseline；对应分母为零、缺失或输入不可比时比值为 null 并记录原因 |

已确认基线的合格行为配对数为零，不能计算合格吞吐的加速倍数；若候选仍无合格证据，首份合格证据耗时也为 null，并记录截至预算上限的等待时间和截断状态。时间比、吞吐比和内存比使用不同字段，不用一个 speedup 数字混报。

结果、覆盖率、恢复或证据范围出现不解释的差异就回退。速度改善和内存上升同时报告，超出预注册预算不得默认启用。回退保留原始证据和失败记录。

# 工程验证提速协议

这是 1.0.0 交付计划的从属执行协议，不是第二份产品计划。优先级固定为：正确性第一、速度第二、内存第三。

## 提速顺序

1. 先复用不变的快照、生成物、源指纹和离线报告，避免重复分析游戏树。
2. 先运行受影响的定向测试，再在提交前集中运行完整 Python 回归；默认 `-n auto --dist loadscope`，worker 数受 CPU 与内存预算限制。
3. 将互不共享写入的检查并行，将基准和会改变用户/游戏状态的命令串行；避免多个游戏进程、部署事务或日志采集互相污染。
4. 基准固定输入、版本、选择集、worker、重复次数和资源口径；速度和内存收益必须在同一正确性与输出契约下复测。
5. 失败、跳过和外部阻塞保留原件；不能通过删用例、放宽门禁、增加预算或改名获得“提速”。

## 资源口径

- 墙钟：命令开始到结束，报告并行度和是否含收集/覆盖率。
- Python 分配峰值：`tracemalloc`，只说明 Python 对象分配。
- 进程 RSS：进程树峰值，说明 worker、插件和游戏进程是否计入。
- ZIP/源产物大小：固定压缩级别和路径排序，说明是否含 BOM。

没有同口径旧基线时只报告绝对值。工程提速不能推断 Mod 游戏内速度；游戏内性能由用户在标准包上长期验证。

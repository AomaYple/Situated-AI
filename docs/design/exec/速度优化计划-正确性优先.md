# Mod 制作与验证提速协议

> 2026-10-17：从属[Mod 全目标实现优先与集中验证计划 4.0](mod重设计-实施计划.md)，只维护方法，不创建另一套排期。主计划先完成 F0，再进入 F1 集中验证；本页只说明如何在正确性不变的情况下减少验证成本。旧 2.1–2.4 通过 Git 历史和日期化审计核对；旧测量不追认为新收益。

## 1. 先完成 F0 候选，再集中 F1 实机

实现轨必须先完成四模块、组合、解释、全语言翻译初稿、玩家路径、保存/重载、配置与实验交付；F0 出口成立后，F1 集中进行加载修正和模块行为质量验证，F2 完成长期性能与发布。候选不冒充已验收模块。

开发期保留数据校验、生成一致性、实际生成脚本测试、静态检查和回退契约；接口基于原版来源实现，未实测标明假设，已否证读法不复用。只在源码批次冻结与受影响出口需要时完整回归，不在每个小改动后重复全套。

F0 期间发现的缺口必须回到实现队列处理；不能用一局加载成功、一个评分变化或一份界面截图把缺口标成完成。F1 期间发现的行为问题只修复已定位原因，修复后重新生成候选并按依赖范围验证。

## 2. 减少重复与共享状态

- 复用 src/pdx、现有生成器、快照、分析、package、game_run、账本和恢复流程；不新建常驻服务或第二套运行器。
- 完整与单模块候选由同一数据源生成，独立输出目录；原版默认策略只补一次，组合不反复解析同一个底本。
- 规则与说明从实际参数生成，避免手抄权重、测试数量或输出指纹。只为当前问题补必要观测，不复制完整引擎内部模型。
- 离线任务互不覆盖输出/代码时才可并行；游戏、完整回归、正式性能与剖析错峰，游戏始终单机串行。

## 3. 按依赖复用证据

同版本、源、接口、输入、探针与窗口依赖未变的证据可引用原件；未知依赖不算相同。文档日期或提交 SHA 变化不自动使整个世界失效；影响生成/运行行为的修改必须重验受影响范围。

current/control/disabled 保留既有语义；完整实验包和单模块变体有明确身份与实际开关。零 Mod、带观察器、受控机会、财政注入、行为配对和资源诊断分别登记，不相互冒充。

## 4. 有界实机与故障修正

加载/安全实验按自身问题执行，不先要求正式质量样本。先定位解析、作用域、挂载和生命周期错误，再按单因素验证行为；整包差异不能归因某模块。

每次运行前冻结问题、输入、允许差异、观测、预算和恢复；单次回答明确问题。阴性或缺机会按原标准记录，在预算内决定修正/替换，不自动延窗。正式 M3/M4 预算与出口只由主计划定义。

原账本停止条件保持，不清账、不换名或改探针刷新预算。外部阻塞明确输入/接口/环境及独立下一动作，先完成不依赖它的实现，不能把环境摘要当产品成果。

## 4.1 F1 集中验证的提速流水线

验证按同一候选包和同一问题尽量合并，顺序固定为：

1. **快速门禁**：先核对候选包 SHA、版本、挂载和输入身份，再运行受影响的 encoding、生成一致性、静态检查和定向测试；前置失败时不启动游戏。
2. **复用冻结结果**：F0 已冻结且依赖未变的完整回归与成本结果直接引用，不在进入 F1 或每次启动前重跑。F1 修复形成新的源码或本地化批次时，先做定向检查，批次冻结后再集中运行一次所需的完整 `n-auto`、覆盖率和成本测量；文档修改不触发无关回归。
3. **一次启动多项烟测**：同一安全诊断窗口内顺序完成加载、观察者、快捷键 `5`、空格、后台推进、日志采集和恢复清理；互相改变状态的项目拆开，不能为省一次启动合并不相容输入。
4. **模块优先、组合随后**：先用隔离变体回答接口和生命周期问题，再用完整包回答组合问题；不通过整包差异推断单模块因果。
5. **语言批次化**：语言加载和解释键按固定版本与固定候选逐一登记；可以复用静态键集和占位符检查，但每种语言的游戏内结果必须独立记录，不能用 GUI 模板语言范围代替本地化范围。
6. **资源错峰**：游戏、完整回归、正式性能和剖析不并发；离线扫描只有在不共享输出和缓存时并行。`n-auto` 的 worker 由实测 CPU/内存预算选择，不为速度突破门禁。
7. **证据复用**：候选、输入、探针、窗口和环境身份未变时复用原始证据；任何身份变化都重新判断依赖，不能用摘要或旧 `ok=true` 绕过当前门禁。

## 5. 测试与性能

正确性第一、速度第二、内存第三。定向测试随实现；完整 pytest 默认 -n auto --dist loadscope，worker 由 CPU/内存预算控制，测试写临时目录。完整覆盖率与各核心下限保持。

新增 Python 路径以固定输入串行测耗时、峰值内存及重复波动，基准清普通 addopts，与实机错峰。无同语义旧实现时报告绝对成本，不计算提速比例；工具提速不等于游戏提速。

端到端记录实现到候选、启动/读档、测试、有效样本、重复失败与资源成本。只优化有证据的热点；不为局部收益增加维护层、破坏行为或降低验收。

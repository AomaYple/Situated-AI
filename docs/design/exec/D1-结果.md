# D1：统一行动接口与生产 bundle

状态：`in_progress`。证据类别：`static_check`。D1 尚未关闭；本收据只记录已落地的统一生产身份和仍未完成的语义工作。

## 已落地

- `ConsumerIRBundle` 是 `load_model()` 的统一 writer 汇总入口。当前候选包含当前生产源的 1,414 条规则 writer（历史基线 1,401 条、前向新增 13 条）与 11 条显式行动卡，共 1,425 条唯一 writer；冻结基线中的 7 张卡仍保留为历史对照，不与当前候选混算。
- 每条 legacy writer 都绑定精确的 source、definition、field、actor、target、operation、vanilla tail 和已解析谓词；作用域/操作漂移会在生成期失败。
- 每条显式行动行保留资格、辅助事实、硬负面、退出、收益、承诺、政治成本、限幅、关系和 unknown policy；`single_clamp=true` 为 lowering 合同字段。
- 显式行动 lowering 和独立 PDX AST 求值均读取 `model.decision_ir`，不再从 `ActionCard` 另行拼接。行动预算超限会硬失败，不能静默切掉候选。
- 辅助互补事实未知时，独立求值保留已知基础档并回退该增量；核心资格未知仍保留原版回退。
- 本轮 D5 语义修复补充了核心/辅助证据的未知分流：核心证据未知或硬资格为假时不替换原版，辅助证据未知时只保留基础档并标记 `lower_tier`；过期事实和非有限数值不再作为当前健康证据。

## 追加静态见证（2026-11-02）

新增 `tests/test_situated_migration_oracle.py`，作为独立迁移语义见证，不调用 `compiler.evaluate_policy` 或生成器作为 oracle：

- 按原始 `RuleSet.rules` 和 reader 类型合同独立实现三值求值；已知假条件优先于未知，未知不会被伪造为假。
- 对当前全部 1,414 条 legacy 规则逐条执行隔离正例、合法反例、每个输入的 unknown/invalid/NaN、玩家边界、reader 最小/最大值及条件阈值候选点。
- 每条规则同时比较未 lowering 的原始求值、`ConsumerIR` lowering 后求值和独立 oracle；另在完整 consumer 上下文复核优先级短路。
- 变异一个 writer 的值时，`lower_legacy` 必须拒绝语义漂移。

验证：`.venv\Scripts\python.exe -X utf8 -m pytest -n0 -p no:randomly tests/test_situated_migration_oracle.py`：`4 passed`，11.38 秒；Ruff 检查和格式检查通过。随后共享工作区的 `domain_actions.toml` 与合同解析器正在并发调整，重跑在 `load_model()` 报“联合链字段无效”（2 failed、2 passed）；最终候选须在相关生产修改收拢后重跑，不能沿用此前通过结果验收。

该见证覆盖 D1/D2 的静态规则迁移语义边界，但不证明 PDX 引擎运行期条件、原版消费者资格/成本/随机尾部的实机行为，也不证明生成 AST 与最终 ZIP 游戏载荷逐字节等价。

## 未关闭

- 规则 writer 仍由原版 RuleSet 负责资格和尾部 lowering；bundle 当前提供精确身份和统一索引，不等于历史 1,401 条或前向新增 13 条规则已经迁移为同一动态行动公式。
- 成本、动态 rank、关系、尾部 AST 指纹及 PDX/参考逐 writer 反事实尚未全部一致；D2、D4、D5 及后续域阶段仍 pending。新增的 unknown/过期/单位拒错只关闭相应局部合同，不改变全量范围 pending。
- D0 仍为 `incomplete`：原版发现面中缺少字段级作用域证据的项目保持 pending。

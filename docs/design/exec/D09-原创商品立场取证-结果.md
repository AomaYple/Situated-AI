## 原创对照

从仓库根按下例生成诊断树。商品选 `oil`、`radios` 或 `telephones`。同轮只启用一组，从同一冻结暂停档分叉，记录 DLC、游戏校验和、Mod 挂载顺序和样本 SHA。先用同构建、同 DLC 的原版档开局并验证原版当前策略及目标商品槽。实验组单独加载，以发行包复现的现象作为历史线索。

```powershell
py -3.15 -X utf8 -B research/situated/1.15.2/d09_stance_probe.py fixture-positive oil tools/out/d09-oil-positive
py -3.15 -X utf8 -B research/situated/1.15.2/d09_stance_readback.py 'C:\path\to\local-text-save.v3' JAP
```

下表列出七组基础对照，均带市场读取效果。另有首轮共用对照 `fixture-first-round`，在同一包的独立文件中放入显式 OR 卡和重复商品键卡。四张诊断管理卡只供调试赋予指定 AI 国家。用独立用户目录将生成树登记为本地 Mod。以法国玩家观察日本时，调试控制台先给日本设相应诊断卡标记，例如 `sitai_d09_fixture_on`，再赋指定诊断策略。例如可在暂停时运行 `effect c:JAP = { set_variable = { name = sitai_d09_fixture_on value = 1 } set_strategy = sitai_d09_fixture }`。切换卡前撤回前一卡的标记。原版默认注入两组额外给诊断国设 `sitai_d09_native_probe`。每组读实际生效卡和同日、下一次 AI 更新以及再下一次同条件更新。卡未生效、换卡、零进度或读到前轮缓存时，该格待证。 [油品首轮实机交接](D09-油品首轮实机交接.md)

| 组 | 写入 | 识别用途 |
| --- | --- | --- |
| `fixture-base` | 自有策略单块，目标由 `sitai_d09_base` 守卫，另有瓷器 `wants_high_supply` | 基础条件与基础独立键。另用本组的独立 `sitai_d09_reference` 卡核验艺术品 `wants_export` 的读点。 |
| `fixture-repeat-field` | 对同一自有卡顶层追加新 `goods_stances` 块，含同商品及艺术品 | 测数据库追加后已有字段的重复处理。 |
| `fixture-repeat-good` | 在单一自有 `goods_stances` 内写两条同商品 | 直接区分字段问题与同商品键载入问题。 |
| `fixture-positive` | 目标商品只写一次，两个原创条件在一棵显式 OR 下，保留瓷器与艺术品 | 同轮读档与两条件正控，定义预期真值。 |
| `native-base` | 原版默认策略，提供空的诊断管理卡 | 找到同一商品的原版真／假档，在诊断空卡下复核原版兄弟项确实来自默认策略。 |
| `native-flag` | 向原版默认策略顶层追加，目标用标记守卫，并加艺术品 | 逐商品移走市场阈值这个变量，测真实默认数据库目标。 |
| `native-market` | 同上，目标改用 AI 当前市场、该商品存在、价格压力严格大于 0.25 且订单差小于零 | 定位真实游戏市场谓词。仍需实际供给候选与运行结果。 |

先开 `fixture-positive` 做同轮正控。依商品用无覆盖的 `sitai_d09_clean` 与只给目标商品 `wants_export` 的 `sitai_d09_shadow` 配对，实测其变位以绑定商品下标，并校验 `fine_art`、`porcelain` 的独立位置。原版 `game/common/goods/00_goods.txt` 有 54 个商品。按文件载入顺序的候选下标为油 30、无线电 49、电话 48、艺术品 53、瓷器 37、纸张 14，均从零计。以 `player_manager.database` 的实际玩家国家、国家表的国家／市场实例以及 `ai.database` 的国家引用复查。商品槽位在 `spending_variables.goods_stance`，策略在同一 AI 记录的 `ai_strategy.type`。采样间每次重新确认玩家和 AI 控制。关闭测试标记、换市场及切为玩家后重新采样。

四格由对同一起点分别设置或移除 `sitai_d09_base` 与 `sitai_d09_added` 产生，次序固定为 00、01、10、11，先记录两标记的实际值。正常 OR 的预期为中性、高供给、高供给、高供给。仅原分支有效为中性、中性、高供给、高供给，新增键替换为中性、高供给、中性、高供给。保持当前诊断卡标记 与相同实际管理卡，比对重复块组、同商品组、唯一 OR 组。

- 瓷器持续而艺术品与新增单真格都缺席，检查冲突与错误日志。存在明确拒绝诊断时归拒绝。只有沉默时仍待区分块未解析、被忽略或策略重算未发生。同一活动策略下，瓷器消失且艺术品出现时可辨整块替换。两独立键持续而旧单真变中性时可辨同商品替换。
- `native-flag` 按原版对照中实得的旧单真／单假样本运行新标记开／关。用同国有／无油覆盖的卡对照。若默认新增艺术品能出现，而活动卡给油 `wants_export` 时油不取默认新增结果，归于活动卡覆盖该商品。若其他默认/新增键也一同消失，记录疑似整体遮蔽，另查兄弟字段。实际活动卡、原版分支和确已重新求值须同档回读。
- `native-market` 在同一暂停帧执行 `effect c:JAP = { sitai_d09_sample_market = yes }`，读执行标记 `sitai_d09_sampled`、商品存在标记 `sitai_d09_sample_available` 及稀缺标记 `sitai_d09_sample_scarce`，与同日市场面板核对。当标记正控有读数、艺术品仍有效而稀缺标记未真时，先按实际条件分类。区分无市场商品实例、无订单、价差临界、零差及正差。立场更新和取样存在时间差时保留未知。 `game/gui/goods_panel.gui:2129–2147/2161–2180` 给出价格相对值、实际买单、卖单和净订单读点。
- 11 格读到一个最终槽是序列化结果。若要验内部只有一笔商品枚举，还须引擎的枚举读点或能看出顺序、重复贡献的消费者见证。先后调换第二块及同键次序，复跑 01、10、11，并在另一路兄弟原版立场为真的档上复验默认分支保留。

## 国家行动与结果

用日本 18、市场 6 和关西捕鲸作油的早期候选。原档先验本国真实可建、方法确实产油，以及当前项目竞争、政府可用建设份额和预期投入。要以同种子另配可建油井条件，可从同一已发现油资源且已取得相关科技的起点分叉。初筛没有合法机会时，转用有资格的本国油品条约候选，其发起、受理、生效、交付和付款分别观察。建筑定义见 `game/common/buildings/09_misc_resource.txt:64/89`，产油方式见 `production_methods/09_misc_resource.txt:388–449/555/586`。夏威夷纯原版公共捕鲸队列是建设读取对照，该现象的历史见证在初筛清单。 [D03 公共队列](../domains/D03.md#d03public_queue) · [D10 贸易](../domains/D10.md#d10trade_flows)

电话和无线电各找一个原版分支为假而本国可增供的市场。国内项目先核电气产业及已解锁的原版 PM；无线电方式兼产电话，需分别跟踪产出。电话可另走合资格商品转移，先确定本国市场归属、可交易量、条款双方和真实到货。见 `game/common/buildings/01_industry.txt:616`、`production_methods/01_industry.txt:2279/2304`、`treaty_articles/13_goods_transfer.txt:31/94/149/191/242`。从市场面板、施工队列与条约面板回读本国主动安排、公共出资、实际施工／履行、投入、就业、产出、到货和次期订单。同市场成员、公司、私营队列及贸易中心自治成交分别归实际执行者。式中市场总价与订单是市场信号，单州可达性、已支付成本及实现供给各用自己的后续见证。无真人干预的行动窗口用于归因，调试控制台用于建对照和只读采样。

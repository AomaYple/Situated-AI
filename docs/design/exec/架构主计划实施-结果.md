当前阶段为开发与验证。实施分支以 `c3796adc939d1b97bc93e8568571832a8dd80fa4` 为生产对照，
游戏合同为 Victoria 3 1.15.2。实施拟用 Mod 版本为 `3.4.0`，目前生产声明仍为 `3.3.1`。

## 复现与阶段待项

本阶段检查点以 `3.3.1` 进行工程复现。实际安装的 `modgen --write` 完成 100 个生产文件，
随后 `modgen --check` 逐字节回读一致。Git 中的生成变更集中于
[`generation-lock.json`](../../../mod/generation-lock.json)，其 SHA-256 为
`838d5e5129627fc475bb3daaf2f79641407b79a852ec888db18007292f8652e1`。
同一工作树连续调用 `package --profile 1.15.2` 两次，产物 SHA-256 均为
`0fa392c36d3644e72c05ef054f4d939c55249e4949b69abf18bf6218619e6d06`，两个 ZIP 均通过存档完整性检查。
该树对参考机、发布、条约标准包回读、动员与军事生产接口的 287 个定向用例全部通过（136.72 秒），
`baseline-offline` 七项通过。正式版本的包身份另随交付提交登记。

基线和候选各自需要在对应 Git 树及 CPython 3.15.2 环境核对。参考机和发布参数可以分开复现。防御条约测试会调用标准包入口，要求该树的生产生成锁已基于同树源码核对通过。

```powershell
$py = '.venv/Scripts/python.exe'
& $py -B -X utf8 -m pytest -o addopts= -q tests/test_situated_reference_strategy.py
& $py -B -X utf8 -m pytest -o addopts= -q tests/test_one_click_publication.py
& $py -B -X utf8 -m pytest -o addopts= -q tests/test_defensive_pact_projection_delivery.py
& $py -B -X utf8 tools/ci/run_check.py baseline-offline
```

- 跨期生产闭环待固定同一候选的原版裁决、结果观测与重评顺序。条约对手回应、批准、生效、退出及其对军需和产业选择的关系仍缺同局证据。其他链路若作为代表性闭环，同样需要证明至少两个相位或消费者及反馈。
- 正式版本的工程和静态语义验收待绑定同源候选的生成锁、经过独立回读的标准包、完整回归和拟改变的生产差异。检查点的生成与 CLI 发布测试已有本机验证。
- 引擎与玩法验收待绑定包、安装构建、玩法 DLC、场景和国家分母。需要记录加载与存读、逐相位推演、原版与分组部署对照、结果反馈及能够支持的采用范围。
- 正式发布待记录合并提交、正式标签、标准包摘要和逐渠道回读。剩余领域与方面以首个已发布版本为基线。

## 已实现与边界

自然响应分析复用原有唯一绑定、完整两国矩阵和连续日序号门禁，增加 `role_timing`：记录观测到的加入/失去支持者角色区间，以及相对首次连续可支持样本的区间。已在开窗前加入、末尾仍支持和无记录分别保留截断/未知。角色丢失不是主动退出，END 不补一行退出，日内变化可能漏测；不能把采样区间当精确日历或引擎真实响应时延。历史日期日志仍按旧接口解析。

预算校准默认关闭，`decision_behavior.py --cost-calibration` 仅允许 instrument/control、fiscal-injection none、受控机会；不进入自然、市场或正式包。复用机会事件的确切 scope 与共享 sample-N，在显式国家上下文读取 `GetIDString`、原版承诺触发器 `is_diplomatic_play_committed_participant`、已在独立财政仪器中验证过的 `GetPrincipal`、`GetMaxCredit`、`GetGoldReserves` 和 `GetWeeksUntilBankruptcy`。曾触发原版 `GameStateAccess` 断言的 `GetMilitaryGoodsExpenses` 与 `GetMilitaryShipMaintenanceExpenses` 已从默认路径移除；独立模式不加载额外财政观察器或无关政治 getter。

本金/储备是货币存量，信用是可用额度，破产周数是引擎显示值，保留三位小数。每个字段的作用域、采样精度、未知值、哨兵值和不可归因边界同时写入 `cost_probe.configuration().fields`；国家总量和全局承诺状态不能归因单场外交行动。解析器检查身份稳定与两国不同、同样本完整矩阵、连续序号、有限数值、零与未知，仍输出 `action_cost=null`、`adverse_outcome=null`、`quality_improvement_proven=false`。没有同 tick 独立预算真值时 `engine_interface_validated=false`，不将数值可解析升级为数值真值校准。

## 响应钩子的脚本链作用域复核（2026-10-15）

官方镜像 `research/official-docs/game/common/on_actions/_on_actions.md:106` 说明 on-action 只能访问触发来源链可用的 default/saved scopes；并发触发的 effect 与事件拥有不同的链，局部值和 scopes 不自动相互传递。当前绑定器在 `on_diplomatic_play_started` 的 effect 保存 `scope:sitai_opportunity`，每日延迟事件从此链触发；三个独立响应 hook 的 `this = scope:sitai_opportunity` 却没有证明继承同一链。

这是一个需要独立验证的**潜在漏记原因**：没有响应行不能区分“没有响应事件”与“跨链守卫无法匹配”。下一项观测任务应先验证跨链可恢复的同一博弈身份，或增加明确不绑定原机会的根事件诊断并单列归因边界；不得靠移除守卫把同一国家对的另一场博弈混为原机会。未完成实际触发与身份复核前，根 hook、逐国 actor 和响应时延继续未验证，不改 `quality_improvement_proven=false`。

补充原版来源：当前 `common/on_actions/00_code_on_actions.txt` 的 join/abandon 包装分别在第 4322–4325、4336–4339 行调用对应通知，`common/messages/00_messages.txt` 第 325、345 行声明通知类型为 `diplomatic_play`；`localization/english/interfaces_l_english.yml` 第 9470–9471、9474–9475 行明确读取 `SCOPE.sC('actor')`、`target`、`recipient` 来描述加入/退出双方。这给出逐国 actor 的**候选读取链**，比只有根入口字面量更具体，但通知使用的 scopes 是否完整传给追加的 on-action 仍待验证。下一实现先用存在性守卫与显式未支持值采样，不读取未经验证的军事费用 getter，不把局部通知源说明当成所有 hook 的 actor 契约。

## 独立根事件诊断实现（2026-10-15 后续定时任务）

本轮将响应钩子的诊断协议独立到 `pdx.response_probe`。三个根 hook 不再只有跨链绑定守卫内的旧日志：每次进入都在存在性分支中输出 `SITAI RESPONSE ROOT;<hook>;<saved_scope>;<actor_id>;<escalation>;<date_text>`。`saved_scope` 明确区分 `missing`、`same`、`different`；仅在 `exists = scope:actor` 内读取国家 ID，缺少 actor 时记为 `missing`。旧 `SITAI RESPONSE;` 仍只在保存作用域存在且匹配时输出，不把任意根事件归入已绑定机会。

冻结元数据和运行上下文同时记录诊断版本 1、`chain-local-diagnostic`、`guarded-id-unvalidated` 及未绑定根事件范围。分析器单列 `response_diagnostics`，保留轮转日志顺序和重复记录，严格拒绝未知钩子、越界升级值、未展开 getter 和缺失日期。只有根事件而没有机会也可输出诊断报告，但机会仍未捕获、可配对状态仍为 false。日期只保留引擎文本，不与共享 `sample-N` 拼接，不计算响应时延。

解析正反例、生成 AST 分支、缺 actor、跨链三种状态、同日重复事件、入口用途限制和实际生成→分析回调均有离线测试。入口仍只允许 `instrument/control/none/自然观察`，禁止制作存档；正式资格重建实际源码，即使把诊断源指纹全部同步也拒绝。没有放宽错误、挂载、恢复或产品出口。

历史失败局 `20261014-215820/logs` 经新分析器回放得到 `no_root_events_observed`、根事件数 0、自然样本 0、机会分母 null，质量仍为 unsupported，所有质量读数为 null。旧仪器本来不生成新 ROOT 协议，因此该回放只验证向后解析边界，不能证明新 hook 不触发。本轮没有启动游戏：账本已停止同环境同类错误，上一轮 Steam 校验未产生环境变化；修改诊断源码也不自动解除原版错误停止。下一步是研究可跨链恢复的真实 Diplomatic Play 身份及 actor 类型契约，并在出现可核查的新环境/输入前提后登记一次有界实机；不能按同一国家对或日期猜同一博弈。

提速措施是让下一次合法实机一次分清根事件、绑定缺失和 actor 缺失，减少不可解释的空日志；这不是已测得的开发提速比例。仓库 Python 3.14.7/Windows 11 串行五轮中位数：生成含诊断的完整机会包 0.411 毫秒、Python 分配峰值 54,028 字节；回放 10,000 条合成根事件 21.410 毫秒、分配峰值 3,737,630 字节。两项含解释器启动的独立进程采样 RSS 峰值分别为 54.87 MiB、56.23 MiB（50 毫秒采样，不是精确高水位）。原始结果位于本地忽略目录 `tools/out/benchmarks/response-hook-diagnostics-20261015/result.json`，五轮输出指纹一致；没有同语义前版，因此只建立成本基线，不计算提速比。游戏运行开销和新 hook 的实际触发、逐国归因均未实测，`opportunity_identity_verified=false`、`actor_scope_supported=false`、`absence_proves_no_response=false`、`quality_improvement_proven=false` 保持。

本轮新增 31 条用例（其中新诊断文件 30 条），当前收集 **3722 条、119 个测试文件**。新增接线测试的初版财政夹具曾被真实严格分析器拒绝；已修正为双国合法 `sample-1` 并修正机会分母字段名，没有放宽生产校验。随后完整 `v3 cov` 使用默认 `n-auto`：**3703 passed、19 skipped、1551 subtests passed、0 failed，574.37 秒、4 worker**；包含行与分支的总覆盖率 **89.34%**，新诊断模块 **96.6%**，整体 86% 和 11 个核心模块下限全部通过。19 个跳过为 11 个 Windows 符号链接权限不足、1 个 Windows 无 FIFO、7 个用户目录引擎日志缺失。Ruff、格式、mypy（212 个源文件）、编码及离线 baseline 通过；死代码审计覆盖 2385 个定义。此前 3691 条集合的结果保留在上一节，不将不同集合和缓存的耗时差解读为提速或退化。三平台工具验证以本轮 PR 的实际 CI 为准，macOS/Linux GUI 仍未实测。

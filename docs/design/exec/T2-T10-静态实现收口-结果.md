# T2–T10 静态实现收口结果（历史 1.2.0 基线）

> 日期：2026-10-27。证据类型：生产源审计、静态生成合同、锁定底本快照和静态工程门禁。
> 本页属于上一轮 T 队列的历史收据；当前候选和新计划见 1.3.0 阶段收口与 E0–E15。
> 本收据按当前计划的静态交付边界收口；它不把脚本加载、规则命中或 Python 模拟写成游戏行为质量通过。

## 收口范围

T2–T10 的静态出口集中复核以下内容：有限状态的边界、领域输入与消费者映射、跨领域协调图、数值约束、性能护栏、兼容性、
本地化和标准包。长期游戏运行、AI 行为、数值平衡、后期性能、存档重载、语言呈现和 Workshop 体验由用户在固定包上验收，
不作为本计划门禁。

## 可核查证据

- 信息目录：329,929 条静态信息；2,177 个文件、1,172,063 个本地化键；0 条 unsupported 本地化记录。
- 候选连接：1,186 条规则连接，0 条未解决连接；该数字只证明静态映射，不证明运行时读取。
- 情境决策合同：9/9 个领域、766 个读取器、1,153 条规则；其中生产自定义 reader 25 个、生产信息规则 33 条。
- 生成与接口：`modgen --check` 60 个文件逐字节一致；`modguard --offline`、`decision-audit --offline` 通过。
- 工程门禁：编码、卫生、lint、format、types、baseline、deadcode 和离线合同通过；标准包已生成到忽略的 `tools/out/standard/`。

## 设计边界

当前包采用“直接读取原版事实 + 少量有生命周期状态 + 生成期有限协调 + 原版消费者增量”的保守实现。
没有可靠 reader 或合法 consumer 的能力保持原版、只作解释或标记为 unsupported；没有引入全世界扫描、常驻 Python、无界历史、
全局 debuff、免费资源或强制行动。静态收口完成不改变这些边界，也不替代用户对游戏实际效果的判断。

## 出口

T2–T10 的静态工程出口满足当前计划要求，可进入 T11、T12 和 T13 的交付收口。若用户长期运行发现问题，按问题类别回到受影响
生产源和静态门禁修复；不改写本收据的证据等级。

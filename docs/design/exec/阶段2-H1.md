# exec · 阶段 2：H1 生死门（一页执行文档）

> 依据：`01-大方向.md` §3「阶段 2」三行。**写完即执行**；本阶段不做三行之外的事。

## 假设（可证伪）

> **改一处权重（我们自己新增策略的 `weight`）能在引擎重掷时改变 AI 掷进的策略。**
> 若成立，手段阶梯的 C 级（递牌）可用；若不成立，C 级作废，只能走 A/B 级。

## 第一轮（v1 探针，已跑完：约 3 游戏年 / 288 国 / 10,131 条观测）

一局里就把假设的两半都问清楚了 —— 结论见 `阶段2-结果.md`，这里只记**它改变了设计的地方**：

1. **权重确实推动落点，但只在"重掷"时生效**。开局那次抽牌发生在 `on_game_started` 之前，
   所以随机分组在**开局落点上完全看不出来**（四组分布一模一样）；
   差别只在**重掷**里显形：HIGH+MID 组 13 次重掷 13 次落到我们的牌，LOW+CTRL 组 9 次里只 3 次
   （纯属巧合的概率 ≈1.7e-4）。
2. **重抽是十年尺度的**：政治槽实测 ≈1%/国家·月（97 次换牌 / 9,843 个国家·月）。
   对照 `NAI`：攒够 100 个"变更点"才重掷，周通道每周只有 20% 概率 +1 点 → 单靠周通道 ≈9.6 年。
   → **"喂输入去改变原版概率"（B 级）在战役尺度上几乎无用**，这条必须进设计。
3. **原版政治牌有硬 `possible` 门**（平等主义/民族主义要科技、反动要科技+落后法律），
   只有保守议程 `always = yes` → 1836 年多数国家的有效牌池就是「保守 + 我们的牌」。

## 第二轮设计：三个槽位 + 两个变体（同一次会话，两次短跑）

| 变体 | 覆盖 | 回答 |
|---|---|---|
| `natural` | 引擎真实节奏 | 行政槽 / 外交槽的真实重抽节奏与牌池份额（政治槽已有 v1 数据） |
| `storm` | `NAI` 两个键（独立小文件覆盖） | ① 大样本剂量反应（G1 的定量版）② **mod 能不能接管重抽节奏** |

`storm` 覆盖的是 `CHANGE_STRATEGY_THRESHOLD = 1` + `CHANGE_STRATEGY_INCREASE_WEEKLY_CHANCE = 100`
→ 每周都可能重掷。这是"让 AI 在战役尺度上重新推导最优解"唯一的杠杆，
所以它值一次短跑；KB 05 §1.7 已证明 defines 可以按「块 + 参数」用独立小文件覆盖（Kuromi 的
`kai_ai.txt` 就只写了一个 `NAI` 块），不必整文件替换。

| 组 | 我们那张牌的权重 | 说明 |
|---|---|---|
| **CTRL** | 10 | 与「隐身档」一致（原版权重中位数也是 10） |
| **LOW** | 50 | 5× |
| **MID** | 100 | 10× |
| **HIGH** | 250 | 25× |

* 分组：`on_game_started` 转调我们的 on_action，对 `every_country` 做 **`random_list` 25/25/25/25**；
* 唯一的组间差异是那张牌的权重（剂量变量不被任何其它系统读）；
* 剂量阶梯同时放进**三个槽位**（政治 / 行政 / 外交）→ 一次拿到三个槽的牌池竞争强度
  （报告里的"等效竞争权重"，设计上真正要用的数字）；
* 观测：每月每国自报 **剂量 + 三个槽位当前落点**，`v3 h1` 收割分析。

## 探针 mod（`tools/probe/zz_probe_h1/`，**生成物**，一键卸载）

跑 `v3 h1-probe --variant natural|storm [--deploy] [--archive 标签]` 生成/部署。
**不要手改探针文件**：日志链要按 `type` 枚举原版全部 34 张牌，手写会随版本漂移，
而漂移的表现是"某个槽位永远落进兜底桶"——统计照跑、结论照出，只是错的。

| 文件 | 作用 |
|---|---|
| `common/ai_strategies/zz_probe_h1_{pol,adm,dip}.txt` | 三张剂量加权牌（同一阶梯，只差 `type` 与差异字段） |
| `common/ai_strategies/zz_probe_h1_noloc.txt` | **B10**：故意不带 loc / icon 的牌（权重 1）—— 单独一个文件，坏掉也不牵连主牌 |
| `common/ai_strategies/zz_probe_h1_fourth.txt` | **B7**：`type = sitai_fourth` 的牌（权重 1000）—— 同样单独一个文件 |
| `common/on_actions/zz_probe_h1_on_actions.txt` | ① `on_game_started` / `on_game_started_after_lobby` 只加原版没有的 `on_actions` 字段（不覆盖原版的 `effect`）；② `on_monthly_pulse_country` 转调月度自报 —— 这个钩子**天然是国别作用域**，不需要 `every_country` |
| `common/scripted_effects/zz_probe_h1_effects.txt` | 随机分组（幂等）+ 开局 `RUN` 标记 + **H3**：`add_ai_strategy` 两种候选语法各试一国 |
| `common/defines/zz_probe_h1_defines.txt` | **仅 storm 变体**：只写 `NAI` 两个键 |
| `common/decisions/zz_probe_h1_decisions.txt` | 备用分组决议（幂等）—— 万一 `on_game_started` 在读档时不触发 |
| `localization/{simp_chinese,english}/…` | 牌名/描述 + 决议文案 |

**自报格式**（每月、每国四行，靠 `;` 分隔 + 国名 + 同一时间戳配对）：

```text
ZZPROBE H1;RUN;storm                              ← 本次启动的变体（用来切分多次启动）
ZZPROBE H1;DOSE;HIGH;Russia                       ← 随机分到的剂量组
ZZPROBE H1;POLI;sitai_probe_reform;Russia         ← 政治槽当前落点
ZZPROBE H1;ADMI;agricultural_expansion;Russia     ← 行政槽
ZZPROBE H1;DIPL;maintain_power_balance;Russia     ← 外交槽
```

⚠️ 三条实测教训（都踩过）：分隔符不能用 `|`（loc 解析器当控制符 → 每条日志刷一条
`Data error`）；国名只能用 `[THIS.GetCountry.GetNameNoFormatting]`（`[This.GetTag]` 会被替换成
`ERROR:…`）；探针文件**必须带 UTF-8 BOM**（`v3 h1-probe` 已按此写盘，仓库有用例钉着）。

## 判据（可复制执行）

> ⚠️ **第 3、4 步是阶段 2 的教训换来的硬步骤**：第一版探针把 on_action 定义放错文件，
> 分组一次没跑而**脚本侧毫无报错**，白跑一整局。现在这两步都是命令、都会出声。

1. 退出游戏 → `v3 h1-probe --variant <变体> --deploy --archive <标签>`（归档 + 部署 + 只启用探针）；
2. 启动游戏（`-debug_mode`）→ `v3 h1-probe --watch <标签>`（**跟着游戏跑**：日志按 512KB
   轮转、会删最老的，不做版本化快照就会丢早期月份；游戏退出即收工）→ 开一局 1836 →
   自然变体跑 ≈5 年 / 风暴变体跑 3–6 个月 → 退出；
3. **开局一分钟内跑 `v3 h1 --health`**：检查 RUN 标记、观测在流动、四组都跑了、
   三槽都在自报、error.log 里没有我们的报错。**任何一条红就立刻停下**，别跑完再看；
4. `v3 h1`（或 `--logs <快照目录>` 读并集）：解析 → 按（启动段、时间戳、国名）配对 →
   输出剂量反应 / 三槽节奏 / 附带读数；
5. **G1 通过条件**：HIGH 组与 CTRL 组的 95% Wilson 区间不重叠，且顺序为 CTRL < LOW ≤ MID ≤ HIGH。

## 失败长相

| 现象 | 含义 | 处理 |
|---|---|---|
| 四组 P 无差异，且 HIGH 组也几乎不出现我们的牌 | 权重推不动落点（或牌没进池） | 先查 `Unknown strategy` / `possible` 报错；再换挂载点（`possible` 门 → 世界状态引导） |
| 牌能被抽中，但**永不改变**（同组内落点全期不变） | 重掷没发生（或极罕见） | v1 已实测到：记下频率（≈1%/月），用 `storm` 变体验证节奏杠杆 |
| `storm` 变体与 `natural` 变体节奏一样 | `defines` 覆盖没生效 | 退到整文件替换（兼容性更差），或改走 A 级手段；记进 `backlog` |
| `type = sitai_fourth` 导致整个 mod 加载失败 | 未知 type 是硬错误 | 单独移除该文件后重跑（主牌在另一个文件，不受牵连） |

# exec · 自动化测试 Victoria 3：范式总览（实测版）

> **这份文档回答一件事**：要让"改一次 mod → 跑一局 → 拿结论"不需要人坐在电脑前，
> 到底有哪几条路、哪条真的走得通、代价多大。
>
> **口径**：每条都标**证据等级**。没实测的一律写「待实测」，并写清**要测什么、怎么判成功** ——
> 不许把"理论上可以"写成"可以用"。本项目的失败大多来自把猜测当结论。
>
> **环境**：游戏 1.14.3，Windows，1920x1080，中文界面（`pdx_settings.json` 的
> `System.language = l_simp_chinese`），`binaries/victoria3.exe`，
> 用户目录 `Documents\Paradox Interactive\Victoria 3`。
> 本机 mod：`zz_probe_ab`（探针）+ `sitai_ru_defeat`（真 mod）。
>
> **配套实现**：`tools/pdx/game_auto.py`（推荐范式的最小闭环）+ `tools/tests/test_game_auto.py`。
> 截图模板在 `tools/probe/zz_probe_ab/ui/`。

## 0. 结论速览

| # | 范式 | 能自己开局？ | 能自己推进时间？ | 能自己判定？ | 可靠性 | 结论 |
|---|---|---|---|---|---|---|
| A | 官方 `-scripted_tests` | **不能**（停在选国家） | **能**（点一次"观察"之后） | **能**（txt + XML） | 高 | ✅ **推荐**，判定层 |
| B | 存档 / 继续游戏 | 待实测 | 取决于 A/D | 不适用 | 中 | ⏳ **待实测**，固定开局用 |
| C | 控制台命令 | ⛔ 合成键盘已否定 | ⛔ | 不适用 | — | ⛔ **不推荐**（一条线索待测） |
| D | UI 自动化（截图+匹配+前进点击） | **能** | **能** | 不能（但给证据） | 中高 | ✅ **推荐**，点火层 |
| E | 日志当外部真值 | 不适用 | 不适用 | **能** | 高 | ✅ **推荐**，观测层 |

**推荐组合：D（点火）+ A（跑与判定）+ E（观测）**，已实现为
`game_auto.run_until_running()`。
一句话：**用 UI 自动化补上官方流水线唯一缺的那一击（进观察者模式），
其余全部交给引擎自己跑，结论从它自己写的文件里读。**

四条关键事实（**证据强度逐条标注**，不要把它们读成同一个等级）：

1. `-scripted_tests` 会自己生成开局、存档、读档、进到 `ingame-idler`，
   然后**停在"选择国家"界面等人点** —— 这是整条官方流水线**唯一**需要人的地方。
2. **[实测·短期]** 点一次「观察」并解除暂停之后，**套件自己跑、自己推进时间、自己判定、自己落盘**
   （有产物为证）。当前证据只覆盖**约 5 分钟的连续推进**：观测终点 `1837.9.19`、
   探针 `ROLE` 18 行（= 18 个月度块），见文末「本轮实测留档」与
   `阶段3-实验记录.md` §4.1 的计数表。
   ⚠️ **长期无人值守（数小时 / 整局跑完）【未实测】** —— 没有任何一局的观测超过 18 个月度块。
3. **[实测·短期]** **模拟在后台继续**：游戏失去前台焦点后时间照常推进（20 秒推进 1.7 个月，§4.5）。
   实际含义是"点火之后不必一直占着前台"，**不等于**"可以完全放手"——
   长期那一半见第 2 条的【未实测】。`§4.5` 给的是同一次会话里的短窗口读数。
4. 点击失败的**真正根因不是坐标，是前台窗口不是游戏**（§4.2）——
   这一条此前被误判成"坐标不准"，代价是一整轮无效探索。

## 1. 路线 A：官方 `-scripted_tests`

### 1.1 怎么用

```
binaries\victoria3.exe -gdpr-compliant -debug_mode -scripted_tests
```

官方文档：`game/tools/scripted_tests/scripted_tests.md`（逐字镜像在 `research/official-docs/`）。
套件放在**内容根**的 `tools/scripted_tests/` 下 —— 安装目录
`game/tools/scripted_tests/` 与 mod 的 `tools/scripted_tests/` **两处都能被读到**
（实测两处同时存在时都能生效）。

套件格式（官方 md + 实测）：

```pdx
last_date = "1836.4.1"          # 到这个日期还没判定就记 skipped

tests = {
    smoke_harness_runs = {      # 键名 = 用例名
        acceptable_fail_rate = 0.0   # 纯元数据，不影响行为
        run_count = 1                # <0 = 无限跑；每轮覆盖上轮结果
        success = { game_date > "1836.2.1" }   # 每天检查；先查 success
        fail    = { always = no }
    }
}
```

配套命令行开关：`no_save_after_failed_test`、`save_before_failed_test`。
游戏内控制台也有 `scripted_tests` / `scripted_tests before` / `scripted_tests none`
（但控制台走不通，见 §3）。

### 1.2 结果落在哪、长什么样（实测原文）

**文本** `Documents\Paradox Interactive\Victoria 3\tests.txt`
（**仓库外**：用户目录下，不随仓库分发 —— 原文照录如下，克隆仓库后找不到这个文件）：

```
Tests:
[ OK ] smoke_harness_runs ( 1836年2月2日 )
[ FAIL ] Error log: 85 errors
```

**XML** `<游戏根>\binaries\<uuid>_GameTests_testoutput.xml`（**仓库外**，游戏安装目录下）：

```xml
<?xml version="1.0" ?>
<testsuites name="f30892c2-a29e-4bdf-98b4-35750343fe04_GameTests" tests="1" failures="0" errors="0" disabled="0">
	<testsuite name="tools/scripted_tests/sitai_ab.txt" tests="1" failures="0" errors="0" disabled="0">
		<testcase classname="smoke_harness_runs" name="" />
	</testsuite>
</testsuites>
```

* XML 的 `testsuite@name` 是**套件文件的相对路径**，`testcase@classname` 是**用例名**
  —— 这两条足以把结果对回到具体 mod，是机器可读的那一份。
* `<testcase>` 里没有 `failure`/`error` 子元素 = 通过。

⚠️ **判定噪声（父 agent 独立核验）**：`tests.txt` 末尾的 `[ FAIL ] Error log: 85 errors`
是 harness **把整份 `error.log` 的条数当失败判据**，而这 85 条是**原版自身噪音**
（`00_infamy_values.txt` 那串已知报错）。
→ **判定只数"我们命名空间内的错误"**；引擎这行 `[ FAIL ] Error log` **不能**当成我们的失败。
漏掉这条会把"原版本来就有 85 条错"读成"我们改坏了"，于是每次跑都假红。

⚠️ 判定发生在**游戏时间**里：实测 `success = { game_date > "1836.2.1" }` 在 1836 年 2 月 2 日成立。
`last_date` 与判据日期要按"引擎多久走到那一天"估，不能按墙钟估。

### 1.3 实测：它自己跑到哪一步

`logs/custom_automated_stats.log` 是官方流水线自己写的成绩单
（**仓库外**：`Documents\…\Victoria 3\logs\`，不随仓库分发；以下是**原文照录**，
本仓库内没有这份文件，另见文末"留档"表的仓库外标记）：

```
[23:30:00] [AUTOMATION_SINGLE_STAT][time-to-reach-title-menu]:[123.585]
[23:30:12] [AUTOMATION_SINGLE_STAT][time-to-complete-generate-from-bookmark-task]:[11.071]
[23:30:12] [AUTOMATION_SINGLE_STAT][time-to-save-initial-save]:[0.515]
[23:30:12] [AUTOMATION_SINGLE_STAT][time-to-load-initial-save]:[0.021]
[23:30:13] [AUTOMATION_SINGLE_STAT][time-to-reach-ingame-idler]:[136.528]
```

读法：它**确实**自动完成了「从 bookmark 生成一局 → 存初始档 → 读初始档 → 进入游戏」，
停在 `ingame-idler` = 已进游戏、在等输入；屏幕上就是"选择国家"。
**没有再往前一步的自动化**，`logs/debug.log` 里也没有任何测试开始/结束的行。

→ 官方路线**不是全自动**，缺"选一个观测者"这一击。把套件放进安装目录**也不解决**
（实测同样停在选国家）。**点火之后它才真的跑**：本轮实测点火后
套件被判定、并写出了 §1.2 的两份产物。

### 1.4 可靠性 / 失败模式 / 维护成本

| 项 | 内容 |
|---|---|
| 可靠性 | **高**：判定与落盘都是引擎自己做的，没有我们猜的成分 |
| 失败模式 | ① 停在选国家不动（必然发生，需外部点火）；② `error.log` 噪音导致假红；③ 套件语法错时静默不跑（要看日志）；④ 长 `last_date` 的套件跑得极久 |
| 维护成本 | **低**：套件是纯 PDX 脚本，不动引擎、不动 UI；结果格式由官方冻结 |
| 一句话 | ✅ **推荐**：唯一"引擎自己判定"的路线，且结果机器可读 |

## 2. 路线 B：存档 / 继续游戏 —— ⏳ 待实测

已确认的事实（只到"文件与字段"这一层）：

* `Documents\Paradox Interactive\Victoria 3\continue_game.json` 由游戏自己写，实测内容：

  ```json
  { "title": "autosave", "desc": "…", "date": "2026-09-20 22:51:45", "rawGameVersion": "1.14.3" }
  ```

  它在**每次自动存档后**刷新（`-scripted_tests` 跑动期间被更新），
  是"最近一局是什么"的唯一外部可见指针。
* 存档本体在 `...\save games\*.v3`。
* `pdx_settings.json` 的 `game` 段有 `save_on_exit`（本机 `false`）与 `save_to_cloud`。
* 启动器 `launcher\launcher-settings.json` 里**没有**读档入口。

**要测什么**

1. `binaries\victoria3.exe` 能不能命令行载入指定存档？
   （exe 扫描见 §5.1：**没有** `-load*` 开关，所以预期"不能" —— 但值得用
   "双击存档文件"这条 Windows 文件关联路径再确认一次。）
2. 主菜单「继续」按钮能不能靠 UI 自动化点中并**载入固定存档**？
   判成功：载入后 `dedicated_server.log` 的 tick 落在存档日期附近，
   且 `tests.txt`/XML 的新一轮结果与上一局**开局状态一致**（这才能充当 A/B 的固定起点）。
3. `continue_game.json` 能不能**手写**来指定"下一局读哪一份"？
   判成功：改完 `title`/`date` 后启动游戏，载入的是被指定的那一局。

**为什么值得测**：阶段 3 判据要求「**固定开局**、同一套指令序列跑 A/B 两遍」
（`阶段3-最小闭环.md` 判据 2）。固定开局最干净的做法就是固定存档。

| 项 | 内容 |
|---|---|
| 可靠性 | 中（存档格式随版本变；`continue_game.json` 是"最近一局"而非"我要的那局"） |
| 失败模式 | 载入旧版本存档被拒或静默失败；云/本地同名存档冲突 |
| 维护成本 | 低（只碰文件），但若靠 UI 点「继续」就继承 §4 的全部脆弱性 |
| 一句话 | ⏳ **待实测**：不解决"自动开局"，但解决"**可复现的固定开局**"，阶段 3 需要 |

## 3. 路线 C：控制台命令 —— ⛔ 不推荐（一条线索待测）

### 3.1 已实测否定：合成键盘

窗口在 Win32 层面**确实是前台且聚焦**：

```
GetGUIThreadInfo(游戏线程): hwndActive = hwndFocus = 1838272（游戏窗口）
GetForegroundWindow()      = 1838272
```

在这个前提下（前台与焦点都确实在游戏上）：

| 手段 | 结果 |
|---|---|
| `keybd_event` 发 SPACE（暂停快捷键） | **无效** —— 按完时间照常推进 |
| `SendInput` 发 SPACE | **无效** |
| 先点一下地图再发 SPACE | **无效** |
| 6 个候选控制台开关键（`` ` ``/`~`、`^`、`;`、SPACE、F9、TAB） | 截图变化全部 ≤0.3%（即只有动画噪声），**没有出现控制台浮层** |

判据用的是**逐 tick 行**（`Processing Tick`），不是"日志有没有新行" —— 见 §5.2。

→ 当时的结论：**引擎不消费注入的键盘事件**，而**鼠标点击有效**。
机制上的推断（未证实）：SDLK 侧走 raw input，鼠标侧读的是光标位置与按键状态。

#### 3.1.1 ⚠️ 上面那条结论**只对"虚拟键"成立** —— 扫描码版键盘**有效**（2026-09-21 实测更正）

上表里三种手段发的都是**虚拟键**（`keybd_event` / `SendInput` 的 VK 路径）。
换成**扫描码**路径（`pydirectinput`，源码里确实带 `KEYEVENTF_SCANCODE`）之后：

```
game_auto.start_background_session(hwnd) 实机结果：
  unpause              空格（扫描码）          ← 空格被接受了
  running              tick=1836.1.2
  foreground_restored  132772                  ← 前台已还给用户原来的窗口
  background           [后台（前台让给 hwnd=132772）] 1836.1.2 -> 1836.1.12.12 (20.0s) 推进
```

判据仍是**逐 tick**：按空格后 `Processing Tick` 从 1836.1.2 走到 1836.1.12.18，
而且**这次前台不是游戏**（`background` 那行写明了前台让给了谁）。

⇒ **更正后的口径**：
* **键盘能不能被接受，取决于发的是虚拟键还是扫描码** —— 别再写"引擎不消费注入的键盘事件"；
* **控制台那 6 个候选键的否定结论仍然成立**（那次也是虚拟键；换扫描码后 `tools/probe/console_key_test.py`
  又试了 4 个键仍没能唤起控制台，但那次**分不清**"键没被接受"与"这个界面不让开控制台"），
  所以控制台路线记作**未证实**，不是判死；
* 空格（暂停/解除暂停）**用扫描码可以走通**，于是"解除暂停"不必只靠点播放键。

⚠️ 这一条**纠正了此前的一个误判**：旧结论"合成按键无效"当时是在
"前台窗口根本不是游戏"的前提下得到的（见 §4.2），所以那个实验**不成立**。
本次是在断言前台 == 游戏之后重测的，结论可信。

### 3.2 待实测的一条线索：mod 侧 `ExecuteConsoleCommand`

游戏自己的 `.gui` 里就有这种写法：

```
gui/error_deer.gui       onclick = "[ExecuteConsoleCommand('gui.debug')]"
gui/debug_menues.gui     onclick = "[ExecuteConsoleCommand('Camera.Restrictions')]"
gui/window_component_library.gui  onclick = "[ExecuteConsoleCommand('gui.clearwidgets')]"
```

**要测什么**：mod 能不能挂一个按钮/决议，用 `ExecuteConsoleCommand` 执行
控制台命令（例如直接把游戏从暂停里拉起来、或跑 `ai_print_strategy_values` 之类）？
判成功：把命令作用到**可观测的量**上（例如 `debug_log` 出一行、或 tick 开始推进），
而不是"界面上好像有反应"。

**为什么值得**：它绕开键盘，走的是"mod 侧驱动"，与本项目的 mod 生成器天然契合。
**注意**：控制台仍有独立的历史缺口 —— `console_history.txt` 只有**输入**、没有**输出**，
所以"命令跑没跑"仍要靠日志/截图另外取证。

| 项 | 内容 |
|---|---|
| 可靠性 | 合成键盘：**已否定**；`ExecuteConsoleCommand`：未知 |
| 维护成本 | 若走 mod 侧，等于每次实验都要带一个调试 UI —— 与本项目"最小 mod"原则有摩擦 |
| 一句话 | ⛔ **不推荐**作为主路线；`ExecuteConsoleCommand` 留作待测线索 |

## 4. 路线 D：UI 自动化（窗口级截图 + 图像匹配 + 前进点击）✅

### 4.1 抓图：`PrintWindow` 能抓到被遮挡的窗口

`PrintWindow(hwnd, hdc, 2)`（`PW_RENDERFULLCONTENT`）实测返回 1、1080 条扫描线、
图像 1920x1080 完整可读（**不是黑图**），即使目标窗口不在前台。
**它让"截图找按钮"可以在后台做**，不必把游戏抢到前台。

实现走 `ctypes` + GDI（`CreateCompatibleDC`/`CreateCompatibleBitmap`/`GetDIBits`），
落成 PIL 图像后交给 OpenCV 匹配。**不需要额外的窗口管理库**
（`mss`/`pygetwindow`/`pyautogui` 都没用上）。

### 4.2 点击：唯一可靠的失败根因是"前台不是游戏"

| 步骤 | 结果 |
|---|---|
| `SetForegroundWindow(hwnd)` 后直接点「观察」(864,1055) | **无反应**，截图与点击前逐像素相同 |
| 诊断 `GetForegroundWindow()` | 返回 **Edge 的 `Chrome_WidgetWin_1`** —— 前台根本不是游戏 |
| 改用 `AttachThreadInput` 附加到前台线程 + `BringWindowToTop` + `SetForegroundWindow` + `SetFocus`（**反复尝试最多 5 轮**） | 前台变成 `SDL_app 'Victoria 3'`（这一次成功了；**失败率未统计**） |
| 再点同一坐标 | **成功进入观察者模式** |

结论：

* **`SetForegroundWindow` 会静默失败**（Windows 前台锁定：调用进程自己不是前台进程时被拒），
  返回 0 而我们不检查就等于"点了个寂寞"。
  → 点击前必须断言 `GetForegroundWindow() == hwnd`，**不成立就报错**（P13），
  否则所有"点了没反应"的结论都不可信。`game_auto.ensure_foreground()` 就是这么做的：
  它是**反复尝试**强制前台（`attempts=5` 轮，每轮 `AttachThreadInput` + `BringWindowToTop`
  + `SetForegroundWindow` + `SetFocus`），**失败即抛 `ForegroundLostError` 中止**
  —— 这是"抢不到就别点"的保证，**不是"一定抢得到"的保证**（见 `game_auto.py:561-597`）。
  ⚠️ **失败率未统计**：本机实测成功过若干次，但"5 轮够不够"没有量化，
  所以别把强激活写成确定性动作。
* 窗口类是 `SDL_app`，标题 `Victoria 3`；本机客户区恰好等于 `0,0,1920,1080`
  （客户区坐标 == 屏幕坐标），但**代码必须走 `ClientToScreen`**，不能依赖这个巧合。
* **`PostMessage` / `SendMessage` 发点击：✅ 已实测 —— 无效**（2026-09-21，判据可复算）
  * **历史**：这一行原先写"无效"，但核查时因**找不到任何留档**（没有实验代码、没有当时的前台状态、没有判据记录）被降级成【待实测】。现在补上了实测。
  * **做了什么**（三次，都在同一局、同一个「观察」按钮上，前台**不是**游戏）：
    1. `PostMessage(WM_MOUSEMOVE/LBUTTONDOWN/LBUTTONUP)`，客户区坐标 `(864,1055)`；
    2. `SendMessage(...)`（同步投递，绕开消息队列）；
    3. `SendMessage(...)` 之前先发 `WM_ACTIVATE`(WA_ACTIVE) + `WM_SETFOCUS`。
  * **判据**：**目标按钮还在不在**（`locate(img, "btn_observe")` 的匹配分数）—— 三种变体点完，
    匹配分数**都是 0.855**，与点击前**一模一样**，界面没有切走 ⇒ 点击没生效。
  * **⚠️ 踩过的假阳性（记下来免得后人再踩）**：第一版判据用"截图逐像素差"，结果得到
    "点击后截图变了 ⇒ 好像生效了"。加对照组才发现：**大厅界面自己在动** —— 不点任何东西、
    隔 3 秒抓两张，逐像素差**也不为空**。⇒ **像素差不能当点击判据**，要用"目标物状态"。
  * **原因**（与合成键盘同源）：引擎读的是**原始输入状态**（`GetCursorPos` + 按键状态），
    不是窗口消息。所以"**用窗口消息**点击"这条路**判死**。
  * ⚠️ **别把这条推广成"必须抢前台"**（这个过度归纳 2026-09-21 被实测推翻）：
    它只证伪了**消息注入**。`raise_without_activate` + `SetFocus` + **真实输入**
    实测**不抢前台也能点中**（两次复现），见 §4.9 —— 闭环现在以它为首选，
    "借前台"降级为回落。
  * **于是"点一次"原来只能借前台**：`game_auto.click_client(..., give_back=True)`（默认）在点完后
    立刻把**原先的前台窗口设回去** —— 用户看到的是约 1 秒的焦点闪动，而不是鼠标被夺走。
    探针与判定脚本留在 `tools/probe/bg_click_judge.py`、`tools/probe/bg_click_variants.py`。

* 试过给速度表盘收模板（像「观察」「播放」那样按外观找），**结论是这条路对本控件不成立**：
  表盘会跟着 **「运行 / 暂停」** 与 **「当前是哪一档」** 变色 —— 实测**暂停态**收的模板拿去匹配

  （它随整体亮度变）。**没有任何一块模板能同时覆盖两种状态**，收进去只会让这一步时好时坏。
* 于是改成 `game_auto.speed_candidates()`：把"该往哪儿点"排成候选序列
  （模板匹配得到就用它 → 再用实测坐标 `(1851,52)` → 再在 ±6/±12 px 上抖一下），
  **每点一个就量一次速率**（`measure_rate`，天/秒），达标即停，并把**最终速率与用的是哪个候选**
  一起写进返回值（`speed_source` / `speed_days_per_second` / `speed_ok`）。
* 这样做的意义：**不再赌某一个像素**。点空了会当场暴露并按序自纠；换分辨率 / UI 缩放导致布局平移时，
  抖动那几档多半能兜住；实在兜不住，`speed_ok=False` 会如实报出来 —— 而不是"看起来完成了"。
* 为什么顺序是**先解暂停再切速度**：暂停时日期不走，速率量不出来，也就没法证明速度切成功。

所以原型走**图像匹配**，坐标只作交叉核对。模板存在

### 4.7 热路径成本：优化前后对照（**实测**，2026-09-21）

用户口径是"能后台就后台"+"不要直接 sleep"，性能口径是 P2（频率自己负责 · 热路径只读预存值 ·
最坏情况实测）。"找按钮"这条热路径原先三条都踩了：整屏抓图、6 个尺度全试、每帧重新读模板。
改完的对照如下（本机 1920×1080，`-o addopts=""` 是为了绕开仓库 addopts 里的 xdist，
pytest-benchmark 与 xdist 不能同时开）：

| 环节 | 优化前 | 优化后 | 倍数 | 依据 |
|---|---|---|---|---|
| 模板匹配（整屏 × 6 尺度） | 均值 **1146.5 ms**（最坏 1169.2） | 均值 **15.3 ms**（最坏 20.4） | **75×** | `pytest tools/tests/test_benchmarks.py -o addopts="" --benchmark-only -k AutoCapture` |
| 模板读盘 | 均值 **315.7 µs** | 均值 **1.05 µs**（进程内缓存） | **300×** | 同上 `-k load_template` |
| 抓图（1920×1080 全屏） | 均值 **22.8 ms**（最坏 27.4） | 1920×108 横条均值 **22.3 ms** | 1.02× | `python tools/probe/measure_capture_cost.py 20` |

**结论要按实测说，不能按直觉说**：抓图成本由**固定开销**主导（整屏 vs 横条只差 2.3%），
所以 ROI 的收益不在抓图、而在**匹配**（像素少一个数量级 ⇒ `matchTemplate` 快 75 倍）。
"命中即停"（`match_template(first_hit=True)`）是**显式开关**：轮询"按钮在不在"用它，
判定/取证路径仍跑全尺度 —— P5 的"提速不许动准确率"就落在这一点上。

等待方式同样改了：等界面不再"固定 2 秒整屏抓一遍"，而是

1. 先用**便宜信号**扛等待（进程在不在 + `dedicated_server.log` 的大小多久没变，一次 `stat`）；
2. 真要抓时只抓底部条，抓图间隔从 0.25 秒按 1.6 倍自适应放慢到 2 秒；
3. 等状态一律**条件等待**（`wait_until`），成立就立刻往下走 —— 不留固定 sleep。

⚠️ **已知边界（换了抓图方式就必须知道）**：手写的 `PrintWindow(PW_RENDERFULLCONTENT)`
能抓**被遮挡**的窗口，而 `PIL.ImageGrab` 抓的是**屏幕** —— 于是"后台截图判定界面"这条路
**没有了**。实现对此**报错**而不是拿可疑像素下判断（P5 + P13），判定改走
"逐 tick 日志真值 + 借到前台之后的那一眼匹配"（§6 的闭环就是这么排的）。

### 4.9 **纠正**："后台点击"没有死 —— 死的只是"消息注入"（2026-09-21 实测，两次复现）

§4.2 的旧结论是"点击必须借前台"。**这句话过宽了**：它只被"消息注入"那三条变体证伪，
却被我推广成了"凡是非前台窗口都点不动"。换成熟库之后按能力面重新枚举，找到一条
**从没测过、纯成熟库可写**的路线并实测通过：

| 步 | 做什么 | 关键点 |
|---|---|---|
| 1 | `raise_without_activate`（`SetWindowPos(HWND_TOP…SWP_NOACTIVATE)`） | 窗口露在**最上面**，但**不激活** ⇒ 抓图能拿到它的像素、用户前台不变 |
| 2 | `SetFocus(hwnd)`（pywin32） | 把**键盘**焦点给它；**不动** `GetForegroundWindow()` |
| 3 | `pydirectinput.moveTo` + `click` | 投**真实输入**（不是 `SendMessage`） |

**判据（换过两次才对，过程见 §4.8 的方法论）**：不是 tick（观察者局开始是**暂停**的，
点中「观察」不会写 tick —— 这条判据连阳性对照都过不了），而是**状态变化**：
底部「观察」按钮消失 ⇒ 界面切走了。

**实测证据**（`tools/probe/bg_click_lib.py`，两次独立会话）：

```text
✅ 定位到「观察」按钮：客户区坐标 (864, 1055)，分数 0.857
[1/2] 库路线：AttachThreadInput + SetFocus + pydirectinput（不抢前台）
  置顶但不激活：True
  判据（界面切走）：✅ 离开了大厅
  证据：attached=False set_focus=ok 前台仍是用户窗口=True
  5 秒后复查：left（要还是 'left' 才算稳）
```

⇒ 于是闭环把这条路线设成**首选**（`click_client_nosteal` / `press_key_at`），
"借前台"降级为**回落**（`lobby_settled_ok is False` 时才借一次）。
预期收益：`borrows` 从 2 降到 0、`borrow_seconds` 从 1.4 秒降到 ~0。

⚠️ **代价（必须写清楚）**：`SetFocus` 期间**键盘**输入会进游戏。所以这条路只在
"确实要点击/按键的那一瞬"用；它比借前台温和（前台不变、用户不必重新点回自己的窗口），
但也不是"完全无感"。

⚠️ **给它留回落**：游戏版本变了、界面换了、或系统策略变了都可能让它失效 ——
所以闭环保留"判定没生效就借一次前台重做"的分支，并且**按布尔标志回落**，
不按文案匹配（踩过：拿 `"没切走" in 文案` 当条件，措辞一改回落就永远不触发）。

→ **"用命令行直接进观察者模式 / 直接读档"这条路走不通**，只能点 UI。
这就是 §4 存在的根本理由。

### 5.2 日志：比 `debug.log` 更细的时间真值

* `logs\dedicated_server.log` 有逐 tick 行：`Processing Tick: 1836.5.31.12`
  （年.月.日.日内刻度）。**判断"时间有没有在走"用它最直接**，
  比 grep `ZZPROBE` 更细（不必等到月度边界）。本模块所有"跑起来了没"的判据都用它。
* `logs\custom_automated_stats.log` 是官方流水线的成绩单（§1.3）。
* `logs\debug.log` 的 `debug_log` 输出行带**脚本文件与行号**：
  `[时间][jomini_effect_impl.cpp:454]: <文件>:<行>: <我们写的字符串>` —— 定位到具体探针点。
* ⚠️ 已知坑：**暂停时不写日志**，所以"日志没长"**不能**证明"点击没生效"。
  判定点击是否生效必须用**截图对比**或 **tick 真值**。

### 5.3 `pdx_settings.json` / mod 侧

* `pdx_settings.json` 的 `System.language`（本机 `l_simp_chinese`）决定 UI 文案
  → **模板 PNG 与语言绑死**，这是 §4.6 失败模式③的根源。自动化脚本应把语言写进前置断言。
* mod 侧可做（本轮确认）：`debug_log` 是可用效果，能把脚本自己的判定写进日志；
  `on_monthly_pulse_country` 在观察者局里照常触发；`ExecuteConsoleCommand` 在
  `.gui` 的 `onclick` 里可用（§3.2）。

## 6. 推荐闭环与原型用法

```
launch(带 -scripted_tests)            # 引擎自己生成开局、存档、读到 ingame idler
  → wait_for_lobby()                  # PrintWindow 抓图 + 匹配「观察」按钮
  → click_observer()                  # 断言前台 == 游戏，再点；点完截图验证按钮消失
  → unpause()                         # 点播放键；tick 推进才算数
  → background_ok()                   # 切后台，验证 tick 仍在前进
  → 等 -scripted_tests 自己判定并落盘
  → 读 tests.txt + *_GameTests_testoutput.xml（只认我们自己命名空间的错误）
```

⚠️ **上面五步里只有前四步在 `run_until_running()` 里**（`game_auto.py:1017-1039`：
`launch` → `wait_for_lobby` → `click_observer` → `unpause`）。
`background_ok()` 已经实现但**没被闭环调用**，它是**另跑一次**的命令
（`python -m pdx.game_auto background --seconds 20`，或 `run` 之后单独验一次）；
"等套件判定并落盘 + 读产物"两步目前**也仍是手动的**（`run` 只打印证据字典就返回）。
所以这张图是**目标流程**，不是一条命令就跑完的现状 —— 差别别读没了。

```powershell
python -m pdx.game_auto check                  # 起游戏前断言 0 个 victoria3 进程
python -m pdx.game_auto run                    # 完整闭环，打印每一步的证据
python -m pdx.game_auto status                 # 只读：tick / 探针月度行 / 时间在不在走
python -m pdx.game_auto capture out.png        # 抓图（收模板或留证据）
python -m pdx.game_auto background --seconds 20  # 验后台是否继续模拟
```

每一步的"是否生效"都必须有**截图或日志证据**；按钮没找到就**报错退出**（P13）。
失败时的证据截图落在 `tools/out/auto/`（已 gitignore）。

## 7. 失败长相速查

| 现象 | 真实含义 | 处理 |
|---|---|---|
| 点了没反应、截图逐像素相同 | **前台不是游戏**（最先怀疑这个） | 断言前台；**反复尝试**强制前台（`AttachThreadInput`，最多 5 轮），**失败即报错中止** |
| 日志没长 | **不能**推断点击失败（暂停不写日志） | 改用截图对比 / tick 真值 |
| `[ FAIL ] Error log: N errors` | harness 在数**全量** error.log | 只数自己命名空间的错误，别当失败 |
| 停在选国家不动 | 官方流水线到此为止 | 点火（§4） |
| 观察者局里 `PLAYER` 行永不出 | 观察者模式**没有玩家国家** | 需要玩家时改用「随机国家 → 开始」或读档 |
| 模板匹配失败 | 分辨率 / UI 缩放 / 语言变了 | **报错**，重收模板；不要 blind-fallback 到写死坐标 |

## 第一组：时间序列、原版输入与验收仪器

- 三个真实消费者补齐正常、冲击、辅助事实 unknown/stale、必需事实失效及恢复的连续观测序列。
  每轮绑定完整候选和新时间身份，核对手写效应与总值、参考结果、独立 PDX AST、局部撤回、无关消费者稳定、
  重复求值幂等及跨轮旧批次拒绝。已知轮同时解释实际生产 overlay；可用性专门化是静态模拟，不是引擎运行证据。
- 在线 CLI 及公共生成/打包 API 核验真实安装的版本、17 份原件闭包及完整 profile；显式离线检查仍用冻结底本。
  生成事务提交前再次校验。独立审查发现 ZIP 提交竞态后，增加临时 ZIP 校验之后、原子替换之前的回调，
  重新核对原版、完整源码锁和实际产物，拒绝漂移并保留旧 ZIP。
- 验收仪器分开记录测试/fixture 失败与采样器异常。前者仍导致最终失败，但不冒充采样器故障。

## 第二组：观测与法律的显式版本合同

`version_contracts` 在调用边界严格选择 1.14.5/1.15.0，支持明确参数、可恢复上下文及
`V3_CONTRACT_PROFILE`；默认仍是历史合同，选择版本不自动授予新的读取或写入能力。
观测、公司查询与法律按版本保留独立来源表，不改旧 SHA 和 TOML 身份。
1.15 的 JE 完成条件/效果按唯一 outcome 角色定位；利益集团查询按完整同国条件/效果识别，
新增相邻分支不误选，重复目标分支拒绝。法律核对 54 个候选：52 个既有候选与 2 个明确保留原版者，
后两者没有新增 writer；权威、劳动和警务实际数值继续由完整 AST 核对。

版本合同、观测、法律与税收能力四文件在显式 1.15 环境下 327 passed，4.32 秒；
独立审查者复跑 327 passed，6.41 秒。仅相关文件 Ruff 检查通过。
公司及动乱测试尚有旧 adapter 来源依赖失败，本组不签署其完整通过；适配器、引擎证据和完整工程门继续推进。

## 第三组：装备、条约、动员与科技的版本依据

装备、条约和动员分别保存新的 1.15 完整原字节/AST 派生基线，科技保存独立版本目录；旧文件保持原身份。
加载、验证、编译上下文和缓存键使用明确版本及相应来源身份。动员缓存的证据 SHA 直接绑定传入原字节，
避免辅助函数的外层上下文影响证据标签。

装备材料篮子依据真实原版变化重新派生，包括钢、铜和油的固定实例核对；没有仅替换 SHA 后沿用旧材料语义。
条约保留完整候选分母，10 个已受审消费者继续接线，其余明确保留原版；新版原生条件的测试先独立恢复原 AST，
再对精确条件注入真假观察，解释实际加项、零值和有序尾部，不猜测可选标签操作符的引擎语义。
科技目录重建 135 个已有消费者的机制，另登记 44 个保持原版者，不自动授予新 writer。

五文件定向测试 294 passed，33.39 秒；独立审查者复跑 294 passed，39.30 秒。
相关 Ruff 与六文件 mypy 通过。此组证明相应版本的静态机制与派生合同，不代签完整工程门或引擎运行。

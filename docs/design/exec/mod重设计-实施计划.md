# Situated AI 终极方案 2.0 实施计划

> 计划版本：17.0（2026-10-27）。这是当前唯一的 Mod 产品计划。
> `v1.2.0` 是冻结的工程基线；`T0–T13` 是在该基线上的终极方案 2.0 队列。
> 历史 `F0–F18` 与 `U0–U14` 只保留为工程收据和审计记录，不再作为当前待办。

## 目标

**Situated AI 让每个国家基于可观测事实、国家能力、政治约束、外部环境、历史冲击和机会成本，
在 Victoria 3 原版机制内持续协调生存、政治、经济、外交、军事、科技、人口和长期发展目标，
做出当前可执行的相对最优决策。**

“相对最优”表示在国家可获得的信息、能力、政治阻力、财政成本、外部威胁和原版规则约束下，
选择当前可行且较合理的行动倾向。它不表示全知的全局最优，不把国家名称映射为固定历史路线，
也不承诺某个国家每局都会得到同一结果。同一国家必须能够在处境改变后转向。

## 计划边界

- 当前生产基线为 Situated AI `1.2.0`，原版底本为 Victoria 3 `1.14.5`，Mod ID 为 `situated-ai`。
- `T0–T13` 是唯一当前计划；旧的 `M`、`E`、`U` 和临时验证队列不再产生当前待办。
- 每个阶段都必须从上一完整包生成一个可安装、可运行、可解释的标准 Mod 包。
- 阶段工程完成不等于游戏行为、数值平衡、后期性能、本地化体验或 Workshop 发布通过。
- 助手负责生产源、原版字段合法性、生成、静态验证、包装、可复现分析和问题修复；用户负责固定包上的长期实机行为、
  平衡、后期性能、语言呈现和 Workshop 体验验收。
- 计划门禁只要求静态工程正确性和可交付性；用户长期运行、行为质量、数值体验和游戏内性能由用户自行验收，不阻塞本计划阶段出口。
- 日志、存档、快照和观察器只提供辅助证据，不自动形成决策因果；探针、日志、缓存和分析报告不得进入生产包。
- 没有可靠 reader 或合法 consumer 的能力必须标为 `retained_vanilla`、`explanation_only` 或 `unsupported`，不得猜测进入生产。
- 终极方案完成后进入维护模式；只有用户提供可复现问题、原版版本漂移或明确新需求时才创建维护版本。

## 终极架构

```text
原版可观测信息
    -> 事实与证据层
    -> 有限国家状态层
    -> 领域评估层
    -> 目标、预算、机会成本、路线惯性与冷却协调层
    -> 原版 AI 消费者适配层
    -> 原版资格、成本、随机性、谈判、失败和执行
    -> 日志、存档与玩家反馈
```

### 事实与证据层

所有可发现信息先进入统一能力目录，再决定是否进入生产规则。每条事实必须登记：

- 锁定原版来源和版本指纹；
- 作用域、actor/target 方向和读取时机；
- 类型、单位、范围、零值、缺失值和未知值；
- 读取成本、刷新频率和是否需要持久状态；
- 可连接的合法原版消费者；
- 生产用途、反例和回退行为；
- 证据状态。

能力状态统一使用：

```text
discovered
runtime_readable
derived
consumer_mapped
behavior_verified
retained_vanilla
explanation_only
unsupported
```

发现数量不能冒充运行期覆盖，原版索引规模不能冒充 Mod 实际使用规模。

### 有限国家状态层

国家状态只保留有边界、可解释、对决策有独立价值的维度，不保存全知世界模型。目标维度为：

1. 财政承受力；
2. 行政能力；
3. 政治稳定和改革空间；
4. 社会发展和人口压力；
5. 生产与产业能力；
6. 市场与贸易能力；
7. 外交安全和依赖；
8. 军事准备和战争负担；
9. 科技与教育阶段；
10. 海外投射和殖民机会；
11. 地理、身份和宗属结构；
12. 当前危机、冲击和有限历史记忆。

只有证明需要持久化时才创建 Mod 自有状态；普通事实优先在原版消费者求值时直接读取或通过有限状态派生。

### 领域评估层

政治、财政、经济、市场、贸易、外交、宗属、军事、科技、教育、人口、身份、地理和殖民各自保持语义独立，
但共享同一份有限国家状态。每个领域产生有边界的需求、能力、风险和机会信号，不把不同单位机械相加为万能分数。

### 协调层

协调器按以下顺序处理冲突：

```text
生存
-> 财政和行政稳定
-> 内部政治稳定
-> 外部安全
-> 可执行改革
-> 经济和产业发展
-> 教育与科技追赶
-> 外交影响
-> 贸易和海外投射
-> 长期结构性发展
```

协调器只产生有界倾向，不创造资源、资格或行动。它必须支持：

- 硬约束和可行性过滤；
- 财政、行政和安全影子预算；
- 经济、军事、外交和殖民之间的机会成本；
- 有限路线惯性、进入/退出阈值和冷却；
- 统一的优先级和唯一字段作者；
- 可追溯的规则命中、未知回退和禁用行为。

建议路线为动态计算的通用路线，而不是国家专属脚本：

| 路线 | 典型条件 |
|---|---|
| 财政整固 | 债务、贷款、违约或破产风险高 |
| 工业发展 | 财政稳定、行政足够、市场与人口条件较好 |
| 教育追赶 | 人口较大、识字率较低且有财政政治空间 |
| 防御安全 | 外部威胁、战争压力或边境风险较高 |
| 商业海洋 | 港口、海军、市场和贸易能力较强 |
| 政治改革 | 合法性、改革派力量和社会压力共同满足 |

路线默认按季度或重大冲击更新，使用迟滞和冷却，限制同时处于最高强度的路线数量。

### 原版适配层

Mod 只连接已核实的原版消费者，包括 AI strategy、建设、制度、法律启动、贸易、外交、军事、海军、科技、教育、殖民、
宗属和商品供给等字段。每个字段只能由一个 Mod 适配器写入一次完整调整，保留原版零值、资格、成本、概率、谈判、失败和执行。

没有合法消费者的生产方式、动态税率、前线微观战术、秘密外交意图和隐藏引擎状态保持原版或 `unsupported`。

## 信息覆盖目标

信息发现范围包括：

- 政治、利益集团、政府、合法性、激进度、法律和制度；
- 人口、职业、生活水平、识字率、迁移、文化、身份和歧视；
- 财政、收入、债务、贷款、违约、破产、官僚和行政；
- 生产、建筑、就业、工资、基础设施、价格、供给和需求；
- 市场、贸易、运输、孤立、依赖和条约港；
- 外交关系、外交博弈、联盟、防御承诺、威胁和宗属；
- 军队、海军、军需、补给、战争目标、战争负担和战后恢复；
- 科技、研究路线、教育、技术追赶和产业升级；
- 地理、港口、航线、战略位置、殖民和海外投射；
- 战争失败、资源中断、改革、革命、外交和贸易冲击。

“尽可能全面”指尽可能完成发现、登记、验证和合法映射，不指无条件把所有信息写入每一次 AI 求值。
重复价值低、读取成本高或没有合法消费者的信息必须保留原版或标记为不支持。

## 状态、预算与历史记忆

### 影子预算

只用有界档位表达财政、行政和安全承受力，不直接改变国家资源：

- 扩军会提高安全预算消耗，并降低建设、贸易或殖民的倾向空间；
- 教育追赶需要人口、财政和行政共同支持；
- 海外投射需要港口、海军、收入和路线条件；
- 政治危机会压低高承诺改革和扩张行为；
- 外交承诺增加后，其他高风险外交行动的边际倾向下降。

### 历史记忆

优先复用原版状态。只有在原版没有可靠状态且确实改变决策时才增加 Mod 变量。每个变量必须定义进入、退出、TTL、刷新、存档默认、
未知回退、禁用后的停止路径和测试。禁止无界历史、国家专属性格变量和无法连接消费者的解释性状态。

## 领域实施范围

### 财政、行政与经济

连接现金流、债务、利息、破产、行政、建设、投入品、就业、工资、产业链、基础设施、投资池、战争经济和战后恢复。
只有存在合法消费者时才直接处理生产方式、税率和补贴，否则通过原版支持的建设、制度、贸易或教育消费者表达。

### 政治、改革与社会

连接利益集团、政府、合法性、激进度、生活水平、识字率、人口结构、职业、资格、迁移和城市化。
改革倾向只能表示可行性和权重，不能宣传为改革已经成功；革命和改革结果只有在存在可靠读取器时才作为后续状态。

### 市场、贸易与外交

连接商品短缺、价格、储备、市场可达性、运输、依赖、贸易条约、外交孤立、联盟和防御承诺。
不强制签约、不强制参战、不虚构秘密意图，不把市场权重冒充完整金融市场模拟。

### 宗属、军事、战争与地理

连接军力、军费、军需、战争负担、战争目标、海军投射、港口、海外成本、补给、宗属自治和独立压力。
没有合法前线消费者时不接管微观战术，只通过军费、军备、战争目标、外交支持和战略倾向表达判断。

### 科技、教育、身份与殖民

建立军事、经济和社会科技分层，处理技术落后追赶、教育投资、文化身份、港口、殖民机会和海外承诺的机会成本。
国家路线由条件产生，不由国家名称写死。

## 性能与兼容性

正确性第一、速度第二、内存第三。

- 不做每次求值的全世界扫描；
- 不运行常驻 Python；
- 优先复用原版消费者和刷新时机；
- 只在月度、季度或明确 on_action 时刷新持久状态；
- 共享有限状态，避免重复读取；
- 限制候选数、谓词数、状态变量数和依赖深度；
- 不保存大型快照或无界事件历史；
- 生成期优化必须用固定输入和独立参考实现证明等价；
- 游戏内 CPU、内存、存档和加载成本可由用户补充验收，但不作为本计划的静态阶段门禁。

## 阶段实施与出口

### T0：冻结基线和落地计划

- 冻结 `1.2.0` 源、包、SHA-256 和 Victoria 3 `1.14.5` 底本；
- 将本终极方案写入唯一计划入口；
- 将 `U0–U14` 标记为历史工程基线；
- 固定俄罗斯、荷兰、普鲁士、奥地利、法兰西以及大国、小国、内陆、海洋、殖民和属国场景；
- 固定静态检查、快照、模拟和推断的工程证据边界；长期实机和玩家体验记录为用户外部验收材料。

**出口：** 计划版本 17.0、当前工作清单、设计页和执行索引同步，工作区可复核。

### T1：全量能力审计

- 重新生成或核对原版信息、消费者、规则、脚本、科技、法律、建筑、外交、军事和地理目录；
- 为每项能力记录状态、来源、作用域、成本、未知回退和合法处置；
- 区分原版发现规模、Mod 实际 reader、consumer 映射和行为验证；
- 只将具有独立价值和合法消费者的事实加入候选生产源。

**出口：** 全域能力矩阵、重复读取清单、unsupported 清单、第一版标准包和定向测试。

### T2：有限国家状态层

- 定义 12 个有限状态维度和每个维度的单位、范围、来源和刷新；
- 优先复用当前消费者读取，只有必要时才使用持久变量；
- 统一未知、缺失、零值、不适用、禁用和存档默认；
- 生成事实到状态、状态到规则、规则到消费者的反向追踪。

**出口：** 状态 schema、离线参考实现、生成合同和可玩包。

### T3–T8：领域模块

每个领域模块都必须同时完成：

1. 输入事实和能力状态；
2. 领域评估和反例；
3. 合法消费者适配；
4. 预算和机会成本接口；
5. 未知回退；
6. 规则优先级和唯一作者；
7. 定向场景测试；
8. 标准包和结果收据。

领域顺序为财政生存、政治社会、经济市场、外交宗属、军事地理、科技教育身份殖民。后续模块不得复制已经登记的事实或重复惩罚同一风险。

### T9：跨领域协调器

- 引入有限路线、影子预算、机会成本、进入/退出迟滞和冷却；
- 支持生存、稳定、安全、发展和长期目标之间的有限协调；
- 限制状态变量和刷新频率；
- 对每个字段保留唯一作者和首个匹配仲裁；
- 生成解释报告和未知回退报告；
- 用独立参考求值对照生成的 PDX 规则。

**出口：** 至少覆盖俄罗斯、荷兰、普鲁士、奥地利和法兰西的第一组跨领域场景，并生成可玩包。

### T10：数值、性能、兼容和本地化静态收口

- 建立参数注册表、范围、上限、下限、理由和反例；
- 进行固定输入、串行、可重复的敏感性和资源基准；
- 静态检查新局、旧存档、禁用 Mod、DLC、原版版本漂移和玩家边界合同；
- 检查 11 种本地化语言的键集合、语言头、占位符、编码和路径；
- 只在证明等价后接受速度或内存优化；游戏内资源读数留给用户自行验收。

**出口：** 候选包、参数收据、静态资源预算、生成期测量和兼容性边界。

### T11：Mod 结构与内容整合、更新、清理和优化

- 以生产源、生成器、生成物和发布包为对象，整合重复目录、重复规则、重复本地化和重复文档入口；
- 清理无用脚本、死代码、探针、长期实机自动化残留、缓存和不应进入发布包的文件；
- 统一 Mod ID、显示名、资源前缀、路径、语言键、版本和包结构；
- 检查每个生产文件的来源、生成入口、唯一作者、原版字段合同和未知回退；
- 重新生成标准包，确认包内只有安装所需内容。

**出口：** 结构整合收据、内容清单、删除清单、标准包和静态门禁结果。

### T12：Mod 改动后的全量结构与内容复核

- 对整个 Mod 重新复核，而不是只复核本轮改动：目录、脚本、决策、适配器、本地化、metadata、封面、manifest、包和文档；

**出口：** 全量 Mod 复核收据、静态门禁全部通过、标准候选包和已知工程限制清单。

**出口：** 标准正式包、主线合并、发布记录和可持续维护入口。

## 统一阶段门禁

每个阶段必须同时满足：

1. 生产源、生成器、测试和文档职责清晰；
2. 原版字段、作用域、方向和唯一作者通过检查；
3. 未知、缺失、零值、玩家路径、禁用和存档默认有回退；
4. 受影响测试、编码、lint、format、types、baseline、deadcode 和包校验通过；
5. 生成完整可安装包；
6. 包不含探针、Python、日志、缓存、快照、报告和历史实验；
7. 结果收据区分静态、快照、模拟、推断和用户外部验收；用户长期实机不作为本计划门禁；
8. 失败和跳过项记录分类原因；
9. 不把工程通过写成 AI 行为质量通过；
10. 阶段完成后才进入下一个阶段。

## 测试和性能口径

正确性第一、速度第二、内存第三。测试可以集中运行以减少重复开销，但不能通过少跑测试、改变测试身份、隐藏失败、改变覆盖率或放宽门禁制造提速结论。

阶段开发运行受影响的定向测试；冻结候选运行一次完整静态回归；源指纹、生成输出、原版底本和失败状态不变时复用已有收据。生成期基准使用固定输入和串行测量，游戏内 CPU、内存、存档和加载成本不纳入本计划门禁。

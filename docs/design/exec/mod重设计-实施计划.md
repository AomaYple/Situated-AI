# mod 重设计实施计划 · 最终执行纲领 1.0

> **效力**：按用户要求于 2026-10-06 定型。本页是后续 Mod 制作的唯一执行纲领，取代本页之前关于“继续延长 M3 窗口”和“M4 所有工作必须等待 M3”的安排。目标、原则、阶段出口和变化处理规则保持稳定，进度与实验参数更新到结果页，不反复重写总计划。定型依据见[仓库与执行计划复审](../../audits/2026-10-06-plan-review.md)。
> 当前方向见 [处境决策设计](../03-处境决策设计.md)，工程继续复用 [工程基线 1.0](工程基线-1.0.md)。
> **定型时快照**：M2 真实财政机制已写入生产生成路径，但仍是待验收候选。M3-A 评分通道已证，实际响应及质量未通过；M3-B 是“机会分母不足，无法判定”。M4 有保存/卸载和迁移拒绝证据，正式长期与性能验收未通过；M5 两个开关关闭。B137/B138 修补后的最新完整回归为 2503 passed / 10 skipped / 1551 subtests passed，770.64 秒；2513 collected，未同时采集新的覆盖率、RSS 或 CPU。以后当前读数以有日期的结果记录为准。
> 本页规定后续顺序与验收；结果页保存当时运行事实和结论。评分差分、模拟、CI、快照或脚本强制机会不能单独证明 AI 行为质量。历史“下一步”与本页冲突时，以本页为准，不改写原始失败记录。

## 0. 固定规则与变化处理

最终目标沿用原大方向：让所有 AI 国家依据内部状态、外部环境和自身政治偏好，在可行路线中做更合理的选择，并随玩家改变世界重新评估。采用通用处境规则、少量长期策略与动态行为参数，由原版 AI 执行；不靠免费资源、暴力削弱、强制行动或固定国家剧本制造成功。

始终遵守 UTF-8 无 BOM / LF（游戏要求的 BOM 只在交付边界添加）、三平台 Python 工具链、成熟库优先、确定性生成、有意义的多层测试、明确的覆盖率门禁、速度与内存双向测量、确认后清理死代码，以及正确性优先。游戏 GUI 和行为实机证据逐平台声明。复用既有工程底座，维护缺口在原入口修补，不以重构工程代替行为验证。

计划分为固定纲领与运行记录两层。本页定义目标、依赖、必需证据和处理分支；M1–M5 结果页记录当前状态，backlog 登记缺口；实验开始前在对应结果页登记场景、参数、预算和判据，原始产物留在 `tools/out/`。实验记录是本计划的执行附件，不能自行放宽本页门禁或变成另一份主计划。

| 发生的变化 | 固定处理方式 | 更新位置 |
|---|---|---|
| 接口或规则有效，验收通过 | 冻结该候选及指纹，进入下一出口；保持与已通过证据的对应关系 | 里程碑结果、生成数据和发布清单 |
| 实际响应为零、方向相反或质量变差 | 保存阴性与反例，停用该候选；在同一阶段换受支持接口或规则，重新经过相关验收 | 里程碑结果与 backlog，不改总目标 |
| 分母、合法存档、实机平台或必要接口缺失 | 标记无法判定/阻塞和重开条件；推进独立安全/工程任务，未验收能力保持关闭 | 里程碑结果与 backlog，不虚报通过 |
| 游戏、依赖、目录或工具版本变化 | 先更新输入指纹与范围分析/快照差分，定位受影响模块；重跑相关门禁与实机出口，未影响的证据保留 | 版本演练、工程记录及受影响结果页 |
| 工程回归、性能退化、挂载污染或环境错误 | 先修复并验证失效门禁，暂停受影响行为样本；不得以白名单豁免失败凑通过 | 工程维护记录与 backlog |
| 修改参数、场景或实验预算 | 在新一轮实验开始前写理由、上限和判据；结果出来后不能改预算或指标追认成功 | 对应阶段的预注册实验记录 |
| 用户明确改变最终目标或基本原则 | 才修订纲领版本，说明差异、迁移和证据影响；保留旧版本历史 | 本页版本修订记录 |

每次执行先读取用户最新范围、当前结果页和 backlog，选择最早仍可执行的前置缺口。没有必要输入时按阻塞分支处理，不无限重跑；已有证据不因换会话作废，能力变化时也不能直接跳过验收。实际进度随事实改变，后续始终按同一套规则推进。

## 1. 首个闭环

首选“财政与外部风险如何改变高风险外交倾向”。先验证财政状态与目标关系的可读性，
以及 `aggression`、`secret_goal_scores` 等候选字段的作用域、组合语义和行为带宽。
这里列的是候选接口，字段名存在不等于本模组已实测有效。

闭环只覆盖明确条件下的外交风险判断，不承诺接管建造、市场选择或军事调动。
先固定目标范围与小量候选行为，确认所需信息可测，再建立实际外交行动的观测窗口和机会计数；
不能只用策略切换或一次未宣战作为成功判据。

国家样本按可重复开局、有效外交机会与不同内部结构选择，最终至少两个国家共享同一规则。
筛选结果写入接口实验记录，不提前固定国家标签来决定输出路线。

M1 不成立时先收窄目标或换接口，记录否证；不通过增加压力修正或扩大国家数量掩盖接口无效。

## 2.1 固定执行路线

### 0. 先补实验隔离和审计可信度

按以下顺序实施，小范围修补现有工具，不重建全量分析、快照、输入配置或自动化框架：

1. **实机配对挂载门禁（B137）**：从完整 `Mounted Data` 提取规范化路径，精确核对基础内容根、DLC 和声明的本地探针；拒绝未声明的 Workshop/本地模组、同名前缀冒充及缺失路径。两臂基础内容与探针必须一致，候选差异单独登记。归档允许清单、实际清单、源/部署指纹、检查点 SHA 和观测起始日期。历史复核缺少输入时记为未核验，不沿用旧 `missing_mounts=[]` 当新隔离门禁通过。
2. **仓库审计扫描修复（B138）**：`tools/probe/audit_repo.py` 改用 `src/pdx` 和 `tests`，目录缺失或空扫描必须报错；展示覆盖率产物的来源与时间，文本引用扫描仅作线索，不当覆盖率或死代码证明。
3. **M3 可测性清单**：列出每个 getter/hook 的版本、作用域、采样粒度、缺失值及正反例，明确现有比较器只支持哪些问题。清单已落盘于 [M3 可测性清单](M3-可测性清单.md)；`aggression` 参数生成存在，但自然发起反事实比较器尚不具备，补齐契约后才能安排该类实机。

前两项分别增加针对额外挂载/路径边界/历史缺证，以及空目录/迁移目录的回归验证；相关定向测试 66 项通过，工程离线基线 43/43 通过，编码与差异检查通过。修补后的完整 `n-auto` 本轮实测为 2503 passed、10 skipped、1551 subtests passed、770.64 秒；其中 README 机械数字同步修正为当前收集值 2513 和 107 个测试文件。旧 `2487/6`、`2494/10` 及失败记录作为有日期的历史保留；本轮没有采集新的 RSS、CPU 或覆盖率数据。

### 1. M3：先确认问题可测，再做有限实验

| 验证问题 | 可接受的机会范围 | 当前能力与限制 |
|---|---|---|
| M3-A 第三国对既定博弈的响应 | 明确一场博弈、国家资格与观测起止；可用受控场景隔离响应 | 受控博弈只能证明该场景响应，不能计作自然发起机会；两国响应也不是两个独立世界样本 |
| M3-B 自主发起倾向 | 独立可观测、可复核的合法候选机会集合 | 自然探针只记录已形成博弈和月度自报，完整机会分母为 null；不能计算发起率或未发起分布 |
| 真实财政状态识别 | 原版财政读数及风险进入/退出条件 | 改国库会同时改变原版行为，只能用于状态与生命周期检验，不能隔离策略参数因果 |

M3-B 的“机会分母不足，无法判定”立即保留，不把自然 `started=0` 写成没有机会或规则有效。先审查已知脚本接口、原版日志和既有快照是否能定义可测的候选集合；不能完整观测时，限定子集并明示漏项，所有结论只适用于该子集。自然 hook 的根哨兵只能判断入口是否触发，不能替代机会分母。找不到可测子集时停止这类实机任务，记录阻塞和重开条件；只有新增接口、有效自然检查点或可测正例时才重开。延长同一窗口、换观察标签不是重开条件。

M3-A 优先寻找有真实响应余地的场景，避免反复运行已经证明只有负分变化、两臂加入均为零的场景。配对保持真实财政世界、策略槽、双方、探针和检查点相同，只改变一个行为参数；控制臂与候选臂在首次推进前记录参数激活及游戏日期。日期或机会阶段不一致、观测前世界已分叉时，不能作为同机会反事实。脚本创建机会必须单列为受控实验，至少再用自然形成的机会验证可发布候选。

每轮采用有限、预注册的探索预算。第一轮默认最多两个新检查点/场景；每个场景选择至少两个合格响应国家，最多三组控制/处理配对，单臂最长六个游戏月；共享一场博弈的国家不重复计算运行次数。先审查既有检查点，再跑一组仪器验证；有资格、激活和可读响应后才用剩余配对预算。没有有效机会的窗口记为无法判定，不凑入成功样本。到预算上限仍无实际差分就形成阴性或无法判定结论，转换接口设计，不自动扩国、延时或加大生产惩罚；后续新一轮预算按第 0 节事前登记，不能边跑边无上限续期。

任何十类错误、挂载、源指纹或恢复失败都会使本局不合格；保留两臂失败和原始证据。相同环境/检查点的同类原版错误重复两次后，停止该场景，先处理环境或改用合法检查点，不因两臂共同失败放宽门禁。采样间隔必须记录；未采到短暂角色、精度不足或随机种子不可控时，说明结论范围。

### 2. M3 出口：区分行为差异与质量改善

| 层级 | 出口 |
|---|---|
| 仪器有效 | 挂载和恢复完整，资格/输入/激活/评分/角色可读，缺失与零值区分，正反例及采样边界清楚 |
| 评分通道有效 | 单字段配对有方向一致、可重复的评分变化；现有 neutrality 证据只到这一层 |
| 实际响应差分 | 两国共享规则，各有至少三组有效配对；实际支持角色、加入/退出或发起变化可归因，逐组列出时延、无变化和方向反例；重复运行不冒充独立随机样本 |
| 有限场景质量 | 运行前给出该机会的风险/收益假设与判定指标；同时观察不利结果和正常防御/有利行动，参数敏感性复核不依赖极端值；实际响应差分不能自动升为质量改善 |

指标预注册至少包含：候选与有效资格数量、风险激活、支持/中立评分、实际角色、进入/退出及采样时延；对已观测承诺记录新增战争/承诺、财政风险持续时间、债务/财政读数和退出结果。更少宣战、更高中立或更少立法本身不是质量目标；若测不到行动代价和放弃收益，质量保持未证明。整数评分变化不能替代实际行动，三组配对也不能支持总体统计显著性或所有国家都更合理的宣称。

M3-A 与 M3-B 独立记录结论。首版若只证明第三方响应，则必须撤下未验证的自主发起参数并明确缩小行为范围；保留 `aggression` 生产偏置就仍需要对应出口。这是一项数据/生成器变更，当前代码未执行；不能仅改发布文案忽略仍在生效的字段。最终目标仍是内部、外部与政治偏好的通用决策增强，每个新增行为出口逐项验证。

### 3. M4：独立安全验证先做，正式候选验收后做

保存/重载、TTL、安装/卸载、迁移输入盘点、采集仪器和 vanilla 环境基线可独立执行，不受 M3 阻塞；已有有效证据在源、版本和条件未变化时复用。M3 无法判定时可以完成这些工作，但不能据此宣布行为候选可发布。

正式稳定性与性能验收使用通过 M3 的冻结候选。先预注册检查点、样本数量、窗口、资源预算与错误停止条件：至少早期和一个真实后期检查点，各三组 vanilla/候选配对，同速、同窗口、同探针和同机器状态；先短窗口确认 vanilla 干净，再执行至少 24 个游戏月的长期窗口。后期输入缺失时明确等待合法存档，不用早期长跑冒充后期。

每组报告财政风险/策略切换与残留、保存前后状态、RSS 峰值及随时间趋势、CPU、每游戏日耗时和 `ticktask_timings` 的均值/最坏值；分别计算成对差分，列出所有波动。先用三次 vanilla 测量确定噪声和可接受开销并落盘预算，再跑候选；噪声大于预算时先解决测量问题。当前没有已批准的实机性能预算，不追认历史采集为性能通过。目标是受控开销，不预设模组比 vanilla 更快；现有仪器量不到“单帧耗时”，不换算假帧数。

发布兼容范围必须由证据决定并随包声明。定型时首个候选范围为 Victoria 3 1.14.5 新局及该候选的同版本存档重载；旧九国 Mod 状态与跨游戏版本升级不支持，启动前继续拒绝。以后扩大兼容承诺时，分别获得真实干净旧版本输入和旧 Mod 迁移方案，完成载入、推进、再保存/重载与完整门禁；没有合法输入时保留未验证，不伪造存档或删除拒绝器。升级到新游戏版本按第 0 节演练，不把 1.14.5 永久写成产品目标。卸载 TTL 退出不能回滚已经发生的世界/法律变化。

### 4. M5：逐模块扩展

政治与市场可以进行开关关闭的接口侦察、独立仪器验证和隔离实验；进入正式候选及启用仍需各自完成 M1–M4。政治先核对完整 AI 候选、排名、方向限制、风险否决、更新时点和最终 chance 组合；源码基值1加实验贡献99不能宣称引擎最终100%启动，不调用直接开始立法制造成功。市场先取得可分辨的实际支持角色、加入/退出和不利结果，评分 margin 改变不等于参与改善。两个生产开关保持 `false`。

### 5. 发布与工程维护

生成成功与工程测试通过不等于可发布产品。首次发布必须列明实际启用的行为字段及对应 M3 出口、M4 冻结候选验收、游戏版本/覆盖文件指纹与同路径覆盖冲突、安装/卸载及存档限制、扩展开关和平台证据矩阵。任何启用字段没有行为与质量证据时，继续作为实验包或撤下该字段后重新回归，不宣称整个 Mod 制作完成。

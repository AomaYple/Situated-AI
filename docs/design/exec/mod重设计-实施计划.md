## 最终目标和本轮完成标准

**Situated AI 让每个国家基于自身处境和可观测信息，在原版机制内持续做出符合自身约束与利益的相对最优决策。**

本轮把信息覆盖、跨域组合、政治可行性、对外依赖、战争负担、有限记忆和解释推进到锁定原版接口可支持的范围。尽可能全面地发现和分类信息，但只让有可靠读取方式、合法消费者、独立价值和可接受成本的事实进入运行期。国家差异来自结构与环境，不来自国家名称剧本。

“相对最优”是受信息、能力、财政、政治阻力、外部威胁和原版规则约束的选择。每个消费者在自己的单位、作用域和候选内比较，不能把不同量纲直接相加成万能分数，也不能保证全知全局最优。

本轮工程完成须满足：锁定版本的候选信息和消费者都有明确处置；被接入的事实能追溯到原版来源；每个生产字段有唯一作者、回退和反例；每阶段留下完整标准包与收据。发现更多字段、增加规则数量或提高倍率本身不算产品进展。长期行为仍由用户验收。

首次新增行为以 `1.2.0` 为目标，后续按实际变更采用语义化版本。仅修改目录、报告或保持交付字节不变的整理，可以复用上一标准包并附新收据；
包内字节变化的候选使用独立阶段目录及哈希，正式交付时分配新版本，即使只改本地化或打包也不覆盖同版本旧包。已发布标签与附件保持冻结，
不移动标签、不覆盖旧包、不自动更换用户当前安装版本。

## 阶段状态机、产物和回退

正常推进使用以下状态；检查失败或输入变化时须回到相应状态修正：

```text
未开始 → 盘点中 → 实现中 → 候选冻结 → 工程完成
                  ↑          │
                  └── 检查失败或输入变化 ──┘
```

- **未开始：** 只有计划项和前置条件，不能在工作清单中写“已实现”。
- **盘点中：** 已固定输入指纹并完成影响面盘点；可以修改目录/合同，但不改变生产包行为。
- **实现中：** 已有源文件改动和定向测试；生成物仍视为候选，不能替换正式安装包。
- **候选冻结：** 源、底本、规则合同和测试选择集固定，生成一个完整候选包，等待集中门禁。
- **工程完成：** 本阶段的必需产物、定向检查、静态合同及包校验通过，收据明确适用候选与未运行检查；全计划最终门禁在 F18 完成，阶段工程完成不得冒充全计划已验收。
- **局部阻塞：** 作为具体条目的附加标记记录缺失证据、原因、恢复条件和独立可做项，不另立整仓停止状态。缺少锁定游戏底本时仍可开展离线工作，但不能勾选生产生成/打包出口；用户长期行为反馈缺失本来就在工程出口之外。

没有生产改动的 F9 等阶段可以从“盘点中”直接冻结复用的已有包及新报告，不为走完状态机虚构实现改动。候选冻结后如改动源、生成器、底本、语言或测试门禁，
必须重新计算指纹并回到受影响阶段；原收据只对原候选有效。阶段状态统一在[当前工作清单](../当前工作清单.md)更新，不追改历史结论。

阶段收据使用 `docs/design/exec/F<编号>-<主题>-结果.md`，只记录事实、输入指纹、变更文件、测试选择集、跳过分类、实际资源读数、包路径/哈希和未完成边界；
未测量项写明未运行及原因。可再生 JSON、快照和资源报告写入 `tools/out/` 的阶段/候选目录，只有明确登记且离线合同需要的精简快照才按证据契约入库。
生成物通过 CLI 更新，不能手改。阶段失败保留失败报告和源差异，修复后重新冻结候选；不得把失败候选安装到用户目录。

阶段回退优先复用并校验上一已交付包；若新增行为无法证明字段、作用域、保存边界或资源成本，则撤回该增量并登记实际原因和保留原版处置。
需要历史重建时只从对应冻结提交构建并对照原哈希；无法得到原字节就不得冒充同一历史包。行为回退若已对外交付，应使用新的维护版本；
用户存档中已经发生的世界变化不能由卸载或重新打包撤销。既有 `new-game-only` 声明保持有效，状态默认/过期的静态测试不等于旧存档兼容实测。

## F9：全量能力、消费者与缺口矩阵

**目的：** 找齐锁定原版可发现的候选信息和决策出口，再决定哪些值得接入；不把静态同名关联当作运行时能力。

**实施入口：** `src/pdx/information_catalog.py`、`vanilla_index.py`、`decision_interfaces.py`、`decision_report.py`、`snapshot.py`；规则来源为 `mod/decisions/*.toml`。

- [x] 固定游戏 `1.14.5`、源码、快照、生成锁和 1.1.0 规则合同指纹；复用现有分析与快照，不重新建设采集系统。
- [x] 按政治、人口社会、财政行政、生产建筑、市场贸易、科技、外交宗属、军事战争、殖民地理、身份文化、时间冲击盘点；未提供的作用域/单位保留为 `unknown`。
- [x] 复核 `InformationItem` 与 `decision_report.build()`；仅补充逐条候选处置输出与 metadata 来源声明，未扩大运行期 schema。
- [x] 为每条目录信息生成单一处置和理由；能力状态、静态消费者映射、生产候选连接与行为证据分开表达。
- [x] 输出当前已连接集合和停止探索边界；未证明的消费者留在后续阶段审计，不以目录同名关系进入生产。

**关键判定：** 覆盖来源漂移、缺失 getter、同名假阳性、确定性和未知回退；能力状态不是线性升级阶梯，派生值不是所有事实的必经步骤。准确测试选择只在本计划的验证矩阵维护。

**出口：** 一份 Python 生成的能力/消费者/缺口矩阵、一份基线差分和 F9 收据；无行为变化时复用 1.1.0 标准包。所有运行期接入项都有合法 reader 与 consumer 证据，不以目录条目数作为优化指标。

F9 的最小产物集合固定为：`tools/out/game/information-catalog.json`、`tools/out/game/consumer-matrix.json`、`tools/out/game/candidate-coverage.json`、`tools/out/game/candidate-dispositions.jsonl.gz`、`tools/out/game/candidate-dispositions-summary.json`、`tools/out/ci/decision-audit-production.json`、`tools/out/ci/decision-audit-offline.json` 和 `docs/design/exec/F9-信息能力矩阵-结果.md`。逐项清单流式生成并以 POSIX 形式记录仓库相对目录；外部输出只记录文件名，避免固化本机绝对路径。报告主体保存在可再生产目录，收据只记输入和产物指纹。

首批执行入口如下；候选覆盖直接从当前生产源生成 integrated 合同，不用启动器 descriptor 或人工拼装的测试候选冒充生产包。新矩阵需要扩展时沿用该入口，不建立另一套扫描器：

## F10：财政、产业、市场、贸易、科技和基础设施联动

**目的：** 把机会、成本和国家能力放到同一个消费者的规则合同中，避免“缺什么就无限造什么”。

**实施入口：** `mod/decisions/economy.toml`、`fiscal.toml`、`information.toml`、`strategic.toml`、`adapters.toml`；`src/pdx/decision_economy.py`、`decision_adapters.py`、`decision_rules.py`、`decision_intents.py`。

- [x] 从 F9 已证明的输入中组合现金流、债务、破产窗口、行政、建设能力、就业、识字率、科技、投入成本、价格、储备和市场可达性；区分供给瓶颈、需求机会与财政危机。
- [x] 为产业、教育、制度、基础设施和贸易消费者声明收益方向、资源约束、短期代价和互斥档位。高档须是普通档的严格子集，同一字段首匹配而不叠乘。
- [x] 对同一短缺/价格/市场事实登记唯一作用路径和机会成本，避免建筑、补贴、商品立场和战略权重重复补偿；税率枚举、补贴与建筑组权重默认保留原版，改变处置须有独立接口与价值证据。
- [x] 先复用现有共享信号；只有接口表达能力不足且反例明确时扩展规则 schema。不能从普通权重消费者推导出直接生产方式控制或动态税率优化器。

**关键判定：** 成对比较“同需求不同投入成本”“同失业不同市场可达性”“同机会不同债务/行政”；验证阈值两侧、未知值、原版零目标、战争中和玩家路径。比较生成脚本与独立参考求值，验证非叠加和原版尾部。准确测试选择只在本计划的验证矩阵维护。

**出口：** 完整经济增量包、字段级解释和覆盖差分。证据仅证明条件与输出合同，不保证固定 GDP 增长或投资结果。

F10 结束前必须能从候选覆盖报告反查每个新增经济规则的事实来源和唯一字段作者；经济规则不因为“缺少直接消费者”而改写原版生产方式、税率或市场机制。

## F11：社会、政治、制度和改革可行性

**目的：** 分开“改革收益”“政治阻力”和“当前执行能力”，让保守结构可以在条件改变时调整，也让危机国家避免盲目叠加改革。

**实施入口：** `mod/decisions/information.toml`、`strategic.toml`、`adapters.toml`；`src/pdx/decision_rules.py`、`decision_adapters.py`、`decision_security.py`、`decision_report.py`。

- [x] 复核政府组成、利益集团力量、合法性、批准度、激进度、革命风险、识字率、生活水平和身份结构在各字段的实际可见范围；不可见值不从国家名称估算。
- [x] 在法律、政府和制度消费者中组合收益、能力、阻力与危机档位，保留意识形态、资格、协商、失败和原版零值。共享财政约束不等于所有政治行动套同一个财政阈值。
- [x] 以结构相同但合法性/集团力量不同、改革收益相同但危机程度不同的成对场景检查方向；战争失败只影响有明确连接的消费者，不自动触发改革。
- [x] 对保留的政策身份和意识形态字段给出理由，消除重复作者。改革结果历史没有 reader 时仅使用当前事实，不创建虚构成功记忆。

**关键判定：** 覆盖强保守阻力、高收益低可行性、政治危机优先、未知输入、玩家边界和尾部资格失败。准确测试选择只在本计划的验证矩阵维护。

**出口：** 政治增量包与解释合同，能指出收益、阻力和约束分别来自哪里。不得把法律权重变化写成改革已通过。

F11 结束前必须保留至少一组“收益相同、政治阻力不同”和一组“阻力相同、财政能力不同”的反例，证明规则没有按国家名称硬编码。

## F12：外交、宗属、经济依赖和安全承诺

**目的：** 让合作、冒险、宗属与安全选择同时受对方关系、承诺方向、市场依赖、威胁、军力和财政能力约束。

## 覆盖和优先级的验收口径

F9 固定候选分母为锁定底本、指定采集入口和候选 metadata 所形成的去重集合；报告保留三者指纹。集合更新时先生成差分，不通过缩小分母提高覆盖率。信息发现、运行期读取、消费者映射和用户行为验收分别统计，读取器注册数不能冒充不同引擎 getter 数。

- **处置覆盖：** 候选信息和消费者的处置覆盖率为 100%，未分类项为零；这不要求运行期接入率为 100%。排除项写明来源、理由和替代路径。
- **接口完整：** 所有新增生产输入都有可核对 reader、作用域、单位和未知值合同；所有新增作者都有合法 consumer、可达位置和原版尾部证据。缺一项就不进入生产。
- **规则完整：** 每个消费者集合都有支持场景、成本/约束反例、未知值、玩家和原版资格拒绝测试；每个字段唯一作者，非叠加和确定性门禁无失败。
- **交付完整：** 包校验、生产/离线合同、现有整体 86% 分支覆盖率与核心模块门禁通过；跳过项分类公开，不计入通过。不支持项与用户尚未验收项公开列出。

同一阶段内先处理复用面大、证据充分且能消除明显反例的消费者，再扩展收益不明的边缘项。是否接入还要检查三类因果：当前状态与可持续能力、短期代价与长期收益、国内约束与对外承诺。短期/长期只是不同消费者和刷新时机的设计维度，不凭空新增引擎预测能力。

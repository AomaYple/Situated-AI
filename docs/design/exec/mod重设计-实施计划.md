# Mod 全目标实现优先与集中验证计划 · 6.0

> **效力**：2026-10-18 按用户批准的“全量信息、全域决策、原版适配、集中验证”目标重定型。本页是唯一产品主计划，实施[处境决策设计](../03-处境决策设计.md)中的 **Situated AI：全域处境驱动国家决策扩展 2.0**。计划版本 6.0 与产品版本 V1.0 分别编号；5.1 及更早版本从 Git 历史和日期化结果页恢复，原始证据和实验账本继续保留。
>
> **优先级**：正确性第一、速度第二、内存第三。F0 先完成完整目标候选，F1 集中实机验证和修正，F2 完成真实后期、长期性能、兼容和正式交付。工程检查、离线契约测试和生成校验可以在 F0 内持续运行，但不能替代游戏行为质量证据。
>
> **全量边界**：全量信息指锁定 Victoria 3 版本的游戏文件、脚本、定义、策略、触发器、效果、本地化、快照和公开运行时作用域能够发现或读取的信息。引擎内部没有可靠入口的数据登记为 `unsupported` 或 `unknown`，不得用外部 Python 常驻服务、探针或伪变量绕过边界。
>
> **状态边界**：F0 已交付当前公开脚本能力范围内的完整实验候选；F1 已完成同盟接口修复及短诊断，全部 F1/F2 尚未完成。实现完成、短加载通过、行为质量通过和正式发布是四个不同结论。当前候选、输入资格和下一动作只在[工作清单](../当前工作清单.md)维护，命令与证据只在[完整候选结果](完整候选-结果.md#当前证据索引)维护。
>
> **执行口径**：所有 F1 实机从生成器产生标准 Mod 目录，经 `pdx.game_run` 的互斥、部署、日志、归档和恢复流程验证实际加载内容。解释、日志和字段探针只能显式附加到本次验证副本，并在 `manifest` 与 `f1_context.json` 中标记候选类型；验证结束后由部署事务清理。

## 1. 目标、范围与完成定义

### 接续顺序与证据依赖

F0 冻结后按真实依赖推进 F1，不因文档整理重做整套实现，也不让单个行为实验的阻塞变成所有工作的前置条件：

| 接续任务 | 输入与产出 | 依赖和停止边界 |
|---|---|---|
| **M1 观测设计** | 从冻结 metadata 的逐消费者待证清单确定实际资格、选择或行动输出，补齐观测入口、允许差异、机会集合与代价 | 已有清单直接复用；没有数值 getter 时观察实际行动，不再重复只看持牌/评分的诊断 |
| **M2 独立准备** | 按当前标准包准备玩家新局、保存/重载、禁用/卸载及逐语言显示/语义检查；仪器仅在必要时附加 | 与不依赖它的 M1 准备分别推进；实际开游戏仍须满足对应输入、错误与恢复门禁 |
| **输入资格与因果修复** | 只读复核版本、来源、挂载、原始错误和账本；只有可核查的新输入/环境或对应原因修复才登记重开 | 缺少新依据时不重跑同类停止窗口；明确哪些任务被拒绝、哪些独立准备仍可完成 |
| **有限 M1/M2 实机** | 使用合格输入完成六个月烟测、真实接口及可合并的生命周期采样；玩家和语言按所需状态分别验证 | 同候选且互不扰动时合并采样；短加载不替代六个月或未触发分支，逐件恢复后才开下一局 |
| **M3 行为与组合** | 控制先行，取得匹配的有限配对、自然机会、行动收益/代价、阴性结果与反例 | 依赖对应消费者、机会分母及输入资格；预算和停止条件按第 4 节，不自动延长 |
| **F2/M4 与增量交付** | 对满足 F1 的冻结能力完成真实后期、长期、压力、资源、兼容和正式包出口 | 对应出口成立才交付相应可玩版本；不等待无关模块，也不以 M3 单独替代 M4 |

上述顺序组织依赖，不新增产品阶段或另一套任务数据库。每项准备、运行和拒绝都以实际产物及证据验收；任务状态见[当前队列](../当前工作清单.md#当前队列)。

### 已完成批次的引用

2026-10-19 战略协调、完整测试体系和同盟接口修复分别经 PR #31、#32、#33 合入。原 A–E 批次已结束，不再作为待办重复执行；实现、失败、复验及 Git/CI 收据见[完整候选结果](完整候选-结果.md#2026-10-19-dev2-交付收据)。这些批次完成不代表全部 F1 或 F2 完成，历史候选、原始失败和累计停止保持原范围。

目标以[处境决策设计](../03-处境决策设计.md)及[Mod 开发原则](../../principles/Mod开发原则.md)为准：尽可能收集游戏中可获得的政治、人口、财政、行政、经济、产业、资源、科技、市场、贸易、物流、外交、军事、战争、宗属、殖民、地理、身份和世界状态信息；对能够影响原版 AI 的信息建立真实消费者映射；通过领域评估与跨领域仲裁，使国家在原版执行系统内根据处境重新选择。

产品保持后台自治和原版执行系统。Python 用于开发期分析、配置、生成、测试和证据处理，游戏运行时只加载标准脚本和本地化。产品不承诺读取不可见的 C++ 内部状态、不承诺全局最优、不替换整个原版 AI、不提供免费资源或强制行动，也不通过固定国家剧本伪造改善。

**全量完成定义**：每个可发现信息都进入能力目录并标注 `discovered`、`runtime_readable`、`derived`、`consumer_mapped`、`behavior_verified` 或 `unsupported`；每个 A/B/C 级可影响消费者都有实现或明确缺口；各领域共享事实、处理冲突并保留原版资格、成本、失败和回退；标准包可以直接安装；F1/F2 另行证明实际行为、性能和兼容。

| 阶段 | 主要内容 | 出口含义 |
|---|---|---|
| **F0：全目标完整实现** | 全量信息目录、运行时读取、领域评估、跨领域仲裁、原版适配、解释、本地化、生命周期、标准生成和离线工程验证 | 完整目标候选已写出，可进入集中实机；仍是 experimental |
| **F1：集中验证与修正** | M1 真实接口、M2 生命周期/语言/玩家路径、M3 行为质量/反例/组合；按证据修复和复验 | 声明场景内的消费者、方向和行为质量成立；仍不替代 M4 |
| **F2：稳定性、性能与正式交付** | M4 真实后期、长期、压力、速度、CPU、内存、兼容、恢复、本地化和包验证 | 对应版本正式交付出口成立，不超出已验证范围 |

**主顺序固定为 F0 → F1 → F2。** F0 不等待某个模块先通过行为质量才实现其余模块；F1 发现问题时只重做受影响的 F0 任务和证据。模块未验证不等于可以删除目标，确无接口时必须登记缺口和替代方案。

**变体和历史边界**：`current`、`control`、`disabled`、`complete`、`fiscal`、`security`、`market`、`reform` 及旧七模块 `full` 保留原身份，不能因为 6.0 改名而冒充全域目标。新候选仍使用稳定 Mod ID `sitai.decisions` 和用户可见目录 `Situated AI`；新增变体必须同时更新生成器、CLI、清单和测试。

## 2. 信息覆盖与决策消费者矩阵

F0 的完整性不是“模块开关存在”，而是每项信息都有来源、作用域、单位、更新方式、成本、可见性、未知处理、决策用途、消费者、生命周期、反例和待验假设。矩阵由 Python 工具生成，结果归档在[完整候选结果](完整候选-结果.md)和接口台账，不建立第二个状态数据库。

| 信息领域 | 主要覆盖 | 目标消费者 |
|---|---|---|
| 世界、时间、地理和身份 | 日期、全球冲突、地形、基础设施、战略位置、国家身份和长期偏好 | 策略资格、目标范围、长期路线、重评估频率 |
| 人口与社会 | 人口、文化、宗教、阶层、生活水平、失业、识字、迁移、激进派和效忠派 | 政治路线、法律、劳动力、移民和社会稳定 |
| 政治与制度 | 政府、合法性、利益集团、政治运动、革命风险、法律和制度容量 | 法律资格、改革倾向、支出和危机响应 |
| 财政与行政 | 收入、支出、债务、利息、信用、违约、税收、行政力和机构成本 | 发展、军费、改革、外交承诺和生存约束 |
| 经济与产业 | 建筑、生产方式、投入/产出、工资、利润、就业、资源和科技 | 建设、生产、研发、产业和财政平衡 |
| 市场、商品与贸易 | 价格、供需、短缺、贸易路线、关税、护航、封锁、依赖和替代 | 生产、贸易、外交、军需和市场路线 |
| 外交、安全与宗属 | 关系、条约、博弈、盟友、威胁、宗主/属国、自治和依赖 | 支持、目标、保护、合作、独立和退出 |
| 军事与战争 | 陆海军、编制、装备、训练、补给、前线、占领、战损、战争目标和战争负担 | 军费、军力规模、军事结构、目标和战争承受力 |
| 殖民与海外 | 殖民地、竞争、海外资源、海外成本和海外军事需求 | 殖民、外交、军事和资源路线 |
| 规则与接口 | 策略字段、触发器、效果、作用域、叠加/覆盖、候选资格和退出语义 | 真实消费者映射、生成和版本漂移检查 |

每个信息项按影响等级标记：A 直接行动或候选、B 策略权重或持牌行为、C 资格/目标/时机、D 解释诊断、E 暂无可靠消费者。A/B/C 进入行为实现；D 进入解释和证据；E 保留为缺口。

## 3. F0：全目标完整实现

F0 按锁定版本的公开脚本能力交付一个能直接生成标准 Mod 的完整候选。全量发现、实际读取、原版保留、尚无可靠入口和实机假设分别登记；静态资源不强行转成运行时变量。以下完成只表示源码与离线契约，不表示 F1/F2 或所有引擎内部算法已实现。具体数量、指纹、命令和未实现能力只在[完整候选结果](完整候选-结果.md#2026-10-19-f0-全域候选收口)记录。

### 4.0 启动决策、状态与阻塞

F0 出口后，每次实机先使用现有 `pdx.game_run` 核对游戏版本、包、输入、进程、用户目录、挂载、恢复指针、资源与原实验账本，并分类：

| 类型 | 启动条件 | 可支持的结论 |
|---|---|---|
| 正式行为样本 | 来源、输入、机会、预算、账本、挂载与恢复门禁全部满足 | 对应 M1–M4 的声明范围，失败照常计入 |
| 独立安全诊断 | 与被停止的样本独立，问题可由该诊断回答，使用同一安全事务 | 本次加载、界面、自动化、日志或恢复；不产生正式质量/性能资格 |

同输入/环境同类错误两次停止；既有 preparation、seed、新局配方及复制件的停止保持。新计划、新包、改名、改探针、资源增加、清记录或拼接会话不提供重开依据。真实独立输入、可核查环境变化或针对失败的因果修复仍由原规则判断。单项拒绝不泛化为所有实机都不可运行；仅缺图标时继续判断独立诊断，不改本体、不白名单错误。

每次要求实机都记录四态之一：`已启动并完成`、`已启动但诊断失败`、`启动前被具体门禁拒绝`、`尚未派发，属于执行遗漏`。附候选与输入 SHA、版本、实际命令、窗口、原始日志、截图和恢复结果；不得用“未验证”掩盖执行遗漏。未知错误、脚本/模拟断言、挂载污染或恢复失败按基线停止。

执行事实、原始目录、失败、修复和运行读数集中见[完整候选结果](完整候选-结果.md)，当前状态与下一派发项集中见[工作清单](../当前工作清单.md#当前队列)。本页只保留启动分类、停止条件、阶段依赖和出口，不再逐局复制结果。

### 4.1 最少重复的验证顺序

因果顺序保持为输入与接口资格、单模块归因、无干扰组合、实际行为及反例、长期与交付。具体批次只由[第 7.1 节](#71-执行批次与并行边界)编排，阻塞解除与就绪依赖只由[第 7.2 节](#72-阻塞解除与就绪顺序)维护；证据复用按[贡献流程](../../../CONTRIBUTING.md#验证提速与证据复用)执行。

完整包烟测仍要求至少六游戏月、观察者、快捷键 `5`、空格、后台推进、严格日志和逐件恢复。修复先跑受影响检查，批次冻结再跑适用完整回归。共享对照只有一个样本身份，相关国家不是独立重复；短加载、整包差异和诊断成功不能替代未触发字段、模块归因或正式行为资格。

### M1 · 真实接口

核对全部声明领域的真实输入、作用域、字段组合、未知值、仪器扰动、仲裁与原版实际消费者；同时核对语言集合、路径/语言头/键覆盖及占位符。没有真实接口证据的字段仍是 unknown/unsupported，评分变化和根 hook 不能提升为行为质量。

### M2 · 生命周期、语言与可玩路径

有状态模块核对进入/持续/退出、重复触发、迟滞/冷却/TTL、过期清理、关闭和保存/重载；无缓存模块按事前声明验输入即时变化。验证国家切换、正常玩家新局/推进/保存/退出/重载和解释显示。

逐语言审校机制含义、原版术语、占位符、特殊字符与布局，逐语言记录加载、解释键和保存/重载。缺语言 GUI 模板时复用可用检查点、引擎与截图证据；需要新模板先补最小模板，不把中英模板范围当 11 语言实测，也不把结构覆盖当翻译质量。

### M3 · 有限行为实验与反例

- **M3-A 第三方响应**：同一机会、两个合格响应国、处理前状态及完整观测起止；受控机会单列，发布候选至少再有自然机会验证。
- **M3-B 自主发起**：研究范围内完整且可审计的合法候选分母；缺项不阻止独立 M3-A，未验自主发起字段不发布。aggression=0 不算自主发起优化已完成。
- 第一轮最多两个新检查点/场景，每场至少两个响应国、最多三组控制/处理配对，单臂最长六游戏月；失败计预算，不自动延长阴性窗口。
- 两个国家各至少三组有效配对，逐组报告评分、角色、加入/退出及采样时延、风险持续、债务/承诺、行动代价、放弃收益、不利结果、无变化和方向反例。正常防御/有利行动不得恶化，不靠极端参数制造效果。
- 政治另记录真实法律可行性、方向、风险和自主立法；IG/启动节奏不是完整排名，市场/安全支持不是资格或行动。正式财政注入为 none；版本、检查点、世界、挂载、源、探针、时间和资格匹配，只改变声明因素。
- 十类错误、额外文件错误、Mod 错误、来源和恢复门禁保持；变更假设/参数/预算事前登记，不追认失败、事后改指标或无限重试。预算内无收益则修改/替换该机制，保留其它模块和证据。

经济行政、外交目标与宗属关系不能硬套外交支持分母。每个新增行为在首次运行前登记自己的可行机会集合、决策单位、对照、观测窗口、实际行动、收益/代价和反例，并写入[完整候选结果](完整候选-结果.md)。沿用每场至少两个合格国家、各三组有效配对及首轮最多两个新场景、单臂最长六游戏月的有界探索；六个月不足以回答的问题另登记长期验证，不能事后延长阴性窗口。经济观察合法发展选择及财政/行政机会成本，外交观察目标/战争代价，宗属同时观察两侧的保护/依赖/自治结果。单模块归因成立后按共享输出与高风险冲突安排组合试验；全域组合效果不能从旧四模块证据外推。

## 5. F2：稳定性、性能与正式交付

正式 M4 使用 M3 冻结候选。真实早期和至少一个真实后期检查点各三组 vanilla/候选配对，同速/窗口/探针/机器；先三次 vanilla 测噪声并冻结速度/CPU/内存预算，长期至少 24 游戏月。阶段增量包也必须满足适用的 M4，不把它延期到 V1.0 才做。

逐组报告模拟每游戏日耗时、CPU、RSS 峰值/趋势、状态残留、保存前后和可靠 ticktask_timings；不以 Python 基准代替游戏性能，不以早期长跑冒充真实后期。噪声超预算先修测量；OOM、泄漏和无界增长优先处理。优化先证明相同语义和证据完整，再比较速度；速度等效时选择低内存方案。

安装/禁用/卸载、重复执行、同版本保存重载、旧状态拒绝、兼容与恢复通过；全语言文本审校完成、`fallback_languages` 为空。回退依靠前包与处理前存档，卸载不撤销已发生战争/法律。Windows/macOS/Linux 的工具、CI、无头和 GUI 证据分开申报，未实测不写通过。

最终 ZIP/manifest 由 Python 生成，记录实际模块、版本、全部语言、SHA、来源、存档/兼容限制、安装/禁用/回退说明和平台证据。最终包与被验证冻结候选一致，适用工程、产品和交付门禁通过后才建通过标签或正式发布。

## 7. 生产交付与执行编排

### 7.0 生成、部署、测试、探针和发布统一契约

所有可安装或可验证的候选都必须经过同一条 Python 交付链：

1. `pdx.decisions` 从 `mod/decisions/` 生成仓库源码产物；不手改生成物。
2. `pdx.distribution.package` 将选定变体转成确定性 ZIP，在交付边界为游戏脚本和本地化添加 BOM，并写入 `DISTRIBUTION-MANIFEST.json`。
3. 清单固定记录稳定 Mod ID `sitai.decisions`、用户可见安装目录 `Situated AI`、变体、候选类型、探针开关、实际文件 SHA-256、元数据契约和输入/生成器指纹。
4. 标准包使用 `Victoria 3/mod/Situated AI`；`pdx.game_run.Deployment` 只接收冻结源目录，负责互斥、备份、部署、日志/存档隔离和逐字节恢复。它不修改启动器现有 playset。
5. F1 验证 2.0 必须显式部署标准 `integrated`；旧七模块研究仍用 `full` 或对应单模块标准包；解释 GUI、资源和本地化诊断只能显式附加到本次临时副本，并在 `f1_context.json` 中标为 `instrumented_candidate` 或 `diagnostic_candidate`。
6. `pdx.distribution.validate_package` 是发布前门禁：逐项核对 ZIP 路径、清单身份、变体、目录名和文件 SHA-256；标准发布校验拒绝含解释探针的包，允许探针仅用于明确标注的临时验证。
7. 只有生成、清单校验、适用工程门禁、对应实机/行为质量出口、兼容/回退和本地化出口全部满足时，才可把候选提升为发布包。加载成功、脚本解析、评分变化或根 hook 不替代行为质量出口。

该契约只规定当前生产交付；历史 `sitai-decisions`、`sitai_full_f1` 和旧探针目录保留在历史证据中，不作为新的部署名称。目录名变更不重开既有实验窗口，行为证据仍按原输入、源指纹、游戏版本和探针边界判断有效性。

### 7.1 执行批次与并行边界

2026-10-19 按推进成本重排为以下执行批次，继续使用计划 6.0 的产品目标和全部出口。批次是工作编排，不新增质量门或状态数据库。优先完成能解除下游依赖、一次采样可回答多个问题的工作；没有证据收益的重复扫描、重新打包和完整回归不进入关键路径。

| 批次 | 实际产出与集中方式 | 启动、完成和后续依赖 |
|---|---|---|
| **B0 冻结与逐项观测准备** | 复用已冻结标准包和联合验收；从同一 metadata 逐字段连接来源、规则、输入、真实行动、机会、代价与反例，按消费者家族安排采样；同步逐语言和玩家路径检查表 | 清单必须无漏项、无重复，逐项保留 pending；清单本身不提供运行期资格。文档或编排变化只跑受影响检查 |
| **B1 最小因果诊断** | 先分析已有错误、源码和发生阶段；尚无独立原版证据时，最多一次零 Mod、无探针、有界新局诊断区分环境与候选依赖 | 仍走 game_run 严格日志/挂载/恢复；不能重开旧停止窗口。错误发生前未到达的分支记未回答；保留因果修复依据后才重新判定原输入资格 |
| **B2 M1 与无干扰 M2** | 同冻结候选、同输入、同仪器、同窗口，合并六个月加载烟测、实际消费者观测、无状态即时读取及只读解释采样；有状态模块按适用状态单列 | 先证明对应接口，不能把整包加载当全部字段执行；观测扰动或无法归因则拆开。共享输出及高风险冲突在单模块归因后验证 |
| **B3 可玩路径与逐语言** | 同一语言内顺序完成玩家新局、正常推进、解释显示、保存、退出和同版本重载；逐语言独立登记。禁用/卸载另起事务，保留处理前存档和前包 | 语言切换、玩家/观察者切换、禁用和卸载改变输入或世界时必须拆局。静态键集可复用，实际语义、布局和恢复不能推断；B2 被拒不阻断独立准备 |
| **B4 M3 机会驱动配对** | 控制先行，按实际合法机会选择消费者与国家；同一窗口可采多个互不扰动的结果，按共享依赖选有限组合 | 第 4 节的场景/配对/国家/窗口/自然机会/反例预算不变；共用控制只有一个样本身份，各响应国与指标不充当独立重复。无机会不能事后换指标或延窗 |
| **B5 F2/M4 与交付** | 已满足 F1 的冻结模块按第 5 节集中真实早期、真实后期、压力、长期、资源、兼容和发布验收 | 性能窗口与行为探针、玩家操作分开；同一无扰动长期窗口可采稳定性和资源，但不补足缺失的三组配对。满足适用出口后逐个交付增量可玩包 |

每次实机在开始前写明候选/输入/语言/挂载/仪器/窗口身份、主要问题、兼采问题、干扰排除、预算、停止条件及逐项判据。兼采问题没有到达触发条件时保留未回答；不能看到结果后把短窗口升级成完整窗口。

修复先定位再按影响批量完成。改变 reader、规则、消费者补丁、本地化、仪器或输入时，列出受影响的字段、语言、场景与证据；只重验依赖它们的结论。共享底层或依赖未知时扩大重验范围。修复批次冻结后做一次适用完整回归，不将“集中”解释为延期必要的安全/恢复检查。

只有真实消费者、输入或仪器相互依赖的问题才串行等待；某字段不可读或正式样本被拒绝时，继续其它可独立回答的组合、GUI、语言和玩家路径问题。实机进程始终互斥，不把独立工作理解为并行启动游戏。阶段出口、账本停止条件和诊断资格不变，当前派发状态只在[工作清单](../当前工作清单.md)维护。

### 7.2 阻塞解除与就绪顺序

按下列依赖处理 B0–B5，持续执行流程统一见 [贡献流程](../../../CONTRIBUTING.md#持续执行与阻塞分流)。以下产出是原有批次的具体工作，不另设产品阶段或追加同类失败预算。

1. **先用原件回答 B1 原因**：关联完整归档错误、当时挂载、原版引用、实际资源/语言键与事件调用作用域；核对当前版本和安装状态。检查不能只搜索已有十类或 Mod 名称，新的引擎错误先补统一检测再复核受影响旧结论。确认安装损坏才使用官方修复途径；确认接口/仪器缺陷则最小修复并保留失败复现。加载解析问题优先做停止于菜单输入之前的字段级因果诊断，无需等待无关 GUI 或运行世界；不把主动结束的诊断报告写成标准烟测通过。缺翻译、缺图片、解析和后续事件断言逐项判断，不能从其中一个错误推断另一个已解决。
   舰队 `mission_type_weights.protect_supply` 须保留完整条件及原值，使用独立具名脚本值；原版注释不能替代实际解析与求值证据。先逐字段归因，再分别验证生产生成物加载、动态值和真实任务行为；不靠恢复常量或删除动态规则宣称功能完成。
2. **凭因果证据恢复资格**：保存修复前后指纹、预期变化和受影响结论，重新执行既有输入及账本门禁。原件未变、仅换名称/语言/探针或复用复制件不构成重开。诊断临时覆盖不提升为正式原版环境；依赖相同停止原因的运行仍等待该原因被证明解除。
3. **B0 与 B3 离线部分不等实机**：将每个消费者连接到具体输出来源、作用域、时序、实际行动和合法机会分母，登记无法直接读取的项。原版 hook 存在不等于具体字段执行；GUI 表达式须另验其在 AI 脚本中的可用性；建设分页与过滤、研究/传播、立法/事件激活分别处理。逐语言审校全部自有文本及术语，修复文案另冻候选并逐字节比较行为脚本。显示、布局、玩家推进、保存与重载仍分别需要 B3 证据，审校不能替代它们。
   研究观测先完整冻结科技键与来源字节，显式选择响应国，分开记录合法研究集合、已研究状态及取得/传播原因；通过现有薄入口临时附加，坏帧不得作为有效观测。禁止恢复曾触发游戏状态访问断言的 GUI `IsResearching`；当前改用原版事件中已有静态用法的国家 trigger `is_researching_technology`，运行期安全与时序必须按实际窗口登记，历史 unknown 不回填。原生读取已在两国短诊断中取得启动/月度一致状态，后续复用该证据，不重复相同安全诊断；复用已完成的研究 hook 目标交叉核对，转向真实选择的合法机会及因果证据；法律对象、可用性条件、现行法、立法中和激活目标分别记录，未触发 hook 不提升为已验证。完整 AI 候选分母仍待证明，不能将“全科技已枚举”升级为内部 AI 排名完整，也不能借新仪器重开停止窗口。
   持续日志的源句柄第二遍复读区间已经过独立边界检查、串行成本预算和一次有新问题的有限实机诊断，磁盘区间覆盖全部 captured。复用这项证据，不重复旧消费者读取安全或原件未变的正式资源失败窗口；区间与最终引擎原件分别登记，不把来源保留修复写成行为质量。
   菜单输入按实际状态诊断：已匹配按钮及发送输入不等于成功回调。保留无响应的截图和日志；库替换或延长按住若未获支持则撤回，不能在同一失败窗口盲点或增加等待来凑通过。
4. **就绪后立即执行 B2/B3**：标准冻结候选按原资格派发六个月烟测及逐项接口观测；有扰动则拆分。玩家、语言和生命周期按实际依赖安排，不因其它领域未知而统一搁置。每次事务完成先核对恢复，再派下一局。
   新局生成的检查点与载入既有存档的行为报告分别审计；复用可核验的现存检查点验证保存/重载，避免仅因报告类型误判重复制作世界。挂载 Mod 的准备来源仅供安全/仪器诊断，保留实际挂载和状态，不产生纯原版、自然机会或正式 M3/M4 资格；具体来源契约见[工程基线](工程基线-1.0.md#6-证据边界与未完成事项)。
5. **B4 与 B5 按证据接续**：先冻结具体机会、对照与反例设计，再执行有限配对；质量成立的模块接早期/真实后期、压力、长期及正式交付。保留全部既定样本、语言和平台边界；没有真实后期输入时处理其来源和资格，不能以早期长跑替代。

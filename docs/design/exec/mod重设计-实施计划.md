## 1. 目标、依据与唯一入口

目标沿用[处境决策设计](../03-处境决策设计.md)：让 AI 国家依据真实内部因素、外部环境和政治偏好，在可观察、可表达且受约束的路线中选择，并随世界变化重新评估。原版 AI 负责具体执行，玩家正常游玩，不需要 Python 服务或逐国下达大量命令。

持续要求见[工程原则](../../principles/工程原则.md)、[Mod 开发原则](../../principles/Mod开发原则.md)，工具与证据契约见[工程基线](工程基线-1.0.md)。不以免费资源、暴力削弱、强制行动、全知输入或固定国家剧本制造改善。世界机制与决策增强分别开关、分别归因；未知输入、失效状态和退出按设计显式处理。

本次编排采用小批次的可用增量、独立开关、短期分支和完整交付，参考于 2026-10-14 核对的 [DORA 小批次实践](https://dora.dev/capabilities/working-in-small-batches/)、[功能开关实践](https://martinfowler.com/articles/feature-toggles.html)和 [GitHub Flow](https://docs.github.com/en/get-started/using-github/github-flow)。这些是工作方法参考，不是 Victoria 3 接口有效或 AI 质量改善的证据。

## 2. 什么才算一个阶段完成

**完成的阶段必须包含新增产品能力和一个可玩包。** 只修改文档、修工具、生成 ZIP、加载成功或观察到评分变化，都不能单独算阶段完成。首版完成一个最小行为闭环，之后每版只增加一个闭环，继承上一版可用能力。

候选包和完成的阶段包分开管理：开发过程中可以生成明确标为“实验、行为质量未验收”的包供隔离测试；实验包不移动正式开关、不建立通过标签、不作为下一阶段的已验证父版本。完成的阶段包必须满足：

1. **工程**：单一数据源、生成一致性、严格编码、相关测试、离线 baseline、完整回归和现有覆盖率门禁通过；
2. **新增模块**：M1 接口、M2 生命周期、M3 行为与质量、M4 稳定性与资源全部有对应证据，继承证据的依赖边界可核查；
3. **玩家可玩**：干净安装，选一个正常可玩国家进入新局，看到实际启用内容和限制，推进、保存、退出、重载并继续游玩；玩家世界规则与 AI 一致，不强制替玩家决策；
4. **自动烟测**：新局进入观察者，原版快捷键 5 切五速、空格推进，必要前台输入结束后最小化后台；默认至少六游戏月，目标机制实际运行，完成保存、退出、重载和继续推进；
5. **恢复**：文件安装、卸载、重复执行和失败恢复可核查；存档状态退出另测。回退到上一包和处理前存档，不声称卸载能逆转已发生的战争、法律或世界变化；
6. **交付**：Python 生成 ZIP、文件 manifest、SHA-256、版本说明、安装/卸载和回退步骤，声明游戏版本、实际启用模块、兼容限制及平台证据；
7. **可追溯**：冻结源提交、输入和部署指纹、包 SHA、实测与跳过项都有记录；核对实际测试的包后才建立标签。

首次兼容候选沿用已审查的 Victoria 3 1.14.5 新局及同候选的同版本存档；这不是永久版本承诺。扩展到新游戏版本前按第 6 节重审。Windows GUI 已有实测基础，macOS/Linux 工具、CI、无头和 GUI 分别声明，未实测的 GUI 不写成通过。

每版补丁也必须能安装和游玩；故障修复不能让已完成阶段失去可玩性。无需为了修一个缺陷把全部无影响模块重新研究。

## 3. 五个连续产品阶段

| 阶段与版本 | 本版新增能力 | 父版本与开关 | 玩家实际得到什么 | 完成出口 |
|---|---|---|---|---|
| **第一阶段 V0.1：最小处境决策闭环** | 优先财政风险与存续状态影响第三方高风险外交响应；两个或更多合格国家共享一条规则 | 首版；财政模块须补独立开关，aggression、市场、政治保持关闭 | 可正常游玩的首包；危机国家对可承担和不应承担的外交风险作出有证据的不同响应，并有最小解释 | A1–A5、该闭环 M1–M4、第 2 节全部通过 |
| **第二阶段 V0.2：外部安全与承诺** | 只增加外部安全、保障或既有承诺中的一个受支持闭环 | V0.1；新增独立开关，不隐式启用其他实验模块 | 同一财政处境下，外部威胁和承诺关系可以改变可行响应 | 新模块自己的 M1–M4，V0.1 兼容回归，可玩包与回退 |
| **第三阶段 V0.3：市场依赖** | 只增加市场依赖、供应风险或贸易约束中的一个可测闭环 | V0.2；市场开关通过后才打开 | AI 将关系破裂的经济代价计入外交或经济选择；不是只有分数不同 | 真实角色、实际行为、代价、不利结果；模块 M1–M4、继承回归和可玩包 |
| **第四阶段 V0.4：政治可行性与身份偏好** | 只增加政府、统治联盟或政治身份对可行路线的一个通用影响 | V0.3；政治开关通过后才打开 | 相似危机中的国家因政府与政治约束选择不同路线；保留合理惯性和失败 | 候选、方向、排序、风险、更新和实际法律/策略行为；模块 M1–M4、回归和可玩包 |
| **第五阶段 V1.0：组合、解释与正式维护** | 组合已经通过的四类因素，处理冲突、优先级、迟滞、冷却和解释一致性；完成正式交付 | V0.4；只组合已通过的模块 | 内部、外部、市场和政治影响形成可解释的自治世界，保持正常防御与有利行动 | 多国家反例、组合质量、长期/真实后期/压力、性能、存档、兼容矩阵和发布交付 |

上表描述目标效果，不是当前已实现效果。V0.1 未完成；V0.2–V1.0 尚未开始产品验收，市场和政治的既有隔离侦察不计版本完成。

每版只冻结一项主要新增能力；组合和发布属于 V1.0 自身增量，不被误称为“新增一个机制”。若新增模块包含两个独立行为问题，拆成同一版本的两个候选迭代，逐一验收，不在一个配对中同时改变。

每阶段在首次 pilot 前，把以下内容登记到对应结果页：行为问题与因果假设、声明启用的规则、处理前输入与允许差异、质量指标及判定阈值、反例与有限预算。质量指标要落到该闭环可观察的风险承担、实际代价、放弃收益或不利结果，不能只统计宣战、中立或改革数量；阈值和反例不根据结果事后挑选。三组有效配对仍只是有限场景证据，发布说明保留适用范围，不宣称总体最优。

每版明确支持的开关组合和存档迁移范围。验证全关、交付默认组合、每个新增开关两侧及共享策略槽/状态的冲突边界；不声明未验的任意组合。阶段升级使用真实前版包和对应存档验证，不从“同版本保存重载通过”推断跨版本升级通过。

## 5. 保留的质量门和实机预算

M0 表示设计/文档收敛；M1–M4 是每个新增闭环的质量门；M5 结果保存政治/市场研究。G0/G1 是提速协议的准备/pilot 门，不能和历史阶段 2 的旧 G1 混用。

### M1、M2：接口与生命周期

M1 核对真实输入、作用域、字段组合、未知值和仪器扰动；接口可读不是行为有效。M2 验证进入、持续、退出、重复触发、迟滞、冷却、紧急例外和 TTL。保存/重载及过期清理必须有实机；如果机制不需要某类缓存或冷却，事前说明为何不适用，不能漏验状态残留。

### M3：先可测，再有限实验，再判质量

| 问题 | 可接受的范围 | 禁止外推 |
|---|---|---|
| M3-A 第三方对已有博弈响应 | 同一机会、两个合格响应国、处理前风险与观测起止；受控场景单列 | 受控创建不等于自然发起；至少再用自然形成机会验证可发布候选 |
| M3-B 自主发起 | 研究范围内完整且可审计的合法候选分母；受支持子集明确边界 | 根哨兵、已发生事件或 started=0 不替代完整机会分母 |
| 财政生命周期 | 真实财政读数、风险进入和退出；压力注入只用于隔离状态实验 | 注入改变原版世界，不能隔离策略字段因果或作为正式无注入处理 |

第一轮最多两个新检查点/场景，每场至少两个合格响应国家、最多三组控制/处理配对，单臂最长六游戏月。先仪器，再 G1，再正式样本；失败消耗预算，共享一场博弈的国家不重复计运行。后续预算必须在运行前说明新前提、上限和判据，不能追认。

M3 通过要求两个国家各至少三组有效配对，逐组列评分、实际角色、加入/退出及采样时延、财政风险持续、债务/承诺、代价、放弃收益、不利结果、无变化与方向反例。正常防御和有利行动不得因一律中立而恶化；参数敏感性不能依赖极端值。测不到行动代价或放弃收益，质量仍未证明。三组不是总体统计显著性证据，两国不是两个独立世界。

控制和候选使用相同版本、检查点、世界/策略槽、双方、探针、日期、激活起点和机会阶段，只改变事前声明的字段；正式财政注入为 none。完整挂载、源/部署 SHA、十类错误和恢复门禁保留；同一环境/检查点同类原版错误两次即停止。M3-B 缺完整分母不阻止独立 M3-A，但不能发布未验收的自主发起字段。

### M4：安全工作可先做，正式候选后验收

正式 M4 使用 M3 冻结候选。至少真实早期和一个真实后期检查点，各三组 vanilla/候选配对，同速、同窗口、同探针和同机器状态。先三次 vanilla 测量噪声并冻结速度/CPU/内存预算，再测候选；长期窗口至少 24 游戏月。缺后期合法输入时明确未通过，不用早期长跑冒充后期。

逐组报告模拟每游戏日耗时、CPU、RSS 峰值和时间趋势、财政/策略切换及残留、保存前后状态、可可靠采集的 ticktask_timings 均值/最坏值；预算包含噪声、硬性资源上限和停止条件。噪声大于预算先修测量，不预设 Mod 必须比 vanilla 更快，不把任务耗时换算成未测的单帧。Python 提速不是游戏性能证据。

同版本保存重载、安装/卸载、重复安装、受影响存档状态清理必须通过；旧九国 Mod 状态和跨版本升级仍拒绝，扩大支持前另取得真实干净输入并验证。卸载/TTL 不逆转已发生世界变化。游戏、正式性能、完整回归和剖析错峰，避免资源竞争污染测量。

### 测试目的与已知界面资源问题

仅缺图标不能停止全部工作；可独立登记启动、后台推进、只读仪器、输入准备和资源诊断。诊断挂载默认关闭，只能在允许的 instrument/safety vanilla 臂提供经 SHA 核对的本地原版图片及元数据，不修改游戏本体或模拟脚本。保留完整错误、挂载、来源、部署和恢复。

诊断通过不等于纯 vanilla、干净正式输入、无扰动或 M3/M4/M4-noise 许可；影响未独立验证时不得晋级。未知资源错误、脚本/模拟断言、来源污染、挂载和恢复失败继续停止，不用白名单或两臂共同失败凑合格配对。

## 6. 后续阶段的固定开发闭环

V0.2、V0.3、V0.4 都执行：冻结一个行为问题 → 选已支持接口和最小质量指标 → 独立开关/数据源 → 生成与定向测试 → G0/G1 → 模块 M1–M4 → 继承回归 → 玩家与观察者烟测 → ZIP/manifest/回退 → 版本记录。

- **V0.2**：先读 M1/M3/M5 证据，选一个外部安全或承诺接口；扩展数据显式接入生成器，不假定 extensions.toml 已支持外部模块。测试真实角色、资格、代价、进入/退出和保存；不同时开发市场或政治生产行为。
- **V0.3**：复用市场隔离侦察与 economic_dependence 来源，补实际角色、加入/退出、关系破裂代价和有利选择反例。tests/test_extensions.py、test_market_compare.py 及仪器/资格测试覆盖组合；market.enabled 只有出口通过后改变。
- **V0.4**：复用政治候选索引，补候选/方向/排名/风险/更新和最终组合语义；已触发断言的概率 getter 保持停用，只有新的安全调用依据才重开。test_political_surface.py、test_political_approval.py、test_extensions.py 及对应探针测试跟随改动；不能用强制立法代替实际行为。
- **V1.0**：只组合已通过模块，补可解释的冲突裁决和生命周期，不重建通用规划器；用多国、正常/危机、早期/真实后期/压力反例完成组合 M3/M4；核验解释、版本拒绝、同版本存档、卸载/回退和发布矩阵。工具跨平台与游戏 GUI 分层声明。

继承模块依赖未变化时重跑相关兼容回归并引用原证据；依赖变化或未知时重跑受影响出口，不能为提速跳过因果或用全部文件哈希变化强迫无关模块从零研究。每阶段保持一个主候选，至多一个独立研究问题；后续接口只读准备可并行，生产实现和实机不争用共享状态。

## 7. 验证、提速与日常执行

优先使用仓库 .venv 的 Python；macOS/Linux 将下列入口替换为 .venv/bin/python。下面都是当前真实命令，扩展接口实现后须通过 --help 和契约测试再写工具手册。

    .venv\Scripts\python.exe -X utf8 -m pdx.cli modgen --write
    .venv\Scripts\python.exe -X utf8 -m pdx.cli modgen --check
    .venv\Scripts\python.exe -X utf8 tools/ci/run_check.py baseline
    .venv\Scripts\python.exe -X utf8 tools/ci/run_check.py test
    .venv\Scripts\python.exe -X utf8 -m pdx.cli cov
    .venv\Scripts\python.exe -X utf8 -m pdx.cli package --output tools/out/releases/situated-ai-candidate.zip

数据/生成器变化按顺序 write→check，再测范围契约、baseline 和对应实机；普通纯文档按贡献指南检查编码、链接、事实和受影响文档测试，不堆文案镜像测试。完整 pytest 默认 -n auto --dist loadscope，worker 由 CPU/内存预算决定；并行测试耗时不是性能基准，基准串行并清除普通 addopts。

P0–P3 的规则、输入、实现、观测准备可在无共享写入、无正式测量争用时并行；R 层串行使用既有 RunLock、Deployment 恢复事务和 ExperimentLedger。先复核原件、回放和资格再启动；命令输入成功、后台 tick 和零错误分别记录。不得另建常驻服务、重复阶段 JSON 状态机或平行实验入口。

每个完整目的形成小变更与中文提交，经短期 codex 分支和 PR；不长期囤积待验收功能。记录从问题登记到有效样本、阶段包的端到端时间，以及启动/读档/分析/测试成本、有效样本比例、重复失败和资源峰值；本次没有前后性能对照，不承诺提速倍数。

## 8. 失败、重开与计划变更

| 变化 | 执行决定 | 记录 |
|---|---|---|
| 工程、编码、生成、引用或恢复失败 | 修相关源与入口，先重跑失效门禁；不手改生成物/黄金指纹凑通过 | 对应测试与工程审计 |
| 机会、输入或质量不足 | 标无法判定，停止依赖样本；继续独立观测/输入/接口任务 | M3/M5 结果和 backlog，附新前提 |
| 响应为零、方向相反或质量变差 | 停用候选，在同阶段换受支持接口或规则；保留全部阴性 | M3 结果，不扩大惩罚或事后改指标 |
| 有界路线连续被否证 | 形成最小否证包，登记替代接口、可观察效果、范围和重验任务；找不到安全闭环则阶段未完成 | 结果页与工作清单；不无限等待同一输入 |
| 资源、错误、存档或包烟测失败 | 不晋级、不建通过标签；用上一可玩包和处理前存档恢复 | M4/交付记录 |
| 游戏/依赖/源版本变化 | 指纹、分析/快照差分、受影响范围和重新生成，重跑相关工程与实机 | 兼容演练及对应结果 |
| 同阶段场景、参数或预算变化 | 开跑前登记新依据、有限上限和指标；已有样本不追认 | 相应实验预登记 |
| 用户改变目标或长期原则 | 才改主计划目标；说明版本、迁移、证据影响 | 本页与原则/设计 |

日常执行不需要反复重写总计划：结果、预算登记、下一任务写结果页和工作清单。发布、推送、合并按实际任务授权和贡献流程；设计任务的完成不自动等于公开发布许可。

## 9. 当前起点与整体完成定义

本次全仓重审覆盖受控目录、源码/测试入口、生成/打包契约、分析/快照、实验资格、自动化恢复和现有结果。工程最近一次完整结果为 3576 passed、19 skipped，4 worker，522.49 秒；覆盖率 89.19% 是 2026-10-13 历史读数，详见[工程收口审计](../../audits/2026-10-13-仓库原则收口.md)。本轮计划检查不刷新这组工程或 GUI 读数。

当前立即队列是 A1 开关/包契约，与独立 A2 输入复核、A3 质量观测补齐；A4 必须等资格，A5 正式候选必须等 M3。当前质量 unsupported、共同激活和自然机会不足、严格原版错误都有明确处理任务，不能用“没有输入”代替继续解决可测性。

**阶段完成**只看该版声明的启用模块、玩家路径、M1–M4、兼容回归和可恢复包是否全部通过。**整个 Mod 完成**还要求 V1.0 的内部、外部、市场、政治四类通用闭环、跨国家行为质量、组合稳定性、长期/真实后期性能、解释和正式交付都完成。研究 backlog 不必清零，但受引擎限制的缺项明示；局部财政包不能叫完整 Mod。

当前计划按 V0.1→V0.2→V0.3→V0.4→V1.0 执行，每阶段都有可玩版本。未达阶段出口就修复或否证同阶段候选，保留上版；不通过改名、统计、文档勾选或排除失败取得“完成”。

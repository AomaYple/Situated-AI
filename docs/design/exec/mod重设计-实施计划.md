# Situated AI 终极方案 3.0 实施计划

> 计划版本：19.0（2026-10-27）。这是当前唯一的 Mod 产品计划。
> 当前生产候选为 `Situated AI 1.3.0`，原版底本为 Victoria 3 `1.14.5`，Mod ID 为 `situated-ai`。
> 旧 `T0–T13`、`U0–U14`、`F0–F18` 只保留为历史工程收据；本计划尚未执行，等待用户下令。

## 1. 目标和完成定义

**Situated AI 让每个国家基于自身处境和可观测信息，在原版机制内持续做出符合自身约束与利益的相对最优决策。**

终极方案 3.0 要把这个目标落实为一条可追溯的生产链：原版事实经过来源、作用域、单位和时机核验，进入有限国家画像；各领域独立评估风险、能力、机会和约束；协调层处理预算、机会成本、路线惯性和冲击；最后只通过合法的原版 AI 消费者施加有界倾向，仍由原版负责资格、成本、随机性、谈判、执行和失败。

“尽可能全面”指尽可能完成发现、登记、合法读取、消费者映射和验证；不指把无法可靠读取的引擎内部状态假装成已知，也不指每次求值都扫描整个世界。没有独立价值、合法消费者或可控成本的事实保留原版、只作解释或标记为 `unsupported`。

本计划完成的工程出口是：生产源完整、字段和作用域经过锁定原版静态验证、标准 Mod 包可安装、生成和回退合同通过、文档与目录整合干净、Git 交付可追溯。长期游戏行为、数值平衡、游戏内性能、本地化呈现和 Workshop 页面由用户在固定包上验收，不被静态结果冒充。

## 2. 目标架构

```text
锁定原版事实和证据
    -> 信息目录与能力状态
    -> 有限国家画像与短期冲击
    -> 政治 / 财政 / 经济 / 市场 / 外交 / 军事 / 科技 / 社会 / 地理领域评估
    -> 生存优先的协调器（硬约束、预算、机会成本、路线、迟滞、冷却）
    -> 原版 AI 消费者中的有界增量
    -> 原版资格、成本、概率、谈判、行动和失败流程
    -> 解释、日志/存档辅助证据与可复核交付
```

架构分为七层：

1. **事实与证据层**：登记原版文件、行号、指纹、作用域、actor/target 方向、类型、单位、读取时机和成本。
2. **能力层**：把每个事实标为 `discovered`、`runtime_readable`、`derived`、`consumer_mapped`、`behavior_verified`、`retained_vanilla`、`explanation_only` 或 `unsupported`。
3. **有限国家状态层**：只保留具有独立决策价值且有生命周期的少量状态；普通事实优先在原版消费者求值时读取。
4. **领域评估层**：政治、人口社会、财政行政、生产产业、市场贸易、外交宗属、军事战争、科技教育、殖民地理、身份时间分别保持语义独立。
5. **协调层**：按生存、财政行政、政治稳定、安全、改革、经济、教育科技、外交、贸易殖民和长期发展排序，处理硬约束、影子预算、机会成本、路线惯性、迟滞和冷却。
6. **原版适配层**：每个原版字段只有一个 Mod 作者；只写已核实消费者的有界权重，保留原版零值、资格、费用、拒绝、随机和玩家路径。
7. **解释与交付层**：生成解释键、静态审计、包 manifest、日志/存档辅助分析、版本标签和安装材料；辅助证据不升级为行为质量结论。

## 3. 信息覆盖范围

执行阶段必须逐项盘点并给出处置，覆盖以下信息域：

- 政治：政府、利益集团、合法性、激进度、法律、制度、改革阻力和革命压力；
- 人口与社会：人口、职业、生活水平、识字率、迁移、文化、宗教、歧视、城市化和社会结构；
- 财政与行政：收入、支出、净结余、债务、贷款、利息、违约、破产、官僚、行政和机构承受力；
- 生产与产业：建筑、就业、工资、投入品、产出、生产方式、基础设施、投资池和供应瓶颈；
- 市场与贸易：价格、短缺、过剩、储备、运输、可达性、孤立、依赖、贸易路线和条约港；
- 外交与宗属：关系、外交博弈、威胁、联盟、防御承诺、宗主属国、自治、独立压力和依赖；
- 军事与战争：军队、海军、军费、军需、补给、战争目标、战损、战争负担、战后恢复和防御压力；
- 科技与教育：研究队列、已完成科技、技术阶段、教育机构、识字率、产业追赶和机会成本；
- 殖民与地理：港口、邻接、航线、战略位置、殖民机会、目标州价值、海外成本和海军投射；
- 身份与时间：本土/非本土、文化联系、宗教和身份结构、可靠的原版冲击变量、日期和时代窗口。

每个条目必须回答：原版依据是什么、运行期是否可读、作用域和单位是什么、未知如何回退、刷新成本是多少、能影响哪个合法消费者、是否需要持久状态、有哪些反例。

## 4. 生产设计约束

### 4.1 正确性、兼容性和速度

- 正确性第一、速度第二、内存第三；任何优化必须先证明输入输出、异常、回退、覆盖率和失败语义不变。
- 只使用锁定原版中存在且作用域、参数、方向和时机已核实的字段、触发器、效果、hook 和消费者。
- 不整体替换 Victoria 3 AI，不强制执行行动，不赠送资源，不绕过原版资格/成本/概率/谈判/失败，不改变玩家决策路径。
- 禁止每次求值的全世界扫描、Python 常驻进程、无界历史、无界缓存和重复状态；只在月度、明确 on_action 或必要消费者时机刷新。
- 状态必须有进入、保持、退出、TTL、冷却、存档默认、未知回退、禁用清理和测试；不具备这些条件的事实不得进入持久状态。
- 生成物不手改；TOML/登记表是唯一生产来源，Python 负责生成、验证、解释、打包和报告。

### 4.2 数值和决策

- 先做可行性过滤，再在同一量纲内比较风险、能力、收益和机会成本；不把所有事实机械相加成万能分数。
- 路线是动态、通用、可解释的，不按国家名称写死历史；同一国家在战争、财政危机、改革机会或市场变化后可以转向。
- 紧急生存路线可以抢占普通路线；普通路线必须满足财政、行政和安全影子预算，并保留唯一活动路线和冷却。
- 每个权重提供反例、边界、范围、敏感性和原版零值回退；负向调整不得制造全局 debuff。

### 4.3 本地化、跨平台和交付

- 源码、TOML、JSON、Markdown、测试和文档统一 UTF-8 无 BOM、LF；游戏 `.txt/.yml` 只在打包/安装边界加 BOM。
- Python 3.11+，支持 Windows、macOS、Linux；优先使用仓库 `.venv` 和成熟库，不把平台绝对路径写进生产源。
- 锁定版本支持的全部本体语言（当前为 11 种本体语言），统一键集合、语言头、占位符、路径和交付编码；未完成译文必须显式标记为未支持。
- 标准包只含安装所需的 PDX 文件、本地化、metadata、封面、manifest 和安装说明，不含 Python、探针、日志、缓存、快照、报告、原始底本或历史实验。

### 5.1 各阶段共同出口

每个阶段必须同时具备：生产源、生成入口、影响范围、定向测试、未知回退、唯一作者、编码/路径合同、证据分类和失败记录。E3/E7/E11/E15 的包必须可独立安装；包结构、manifest、语言、哈希和无探针合同必须通过。

### 5.2 观察器、日志和存档

`v3 observe`、日志解析、存档摘要、快照和根 hook 只用于辅助定位：记录实际发生的事件、变量、时间线和可观察差异。它们不能单独证明因果、历史合理性、数值平衡或长期性能。用户提供材料后，按 `runtime`、`snapshot`、`simulation`、`static_check` 和 `inference` 分开写入反馈收据。

## 6. 验证和提速方案

- 阶段开发只跑受影响测试；候选冻结后跑一次完整静态回归，避免重复全量运行。
- `pytest -n auto --dist loadscope` 只在测试身份、集合、覆盖率和失败语义不变时使用；资源报告记录实际 worker、墙钟、进程树 RSS、跳过项和覆盖率。
- 生成器、独立参考求值和 PDX AST 解释器必须做等价测试；任何性能优化都先通过等价、边界、异常、覆盖率和资源门禁。
- 本地扫描、文档生成、目录盘点和批量文本处理优先使用 Python；成熟库优先于手写解析器。
- 清理缓存和卫生检查放在测试之后；可再生输出写入 `tools/out/`，历史证据保留原始字节。
- 三平台 CI 负责 Python 静态合同；本机游戏启动、长期行为、后期资源和 Workshop 由用户验收，不被 CI 冒充。

## 7. 交付和维护

E15 只从通过静态门禁的主线提交创建版本 tag，保留历史 tag，不强推、不移动旧 tag。标准包从合并后的生产源重新生成，附 manifest 和 SHA-256；PR、提交、发布说明使用中文。游戏更新、可复现工程错误、用户日志/存档反馈和明确新需求分别进入维护版本，不把不同证据混为一类。

本计划落盘后，下一步只在用户明确下令时开始 E1；在此之前不把“计划已写好”写成“计划已执行”。

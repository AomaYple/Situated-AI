# Mod 全目标实现优先与集中验证计划 · 5.0

> **效力**：2026-10-17 按用户批准的七模块扩展方案更新。本页是唯一产品主计划，实施[处境决策设计](../03-处境决策设计.md)中的 **Situated AI：处境驱动国家决策扩展 1.0**。计划版本 5.0 与产品版本 V1.0 分别编号；本页替代 4.0 的四模块终版范围，旧版本从 Git 历史恢复，原始结果和实验账本继续保留。
>
> **优先级**：正确性第一、速度第二、内存第三。实现期保留必要的代码、生成、离线测试和恢复契约检查；集中实机、行为验收与正式性能在完整实现后进行。未经实机的引擎契约标记为假设，已知非法或被否证的读法不得复用。
>
> **当前边界**：四模块、组合、解释、生成和隔离打包已有代码；2026-10-17 已新增经济行政、外交目标与战争负担、宗主国与属国三个模块的离线参考模型、数据源、触发器、原版策略补丁和 `full` 七模块候选包。其真实接口、消费者作用域、跨模块反例、生命周期、行为质量和长期性能仍须核对；`full` 候选的 11 种语言结构已生成，旧实验包仍保留历史回退声明。七模块 F0 仍未完成。已有工程通过不构成新组合的实机或行为通过；本批没有新增游戏样本。

## 1. 目标、范围与完成定义

目标以[处境决策设计](../03-处境决策设计.md)及[Mod 开发原则](../../principles/Mod开发原则.md)为准：通过七个决策因素模块、统一仲裁、原版执行适配和解释交付，使国家根据真实处境作选择，并随世界变化重新评估。保留原版执行系统，后台自治，玩家无需 Python 服务或逐国指挥。

**1.0 范围封闭**：财政存续、外部安全与承诺、市场依赖、政治约束与身份偏好、经济与行政能力、外交目标与战争负担、宗主国与属国关系。1.0 之后进入错误修复、兼容、本地化和性能维护；新行为机制须另行批准版本范围，不能在执行中无限加项。战争创伤等新增世界模拟、通用长期规划器、完整法律排名、战术与寻路、具体建筑选址及贸易执行均不作为本次新增承诺；仍须完整实现上述七模块的核心效果，不能以引擎未知或删目标凑完成。

[工程原则](../../principles/工程原则.md)、[CONTRIBUTING.md](../../../CONTRIBUTING.md)和[工程基线](工程基线-1.0.md)约束工具、编码、跨平台、测试、性能、Git 与证据。无免费资源、强制行动、暴力削弱、全知信息或固定国家剧本；不承诺通用规划器、接管全部 C++ 决策或普遍最优。

| 阶段 | 要完成的事 | 出口含义 |
|---|---|---|
| **F0：全目标完整实现** | 补齐七模块、统一仲裁与原版适配、解释、全部语言翻译初稿、生命周期、玩家/存档契约、安装回退及必要工程验证 | 有来源的实现完整，可进入集中实机；仍是 experimental |
| **F1：集中验证与修正** | 加载与自动化、M1 接口、M2 生命周期和语言、M3 行为质量、反例与玩家路径；按证据定位并修复问题 | 对应模块与组合在声明场景内有效；不替代 M4 |
| **F2：稳定性、性能与交付** | M4 长期/后期/压力、速度/CPU/内存、存档恢复、兼容、包与版本核验 | 对应正式交付出口成立；不超出已验证版本、平台和场景 |

**顺序固定为 F0 → F1 → F2。** F0 不等待某一模块的行为质量通过才实现其它模块；接口来源审查属于实现期，集中实机在 F1。F1 发现问题后按受影响范围修复和回归，不从头重做全部计划；核心机制失效时替换该机制并保留无关有效实现和证据。实验包与已验收可玩包分别标识。

**现有包身份保持**：current/control/disabled 和现有 complete/fiscal/security/market/reform 的实际开关、四模块完整包及 manifest 不能因计划改版而冒充七模块；`economy`、`diplomacy`、`subjects` 和 `full` 已作为独立的七模块扩展候选变体接入，但 `full` 仍是 experimental/candidate。新增变体、命令或 manifest 契约须随生成器、CLI、打包和测试一起实施，并显式区分新旧配置；此处的产品里程碑不是现有 CLI 选项。

## 4. F1：集中验证与修正

### 4.0 启动决策、状态与阻塞

F0 出口后，每次实机先使用现有 `pdx.game_run` 核对游戏版本、包、输入、进程、用户目录、挂载、恢复指针、资源与原实验账本，并分类：

| 类型 | 启动条件 | 可支持的结论 |
|---|---|---|
| 正式行为样本 | 来源、输入、机会、预算、账本、挂载与恢复门禁全部满足 | 对应 M1–M4 的声明范围，失败照常计入 |
| 独立安全诊断 | 与被停止的样本独立，问题可由该诊断回答，使用同一安全事务 | 本次加载、界面、自动化、日志或恢复；不产生正式质量/性能资格 |

同输入/环境同类错误两次停止；既有 preparation、seed、新局配方及复制件的停止保持。新计划、新包、改名、改探针、资源增加、清记录或拼接会话不提供重开依据。真实独立输入、可核查环境变化或针对失败的因果修复仍由原规则判断。单项拒绝不泛化为所有实机都不可运行；仅缺图标时继续判断独立诊断，不改本体、不白名单错误。

每次要求实机都记录四态之一：`已启动并完成`、`已启动但诊断失败`、`启动前被具体门禁拒绝`、`尚未派发，属于执行遗漏`。附候选与输入 SHA、版本、实际命令、窗口、原始日志、截图和恢复结果；不得用“未验证”掩盖执行遗漏。未知错误、脚本/模拟断言、挂载污染或恢复失败按基线停止。

**2026-10-17 F1 实际执行记录**：`full` F1 候选已通过生成检查、版本/配置/进程/日志/资源静态门禁并生成 `tools/out/releases/situated-ai-full-f1-candidate.zip`。Windows 实机进程实际运行约 43.07 秒，记录阶段为 `startup`；用户在观察者、快捷键 `5`、空格推进和六游戏月采样前主动暂停。随后进程、部署指针、临时 Mod、日志、存档和 `content_load.json` 均恢复到启动前状态，RunLock 可重新获取。证据见 `tools/out/evidence/f1-full-smoke-20261017/20261017-104626/{live.json,pause-closeout.json,recovery-result.json,deployment.json}`。这次应标记为“用户主动暂停，启动阶段中断”，不归为诊断失败，也不产生加载、接口、行为质量或性能结论；后续从启动前门禁和一次完整烟测重新开始，源码未改变时不重复无关的完整离线回归。

### 4.1 最少重复的验证顺序

1. **静态与输入先行**：只重验相对 F0 已改变的源/接口和输入依赖；不在每局游戏前重复整套工程回归。先生成已支持的输入目录核验结果，正式资格不足时具体记录拒绝，同时判断独立诊断。
2. **一次启动烟测**：条件允许时同局完成完整包加载、观察者、快捷键 `5`、空格、至少六游戏月后台推进、日志归档与安全恢复；前台只保留必要输入。已有运行器不足时先补必要能力，不启动第二套自动化。
3. **M1/M2 合并采样**：同候选、同输入、同仪器且互不扰动的接口、生命周期和解释问题可在同次启动采集；单模块隔离验证后再验组合，不能从整包差异归因单模块。逐语言和玩家/存档路径按需要的状态分别运行。
4. **M3 集中配对**：先校准、控制先行 pilot，再按已冻结问题派候选；同局观察多个响应国，但不能把相关观测当独立运行。对照只有输入、世界、挂载、探针、参数和窗口均可复核一致时才能复用。
5. **修复与复验**：失败归类为实现、仪器、环境/输入或阴性质量结果；保留原件，只修已定位原因。代码修复重跑受影响门禁，阶段冻结再做完整回归；依法重验受影响场景，保持其它有效证据。

### M1 · 真实接口

核对七模块真实输入、作用域、字段组合、未知值、仪器扰动、仲裁与原版实际消费者；同时核对语言集合、路径/语言头/键覆盖及占位符。没有真实接口证据的字段仍是 unknown/unsupported，评分变化和根 hook 不能提升为行为质量。

### M2 · 生命周期、语言与可玩路径

有状态模块核对进入/持续/退出、重复触发、迟滞/冷却/TTL、过期清理、关闭和保存/重载；无缓存模块按事前声明验输入即时变化。验证国家切换、正常玩家新局/推进/保存/退出/重载和解释显示。

逐语言审校机制含义、原版术语、占位符、特殊字符与布局，逐语言记录加载、解释键和保存/重载。缺语言 GUI 模板时复用可用检查点、引擎与截图证据；需要新模板先补最小模板，不把中英模板范围当 11 语言实测，也不把结构覆盖当翻译质量。

### M3 · 有限行为实验与反例

- **M3-A 第三方响应**：同一机会、两个合格响应国、处理前状态及完整观测起止；受控机会单列，发布候选至少再有自然机会验证。
- **M3-B 自主发起**：研究范围内完整且可审计的合法候选分母；缺项不阻止独立 M3-A，未验自主发起字段不发布。aggression=0 不算自主发起优化已完成。
- 第一轮最多两个新检查点/场景，每场至少两个响应国、最多三组控制/处理配对，单臂最长六游戏月；失败计预算，不自动延长阴性窗口。
- 两个国家各至少三组有效配对，逐组报告评分、角色、加入/退出及采样时延、风险持续、债务/承诺、行动代价、放弃收益、不利结果、无变化和方向反例。正常防御/有利行动不得恶化，不靠极端参数制造效果。
- 政治另记录真实法律可行性、方向、风险和自主立法；IG/启动节奏不是完整排名，市场/安全支持不是资格或行动。正式财政注入为 none；版本、检查点、世界、挂载、源、探针、时间和资格匹配，只改变声明因素。
- 十类错误、额外文件错误、Mod 错误、来源和恢复门禁保持；变更假设/参数/预算事前登记，不追认失败、事后改指标或无限重试。预算内无收益则修改/替换该机制，保留其它模块和证据。

经济行政、外交目标与宗属关系不能硬套外交支持分母。每个新增行为在首次运行前登记自己的可行机会集合、决策单位、对照、观测窗口、实际行动、收益/代价和反例，并写入[完整候选结果](完整候选-结果.md)。沿用每场至少两个合格国家、各三组有效配对及首轮最多两个新场景、单臂最长六游戏月的有界探索；六个月不足以回答的问题另登记长期验证，不能事后延长阴性窗口。经济观察合法发展选择及财政/行政机会成本，外交观察目标/战争代价，宗属同时观察两侧的保护/依赖/自治结果。单模块归因成立后按共享输出与高风险冲突安排组合试验；七模块效果不能从四模块旧证据外推。

## 5. F2：稳定性、性能与正式交付

正式 M4 使用 M3 冻结候选。真实早期和至少一个真实后期检查点各三组 vanilla/候选配对，同速/窗口/探针/机器；先三次 vanilla 测噪声并冻结速度/CPU/内存预算，长期至少 24 游戏月。阶段增量包也必须满足适用的 M4，不把它延期到 V1.0 才做。

逐组报告模拟每游戏日耗时、CPU、RSS 峰值/趋势、状态残留、保存前后和可靠 ticktask_timings；不以 Python 基准代替游戏性能，不以早期长跑冒充真实后期。噪声超预算先修测量；OOM、泄漏和无界增长优先处理。优化先证明相同语义和证据完整，再比较速度；速度等效时选择低内存方案。

安装/禁用/卸载、重复执行、同版本保存重载、旧状态拒绝、兼容与恢复通过；全语言文本审校完成、`fallback_languages` 为空。回退依靠前包与处理前存档，卸载不撤销已发生战争/法律。Windows/macOS/Linux 的工具、CI、无头和 GUI 证据分开申报，未实测不写通过。

最终 ZIP/manifest 由 Python 生成，记录实际模块、版本、全部语言、SHA、来源、存档/兼容限制、安装/禁用/回退说明和平台证据。最终包与被验证冻结候选一致，适用工程、产品和交付门禁通过后才建通过标签或正式发布。

## 6. 验证提速与文件维护

详细方法只在[提速协议](速度优化计划-正确性优先.md)维护，不再设另一套产品排期：

- 测量端到端等待、打包、加载、模拟、分析、失败与有效样本成本；先消除重复和已知热点，再考虑架构优化。没有同口径测量不报提速倍数。
- 使用现有 .venv、Python、成熟库、分析/快照/生成/package/game_run/账本；不新增常驻服务、平行运行器、重复阶段数据库或无当前消费者的通用框架。
- 定向测试随实现，源码冻结时完整 pytest 默认 `-n auto --dist loadscope`，worker 按 CPU/内存预算；完整测试不减少选择集或断言。串行基准清普通 addopts，游戏、完整回归、剖析和正式性能错峰。
- 以实际源/包/版本/输入/探针/配置/窗口和环境依赖决定证据失效；提交 SHA、文档日期变化本身不触发全量重验。未知依赖不能当作相同，签名/哈希一致不替代运行语义。
- 清理只删确认无消费者的重复流程、临时产物和死代码；有引用的历史证据保留。受控文本 UTF-8 无 BOM、LF，游戏脚本 BOM 只在交付边界添加，原件依字节契约保留。
- 原则管持续约束，本页管顺序/出口，[当前工作清单](../当前工作清单.md)管事实与下一步，结果页管命令/输入/失败。旧流程通过 Git 历史恢复；不同时维护两套当前计划。短期 codex 分支/PR、中文提交，交付按 CONTRIBUTING 执行。

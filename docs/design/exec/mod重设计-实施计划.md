## 目标与职责

Situated AI 通过锁定 Victoria 3 原版中可发现、可由脚本访问的处境信息，给原版 AI 消费者提供有限、可解释、
可回退的增量。政治、人口、财政、经济、市场、贸易、外交、宗属、军事、战争、殖民、地理、身份和世界状态
都可以进入信息目录；只有存在合法原版消费者的事实才进入运行期规则。

助手负责：

- 维护 `mod/decisions/*.toml`、规则适配器和生成器，扩展信息域与 AI 倾向；
- 使用锁定原版字段、触发器、效果、作用域、路径和本地化契约，拒绝未知接口和版本漂移；
- 运行静态分析、快照、离线门禁、生成、打包和跨平台 Python 工程检查；
- 根据用户提供的游戏日志、版本、存档和最小复现辅助定位与修复，并把证据边界写清楚。

用户负责：

- 启动游戏、启用标准包、观察者长期运行和跨平台 GUI 验收；
- 判断 AI 行为方向、数值平衡、长期性能、语言呈现、存档迁移和创意工坊结果；
- 发现问题后提供原始日志、游戏版本、启用 Mod 集和最小复现，作为后续修复输入。

仓库不再把 GUI 自动化、压力长跑、行为探针或持续游戏会话作为默认工程出口。它们的历史代码和读数已经退役；
可复用的日志解析、快照和静态检查仍保留，用于分析用户提供的证据和保护生成合同。

## F2：按信息域扩展 Mod（持续执行）

每次扩展都走同一条短路径，先保证工程正确，再交给用户观察：

1. 从锁定原版和信息目录选择一个可证实的事实域，写明来源、作用域、单位、未知值和失败回退。
2. 在 `mod/decisions/*.toml` 增加声明式规则与唯一消费者适配器；不把不可比较的单位相加，不写国家名称专属路线。
3. 用 Python 生成 PDX 脚本、本地化和 manifest；运行字段、路径、引用、玩家边界、编码和确定性门禁。
4. 运行相关单元/合同测试、离线 baseline 和包校验；必要时更新快照与结果页，记录 `static_check` 或 `snapshot` 证据类型。
5. 生成新的标准包交给用户进行长期观察。用户反馈日志和最小复现后，再针对性修复，不用模拟或短跑替代行为结论。

优先扩展财政与行政、法律与利益集团、市场与贸易、外交与宗属、军事与战争、科技与人口、地理与身份等域；
每个域必须复用原版消费者并设有频率、状态生命周期和回退边界。正确性第一、速度第二、内存第三，任何优化都要有同口径测量。

## F3：用户反馈修复与版本维护

- 用户提供日志时，先确认游戏版本、启用 Mod 集、日志时间和复现步骤，再区分脚本错误、静态误判、运行期语义和数值体验。
- 只把可复现的工程问题回写源数据、生成器或门禁；行为/平衡建议必须保留原版合法性和玩家边界。
- 每个修复版本从当前主线创建 `hotfix/<topic>`，更新版本、生成锁、结果页和标准包；不改写已发布标签的历史字节。
- 工坊发布、长期性能和跨平台 GUI 由用户验收，仓库只记录用户提供的原始证据和明确限制。

## 证据边界与完成定义

静态检查、原版快照、脚本解析、包安装、评分变化、根 hook、一次短跑和 Python 基准只能证明各自的工程或观测事实，
不能证明 AI 行为质量、平衡、长期稳定性、玩家体验或创意工坊结果。结果页必须标注 `static_check`、`snapshot`、
`simulation`、`runtime` 或 `inference`，不能把跳过、不可核对和推断写成通过。

当前任务完成的定义：F1 的仓库清理、文档收口、静态门禁、标准包和 Git/CI 出口全部完成；F2/F3 按用户反馈持续推进，
直到用户另行指定版本目标。Mod 是否达到预期行为，仍以用户在标准包上的长期验收为准。

# mod 重设计实施计划

> **状态**：2026-10-05 M2真实财政实现、M3评分读数和M4卸载已有实测；本轮补齐政治策略门槛观测、财政输入对照、比较器和正常退出收尾。长期/后期、修复后完整 n-auto 与扩展行为质量仍未宣布完成。
> 当前方向见 [处境决策设计](../03-处境决策设计.md)，工程继续复用 [工程基线 1.0](工程基线-1.0.md)。
> 本页记录 mod 制作顺序；运行证据与结论以各里程碑结果页为准。

## 1. 首个闭环

首选“财政与外部风险如何改变高风险外交倾向”。先验证财政状态与目标关系的可读性，
以及 `aggression`、`secret_goal_scores` 等候选字段的作用域、组合语义和行为带宽。
这里列的是候选接口，字段名存在不等于本模组已实测有效。

闭环只覆盖明确条件下的外交风险判断，不承诺接管建造、市场选择或军事调动。
先固定目标范围与小量候选行为，再建立实际外交行动的观测窗口和机会计数；
不能只用策略切换或一次未宣战作为成功判据。

国家样本按可重复开局、有效外交机会与不同内部结构选择，最终至少两个国家共享同一规则。
筛选结果写入接口实验记录，不提前固定国家标签来决定输出路线。

## 2. 实施顺序与出口

| 步骤 | 产出 | 出口判据 | 当前状态 |
|---|---|---|---|
| M0 设计收敛 | 当前设计、文档导航、工程复用范围与欠账 | 新旧设计效力清楚，未实现能力不写成事实 | 已完成文档更新 |
| M1 接口实验 | 输入/作用域/字段清单及最小实机对照 | 正确读状态，字段变化能造成可解释行为差分 | **接口与观测链完成；因果差分待 M3**（见 [M1 结果](M1-结果.md)） |
| M2 最小实现 | 通用条件与参数、生成模板、统一写入与生命周期 | 相关工程门禁通过，边界和重复触发可验证 | 真实财政规则已实现、两国生命周期已验证；最终门禁收口中（见 [M2 结果](M2-结果.md)） |
| M3 跨国家反事实 | 两国共享机制，多输入对照与行为记录 | 改变一个输入产生合理差分，失败与波动如实报告 | 旧严格结论收窄；日期采集根因已修复，新强依赖配对通过10类门禁且两国评分方向有效，实际行为质量继续验证（见 [M3 结果](M3-结果.md)） |
| M4 稳定性与性能 | 长期、压力、安装与存档迁移结果 | 无路线抖动或残留，CPU/内存与帧尖峰可接受 | 保存/重载、卸载TTL和后台引擎计时已实测；完整错误及后期性能出口继续验证（见 [M4结果](M4-结果.md)） |
| M5 扩展 | 政治改革、市场依赖等独立闭环 | 每个模块重复 M1–M4 后再扩国家覆盖 | 两个实验默认停用；政治活动策略与推进档位观测已实测，全局正控仍未启动立法；市场两国强依赖评分已获有效差分、加入结果相同（见 [M5结果](M5-结果.md)） |

M1 不成立时先收窄目标或换接口，记录否证；不通过增加压力修正或扩大国家数量掩盖接口无效。
不为新路线启动外部 Python 常驻规划器；不把旧阶段完成标记搬成 M1–M5 已完成。

## 3. 旧实现迁移约束

优先处理 backlog B130–B136。迁移要明确停用范围和时点：旧世界修正、JE 强制递牌、空行为策略和
全局重抽参数不能无说明地混入新机制对照。先保持已有实验资产可恢复，再逐模块替换。
旧变量、长期修正与持牌状态在存档中的清理单独验证，不把文件卸载等同于存档恢复。

生产源在 `mod/decisions/`，旧九国源 `mod/data/` 只生成至 `mod/legacy/`，不进入生产ZIP。
后续修改先从最小数据/模板适配开始，保持入口与编码契约；无相关缺口不另建分析或自动化工具。

## 4. 验证与记录

使用仓库 `.venv` 的 Python，在各平台按 [工程基线](工程基线-1.0.md) 运行相关测试和离线基线。
文档只更新方向与状态时检查编码、链接、生成一致性和既有文档契约，不新增重复文案的测试。
实际行为实验使用现有实机自动化、快照和测量工具，执行前按 [自动化范式](自动化范式.md) 核对环境恢复规程。

每步完成后新增对应结果记录，并在本页更新状态和链接。结果写清游戏/工具版本、实验条件、
对照组、输入、实际持牌与行为、指标、失败、性能和原始证据位置。
M0 的文档检查不能用于宣布 M1–M5 通过；跨平台工程通过不能用于宣布各平台 GUI 实机通过。

# Mod 完整候选实现与集中验证计划 · 3.0

> **效力**：2026-10-17 根据用户要求重写。本页仍是唯一产品主计划，替代 2.0 的“先验收前一模块，才实现下一模块”依赖。先完成整个目标的实验候选实现，再集中实机验证和修正。旧计划从 Git 历史恢复；结果页、原始证据和账本保持。
>
> **优先级**：正确性第一、速度第二、内存第三。开发期保留代码、配置、生成、生命周期和恢复检查；行为质量与长期性能不再阻止其它独立模块实现。未经实机的接口是假设，已知非法或已被否证的读法不复用。
>
> **事实边界**：完整实验候选已接通四模块、组合、解释和隔离交付；工程验收以结果页为准。新组合的实机运行、行为质量与正式性能尚未完成。本次重写不增加样本、不修改历史失败，也不把候选当已验收发布。

## 1. 目标与三个完成点

目标沿用[处境决策设计](../03-处境决策设计.md)：增强原版 AI，使国家依据内部存续、外部安全与承诺、市场依赖、政治约束和偏好选择，并随世界变化重新评估。原版系统负责执行，玩家不需要 Python 服务或逐国操作。

持续约束见[工程原则](../../principles/工程原则.md)、[Mod 开发原则](../../principles/Mod开发原则.md)；流程见 [CONTRIBUTING.md](../../../CONTRIBUTING.md)，工具与证据见[工程基线](工程基线-1.0.md)。不提供免费资源、强制行动、暴力削弱、全知信息或固定国家剧本。

| 完成点 | 必需结果 | 不代表 |
|---|---|---|
| 完整候选实现完成 | 四类因素、组合、开关、解释、生成、必要测试、实验 ZIP 与回退接通 | 已经实机运行或行为改善 |
| 实机运行修正完成 | 加载、后台推进、玩家路径、保存/重载、退出清理和解释可用 | 行为质量与长期/后期性能通过 |
| 整个 Mod 验收完成 | 模块与组合 M1–M4、反例、兼容、运行效率和正式交付通过 | 超过实际版本/场景/平台的普遍最优 |

完整候选可组合尚未行为验收的模块，始终标为 experimental。候选开关不等于正式启用；current 和默认安全包不因完整候选存在而悄悄改变。

## 2. 整体实现范围

| 模块 | 真实输入和行为 | 边界 |
|---|---|---|
| 财政存续 | 违约、借款、信用、破产周数；迟滞/TTL，在外部暴露时提高中立倾向 | 保留原版策略和资源；aggression 保持 0，不扩大为未验的自主发起干预 |
| 外部安全与承诺 | 博弈双方、联盟/防御条约、相邻国家与征服/附庸目标；在支持评分中表达防御责任和安全风险 | 只保护明确防御方；同类原因取最高贡献；不强制参战。保证独立的方向未核实前不接入 |
| 市场依赖 | 对双方的原版 directional economic_dependence 差值与有限权重 | 保留 0–5 标度、反对称性与未知边界，不改市场或资格 |
| 政治约束与偏好 | 合法性、战争、叛乱、执政 IG；调整原版立法启动节奏 | 原版继续选择法律/路线，保留 IG/国家偏好；不冒充完整法律排名，不强制立法 |
| 组合与解释 | 同一个锁定默认策略补丁合并贡献；生成中英实际配置、条件和原因 | 财政中立、外部/市场支持、政治节奏分工明确；解释不是最终概率或行动结果 |

这是对整个目标的有边界实现，不承诺通用规划器或接管全部 C++ 决策。候选必须依据当前原版资料与作用域实现，明确未验证假设；不能只写 Python 模型而不生成游戏脚本。

## 3. 第一阶段：完整实验候选实现

此阶段不以 A3/G1/M3 质量通过作为其它独立实现的前提。A1–A5 保留为历史证据分类，不再构成跨模块开发队列。

### C1 · 数据、配置与隔离变体

**入口**：`mod/decisions/*.toml`、`src/pdx/decisions.py`、`src/pdx/distribution.py`、`src/pdx/cli.py`。

- [x] 扩展严格配置校验，提供外部模块开关、有限权重和依据，保持旧配置与调用兼容。
- [x] 现有 package 入口增加完整候选与单模块隔离变体；默认仍为 disabled，current/control 原含义保持。
- [x] manifest 记录实际模块、参数、源与生成器指纹；候选强制 experimental，不借用正式版本身份。

### C2 · 四模块与组合

**入口**：生成器、职责明确的外部模块辅助文件；相关测试放 `tests/`。

- [x] 复用原版 treaty、角色、相邻和 war goal 用例生成有界防御贡献；缺 ROOT/双方时不干预。
- [x] 财政、外部、市场、政治都进入完整变体；共享字段由一个补丁入口合并，原版其余内容逐字保留。
- [x] 检查实际生成脚本的条件分支、攻击/防御方向、无承诺、依赖对称性、未知输入、玩家边界、关闭与组合，不仅测试参考公式。
- [x] 源改后运行 modgen --write、modgen --check；实验变体写入忽略的输出目录，不污染 current。

### C3 · 解释、可安装包与实现冻结

**入口**：`src/pdx/explanation_probe.py`、`src/pdx/distribution.py`、CLI、对应测试。

- [x] 复用原生国家面板候选，为四模块生成配置/当前条件和中英说明，底本版本/SHA/覆盖成本可追溯。
- [x] 完整实验包包含实际玩法、解释、manifest、SHA、安装/禁用/存档回退说明；玩家无需 Python。
- [x] 受影响静态检查、离线 baseline、完整 n-auto/覆盖率通过；新增 Python 路径串行测速度和内存，报告成本，不虚构收益。
- [x] 冻结完整候选、配置与待验清单后进入第二阶段。某模块的待验结论不阻止其它独立实现。

先为真实行为与异常补测试，观察缺能力失败，再实现并跑定向回归。实现过程中不反复完整回归；源码批次冻结后集中运行。准确新增 CLI 命令随实现更新工具手册，不提前写不存在的选项。

## 4. 第二阶段：集中实机运行与修正

完整候选形成后，沿用 pdx.game_run、RunLock、Deployment、ExperimentLedger 串行运行：

1. **加载与安全**：核对版本、输入、挂载、恢复和资源；完整包进入新局、观察者、快捷键 5、空格、后台推进。定位具体模块错误，修源/生成/定向检查后按合法条件重验。
2. **生命周期与解释**：财政进入/保持/退出/TTL；其它模块直接读值，无缓存时说明不适用；核验保存/重载、重复触发、AI/玩家、国家切换、关闭和中英说明。
3. **模块隔离与组合**：分别验证财政、外部、市场、政治接口与实际作用域，再检查组合；不能用整包差异归因单模块。
4. **玩家可玩路径**：正常国家新局、推进、保存、退出、重载继续；观察者烟测至少六游戏月，前台必要输入结束后回后台。

安全/仪器运行按自身问题登记，不要求先有正式质量样本；未校准字段仍为 unknown/unsupported。停止只约束依赖该状态的运行，独立离线工作继续。

已停止的 preparation、seed、新局配方及复制件，不因新计划、新源码或资源恢复重开。派发前核对真实独立输入、可核查环境变化或针对失败的因果依据，依原账本决定；不改错误分类、不清记录、不换名重试。无合法前提时输出具体拒绝，同时完成其它独立任务，不能只等更新。

## 5. 第三阶段：行为质量与迭代交付

<a id="11-增量可玩版本路线"></a>

V0.1 财政、V0.2 外部、V0.3 市场、V0.4 政治、V1.0 组合保留为**验收/交付里程碑**，不再是后续模块代码实现的门。完整实验候选先形成；每验收一个部分，交付对应可玩增量包并保留上版回退。未验模块不进入已验收包，候选不充当已验证父版。

### M1、M2：接口与生命周期

M1 核对真实输入、作用域、字段组合、未知值和仪器扰动。M2 核对进入/持续/退出、重复触发、迟滞/冷却/TTL、保存/重载和过期清理；直接读值、不需要缓存的模块事前说明原因，不增加无用途持久状态。

### M3：有限实验与质量

- 第三方响应 M3-A：同一机会、两个合格响应国、处理前状态和完整观测起止；受控机会单列，至少再有自然机会验证发布候选。
- 自主发起 M3-B：研究范围内完整且可审计的合法候选分母；其缺项不阻止独立 M3-A，未验自主发起字段不发布。
- 第一轮最多两个新检查点/场景，每场至少两个响应国、最多三组控制/处理配对，单臂最长六游戏月；先校准、控制先行 pilot、再正式配对，失败计预算。
- M3 要求两个国家各至少三组有效配对，逐组列评分、角色、加入/退出及采样时延、风险持续、债务/承诺、行动代价、放弃收益、不利结果、无变化和方向反例。正常防御/有利行动不得恶化，不靠极端参数制造效果。
- 政治另记录真实法律可行性、方向、风险和自主立法；IG 代理/启动节奏不冒充完整排名。外部/市场支持不冒充资格或真实行动。
- 匹配版本、检查点、世界、挂载、源、探针、时间和资格，只改变声明因素；正式财政注入为 none。十类错误、额外文件错误、Mod 错误、来源和恢复门禁保持。
- 同输入/环境同类错误两次停止；变更假设/参数/预算在下一场前登记，不追认失败、事后改指标或无限延长阴性窗口。

预算内无行为收益就修改或替换该机制，保留其它模块实现和独立证据；观测工具只补当前问题必需字段，不以完整复制引擎内部系统为所有开发的前提。

## 6. 第四阶段：稳定性、性能与正式交付

正式 M4 使用 M3 冻结候选。真实早期和至少一个真实后期检查点各三组 vanilla/候选配对，同速/窗口/探针/机器；先三次 vanilla 测噪声并冻结速度/CPU/内存预算，长期至少 24 游戏月。

逐组报告模拟每游戏日耗时、CPU、RSS 峰值/趋势、状态残留、保存前后及可靠 ticktask_timings；不以 Python 基准代替游戏性能，不以早期长跑冒充后期。噪声超预算先修测量；OOM、泄漏、无界增长优先修复。

安装/卸载、重复执行、同版本保存重载、旧状态拒绝、兼容和恢复必须通过。回退依靠前包与处理前存档，不声称卸载撤销战争/法律。三平台工具、CI、无头和 GUI 分开申报，未实测不写通过。

仅缺图标不能关闭全部实机；按工程基线可独立诊断资源，不改本体、不白名单错误，不把诊断挂载冒充纯原版或正式样本。未知错误、断言、挂载污染和恢复失败按契约停止。

最终 ZIP/manifest 由 Python 生成，包含实际模块、版本、存档/兼容限制、安装/禁用、SHA、来源和平台证据。对应包真实测试且全部出口成立，才建立通过标签或正式发布。

## 7. 日常执行与完成定义

- 唯一主计划管顺序和出口；[当前工作清单](../当前工作清单.md)管事实；M1–M5/A1–A5 管结果；[提速附件](速度优化计划-正确性优先.md)只补方法，不另排期。

- 相同树不因文档时间/提交 SHA 重跑整套；修改后按依赖重验。必要正确性修复不包装成性能收益。
- 短期 codex 分支和 PR、中文提交；推送/合并按已有授权与贡献流程，不强制推送主线。CI 不能替代产品验收。
- 每轮留下实际源码、包、检查或实机事实；未完成实现就继续实现，实机问题按原因修复。外部阻塞具体到输入/接口/环境，继续不依赖它的任务。
- 不新增常驻服务、平行账本、重复阶段状态机或第二套产品计划；工程整理不能当 Mod 功能完成。

整个计划完成要求四类因素实现、组合与解释、模块 M1–M4、跨国家反例、正常防御/有利行动、长期/真实后期/压力性能、玩家路径、存档、恢复、兼容与正式交付全部完成。实现完成、实机运行完成、质量完成分别报告；未知不填零，不删目标或放宽指标凑完成。

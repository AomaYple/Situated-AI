# Situated AI 1.0.1 当前交付与后续计划

> 版本：9.2（2026-10-24）
> 当前出口：助手负责 Mod 源、生成链、原版接口合法性和静态工程正确性；用户负责长期游戏行为、平衡、后期性能、GUI 和工坊验收。

本页是唯一当前产品计划。旧的 F0–F3、M1–M5、阶段实验和长期 GUI 自动化记录只在 Git 历史中保留，不构成新的待执行队列。
持续约束见[工程原则](../../principles/工程原则.md)、[Mod 开发原则](../../principles/Mod开发原则.md)和
[CONTRIBUTING.md](../../../CONTRIBUTING.md)。

## 最终目标

**Situated AI 让每个国家基于自身处境和可观测信息，在原版机制内持续做出符合自身约束与利益的相对最优决策。**

“相对最优”指受信息、能力、政治阻力、财政成本、外部威胁和原版规则约束的情境最优，不是全知的全局最优，也不是固定国家剧本。
计划的产品出口是一个可安装、可生成、可审计、保留原版资格与执行的 Mod；行为质量仍由用户在标准包上长期观察。

## 交付原则

1. 正确性第一、速度第二、内存第三；任何提速都要先证明字段、作用域、回退、输出和证据契约不变。
2. 先硬约束、后软评分；先国家状态画像、再跨域组合；未知事实不猜测，回退原版。
3. 每个阶段都产出可加载的完整标准包；探针只能放在明确标记的诊断包，不进入生产包。
4. 原版 AI 保留资格、成本、随机性、政治博弈、行动执行和失败处理；Mod 只提供有限、可解释的倾向增量。
5. 每个信息域和消费者都要有唯一作者、来源、作用域、单位、刷新时机、性能预算和验证边界。
6. 工程检查、快照、脚本加载、评分变化和根 hook 只证明各自事实，不能升级为行为、平衡或玩家体验通过。

## 统一实现主线

所有扩展都沿同一条有界数据流实现，不再按国家名称堆叠脚本：

```text
锁定原版可观察接口
    → 信息目录（来源、作用域、单位、刷新、未知值、成本）
    → 国家状态画像（硬约束、能力、压力、机会、结构、冲击）
    → 原版候选消费者（资格和执行仍由原版负责）
    → 单字段有界权重与解释
    → 静态合同、包门禁和用户实机反馈
```

信息目录按政治、社会与人口、财政与行政、生产与建筑、市场与贸易、科技、外交与宗属、军事与战争、
殖民与地理、身份与文化、时间与冲击登记；目录中的事实只有在原版字段、作用域和消费者均能证明时才进入
运行期。不同单位不直接相加，未知值保留 `unknown` 并回退原版。

为了保证推进速度，每次扩展只选择一个消费者集合，先生成一个完整可安装包，再集中执行一次固定验证矩阵；
重复扫描、无界组合、常驻服务和无证据的游戏自动化不进入默认路径。离线合同和生产合同必须调用同一份规则
合同生成器，防止 CI 与有游戏环境出现语义漂移。

## F2：信息底座与国家状态画像（当前主线）

目标是把“能读取什么”与“如何影响什么”分离，并将可发现信息归一到可组合的国家画像。

1. 冻结 `1.0.1` 生产基线、原版 `1.14.5` 指纹和当前规则报告。
2. 盘点政治、社会、人口、财政、行政、生产、市场、贸易、科技、外交、宗属、军事、战争、殖民、地理、身份和时间事实；每条登记来源、作用域、单位、更新时机、未知值和成本。
3. 将事实分为硬约束、能力维度、短期压力、长期结构、外部机会和冲击输入；不同单位不直接相加，并为每条事实登记反例。
4. 生成国家画像合同和解释报告，标明 `discovered`、`runtime_readable`、`derived`、`consumer_mapped`、`unsupported` 和 `behavior_verified` 状态；画像只保留有界维度，不保存无界世界状态。
5. 只把已有合法原版消费者的事实接入运行期规则；没有消费者的事实留在目录，不伪造影响。
6. 对每个消费者集合建立“事实 → 画像维度 → 候选字段 → 原版执行”的覆盖表，并检查唯一作者、单位一致性、上/下限、未知回退和解释文本。

出口：静态信息目录、国家画像合同、`decision-audit` 报告、离线门禁和一个可安装的增量包。

## F3：约束优先的多目标决策层

将现有分散规则统一为可解释的候选评估顺序：

```text
原版资格/能力硬门槛
    → 生存与稳定
    → 财政、经济与市场收益
    → 军事与外交安全
    → 长期结构和国家偏好
    → 政治可行性与阻力
    → 成本、风险、路线冲突和原版尾部限制
```

- [ ] 为每个候选字段声明输入、单位、方向、上限、下限和反例。
- [ ] 统一优先级仲裁，禁止多个模块对同一生产字段重复作者。
- [ ] 先接经济、财政、行政和建筑，再接市场与贸易；每次扩展都生成新包并运行完整工程门禁。
- [ ] 维持 `is_ai = yes` 边界和未知值原版回退；不把国家名称变成唯一条件。

## F4：政治结构与制度可行性

- [ ] 接入利益集团力量、政府组成、合法性、批准度、激进度、革命风险、改革能力和改革阻力。
- [ ] 将“想要改革”和“政治上能通过改革”分开评分；不把保守国家永久锁死，也不强制立即改革。
- [ ] 通过原版法律和政府消费者影响立法候选权重，保留意识形态、资格、协商和失败机制。
- [ ] 形成俄罗斯式“外部失败提高改革收益但仍受保守阻力约束”的可解释合同。

## F5：外交、宗属、军事、殖民和地理联动

- [ ] 在经济与政治基础稳定后，逐个接入外交关系、联盟、宗主/属国、外交博弈、军力、补给、前线、港口、资源和殖民机会。
- [ ] 防御承诺、贸易依赖和战略位置只改变原版候选价值，不创造资格、不强制参战、不替换战争执行。
- [ ] 形成荷兰式贸易金融、普鲁士式军工统一、奥地利式多民族治理等由结构推导的路线差异，不写国家专属剧本。

## F6：冲击、记忆和路径依赖

- [ ] 把战争失败、市场危机、外交羞辱、革命、改革成功/失败和资源断供登记为有来源的冲击。
- [ ] 普通波动平滑调整，重大冲击才突破惯性；必要的冷却和切换成本必须有生命周期与性能预算。
- [ ] 若使用持久状态，明确 TTL、保存兼容、禁用清理和版本迁移；没有这些条件就只使用当前事实重算。
- [ ] 生成规则解释，能回答“哪些事实提高/降低了候选、哪些输入未知、哪些部分仍由原版决定”。

## F7：验证能力补完与集中验证

仓库负责工程可证明性，用户负责长期行为验收。验证按成本从低到高集中运行：

1. 编码、卫生、文档链接、类型、lint、deadcode 和 TOML schema。
2. 原版字段、作用域、路径、唯一作者、玩家边界、未知回退和确定性生成。
3. `decision-audit`：默认复用一次生产构建；`--offline` 从入库源和锁定底本构造同一份报告，并复用同一 `decision_rules.contract()` 规则合同；输出所有信息域、读取器、规则、消费者和反例连接，禁止缺少解释的规则进入包。
4. `modguard --offline`、快照 verify、candidate coverage、包 manifest、语言、BOM/LF、ZIP 和安装字节。
5. 同一候选包集中运行单元、合同、属性、CLI、回归、性能和内存测试；默认使用 `-n auto --dist loadscope`，记录实际 worker、选择集、覆盖率、墙钟和 RSS；基准测试保持串行并清除普通 pytest 参数。
6. 有用户日志后运行 `crosscheck` 和日志分类；不能从没有日志推断运行期行为。

验证输出必须标注 `static_check`、`snapshot`、`simulation`、`runtime` 或 `inference`。静态通过不升级为 AI 行为通过。

## F8：版本化交付与用户反馈

- [ ] 每个阶段生成可安装标准包，生产包无 Python、探针、日志、缓存和历史实验。
- [ ] 用户提供游戏版本、包 SHA-256、启用 Mod 集、存档/新局条件、复现步骤、原始日志和期望行为。
- [ ] 助手先分类工程错误、运行语义、数值平衡和体验反馈；只把可复现工程问题回写源、生成器或门禁。
- [ ] 修复版本从主线创建 `hotfix/<topic>`，更新版本、锁、结果页和包；不改写已发布标签。

## 当前执行顺序和完成定义

当前执行顺序为 **F2（信息覆盖表与画像）→ F3（经济/财政/行政消费者）→ F4（政治与制度）→ F5（外交/宗属/军事/殖民/地理）→ F6（冲击与路径依赖）→ F7（验证矩阵）→ F8（版本化交付）**。每个阶段完成后必须有：

- 一个可安装、可加载、无已知低级字段/路径/编码错误的完整标准包；
- 一份由 Python 生成的规则/验证报告和结果收据；
- 对应测试和资源读数，或明确记录无法测量的边界；
- 用户可据此进行长期游戏观察的版本出口。

“计划完成”只表示仓库工程链、Mod 合法性、解释合同和发布包完成；AI 是否产生历史合理行为、长期平衡、后期性能、跨平台 GUI 和工坊结果，仍以用户实机证据为准。

## C. 门禁：全绿（缺一不可）

### C.0 交付物先过"机器判据"（血的教训）

**不许用 grep/肉眼"看到关键字"就算交付物合格**——实测发生过：某交付的 `.py` 是
**UTF-8 带 BOM + 双重编码（有损）**，`grep` 照样能匹配到 ASCII 标识符，但 `ast.parse` 直接
`SyntaxError`、`import` 全废。所以每个新增/改动的 Python 交付物必须先过：

```powershell
.venv\Scripts\python.exe -c "import ast,pathlib,sys; [ast.parse(p.read_text(encoding='utf-8')) for p in map(pathlib.Path, sys.argv[1:])]" <文件...>
.venv\Scripts\python.exe -c "import importlib; importlib.import_module('pdx.game_auto')"
# 编码：仓库 .py 一律 UTF-8 **不带 BOM**、LF
```

判定：`ast.parse` / `import` 通过 + 无 BOM + ruff/format/mypy 绿，才算"文件存在且可用"。

```powershell
.venv\Scripts\python.exe -m ruff check .
.venv\Scripts\python.exe -m ruff format --check .
.venv\Scripts\python.exe -m mypy
.venv\Scripts\python.exe -m pytest -q -n 4
.venv\Scripts\v3.exe verify            # 不带 --fast：全树扫描
.venv\Scripts\v3.exe tables
.venv\Scripts\v3.exe ai-surface --check
.venv\Scripts\v3.exe modgen --check    # 盘上产物与数据源逐字节一致（P3；不读游戏，CI 也跑）
.venv\Scripts\v3.exe cov               # 整体 ≥86% + 各模块下限（FLOORS 只升不降）
.venv\Scripts\v3.exe modguard          # 五道闸门
```

**一条命令跑完（复制即用，遇红即停）** —— 判据只看**每条自己的结论行**，不看聚合退出码：

```powershell
$gates = @(
  @('python','-m','ruff','check','.'),
  @('python','-m','ruff','format','--check','.'),
  @('python','-m','mypy'),
  @('python','-m','pytest','-q','-n','4'),
  @('v3','verify'), @('v3','tables'), @('v3','ai-surface','--check'),
  @('v3','modgen','--check'), @('v3','cov'), @('v3','modguard')
)
foreach ($g in $gates) {
  $exe = if ($g[0] -eq 'v3') { '.venv\Scripts\v3.exe' } else { '.venv\Scripts\python.exe' }
  $args = if ($g[0] -eq 'v3') { $g[1..($g.Count-1)] } else { $g[1..($g.Count-1)] }
  Write-Host "`n===== $exe $($args -join ' ') ====="
  & $exe @args 2>&1 | Select-Object -Last 4
  if ($LASTEXITCODE -ne 0) { Write-Host "[RED] exit=$LASTEXITCODE —— 停下，先修这一条" -ForegroundColor Red }
}
```

⚠️ **`v3 cov` 的退出码暂时不能当判据**（backlog B42：判据行打绿、退出码却可能是 1，
多半是它内部那次 pytest 的 xdist 偶发）。报覆盖率时**同时报判据行与退出码**，
并用 `v3 cov --check-only`（读现成 `cov.json`，秒级、exit 0/1 与判据一致）复核。

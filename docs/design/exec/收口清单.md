## C. 门禁：全绿（缺一不可）

### C.0 交付物先过"机器判据"（血的教训）

**不许用 grep/肉眼"看到关键字"就算交付物合格**——实测发生过：某交付的 `.py` 是
**UTF-8 带 BOM + 双重编码（有损）**，`grep` 照样能匹配到 ASCII 标识符，但 `ast.parse` 直接
`SyntaxError`、`import` 全废。所以每个新增/改动的 Python 交付物必须先过：

```powershell
.venv\Scripts\python.exe -c "import ast,pathlib,sys; [ast.parse(p.read_text(encoding='utf-8')) for p in map(pathlib.Path, sys.argv[1:])]" <文件...>
.venv\Scripts\python.exe -c "import importlib; importlib.import_module('pdx.game_auto')"
# 编码（判据的主键是**路径**、不是后缀）：
#   * 仓库侧一切受控文本（.py / .md / .toml / .json / .yml / .yaml / .lock …）⇒ UTF-8 **不带 BOM** + LF
#     （本仓库 366 个受控文本里 252 个属这一档；BOM 会让 ast.parse 直接 SyntaxError）
#   * 引擎侧例外：**路径以 mod/ 或 tools/probe/ 开头** 且后缀 ∈ {.txt, .yml} ⇒ **必须带 BOM** + LF
#     （117 条；引擎会静默忽略无 BOM 的文件）
#   ⚠️ 只有路径能当主键：全仓有 2 个 .yml **不在**那两处、且**必须不带 BOM**
#      （.github/workflows/ci.yml 与 tools/tests/test_golden/test_artifact_digests.yml）
#      ⇒ 任何「.yml 一律带/不带 BOM」的后缀式规则都会当场判错。判据只认原始字节：
#      BOM = data[:3] == b"\xef\xbb\xbf"；LF = b"\r\n" not in data；二进制 = b"\x00" in data[:8000] 则跳过
#      不许用 encoding="utf-8-sig" 判 BOM（它会把 BOM 吃掉）、不许用 Path.read_text() 判 LF（文本模式会归一 CRLF）
#      口径与实测见 docs/design/exec/编码口径审计.md
```

**C.0 的三个计数怎么现算**（它们会随新增文件腐烂 —— 下面这组数是 `t2` 当时（2026-09-24）的实测值，
**判据本身不读它们**，读的是 `tools/tests/test_repo_hygiene.py`；口径与两张清单的逐目录明细见
`docs/design/exec/编码口径审计.md` §3–§4）：

```powershell
# 受控集合 = git ls-files（**必须带 -c core.quotepath=false**，否则中文路径会被 git 转义成八进制 ⇒ 判据静默漏文件）
$all = @(git -c core.quotepath=false ls-files); $text = 0; $binary = 0; $missBom = 0; $extraBom = 0
foreach ($f in $all) {
  $p = Join-Path (Get-Location).Path ($f -replace '/','\')
  $fs = [System.IO.File]::OpenRead($p); $buf = New-Object byte[] 8000; $n = $fs.Read($buf,0,8000); $fs.Close()
  $nul = $false; for ($i=0; $i -lt $n; $i++) { if ($buf[$i] -eq 0) { $nul = $true; break } }
  if ($nul) { $binary++; continue }
  $text++
  $engine = ((($f -like 'mod/*') -or ($f -like 'tools/probe/*')) -and (($f -like '*.txt') -or ($f -like '*.yml')))
  $bom = ($n -ge 3 -and $buf[0] -eq 239 -and $buf[1] -eq 187 -and $buf[2] -eq 191)
  if ($engine -and -not $bom) { $missBom++ }
  if (-not $engine -and $bom) { $extraBom++ }
}
$engineCount = @($all | Where-Object { ((($_ -like 'mod/*') -or ($_ -like 'tools/probe/*'))) -and (($_ -like '*.txt') -or ($_ -like '*.yml')) }).Count
"受控 {0} = 文本 {1} + 二进制 {2}；清单①（引擎侧必带 BOM） {3}；清单②（其余，必不带 BOM） {4}" -f $all.Count,$text,$binary,$engineCount,($all.Count-$engineCount)
"违规：清单①缺 BOM {0} · 清单②误带 BOM {1} · CRLF 命中 {2}" -f $missBom,$extraBom,(git ls-files --eol | Select-String 'crlf' | Measure-Object).Count
# 2026-09-25 现算：受控 369 = 文本 366 + 二进制 3；清单① 117；清单② 252；三项违规 0（与 t2 一致）
# ⚠️ **未跟踪文件不在这个集合里** ⇒ 收口必须先 `git add`（见 C.-1 的次序）
```

判定：`ast.parse` / `import` 通过 + 无 BOM + ruff/format/mypy 绿，才算"文件存在且可用"（编码那几条不变量
**全部由 `pytest` 的 `tools/tests/test_repo_hygiene.py` 守着**：`test_全部受控文件_两侧BOM口径` /
`test_全部受控文件_没有文件带CRLF` / `test_二进制文件被排除` / `test_检查范围不为空`）。

### C.-1 收口的执行次序（**次序不能反**）

```text
⓪ 收口开始时**重新读一次** `git status --porcelain`（**不要复用更早的清单**）
① 逐文件 git add（**禁止 git add -A**；中文路径用 `git add -- <路径>`）
② 再跑「编码闸门 + 跨平台闸门」——它们的判据主键是 `git ls-files`，**未跟踪 = 不判定**
③ 再跑下面的 13 道门禁
④ 最后 `git status --porcelain` 只剩预期项（已暂存的 + 明确不提交的）
```

**为什么不能反**：②的判据只认**受控集合**（`test_repo_hygiene._受控文件()` 走
`git -c core.quotepath=false ls-files -z`）⇒ 若在 ① 之前跑，**今天新写的交付物根本没进集合、一个字节都没被判定过**，
而输出照样是绿的。今天（2026-09-25）现算就是这个形态：盘上有 52 条 `M/??`，而 `git ls-files` 仍是 **369** 条 ——
那份"369"里**不含**任何本轮新页。零残留（B 段）与 13 道门禁都该排在 ① 之后。

⚠️ **工作区的 `git status` 数量 ≠ 本轮改动**（2026-09-25 队长补，来源：验证员在 `t46` 的实测警告；必须写进 F 段的记录）：
同一时间有多张卡在并行落盘，所以

* **`git diff --stat` 全仓 34 个文件不代表任何一张卡的产出** —— 实测那一份 `34 files changed` 里含
  `mod/data/*.toml`、`tools/pdx/*.py`、`tools/tests/*`、`tools/out/snapshots/*` 等**多卡并发在制品**；
* **连单文件的 diff 行数都可能是别人先写的**：`docs/design/backlog.md` 在某位当事人**开工之前就已经是 `M`**
  （预存 1 行插入、mtime 早于它的写入）⇒ "我看文件是脏的"不能推出"这是我改的"；
* 所以：⓪ 必须在收口**开始时现读**、**提交清单以逐文件 `git add` 的实际选择为准**，
  并在 **E 段的记录里写明「当时的在制品有哪些卡」**（本清单的 E.1 就是这种记法）。
  ⇒ 判据不是"工作区干净"，而是"**我加进索引的那些文件**是我这次要交付的、且它们全绿"。

### C.1 13 道门禁（逐条命令 + live/offline 两态）

**"live"= 需要本机游戏树/能起实机才判得出（本机收口必须跑）；"offline"= 不读游戏也有等价物（CI 用）。**
⚠️ 仓库既有口径（**别改**）：**离线通道证明的是「与入库快照一致」，不是「与现在的游戏一致」**。

| # | 命令 | 要游戏树？ | offline 等价物（CI） | 判据行（看这一行，不看聚合退出码） |
|---|---|---|---|---|
| 1 | `.venv\Scripts\python.exe -m ruff check .` | 否 | 同左 | `All checks passed!` |
| 2 | `.venv\Scripts\python.exe -m ruff format --check .` | 否 | 同左 | `N files already formatted` |
| 3 | `.venv\Scripts\python.exe -m mypy --no-incremental` | 否 | 同左 | `Success: no issues found in N source files` |
| 4 | `.venv\Scripts\python.exe -m pytest -q` | 否 | 同左 | `N passed`（无游戏时 integration 自动 skip，见 `tools/tests/conftest.py`） |
| 5 | `.venv\Scripts\v3.exe verify` | **是（live）** | `.venv\Scripts\v3.exe verify --from-snapshot` | `通过 N / N　失败 0` |
| 6 | `.venv\Scripts\v3.exe tables` | **是（live）** | `.venv\Scripts\v3.exe tables --offline` | `全部 N 张生成表都与文档一致` |
| 7 | `.venv\Scripts\v3.exe ai-surface --check` | **是（live）** | `.venv\Scripts\v3.exe ai-surface --check --offline` | `docs/design/02-可执行面.md 与生成结果一致 ✅` |
| 8 | `.venv\Scripts\v3.exe citations` | **是（live，见下）** | `.venv\Scripts\v3.exe citations --offline` | `N 条引用全部指得到唯一一行 ✅` |
| 9 | `.venv\Scripts\v3.exe modguard` | **是（live）** | `.venv\Scripts\v3.exe modguard --offline` | `五道闸门全过 ✅`（+ ③ 的 `N 张牌，各槽占用 x%（预算 60%）`） |
| 10 | `.venv\Scripts\v3.exe release` | 否 | 同左 | `发布说明、档案、元数据三边一致 ✅` |
| 11 | `.venv\Scripts\v3.exe modgen --check` | 否 | 同左 | `盘上 N 个产物与数据源逐字节一致 ✅` |
| 12 | `.venv\Scripts\v3.exe snapshot verify` | **是（live only）** | ——（无离线等价物；`snap_verify` 第一步就是 `_require_game()`） | `两次构建结果完全一致 —— 快照是确定性的` |

**第 8 道（`v3 citations`）的硬要求（t44 实测 → backlog B99）**：引用门禁是 **live / offline 双层**，
而**漂移只有 live 那层判得出** —— 离线层手上只有入库快照的「行号 + 内容指纹」，没有工作树内容，
所以"行号漂了、内容下移"在它那里**天然不可见**。实测（`tools/reports/引用锚定方式审计.md` §三，worktree 里
给 `tools/pdx/modgen.py` 顶部插 5 行、被引内容一字未改）：**`live=True` 报 1 条**「第 185 行的内容变了（原版更新？）
—— 核对后刷新快照」，**`live=False` 报 0 条**。
⇒ **收口必须跑 live 版 `v3 citations`**（第 8 道），`citations --offline` **不能替代**它（那一条仍要跑，
它守的是"与入库快照一致"）。当初抓到 `tools/pdx/ab_probe.py:852 → :926` 那次漂移，走的正是 live 指纹这条路。

**第 8 道的另一条（backlog B98，预期行为不是写错了引用）**：**新写的 `文件:行号` 引用在
`v3 snapshot create --compact` 刷新之前会报 `unsupported`**（支撑域属**入库快照**、不从盘上现算）⇒
改过 `mod/data` 的引用之后，收口前先刷一次快照（`v3 snapshot create --compact`），否则会看到一条
看似"引用写错"的红。

**已知边界（backlog B97，写在这里免得 t21 误判）**：`v3 citations` 的**默认扫描目标是 `mod/data`**
（`tools/pdx/citations.py:253`）⇒ **`docs/**` 里的 `文件:行号` 引用不在门禁范围内**（盘点实测 1 146 条，
其中 49 条指向本仓文件）：那一半**由人工守**，本清单不覆盖。要覆盖必须另加一条只扫 `docs/**` 的低频检查
（需白名单，成本更高）—— 见 B97 的两条处置选项。

**第 13+1 道（单列，不与上面 13 道混计）：覆盖率 `v3 cov`** ——
`.venv\Scripts\v3.exe cov`，判据 `整体 ≥86%` + `各模块下限`（`FLOORS` 只升不降，P6）。
它**单列**的理由有两条：① 它本身是一次"带覆盖率重跑的 pytest"（≈3–5 分钟），不是一次独立检查；
② 它的退出码暂时不能当判据（backlog **B42**：判据行打绿、退出码却可能是 1，多半是内部那次 pytest 的
xdist 偶发）⇒ **报覆盖率时同时报判据行与退出码**，并用 `v3 cov --check-only`（读现成 `cov.json`，
秒级、退出码与判据一致）复核。**收口必须跑它，但它不进 13 道的计数。**

**一条命令跑完（复制即用，遇红即停）** —— 判据只看**每条自己的结论行**，不看聚合退出码：

> 并行是**默认**：`pyproject.toml` 的 `addopts` 里带着 `-n auto --dist loadscope`
> （实测 314.2 秒 → 132.8 秒），所以上面不写 `-n`。要读完整失败上下文时才用 `-n0` 覆盖；
> **跑基准**要把 addopts 整个清掉（`-o addopts="" --benchmark-only`）—— `-n0` 不管用。

**第 3 道为什么必须 `--no-incremental` 且不带文件参数**：mypy 的增量缓存按 **mtime** 命中 ——
文件内容回退/被重新生成成旧内容时，它可能直接复用上次的结论，**把真实差异盖掉**；而**带文件参数的
单文件模式与全量模式结论不同**（本轮实测过：同一个文件，单文件模式报 `pdx` 解析噪声、全量模式 0 条）
⇒ 收口的 mypy 只有**全量 + 关缓存**这一种跑法。

```powershell
$gates = @(
  @('python','-m','ruff','check','.'),
  @('python','-m','ruff','format','--check','.'),
  @('python','-m','mypy','--no-incremental'),      # 不带文件参数；关 mtime 缓存
  @('python','-m','pytest','-q'),
  @('v3','verify'), @('v3','tables'), @('v3','ai-surface','--check'),
  @('v3','citations'), @('v3','modguard'), @('v3','release'),
  @('v3','modgen','--check'), @('v3','snapshot','verify'), @('v3','preflight')
)
# 13 道；覆盖率 `v3 cov` 单列（见上「第 13+1 道」）—— 要一起跑就再补一行 @('v3','cov')
foreach ($g in $gates) {
  $exe = if ($g[0] -eq 'v3') { '.venv\Scripts\v3.exe' } else { '.venv\Scripts\python.exe' }
  $args = if ($g[0] -eq 'v3') { $g[1..($g.Count-1)] } else { $g[1..($g.Count-1)] }
  Write-Host "`n===== $exe $($args -join ' ') ====="
  & $exe @args 2>&1 | Select-Object -Last 4
  if ($LASTEXITCODE -ne 0) { Write-Host "[RED] exit=$LASTEXITCODE —— 停下，先修这一条" -ForegroundColor Red }
```

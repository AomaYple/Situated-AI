# Situated AI 1.3.0 阶段收口结果

> 日期：2026-10-27。证据类型：生产源审计、Python 参考求值、PDX 生成合同、静态工程检查和标准包校验。
> 本收据不证明游戏长期 AI 行为、数值平衡、游戏内性能、本地化呈现或 Workshop 体验。

## 本轮收口内容

- 增加有限国家状态生产源 `mod/decisions/country_state.toml`；
- 生成六条互斥路线：财政整固、内部稳定、防御安全、产业发展、教育追赶和商业海洋；
- 统一财政、行政和安全影子预算，保留未知值回退；行政二档要求 `bureaucracy >= 100`，不再与一档重复；
- 生成月度和危机 hook，路线 TTL 为 100 天，切换冷却为 62 天；紧急路线可以抢占普通路线，普通路线只有在满足预算后才介入；
- 将路线状态接入建设、制度、军备、科技、教育、贸易、外交和殖民相关的原版 AI 消费者；
- 增加国家接口原版证据快照、参数审计和路线域测试；
- 修正规则生成器在无数值边界时产生空 `AND = { }` 的问题；
- 将生产候选版本提升为 `1.3.0`，保持 Mod ID `situated-ai`、显示名 `Situated AI`、原版底本 `1.14.5` 和 11 种本体语言。

## 证据口径

| 类别 | 本轮证明 |
|---|---|
| `static_check` | 生产源 schema、字段、作用域、唯一作者、生成入口、编码、包路径和 manifest 合同 |
| `simulation` | Python 参考求值与独立 PDX 子集解释器在路线生命周期、TTL、冷却、预算和未知回退上的一致性 |
| `snapshot` | 锁定 Victoria 3 1.14.5 原版接口和国家策略/科技/变量写入来源 |
| `runtime` | 本轮未由本收据宣称游戏长期运行通过；用户可在标准包上自行观察 |
| `inference` | 俄罗斯、荷兰等国家可能因事实差异进入不同路线，只是设计预期，不是实机结论 |

## 完整工程回归

最后一次 `full-acceptance` 使用仓库 `.venv` 和自动资源预算运行，结果为 `1948 passed`、`11 skipped`、`0 failed`、`0 errors`；Python 覆盖率为 87.66%（语句覆盖 89.89%，分支覆盖 81.66%）。本机自动选择 2 个 worker，墙钟 746.2 秒，进程树 RSS 峰值约 1995.3 MB，私有提交峰值约 3924.6 MB；这组读数只描述工程测试进程，不代表游戏运行期内存或性能。

跳过项已分类为 Windows 符号链接权限、缺少可再生分析产物，以及 Workshop 覆盖原版 GUI 导致的证据不可比；没有隐藏失败或把跳过项计为通过。完整报告写入被忽略的 `tools/out/test-runs/`，收口后已清理可再生运行态目录；精简原版快照保留在 `tools/out/snapshots/`，供离线合同门禁使用。

## 明确限制

当前实现是有界的处境协调器，不是全知世界模型、全局优化器或整个 Victoria 3 AI 的替换。18 个 reader 和六条路线只覆盖已经证明有合法消费者且成本可控的部分；其它发现信息保持原版、只作解释或标为 unsupported。日志、存档、快照和观察器只能辅助归因，不能单独证明因果。

终极方案 3.0 的 E1–E15 尚未执行。本收据只封存当前 `1.3.0` 阶段候选，下一步等待用户下令后从 E1 全量信息盘点开始。

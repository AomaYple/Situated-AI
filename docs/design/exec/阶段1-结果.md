## 五、H1 最小实验设计（阶段 2，**一次游戏会话**）

**目的**：证明"改一处权重能在引擎重掷时改变落点"（G1 生死门），并顺带清掉 6 个未知数。

**结构**
* 探针 mod（独立、可一键卸载）新增 **1 张牌**：`ai_strategy_sitai_probe_reform`（`type = political`），
  差异字段只写 `pro_interest_groups` / `change_law_chance` / `max_progressiveness`；图标引用原版；loc 齐备。
* 权重块：`value = 10`；`if = { limit = { has_variable = sitai_probe_defeat } add = 240 }` → 变量存在时权重 10 → 250。
* 触发变量：探针决议（或 `on_war_end`）给国家 `set_variable = { name = sitai_probe_defeat value = 1 }`。

**分组**
* **A 组**：不给变量（等价"没战败"）→ 我们的牌权重恒为 10（隐身档）。
* **B 组**：给变量 → 我们的牌权重 250。
* 两次会话（或同会话内两个国家），其余条件完全相同。

**观测（不靠肉眼）**
* 探针 `on_monthly_pulse` 用 `has_strategy = <牌名>` 逐张判定，把**三槽当前落点**用 `debug_log` 写进日志
  （`ZZPROBE slot=political card=…`）→ `v3 experiment collect` 自动收割，还能顺带得到**重掷频率与时刻**。

**顺带回答的 6 个问题**
1. 重掷频率（落点变化的时间戳间隔）；2. 权重块求值成本（`gametimer` 对照）；
3. 新牌是否必须带 loc/icon（故意留一张不带，看日志与 UI）；4. `type = sitai_fourth` 会报错还是被忽略（第四槽）；
5. `has_strategy` 对**自定义牌**是否可用（探针观测链本身依赖它）；6. 新牌是否影响原版牌的落点分布（稀释的第一个数据点）。

**失败长相**：A/B 两组的政治槽落点分布无差异，且日志显示我们的牌从未被抽中 →
说明"改权重"不足以推动落点（H1 不成立）→ 换挂载点（`possible` 门 → 世界状态引导）。

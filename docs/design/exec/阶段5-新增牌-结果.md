## 1. test 0（本卡第一道门）：`set_strategy` 直置受不受 `possible` 约束

**为什么必须先做**（t15 `:37-46` 原文）：`possible` 只有两种作用 —— (a) 挡住直置；(b) 不挡（牌照样挂上、
**零报错**）。若是 (b)，「由处境标志驱动牌选择」在**直置通道**上就是假的；而失效是**沉默的**。
t15 因此规定「**不跑出结论，不许往真档案里写牌**」——本卡照此排序。

**做法**（t15 §1.4 的三件，探针侧）：一张 `ai_strategy_sitai_probe_gate = { type = political
possible = { always = no } weight = { value = 10000 } }`（直引同型先例 `common/ai_strategies/00_default_strategy.txt:9474-9481`）
+ 月度块里一句 `set_strategy = ai_strategy_sitai_probe_gate` + 一行自报
`state_line("GATE0", "has_strategy = ai_strategy_sitai_probe_gate", "yes", "no")`。

**实机读数**（一次会话，`stage3_rerun.py --archive ru_defeat --fresh-logs --months 8`，**exit 0**）：

```
[05:48:26][jomini_effect_impl.cpp:454]: common/on_actions/zz_probe_ab_on_actions.txt:61: ZZPROBE AB;GATE0;yes;俄罗斯
（同型共 7 行，1836.2 → 1836.9；`GATE0;no` 0 行；墙钟 05:48:26 → 05:49:22，约 9 s 一脉冲）
[05:48:26][jomini_effect_impl.cpp:454]: common/on_actions/zz_probe_ab_on_actions.txt:109: ZZPROBE AB;STRATEGY;none;俄罗斯
（同局 STRATEGY 链 7 行全是 `none` —— 那张探针牌不在链里）
```

**判决 = (b)**：`possible = { always = no }` **挡不住直置** —— 脚本一 `set_strategy`，牌就挂上了，且零报错。
两条读数**互补自洽**：`has_strategy` 为真、链报 `none` ⇒ 牌确实挂着、而那条链看不见它
（链只装真 mod 产物里的政治牌 + 原版候选）。

**按 t15 §7 的处置**：写「**机制在直置通道上不成立**」；**设计不变**（`possible` + 单值权重的设计本来就不靠直置进场）；
`set_strategy` 通道**降级为不作承重**（它的行为不用改，但**不许**拿它当"处境驱动"的证据）。

**用完即撤**（t15 §1.4）：三件已在**同一次原子改动**里撤掉（牌文件、`set_strategy`、`GATE0` 行）——
理由：那张牌权重 10000，若门在重掷路径上也被忽略，它会被引擎选中并几乎占满政治槽，
**污染 A/B 两臂与之后每一局**。留下的是本节的读数与 `ab_probe.py` 里那段注销注释。

**`error.log` 如实登记**：提到探针文件的 **12 行（6 组）** 全部是难度档家族
`PostValidate of trigger 'has_game_rule' returned false at common/on_actions/zz_probe_ab_on_actions.txt:124/128/132/140/147/154`；
**与 test 0 相关的错误 = 0 条**（`sitai_probe_gate` / `set_strategy` / `Unknown effect` / `Unknown trigger` 一条都没有）。
⇒ 队长原判「应为 0」**在 test 0 这一层成立**，但按文件计不成立（那 12 行是 t88/t91 同族，另计）。

### 5.2 ⚠️ **本卡新暴露的一条口径缺口（待队长裁定）**
```
产物里多出数据源没写的：card.ai_strategy_sitai_ru_defeat_agenda.type = political
```
**成因**：这是本仓**第一张**牌 ⇒ 闸门 ④ 的「数据源事实 ↔ 产物事实」这条比较**第一次被走到**。
数据源侧的键是 `slot`（`Card.slot`，`modgen.py:1006`），产物侧渲染出来的是 `type = <slot>`（`card_text`），
而事实抽取把产物读成 `card.<名>.type`（`modgen.py` 的 `_facts_card`）——**两侧键名不同、语义相同**，
比较器没有这条映射 ⇒ 判「多出」。
**为什么本卡解决不了**：修它要动 `tools/pdx/modguard.py`（或 `modgen` 的事实抽取），
两者都**不在 t18 的 inScope ①–⑥**（t18 = 数据源牌声明 + 探针自报 + 产物 + 结果页）。
**建议的最小修法**（供裁定）：在事实抽取里把 `card.<名>.type` 归一成 `card.<名>.slot`，
或在数据源事实侧同时吐 `card.<名>.type = slot` 的值 —— 两种都是**一行**，但都属别的卡。
**在此之前**：`v3 modguard` ④ 不可能全绿 ⇒ 本卡验收第 9 条（"modguard 五道全绿"）**卡在这一条上**，如实登记。

## 7. 判别性实验的**预注册**（t18 第 10/17 条；跑前写死，跑完只追加读数）

### 7.1 为什么要重做一次：B 臂 0/13 不可归因，而且**功效算错了**

原式（队长 2026-09-25 的功效说明）：权重 40 对 S≈33 ⇒ 单次抽签 p≈0.55，13 次抽签 0 命中 ≈3e-5
⇒「若门确实开着，没抽到几乎不可能是解释」。**这个式子把引擎的重抽节奏当成了每月一次。**
引擎自己的定义（`common/defines/00_ai.txt`）：

| 键 | 原版值 | 含义 |
|---|---|---|
| `CHANGE_STRATEGY_THRESHOLD`（:38） | 100 | 攒够 100 个「变更点」才重抽一次 |
| `CHANGE_STRATEGY_INCREASE_WEEKLY_CHANCE`（:39） | 20 | 每周 20% 概率 +1 点 |
| `CHANGE_STRATEGY_POLITICAL_NEW_RULER`（:41） | 100 | 换统治者一次给满 |
| `CHANGE_STRATEGY_POLITICAL_REGIME_CHANGE`（:42） | 100 | 被改政体给满 |
| `CHANGE_STRATEGY_POLITICAL_LAW_ENACTED`（:43） | 25 | 立一条法给 25 |

⇒ 单靠周通道，期望 **≈9.6 年**才重抽一次（本仓 `阶段2-H1.md:19` 早就写过这一行，实测 0.37%/月）。
按二项分布算（52 周/年、门槛 100 点）：

| 观测窗 | 周数 | P(至少一次重掷) |
|---|---|---|
| 12 个月 | 52 | ≈10^-36 |
| 13 个月（B 臂） | 56 | ≈10^-39 |
| 24 个月（A/B 整局） | 104 | ≈10^-64 |
| 120 个月 | 520 | 0.69 |
| 250 个月 | 1083 | ≈1.00 |

**第一条结论**：B 臂那 13 个月里「引擎重掷过哪怕一次」的概率 ≈10^-39 ⇒ **0/13 在自然节奏下是必然结果**，
它与「牌进不了池」无关（下一次有人读到这一页：别把 0/13 当证据）。所以
① 撤牌/换门**没有依据**（队长裁决对，理由现在更硬）；② 要判「门在重掷路径上是否成立」，
必须**把重抽节奏拉起来**或把窗口拉到十几年 —— 本轮取前者（风暴变体，先例 = `h1_probe` 的 `storm`、
阶段 2 实测生效、`modguard.py:63` 引作改原版全局参数的唯一合法方式）。

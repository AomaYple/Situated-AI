## 3. 核心机制：`set_strategy`

**【实测】** `00_strategy.txt`（176 行）的结构：

```pdx
AI = {
	 # Default AI subject starting strategy depends on LD
	every_country = {
		limit = { is_subject = yes }
		if = {
			limit = { liberty_desire >= 80 }
			set_strategy = ai_strategy_subject_break_free
		}
		else_if = {
			limit = { liberty_desire >= 60 }
			set_strategy = ai_strategy_subject_strengthen_self
		}
		else_if = {
			limit = { liberty_desire <= 20 }
			set_strategy = ai_strategy_subject_overlord_compliance
		}
		else = {
			set_strategy = ai_strategy_subject_maintain_autonomy
		}
	}

	c:SWE ?= {
		set_strategy = ai_strategy_resource_expansion
		set_strategy = ai_strategy_maintain_power_balance
		set_strategy = ai_strategy_conservative_agenda
	}
	# ... 其余国家
}
```

### 3.1 语法要点

| 语法 | 含义 |
|---|---|
| `AI = { ... }` | 文件级包装块（**所有 `history\ai\` 文件都是这个顶层键**） |
| `c:<TAG> ?= { ... }` | 针对特定国家。**`?=` 是安全赋值运算符** —— 国家不存在时不报错 |
| `every_country = { limit = {...} ... }` | 遍历所有国家 |
| `set_strategy = <ai_strategy_键名>` | **分配一个策略** |
| `set_variable = { name = X days = N }` | 设置带时限的变量 |
| `if` / `else_if` / `else` / `random_list` | 块内可用完整脚本逻辑 |

> `set_strategy` 的取值必须是 `common\ai_strategies\` 里定义过的键（如 `ai_strategy_industrial_expansion`）。

### 3.2 关键结构规律：每个国家 3 个策略

**【实测】** 全文 **89 次 `set_strategy` 调用，27 个 `c:TAG ?=` 块，1 个 `every_country` 块**。

绝大多数国家块里**恰好 3 条 `set_strategy`**，分别对应三种 `type`：

```text
c:SWE ?= {
    set_strategy = ai_strategy_resource_expansion      ← administrative
    set_strategy = ai_strategy_maintain_power_balance  ← diplomatic
    set_strategy = ai_strategy_conservative_agenda     ← political
}
```

也就是说：**多数国家在每个策略类别上最多持有一个策略**，正好呼应 `03-AI系统.md` §2.3 中 `type` 字段的三种取值。**但有例外**：`FIN` 的三条里有两个 `diplomatic`、零个 `political`（见 §4 的表）。

### 3.3 特殊案例：JAP 用 `random_list` 做分支

**【实测】** `c:JAP ?= { ... }`（第 127 行起）内含 `random_list`，按天保危机状态随机选择不同的策略组合：

```pdx
c:JAP ?= {
	if = {
		limit = { has_journal_entry = je_tenpo_crisis }
		random_list = {
			50 = {
				set_variable = { name = ai_tenpo_reform_agenda days = 4380 }
				set_strategy = ai_strategy_progressive_agenda
				set_strategy = ai_strategy_placate_population
				set_strategy = ai_strategy_armed_isolationism
			}
			50 = {
				# 另一套组合
			}
		}
	}
	else = {
		# ⚠️ 这个 else 分支同样有 3 条 set_strategy，不能漏
		set_strategy = ai_strategy_placate_population
		set_strategy = ai_strategy_armed_isolationism
		set_strategy = ai_strategy_conservative_agenda
	}
}
```

> 这是「9 次调用出现在一个 JAP 块里」的原因 —— **2 个随机分支 + 1 个 `else` 分支** × 3 个策略。
> ⚠️ 照抄时**不要只抄 `random_list`**：漏掉 `else` 就意味着天保危机未发生时该国一条策略都没有。

### 4.1 属国的全局默认规则

`every_country` 块对所有属国按**自由渴望（liberty_desire）**分配：

| 条件 | 分配的策略 |
|---|---|
| `liberty_desire >= 80` | `subject_break_free` |
| `liberty_desire >= 60` | `subject_strengthen_self` |
| `liberty_desire <= 20` | `subject_overlord_compliance` |
| 其他（21–59） | `subject_maintain_autonomy` |

> 这是**唯一**按条件动态分配的全局逻辑；其余国家都是硬编码。

## 5. 另外两个文件

### 5.1 `00_secret_goals.txt`（15 KB）

**【实测】** 用于初始化国家的秘密目标。开头的逻辑结构：

```pdx
AI = {
	every_country = {
		limit = {
			any_diplomatically_relevant_country = {
				OR = {
					is_in_same_power_bloc = prev
					has_friendly_diplomatic_pact = { TARGET = prev }
				}
			}
		}
		save_scope_as = first_country
		every_country = {
			limit = { ... }
			effect_set_non_hostile_mutual_secret_goal_power_difference = yes
		}
	}
}
```

初始化逻辑：**同一权力集团或有友好条约的国家之间，互相设置非敌对秘密目标**。
文件内注释说明了意图（大意）：历史上的敌国不应一开始就表现出和解倾向，除非在历史脚本中明确写出。

涉及的关键效果（【实测】文件内出现）：

- `effect_set_non_hostile_mutual_secret_goal_power_difference`
- 依赖的触发器/条件：`is_in_same_power_bloc`、`has_friendly_diplomatic_pact`、`has_diplomatic_pact`、`any_diplomatically_relevant_country`
- 作用域工具：`save_scope_as`、`prev`

> 秘密目标的分值字段是 AI 策略里的 `secret_goal_scores`（见 `03-AI系统.md` §2.4）。

### 5.2 `00_behavior_variables.txt`（343 B）

**【实测】** 全文只有一个块，用于设置历史行为变量：

```pdx
AI = {
	# Set historical tendencies for Ottomans vs Egypt
	c:GBR ?= {
		set_variable = veiled_protectorate_support_ottomans
	}
	c:AUS ?= { set_variable = veiled_protectorate_support_ottomans }
	c:RUS ?= { set_variable = veiled_protectorate_support_ottomans }
	c:PRU ?= { set_variable = veiled_protectorate_support_ottomans }
}
```

即：给英、奥、俄、普四国打上 `veiled_protectorate_support_ottomans` 变量标记，
用于在第 1836 年「埃及—奥斯曼危机」中表达历史倾向。

> 变量名可在 `ai_strategies` 的策略条件里用 `has_variable = <名>` 读取
> —— 这提供了一条**从历史脚本向 AI 决策传参**的通路。

## 6. 在 mod 中如何改

### 6.1 场景 A：让某国开局走不同策略

追加自定义文件到 `common\history\ai\`，用同样的 `AI = { c:TAG ?= { set_strategy = ... } }` 结构。

> ⚠️ **注意覆盖语义**：同一 TAG 若被多处 `set_strategy`，行为取决于引擎如何合并（**【未确认】**）。
> 更安全的做法是**直接替换原版 `00_strategy.txt`**（与 `Kuromi's AI` 替换 `00_default_strategy.txt` 同理）。

### 6.2 场景 B：新增一个策略并让它被使用

两步：

1. 在 `common\ai_strategies\<你的文件>.txt` 定义 `ai_strategy_<你的名字> = { ... }`
2. 在 `common\history\ai\` 里用 `set_strategy = ai_strategy_<你的名字>` 分配

> 注意：新策略若想让 AI **自动随机选中**，还需要 `possible` 触发器与 `weight` 权重
> （见 `03-AI系统.md` §2.3）；而 `history` 里的 `set_strategy` 是**强制指定**，绕过随机分配。

### 6.3 场景 C：用 `every_country` 写通用规则

比逐个 TAG 硬编码更优雅，且能自动适配 mod 新增的国家：

```pdx
AI = {
	every_country = {
		limit = { is_subject = yes }
		if = { limit = { liberty_desire >= 80 } set_strategy = ai_strategy_subject_break_free }
	}
}
```

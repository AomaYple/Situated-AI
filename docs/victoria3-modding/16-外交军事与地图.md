#### 2.1.3 🔴 硬规则：`ai` 块中 `root` 恒为 AI 国

**【官方，逐字】** `diplomatic_action.md`：

```text
# IMPORTANT: In the AI block, the AI country is always root and the other country always scope:target, regardless of who proposed the diplomatic action
```

**【官方，逐字】** 文件顶部的作用域声明（**注意：只声明了 `root` 与 `scope:target`，未提 `scope:actor`**）：

```text
# Scopes:

		root = action initiator
		scope:target = action target
```

**【实测】`scope:target` 这个字面量在 1.14.2 的全部 vanilla 外交脚本中出现 0 次**（下表由 `v3 tables` 重算）：
> 口径：前两行与第三行数 `common/diplomatic_actions/` 的 **48 个 `.txt`**；
> 第四行数官方 `diplomatic_action.md`。第三行的正则是 `scope:target(?!_)`（**不跟下划线**）。
> 早先第一行写「全部使用此名 / 48」，实际是 **46 个文件**用了这个名字 ——
> 「全部」是作者的印象，不是计数结果。

| 记号 | 出现次数 | 出现文件数 |
|---|---:|---:|
| `scope:target_country` | 633 | 46 |
| `scope:actor` | 193 | 13 |
| `scope:target`（裸，`scope:target(?!_)`） | 0 | 0 |
| `scope:target`（仅在 `.md` 里） | 2 | 1 |

**结论（精确表述）**
1. **`root` 恒为 AI 国**这条硬规则成立，实测可证。
2. 「另一方」在 vanilla 里有**两个**名字，按方向选用：
   - `scope:actor` = **发起方**（提议者）
   - `scope:target_country` = **行动目标方**
3. 官方文档写的 `scope:target` 在 `.txt` 中零出现，**是否为 `scope:target_country` 的别名 = 未确认**。

**逐字证据 A** —— `03_violate_sovereignty.txt:134`（位于 `ai = { accept_score = { ... } }` 内）：
此处 AI 是**被请求方**（接受与否的评估者），`root` = 自己，`scope:actor` = 发起方：

```pdx
			if = {
				limit = {
					"scope:actor.ai_army_comparison(root)" > 0
				}
				add = {
					desc = "DIPLOMATIC_ACCEPTANCE_ARMY_STRENGTH"
					value = "scope:actor.ai_army_comparison(root)"
					multiply = 2
					max = 50
				}
			}
```

**逐字证据 B** —— `00_relations_actions.txt:136`（位于 `ai = { propose_score = { ... } }` 内）：
此处 AI 是**发起方**，`root` = 自己，`scope:target_country` = 对手：

```pdx
			if = {
				limit = {
					OR = {
						is_subject_of = scope:target_country
						scope:target_country = { is_subject_of = root }
					}
				}

				multiply = 2
			}
```

> **踩坑提示**：写 `ai` 块时**不要**写 `scope:target`（很可能直接无效/报错）。发起方视角用 `scope:target_country`，被请求方视角用 `scope:actor`。

#### 2.1.10 实战提示

- `potential` / `possible` **会自动叠加所有 `requirement_to_maintain` 的判定**（官方明说）→ 不要重复写条件，否则是纯性能浪费。

- `pact.subject_type` 让 pact 直接变成宗主权关系（`19~24`、`48~50` 各 subject 行动即如此用法）。

#### 🔴 `inherent_accept_score` vs `contextual_accept_score` 的性能取舍

这是本目录**最重要的一条**，官方原文说得很明确：

**【官方，逐字】** `inherent_accept_score`：
```text
### inherent_accept_score (default: 0)
A script value determining the reasons for the AI to accept or reject a treaty.
Does not get reevaluated every time the AI tries to add an article, so it's more performant to put as much as possible here.
```

**【官方，逐字】** `contextual_accept_score`：
```text
### contextual_accept_score (default: 0)
A script value determining the reasons for the AI to accept or reject a treaty but with access to the treaty itself
Gets reevaluated every time the AI adds something to its own proposals, so should be avoided if you don't need the treaty scope.
```

**【官方，逐字】** 作用域差异：

| | `inherent_accept_score` | `contextual_accept_score` |
|---|---|---|
| `root` | 要检查接受度的国家 | 同 |
| `scope:article` | ✅ 有 | ✅ 有 |
| **`scope:treaty`** | ❌ **没有** | ✅ **有**（"The current treaty with any articles that might have been added to it"） |
| 重算频率 | **不随 AI 加条款重算** | **AI 每加一条就重算一次** |
| 性能 | 好 | 差 |

**【官方，逐字】** 两者关系：
```text
#### NOTE:
`inherent_accept_score` and `contextual_accept_score` are added together to create the final acceptance value but maths conducted in one script value does not apply to the other and vice versa
```
→ **加和**，但**内部运算不互通**（在 A 里 multiply 不影响 B）。

**【实测】vanilla 的实际写法分布**（本目录 34 文件）：

| 键 | 使用文件数 | 备注 |
|---|---:|---|
| `ai.inherent_accept_score` | **33** | 主战场。内部结构：`.value`(33) `.if`(32) `.else`(25) `.else_if`(9) `.add`(2) `.save_temporary_scope_as`(2) |
| `ai.contextual_accept_score` | **10** | `.if`(10) `.else`(8) `.value`(3) |
| `ai.evaluation_chance` | **34** | 全部文件都设，`.value`(34) |
| `ai.proposal_weight` | 3 | `.value`(3) `.if`(3) `.else_if`(1) |
| `ai.wargoal_score_multiplier` | 5 | |
| `ai.quantity_input_value` | 2 | |

> **结论**：vanilla 自己 33:10 的比例印证了官方的性能建议 —— **默认全写 `inherent_accept_score`，只有确实需要 `scope:treaty` 时才用 `contextual_accept_score`**。

#### 硬性要求（【官方】逐字转述）
- **至少一个**有效档位，否则游戏无法运行。
- 每个 `threshold` **必须唯一**；重复时**按脚本顺序只取第一个**，后面的被忽略。
- 所有 `threshold` 必须在 `MIN_ACCEPTANCE_VALUE` 与 `MAX_ACCEPTANCE_VALUE` 之间（这两个是 defines），越界会**记错误日志并被忽略**。
- **必须有一个档位的 threshold == `MIN_ACCEPTANCE_VALUE`**。
- 档位上限不脚本化，由**下一个档位的 threshold** 推导（避免空隙）；最后一个档位的上限 = `MAX_ACCEPTANCE_VALUE`。
- 内部排序由 threshold 决定，**与脚本书写顺序无关**（但 threshold 相同时看书写顺序）。
- 战争支持公式（官方举例）：`140K/500K * 2 + 160K/500K * 0.5 = 0.72` 每周战争支持损失。

#### 🔴 关键机制：`mirrored_wargoal` 与「计时自动执行」

**【官方】** `fill_per_week` / `deplete_per_week` 控制**占领计时条（0–100）**：被争夺时每周 +`fill_per_week`，不被争夺时每周 −`deplete_per_week`（下限 0）。满 100 则**战中自动执行**。两者可选，**负值（默认）回退到 defines `WAR_GOAL_ENFORCEMENT_FILL_PER_WEEK` / `..._DEPLETE_PER_WEEK`**。

**【官方，逐字核心规则】**：
> The presence of this block also marks the war goal as timer-enforceable; without it (and unless it is `assent_required`) the goal is only enforced via capitulation or a negotiated peace. A war goal with no resolvable `contestion_type` is never timer-enforceable regardless of this block (its bar could never fill).

→ **有 `mirrored_wargoal` 块 = 可计时自动执行**；没有则只能靠投降或和谈。`assent_required` 会把它排除出计时执行。

**8 种 `method` 的官方语义（转述）**

| method | 生成什么镜像 |
|---|---|
| `territorial` | 夺回被占土地。整国吞并 → `liberate_country`（被吞附属国的宗主仍在战时 → 对其旧州的夺回目标）；占一个州 → 对原主的 `return_state`/`conquer_state`（考虑宣称） |
| `swap` | 把 `type` 目标的 holder/target 互换。也用于条约强加类目标生成 `break_enforced_treaties` |
| `liberate_loser` | 对失地方新建的国家生成 `annex_country` |
| `reverse_transfer` | 生成 `transfer_subject` 把附属国还回原宗主 |
| `subjugate` | 新附属国退出战争（中立化），为其一方继续作战者生成 `liberate_subject` |
| `restore_subject` | 为被解放国的原宗主生成 make-subject 目标（类型读自 `subject_types` 的 `re_establish_war_goal`） |
| `reparations` | 生成由受害者持有的 `money_transfer`（enforce_treaty_article）镜像，使强加方每周付赔款 |
| `no_mirror` | 自动执行但不生成镜像 |

> `break_enforced_treaties` 的官方细节：**只废除 target 强加给 holder 的条约/协定**，自愿协定与 holder 强加给 target 的一律不动。

| | `joi_canal_traits.txt` | **54 条** |
| **新增** 本地化 | `localization\{english,french,polish,russian,simp_chinese}\joi_state_traits_l_*.yml` | 5 个 |

**【实测】逐字新增实例（`joi_new_resource_traits.txt:1`）**

    icon = "gfx/interface/icons/state_trait_icons/resources_ore.dds"
	
	modifier = {
		building_iron_mine_throughput_add = 0.25
	}

> 🔴 **这三条组合起来的完整配方**：
> 1. 用 `common\state_traits\` 定义**新的州特性**（省事：新建文件即可，零冲突）；
> 2. 用 `map_data\state_regions\*.txt` 的 `traits = { ... }` 把特性**贴到州上**（费事：必须逐地理区整文件覆盖）；

### 6.2 五条硬规则（违反必出 bug）

1. **`ai` 块中 `root` 恒为 AI 国**（`diplomatic_actions`）。发起方视角用 `scope:target_country`，被请求方视角用 `scope:actor`。**不要写 `scope:target`**。
2. **每个州必须属于且仅属于一个战略区域**（`strategic_regions.md`）。
3. **`state_regions` 里贴特性的键是 `traits`，不是 `state_traits`**。
4. **`combat_unit_types` 同一 `group` 内必须按 tier 升序**，否则默认单位选错。
5. **`acceptance_statuses` 的 `threshold` 必须唯一，且有一个等于 `MIN_ACCEPTANCE_VALUE`**。

### 6.3 三条性能规则

1. `potential` / `possible` **自动叠加所有 `requirement_to_maintain`** → 不要重复写。
2. `ai.evaluation_chance` 只看自身、无目标数据 → 别在里面引用对手。
3. `treaty_articles` 的接受度**默认写在 `inherent_accept_score`**；只有确实需要 `scope:treaty` 才用 `contextual_accept_score`（vanilla 33:10 的比例就是证据）。

   （实测：6 个触及本范围的 mod 全部遵守）

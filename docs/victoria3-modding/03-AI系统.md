### 2.2 `ai_strategy_default` 的特殊地位

**【官方】** 文件开头注释（逐字）：

> This is a special strategy that sets the default values for different AI scores
> All AIs always load data from this strategy, which can then be either added to or overridden by data from its other strategies

**【实测】** 它的特征：

- **没有 `type` 字段**（普通策略有）
- `icon` 字段存在但注释标注 `# Never shown`
- 结尾有：
  ```pdx
  # Trigger for whether this strategy can be randomly allocated to a country
  possible = {
  	always = no
  }

  # Chance that this strategy will be randomly allocated to a country
  weight = {
  	value = 0
  }
  ```
  即**永远不参与随机分配**，只提供基线值。

> **这是 AI mod 最重要的单个文件**：所有 AI 的一切未被子策略覆盖的取值，都来自这里。

### 2.3 普通策略的结构

**【实测】** 以 `02_diplomatic_strategies.txt` 的 `ai_strategy_maintain_power_balance` 为模板：

```pdx
# Generic
ai_strategy_maintain_power_balance = {
	icon = "gfx/interface/icons/ai_strategy_icons/maintain_power_balance.dds"

	type = diplomatic

	will_form_power_bloc = {
		global_country_ranking = 1
	}

	undesirable_infamy_level = {
		value = 25

		if = {
			limit = {
				has_technology_researched = pan-nationalism
			}
			multiply = 1.5
		}
		else_if = {
			limit = {
				has_technology_researched = nationalism
			}
			multiply = 1.25
		}
	}

	recklessness = {
		value = -0.25
	}

	aggression = {
		value = 0.25
	}

	possible = {
		always = yes
	}

	weight = {
		value = 10
		# ... 可用 if/limit 动态调整
	}
}
```

**结构要点：**

| 部分 | 必需 | 说明 |
|---|---|---|
| `icon` | 是 | 图标 `.dds` 路径 |
| `type` | 普通策略必需 | `administrative` / `diplomatic` / `political` |
| 行为字段（§2.4） | — | **每个字段都是一个 script value 块**，可含 `value` / `if` / `else_if` / `limit` / `add` / `multiply` / `divide` / `min` / `max` |
| `possible` | 是 | 触发器，决定该策略能否被随机分配给国家 |
| `weight` | 是 | script value，作为随机分配的权重 |

**【实测】** `possible`/`weight` 覆盖情况：`01_admin`(4/5)、`02_diplomatic`(14/14)、`02_subject_diplomatic`(4/4)、`03_political`(9/9)。

### 2.5 策略选择机制（**【官方】** 注释 + **【实测】** 参数）

**【实测】** `common\defines\00_ai.txt` 中的相关参数揭示了切换机制：

| 参数 | 值 | 含义（原文注释） |

| `CHANGE_STRATEGY_POLITICAL_REGIME_CHANGE` | `100` | 政权更迭时给政治策略加的点数 |
| `CHANGE_STRATEGY_POLITICAL_LAW_ENACTED` | `25` | 通过法律时给政治策略加的点数 |

> 官方提示：本地化键应与立场键同名（如 `strategic_region_stance_none`）。
> **注意**：实际文件里的 `add_diplomatic_relevance` 字段**未出现在官方 .md 模板中**，属于文档滞后。

这些立场的**评分**由 AI 策略中的 `strategic_region_stance_type_scores` 字段决定，同时受 `max_active_stances` 限制。

### 7.3 从中学到的关键做法

1. **文件名前缀分类**：用 `kai_` 前缀放自己的文件，**避免与原版文件名冲突**
2. **`00_default_strategy.txt` 必须整文件替换**（因为要改基线值），而非新增
3. **defines 用独立文件覆盖**（`kai_ai.txt`），不必改 `00_ai.txt`
4. 辅助系统（法律、科技、建筑）被同步调整，说明**纯改 AI 参数往往不够**，需要联动改制度

> `README.md`（19.6 KB）与 `changelog.md`（10 KB）可能包含作者的调参思路，**建议后续精读**（尚未在本文档中展开）。

## 9. 开发 AI mod 的推荐切入路径

```text
① 建立基线认知
   └─ 精读 common\ai_strategies\00_default_strategy.txt（9,067 行）
      这是所有 AI 取值的基线，60 个字段各自的含义与默认值

② 选定改造层次
   ├─ 粗粒度（快）      → common\defines\00_ai.txt 参数（1017 项）
   ├─ 中粒度（推荐）    → 新增自己的 ai_strategy 文件 + 覆盖关键字段
   └─ 细粒度（彻底）    → 整文件替换 00_default_strategy.txt

③ 用 script_values 做中间层
   └─ common\script_values\ 自定义值，供策略字段引用，便于统一调参

④ 联动改造
   └─ 法律 / 科技 / 建筑 / 修正符，让 AI 的新行为有制度基础

⑤ 调试
   └─ -debug_mode 启动 → 看 logs\ai.log、error.log、database_conflicts.log
```

### 9.1 最小可行 AI mod 骨架

```text
mod\StateCraft AI\
├─ .metadata\metadata.json
└─ common\
    ├─ ai_strategies\
    │   └─ sc_ai_strategies.txt      # 你自己的策略，键名不与原版重名
    ├─ defines\
    │   └─ sc_ai.txt                 # 只写要改的 NAI 参数
    └─ script_values\
        └─ sc_ai_values.txt          # 你的调参中间层
```

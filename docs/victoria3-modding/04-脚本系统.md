## 2. 加载与覆盖机制

### 2.1 路径同名覆盖（Clausewitz 通用规则）

`GAME/checksum_manifest.txt` 明确列出了参与校验和（即「内容」）的目录：

```
directory
name = common
sub_directories = yes

directory
name = events
sub_directories = yes

directory
name = map_data
sub_directories = yes

directory
name = gui
sub_directories = yes

directory
name = localization
sub_directories = yes

file
name = paths_checksummed.settings
```

（`checksum_manifest.txt` 共 22 行，完整内容即上述 6 个条目）

这说明 `common/`、`events/`、`gui/`、`localization/` 等目录属于「内容层」，
MOD 通过在这些目录下放置**相同相对路径**的文件来替换原版文件。

**结论（工具链层面可确认）**：MOD 文件与被替换的原版文件**相对路径完全一致**时，
原版文件整体被替换。这是所有 Paradox Clausewitz 游戏一致的加载规则，
也是本任务中「覆盖原版同名键即可替换」的**唯一可靠做法**：
把你的同名键放进一个**与原版同路径的文件**里，从而整文件替换。

**【未确认】**：把同名键放进一个**新增的、路径不同的文件**里会发生什么
（合并 / 后者覆盖前者 / 报重复定义错误）。原版数据无此实例，游戏内文档亦未说明。

### 2.2 三种可靠的 MOD 介入方式

| 方式 | 适用 | 风险 |
| --- | --- | --- |
| **A. 同路径整文件替换** | 任何键 | 会连带丢失该文件内其它原版内容，需完全复制原文件再改 |
| **B. 新增独立文件 + 新键名** | 新增内容 | 无风险，但无法修改原版已有键 |
| **C. 新增文件 + 原版键名** | 想改原版键 | **【未确认】** 行为不明确，不推荐 |
| **D. on_actions 专用：链式追加** | 只给原版 on_action 追加效果 | **官方文档明确支持**，见 §3.4 |

### 3.3 官方文档逐字引用：结构与从脚本触发

**从脚本触发**（`_on_actions.md:36-40`）：

```
## Beyond this, on_actions can also be fired from script by using the trigger_event effect:
	trigger_event = {
		on_action = on_action_name
		days/months/years = X  	# Optional
	}
```

**结构**（`_on_actions.md:43-111`，逐字引用）：

```
on_action_name = {
	trigger = {			# On_actions can have triggers. If an on_action fires and its trigger returns false, nothing happens
		trigger_conditions = yes
	}

	weight_multiplier = {	# Used to manipulate the weight of this on_action if it is a candidate in a random_on_actions list (see below)
		base = 1
		modifier = {
			add = 1
			trigger_conditions = yes
		}
	}

	events = {		# Events listed in "events" brackets will always fire as long as their trigger evaluates to true
		event_id.1
		delay = { days = 365 }		# A delay will mean that all events listed after it will only be fired after the delay has passed. NOTE: For performance reasons, an event will only successfully fire if it is valid both when the on_action is executed AND once the delay is complete. All firing entries support delays, whether for events or on_actions.
		event_id.2
		delay = { months = { 6 12 } }	# Setting a new delay overrides a previous delay. Delays support random ranges
		event_id.3
	}
	
	random_events = {	# A single event will be picked to fire
		
		chance_to_happen = 25	# A percentage chance determining whether the events involved will be evaluated at all

		chance_of_no_event = { 	# An entry that can be formatted as a script value (and therefore have conditional entries). Separated from "chance_to_happen" for performance reasons. Will only be evaluated if chance_to_happen is true.
			value = 0
			if = {
				limit = { trigger_conditions = yes }
				add = 10
			}
		}

		100 = event_id.1 	# The number is the weight for picking a specific event. The weight is factored by the event's weight_multiplier entry. (If no weight_multiplier is defined for the event, it is 1)
		200 = event_id.2
		100 = 0		# Having a "0" entry means that there is a chance no event fires, even if there are other valid events. Good for making sure that rare events don't always fire just because every other possible event is invalid.
	}

	first_valid = {		# Pick the first event for which the trigger returns true
		event_id.1
		event_id.2
		fallback_event_without_trigger
	}

	on_actions = {	# An on_action can fire other on_actions, following the same rules as with events
		on_action_1
		on_action_2
		on_action_3
	}

	random_on_actions = {	# Same as with events. On_actions are also factored by their weight_multipliers, which defaults to 1
		100 = on_action_1
		200 = on_action_2
		100 = 0
	}

	first_valid_on_action = {
		on_action_1
		on_action_2
	}

	effect = { 	# An on_action can run effects. It can access the same default or saved scopes as the script chain/code functionality it was fired from. Note that it happens concurrently to events triggered by the on_action, NOT before. Effects run here create a separate chain than events the on_action fires, so you can for example not manipulate values in the effect, and then reliably access those in an event that was fired at the same time. Scopes or local variables set in the effect here will not carry over to any event fired by the on_action.
		effects = yes
	}

	fallback = another_on_action 	# on_actions can define a fallback on_action. If no events/on_actions are run by the on_action, the fallback gets called instead. Avoid creating infinite fallback loops, or the game may be prevented from advancing time!
}
```

**⚠️ 关键陷阱（逐字引用 `_on_actions.md:106`）**：
`effect` 块与同一 on_action 触发的事件**并发执行，而非先于事件**。
在 effect 里设置的 scope / 局部变量**不会**传递给同一次触发的事件。
不要写成「先设变量、再在事件里读取」。

### 3.4 官方文档逐字引用：MODDING INFO（覆盖机制）

`common/on_actions/_on_actions.md:113-128`，**逐字引用**：

```
### MODDING INFO ###

# You can declare data for on-actions in multiple files, however, you cannot have multiple triggers or effect blocks for a given named on-action. In particular, you cannot append an effect block directly to an on_action which already has an effect block, as this creates a conflict. 

# If a modder wishes to append their own effects to an on_action without overriding a file, they may do it as follows:

some_vanilla_on_action = {
	on_actions = { some_modded_on_action }
}
some_modded_on_action = {
	effect = {
		some_fun_modding_effect = yes
	}
}

# This makes the vanilla on-action call the modded on-action whenever it fires.
```

**对 MOD 开发者的实操结论**：

1. ✅ **可以**在多个文件中声明同一个 on_action 的不同子块（`on_actions` 列表会追加）。
2. ❌ **不可以**给一个已有 `effect` 块的 on_action 再追加第二块 `effect`（冲突）。
3. ❌ 同理，**不可以**给一个已有 `trigger` 块的 on_action 再追加第二块 `trigger`。
4. ✅ **官方推荐的追加方式**：定义自己的 on_action，并在**原版 on_action 的名字下**
   写 `on_actions = { 你的on_action }`，让原版 on_action 反过来调用你的。

**实例佐证（原版自用同一模式）**：
`common/on_actions/00_on_actions_monthly.txt:1` 首行注释为
`# Fired off on_monthly_pulse_country`；其内定义的
`krakatoa_on_action`（`:117`）由脚本通过
`common/journal_entries/00_krakatoa.txt:17-19` 的
`trigger_event = { on_action = krakatoa_on_action }` 调用。
即：**命名 on_action + 从别处调用**是引擎支持的一等公民。

同样，`common/on_actions/00_on_actions_yearly.txt:1` 首行注释
`# Fired off on_yearly_pulse_country`，
`00_on_actions_half_yearly.txt:1` 为 `# Fired off on_half_yearly_pulse_country`，
`00_on_actions_election.txt:1` 为 `# Fired off on_monthly_pulse_country_elections`。
这四组「具名 on_action」都挂在对应脉冲上——**这正是它们出现在这些文件而非定义脉冲本身的原因**。

### 4.3 官方文档逐字引用：公式

`script_values.md:15-67`：

```
# Formulas

For more complex values, it is possible to define mathematical formulas. These allow you to use everything available in
the scope you're currently in.
Be careful with these, as they have to be calculated every single time they're evaluated. Complex formulas can be
performance intensive.
Formulas do not work for true/false values.

A formula is declared using curly brackets, and follow this format:

	name_of_scripted_value = {
		# Mathematical operations
		add = number/scripted value/scope.something
		subtract = ...
		multiply = ...
		divide = ... # Be careful not to divide by 0
		modulo = ... # Also don't modulo by 0
	
		value = ... # Sets the value to this number
	
		max = ... # Sets the value to this number if it is currently higher. E.G., "max = 10" would cause the number 15 to become 10
		min = ... # Sets the value to this number if it is currently lower
	
		round = yes # Rounds to nearest whole number
		ceiling = yes # Rounds up (towards positive infinity)
		floor = yes # Rounds down (towards negative infinity)

		round_to = 5 # Rounds to the nearest specified number (e.g. 26 would be rounded to 25 in this example). Be careful not to round to 0
	
		if = { # These operations are executed if the limit is met. You can also put "if" inside an "if"
			limit = { some conditions }
			add = 5
			divide = ...
			...
		}
		else_if = { # If the "if" above is not met, these operations are executed, as long as the limit is met. You can put several "else_if" in a row
			limit = { some conditions }
			operations...
		}
		else = { # If the "if" or "else_if" above is not met, these operations are executed
			operations...
		}
	
		fixed_range = { # Gives a random fixed-point number in the range (E.G., 1.242)
			min = ... script value
			max = ...
		}
	
		integer_range = { # Gives a random fixed-point number in the range (E.G., 1)
			min = ...
			max = ...
		}
	}
```

**操作符完整清单**（自官方文档提取）：
`add`、`subtract`、`multiply`、`divide`、`modulo`、`value`、`max`、`min`、
`round`、`ceiling`、`floor`、`round_to`、`if`、`else_if`、`else`、
`fixed_range`、`integer_range`。

### 4.4 官方文档逐字引用：执行顺序 / 内联 / 链式 / 区间 / 列表 / 作用域

**执行顺序**（`script_values.md:69-80`）：

```
# Execution order

Operations are executed in the order defined.

		value = {
			add = 5
			multiply = 4
			max = 10
			add = 5
		}

Would result in "15", since "max = 10" would be applied before the last "add = 5"
```

> ⚠️ 这是最容易踩的坑：**操作按书写顺序依次执行**，不是数学优先级。
> 上例中 `add=5, multiply=4` 得 20，`max=10` 截到 10，再 `add=5` 得 **15**（不是 25）。

**内联（Inlining）**（`script_values.md:82-93`）：

```
# Inlining

Formulas can be written inline wherever scripted values work. So if a formula is only to be used once, there's no need
to name it and have it in the scriptvalues folder.

	add_gold = {
		value = gold
		multiply = { # Yes, you can even inline them in the mathematical operators
			value = 1
			multiply = 0.5
		}
	}
```

**链式（Chaining）**（`script_values.md:95-107`）：

```
# Chaining

You can reference named script formulas using scope chaining. For example, if you were to define this formula:

	example_age = {
		value = age
	}

Then the following would work:

	add_gold = {
		value = mother.example_age
	}
```

**区间（Ranges）**（`script_values.md:109-115`）：

```
# Ranges

Script values can also define ranges.
E.G., add_gold = { 1 5 } will add 1 to 5 gold.
add_gold = { named_value another_named_value } will resolve the named values (including formulas).
Note that you can't inline formulas within a range. E.G., you cannot do add_gold = { { value = 1 add = 2 }
some_named_value }. If you need that, use integer_range or fixed_range from the script math system.
```

**列表（Lists）**（`script_values.md:117-131`）：

```
# Lists

Script values support lists.
E.G., add_gold = { every_child = { add = 1 } } will add as much gold as you have children.
All lists should work, including those defined in script.

Ordered lists also work.

	add_gold = {
		ordered_child = {
			order_by = age
			max = 3
			add = age
		}
	}
```

**作用域（Scoping）**（`script_values.md:133-143`）：

```
# Scoping

You can change scope within script values just as you can in regular script.

	add_gold = {
		father = {
			any_child = { add = 1 }
		}
	}
```

**AI 权重的惯用写法**（`ai_script_values.txt:3-97` 的 `base_impose_law_weight` 是最完整范例）：

1. `value = …` 设基线；

- 想让 AI 更/更少做某件事，先找对应权重键是否在 `ai_script_values.txt` 内；
- 复杂权重也要遵守「顺序执行」规则，`max`/`min` 的位置决定结果；
- 用 `desc` 让游戏内数值提示可读（可选）。

## 5. scripted_effects 与 scripted_triggers

这两个系统**没有官方 `.md` 文档**，以下语法均来自原版实际文件与机器提取。

### 5.1 用途与位置

| 系统 | 位置 | 文件数 | 顶层键数 |

| scripted_effects | `GAME/common/scripted_effects/` | 40 | **721** |

**由此确定的语法**：

	retire_character = yes
}
```

**scripted_trigger 实例**（`common/scripted_triggers/00_scripted_triggers.txt:16-40`，**逐字引用**，
`OR` 内 19 项以 `…` 略去）：

```
country_has_voting_franchise = {
	custom_tooltip = {
		text = is_democratic_tt
		OR = {
			modifier:country_voting_power_base_add > 0
			…
		}
	}
}
```

> 注意：scripted_trigger 体内可以直接用 `custom_tooltip = { text = … }` 包裹条件，
> 用于让 tooltip 显示人类可读的说明（`text = is_democratic_tt`）。

### 5.3 调用语法

**无参数调用**：

- 效果：`键名 = yes`
  证据：`common/scripted_guis/journal_entry_sguis.txt:80`
  调用 `je_meiji_restoration_update_japanese_emperor = yes`；
  该效果定义于 `common/scripted_effects/00_sgui_effects.txt:2`。
- 触发器：`键名 = yes`
  证据：`common/on_actions/00_code_on_actions.txt:41`

  该触发器定义于 `common/scripted_triggers/00_scripted_triggers.txt:16`。

定义处在效果体内用 `$参数名$` 占位，调用处写 `参数名 = 值`。

`common/scripted_effects/00_chris_scripted_effects.txt:353-373`（逐字引用，含原版注释）：

```

		limit = {
			c:TUR ?= {
				has_technology_researched = $TECH$
			}
			root = {
				NOT = {
					has_technology_researched = $TECH$
				}
			}

### 5.5 覆盖机制

- **文件路径同名覆盖**：见 §2.1，可用。
- **新文件里定义原版同名键**：**【未确认】**（原版 721/736 个键均无跨文件重名）。
- **推荐的新增方式**：使用带 MOD 前缀的新键名（如 `mymod_do_thing_effect`），

### 9.2 基础语法

**文件名/内容无强绑定**，但原版惯例是「一个 namespace 一个文件」。

**namespace 与事件 ID**（`events/1848.txt:1-6`，逐字引用）：

```
namespace = 1848

# Regicide
# Triggered from enactment pulse
1848.1 = {
	type = country_event
	placement = root
	...
```

**字符串型 namespace**（`events/acceptance_events.txt:1-4`，逐字引用）：

```
namespace = acceptance_events

acceptance_events.1 = { #Heir falls in love with unbecomingly unacceptable pop. The horror!
	type = country_event
	placement = ROOT
	...
```

**结论**：`namespace = <标识符>`，事件键为 `<namespace>.<整数>`。
`placement` 的大小写不敏感（原版同时出现 `root` 与 `ROOT`）。

	global_neg = ADD_ENACTMENT_MODIFIER_NEG
	first = ADD_ENACTMENT_MODIFIER_FIRST
	first_neg = ADD_ENACTMENT_MODIFIER_FIRST_NEG
	third = ADD_ENACTMENT_MODIFIER_THIRD
	third_neg = ADD_ENACTMENT_MODIFIER_THIRD_NEG

**关键差异对照表**：

| 项 | trigger_localization | effect_localization |
| --- | --- | --- |
| 官方 `.md` | ✅ 有 | ❌ **无** |
| 规则键 | `global` / `first` / `third` | 同 |
| 否定后缀 | **`_not`**（`global_not`） | **`_neg`**（`global_neg`） |
| 条目名 | 触发器名（+ `_all`/`_count`/`_percent` 变体） | 效果名 |
| 条目数 | 1681 | 297 |

**给 scripted_effect 提供本地化 —— 原版唯一实证**：

- scripted effect 定义：`common/scripted_effects/00_krakatoa_effects.txt:32-34`（逐字引用）：

  ```
  # Reusable Tsunami
  # scope = strategic region
  tsunami_effect = {
  ```

- 其内部用 `custom_description` 引用同名 loc 条目（`:35-38`，逐字引用）：

  ```
  	custom_description = {
  		text = "tsunami_effect"
  		subject = this
  		value = $value$
  ```

- effect_localization 条目：`common/effect_localization/00_strategic_region_effects_loc.txt:1-3`
  **整文件逐字引用**：

  ```
  tsunami_effect = {
      global = TSUNAMI_EFFECT_GLOBAL
  }
  ```

**结论（可追溯）**：effect_localization 的条目名**可以与 scripted effect 同名**，
其绑定关系是通过该效果内的 `custom_description = { text = "…" }` 建立的。
全库交叉验证：297 个 effect_localization 键与 721 个 scripted effect 键
**只有 1 处重合**，正是 `tsunami_effect`。

> **【未确认】**：effect_localization 条目能否**直接**（不经 `custom_description`）
> 为某个 scripted effect 提供 tooltip。原版无此实例。

**同一效果的另一实证**：`tsunami_effect` 也示范了 `$参数$` 在 scripted effect 中的传递
（`00_krakatoa_effects.txt:4` 等 9 处，逐字引用调用形式）：

```
		tsunami_effect = { value = krakatoa_large_devastation }
```

- **覆盖机制**：**可以覆盖**（同名条目即替换显示文本）。
  这两个目录是**最安全的覆盖点**：只改显示文本，不改逻辑。
  推荐做法：同路径文件替换，或新增文件用唯一名字。

## 12. 「可覆盖同名键」vs「只能新增」——明确区分

### 12.1 可以覆盖（有据可依）

| 系统 / 内容 | 覆盖方式 | 依据 |
| --- | --- | --- |
| **任意脚本文件** | MOD 文件与 GAME 文件**相对路径完全相同** → 整文件替换 | `checksum_manifest.txt` 列明 `common`/`events`/`map_data`/`gui`/`localization` 为内容目录（§2.1） |
| **on_actions 的子块追加** | 在原版 on_action 名下写 `on_actions = { 你的on_action }` | `common/on_actions/_on_actions.md:115-128`（§3.4，官方明确支持） |
| **scripted_rules** | 定义同名规则键 → 替换该判定逻辑 | 引擎按键名查询；`00_scripted_rules.txt` 18 个键均为引擎钩子（§7.2） |

### 12.3 实操建议（基于已确认事实）

| 目标 | 推荐做法 | 理由 |
| --- | --- | --- |
| 只给原版 on_action 追加效果 | 新建 `<mod>_on_action`，在原版 on_action 名下写 `on_actions = { <mod>_on_action }` | 官方文档明确支持，零冲突（§3.4） |
| 修改原版某个 scripted_effect / trigger / script_value | **同路径整文件替换**：完整复制 GAME 原文件到 MOD 同路径，再改目标键 | 唯一有据可依的覆盖方式 |
| 追加新内容 | 新文件 + **带 MOD 前缀的唯一键名** | 避免与其它 MOD 冲突 |
| 覆盖 tooltip 文本 | `trigger_localization` / `effect_localization` 同名条目 | 只改显示，不动逻辑，风险最低 |
| 替换 loc 文本 | `localization/simp_chinese/*.yml` 中重写 loc key | 标准做法 |

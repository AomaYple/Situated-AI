## 1. 法律系统：`laws`

### 1.1 用途

定义**每一条法律条文**。玩家/ AI 在某个 `law_groups` 组内二选一（每组同时只能有一条法律生效）。法律本身承载：

- 通过后对国家生效的 `modifier`
- 绑定到某个 `institutions` 的 `institution` 与 `institution_modifier`
- 分档税率 `tax_modifier_*`
- AI 是否愿意颁布 / 是否愿意强加给附属国
- 与其他法律的互斥（`disallowing_laws`）、依赖（`unlocking_laws`）、继承（`parent`）

### 1.4 【官方】`laws\readme.md` 全文要点（**重要警告**）

这是 `laws` 目录**唯一**的官方文档，全文只讲一个字段 —— `ai_enact_weight_modifier`。原文要点（转述，不整段引用）：

| 要点 | 内容 |
|---|---|
| **语义** | 该值是**加/减到 AI 基础权重上**的修正量。设 0 = 只用基础权重；设 −50 = (基础权重 − 50) |
| **基础权重范围** | 来自 strategy、法律是否被运动支持等因素，**通常在数百量级**（"low hundreds"） |
| **量级建议** | +100 已"相当显著"；+1000 已"非常显著" |
| **⚠️ 单一字段不保证通过** | 原文明确：即使设成 **100000**、并把 `change_law_chance` 设为 **100**，若 AI 缺少政府/运动支持、害怕革命、或 `ai_will_do` 求值为 false，**仍然无法颁布** |
| **配套调整** | 想真正让它通过，还需调 `AI politics strategies` 里的 **`change_law_chance`** 与 **`revolution_aversion`** |
| **作用域** | root = AI 国家；`scope:law` = 该国对应的那条法律 |
| **强加附属国** | 只有**宗主国**能强加法律（`can_impose = { }` 加触发条件，`initiator` 为强加国作用域，但**在目标国作用域下求值**）；`on_impose = { }` 是强加时执行的 effect |

官方给的示例（**逐字引用**【官方】）：

```pdx
	ai_enact_weight_modifier = {
		value = 0
	
		if = {
			limit = { 
				c:GBR ?= THIS
				exists = var:GBR_favorite_law
				scope:law = var:GBR_favorite_law
			}
			add = 10
		}
	}
```

> **对 mod 开发的直接含义**：改 `ai_enact_weight_modifier` 只是"投票倾向"，**不是开关**。
> 想强制 AI 走某条路线，三件套缺一不可：① 法律自己的 `ai_will_do` 不能是 `no`；② `ai_enact_weight_modifier` 给足量级；③ 对应 AI strategy 的 `change_law_chance` / `revolution_aversion`。AI strategy 详见 [`10-AI策略字段参考.md`](10-AI策略字段参考.md)。

### 1.7 覆盖 vs 新增 —— 证据

| 问题 | 答案 | 证据 |
|---|---|---|
| 能否只加一条法律而不替换文件？ | **能** | 【实测】5 个真实 mod 都在 `common\laws\` 下用**新文件名**添加法律：`kai_colonial_affairs.txt`（Kuromi's AI）、`Ultra_P_church_and_state.txt`（UH Politics）、`Ultra_W_army_model.txt`（UH Warfare）、`ULTRA_RE_childrens_rights.txt`（UH Research）、`Ultra_D_colonial_affairs.txt`（UH Diplomacy） |
| 那改原版已有法律呢？ | **整文件替换 _或_ 用前缀关键字** | 【实测】见 §18；`Ultra_CD_replace_cultures.txt` 里逐字出现 `REPLACE:north_german= {` |
| 整文件替换的后果 | **未列出的字段会退回默认值** | 【推断】依据见 §2.5 与 §18.4：真实 mod 都**完整复制了全部 28 个字段**（UH Politics 的 `00_devout.txt` 字段数与内容结构与原版完全一致），说明不复制就会丢失 |

### 1.8 实战提示

1. **加法律 ≠ 改法律**。加一条新法律只需新文件 + 新顶层键，**零冲突**（符合 `12` 号文档"新增 ≫ 覆盖"结论）。改一条原版法律则必须处理覆盖，优先用 `INJECT:`（见 §18）。
2. **`law_groups` 是稀缺资源**。原版只有 26 个组；想在已有组里加法律，只要 `group = lawgroup_xxx` 写对即可；想加**新的法律类别**，必须同时新增 `lawgroup_*` 顶层键。
3. **`progressiveness` 决定 IG 立场基调**。若新增法律未在意识形态里显式给出态度，IG 会按 `progressiveness` 与自身倾向推断 —— 但**具体推断公式未确认**。
4. **`unlocking_technologies` 是 68 处使用的高频字段**，是给新法律设门槛的最常用手段（比 `unlocking_laws` 的 14 处多得多）。
5. **改 AI 通过率务必读 §1.4**：单靠 `ai_enact_weight_modifier` 无效。

### 2.4 与 `ideologies`、`interest_group_traits` 的关系

```text
interest_groups\00_trade_unions.txt
  ├─ ideologies = { ideology_proletarian  ideology_egalitarian  ... }
  │                     └──► ideologies\00_ig_ideologies.txt 里的顶层键
  ├─ character_ideologies = { ideology_moderate  ideology_reformer  ... }

                        └──► interest_group_traits\00_trade_unions_traits.txt 里的顶层键
```

三条链路都是**单向的键引用**，被引用方**不知道自己被谁引用**。因此：

- 新增 IG 特质：只需在 `interest_group_traits/` 加文件加键，再在**某个 effect 里** `set_ig_trait`。
- 新增 IG：必须同时提供 `ideologies` 引用的意识形态键，否则引用失效（**失效后果未确认**）。

```pdx
			}
		}
		rule = {
			trigger = {
				c:ZAN ?= this
				any_primary_culture = {
					cu:bedouin = this
				}
			}
			cultures = {

			}
```

| 做法 | 实例 | 结果 |
|---|---|---|
| **整目录整文件替换** | 【实测】**Ultra Historical Politics**（`2918521358`）覆盖了**全部 8 个** `interest_groups\*.txt`，且**文件名与结构完全沿用原版** | 该 mod 的 `00_devout.txt` 为 27,285 B（原版 19,435 B），深度 1 键 **28 个，与原版完全一致** → 证明它做的是"完整重写"，而非删减 |
| **新增** | 本机 23 个 mod 中，**没有任何 mod 在 `interest_groups\` 下新增文件** | 该目录只有"整文件替换"这一条路 |

> **⚠️ 这是本文档 25 个目录中最危险的目录之一**：想改任意一个 IG 的任意一个字段，目前**只能整文件替换**（除非用 §18 的 `INJECT:` 前缀）。

### 2.6 实战提示

1. **不要照抄 UH Politics 的做法**。它替换 8 个文件 = 与任何其他改 IG 的 mod **硬冲突**。用 `INJECT:ig_trade_unions = { pop_weight = { ... } }` 更安全（见 §18）。

3. **`pop_weight` 是 IG 强度的总闸门**。它决定每个 POP 有多愿意支持这个 IG，直接决定 clout。改它比改任何 modifier 都更"伤筋动骨"。
4<!--claim:pol.ig_trait_fields_doc15-->. **`index` 必须唯一且 0–7**。新增第 9 个 IG 是否可行 —— **未确认**（原版硬编码 8 个的迹象：`index` 连续 0–7、`layer` 命名规整；但游戏是否支持更多未经实测）。

## 4. 意识形态：`ideologies`

3. **政治运动** 通过 `ideology = xxx` 引用 → 决定运动支持/反对哪些法律

## 5. 政党：`parties`

### 5.1 用途

定义**政党**：哪些 IG 可以组成它、党名（可按国家/法律条件变化）、图标、加入权重、科技解锁。

### 5.2 文件组织

**【实测】** 12 个文件，**每个政党一个文件**，命名 = `<政党短名>_party.txt`：

```text

conservative_party.txt      fascist_party.txt          free_trade_party.txt
liberal_party.txt           military_party.txt         radical_party.txt
religious_party.txt         revolutionary_party.txt    social_democrats_party.txt
```

> **命名规律**：唯独 `social_democrats_party.txt` 带复数 `s`，其余都是单数。

**加载方式**：扫描 `common/parties/*.txt`，按顶层键注册。**目录内无官方 `.md`**。

### 5.3 完整字段列表（7 个）

**【实测】** 深度 1 键去重 = **7 个**。

| 字段 | 出现 | 含义 |
|---|---|---|
| `color` | 12 | 政党颜色 |
| `name` | 12 | **党名块**（不是字符串，是 `first_valid` + `triggered_desc` 的条件表，见下） |
| `icon` | 12 | 图标块（`icon = { default = "..." }`） |
| `valid_for_country` | 11 | 该国是否允许存在此政党 |
| `available_for_interest_group` | 12 | **哪些 IG 可以加入此政党** |
| `join_weight` | 12 | IG 加入的权重（script value，带 `desc` 供 UI 显示） |

### 5.4 典型语法 —— 逐字引用

**【实测】** 逐字引自 `GAME\common\parties\revolutionary_party.txt`（该文件全文，含开头的两个空行）：

```pdx
			is_revolutionary = yes

			limit = {
				owner = {
					is_revolutionary = yes
				}

			add = {
				value = 10000
				desc = "base_value"
			}

```

**条件党名**【实测】逐字引自 `GAME\common\parties\liberal_party.txt`（节选，展示 `first_valid` + `triggered_desc` 的用法）：

```pdx
	name = {
		first_valid = {
			triggered_desc = {
				desc = party_civilista_party
				trigger = {
					c:PEU ?= THIS
				}
			}
```

### 5.5 覆盖 vs 新增 —— 证据

| 做法 | 可行性 | 证据 |
|---|---|---|
| 新增政党 | ✅ | 【实测】本机 23 个 mod **无一**触及 `common\parties\`；但机制上它是普通顶层键数据库，加新文件加新键即可【推断】 |
| 改党名 | ✅ **不必动数据文件** | 党名走本地化键，**只改 `localization/` 即可**，零冲突 |
| 改结构 | ⚠️ 用 `REPLACE:<party_key>` | 见 §18 |

### 5.6 实战提示

1. **加政党名字是最低成本的改动**：找一个 `name` 变量里已有的 `triggered_desc` 缺口，或直接用 `REPLACE:` 改 `name` 块，然后在 `localization/` 提供键。20/23 的 mod 都只动本地化（见 `12` 号文档）。
2. **`join_weight` 的 `value = 0` + 条件 `add`** 是原版的标准写法 —— 默认权重 0，只在满足条件时给大额加分，确保政党不会在无关国家出现。
3. **`unlocking_technologies` 只有 7/12 使用**，其余 5 个政党（如 `revolutionary_party`）无科技门槛。

## 6. 政治运动：`political_movements` + 两个配套目录

**【实测】** 它就是一个**键名列表**，逐字引自 `GAME\common\political_movements\00_ideological_movements.txt`：

### 6.7 典型语法 —— 逐字引用

```pdx
	can_have_slave_supporters = yes

	active_law_radicalism_multiplier = 1

		ideology_abolitionist
		ideology_humanitarian
		ideology_radical
	}

		has_law_or_variant = law_type:law_slavery_banned

				pop_type = slaves
				percent >= 0.15
			}

					target = pop_type:slaves
					value >= 0.55 # So South Carolina doesn't count immediately
				}
			}
		}

							prestige > ROOT.owner.prestige

								is_political_movement_type = movement_slave_revolt
```

## 7. 政治游说团：`political_lobbies` + `political_lobby_appeasement`

### 7.1 用途

**游说团** = 由 IG 组成、**对某个外国（或本国）持亲/反立场**的团体。它们会提出诉求，玩家满足 → 绥靖（`appeasement`）；无视 → 不满。

| 目录 | 角色 |
|---|---|
| `political_lobbies` | 游说团定义：立场类别、创建条件、维持要求、可用绥靖因子 |
| `political_lobby_appeasement` | 绥靖"理由"：显示时长、是否所有游说团通用 |

### 7.2 文件组织

**【实测】** 各 1 个 `.txt` + 1 个 `.md`。

- `political_lobbies\00_political_lobbies.txt`（44 KB）→ **4 个游说团**
- `political_lobby_appeasement\00_political_lobby_appeasement.txt`（4 KB）→ **49 个绥靖理由**

**加载方式**：扫描各自目录的 `.txt`，按顶层键注册。

### 7.3 完整字段列表 —— `political_lobbies`（9 个）

**【实测】** 与【官方】`political_lobbies.md` **完全一致**（这是文档质量最好的目录之一）。

| 字段 | 出现 | 含义（**【官方】** md 注释） |
|---|---|---|
| `category` | 4 | **游说团类别**，决定它针对哪类国家以及总体立场 |
| `texture` | 4 | 图标 `.dds` |
| `can_create` | 4 | 创建条件。root = 想加入/退出的 IG；`scope:country` = 游说团所属国；`scope:target_country` = 目标国（国内游说团时与 `scope:country` 相同） |
| `on_created` | 4 | 创建后 effect（额外提供 `scope:political_lobby`） |
| `requirement_to_maintain` | 10 | **维持条件**，可写多个。内部含 `trigger` / `on_failed` / `swap_type_on_failed` |
| `appeasement_factors_pro` | 4 | **亲方**绥靖因子列表 |
| `appeasement_factors_anti` | 4 | **反方**绥靖因子列表 |
| `available_for_interest_group` | 4 | IG 能否加入（**对已在团的 IG 不检查**） |
| `join_weight` | 4 | IG 加入意愿的 script value |

**`category` 的实测取值**【实测】仅 2 个（官方 md 列了 3 个）：

| 取值 | 出现 |
|---|---|
| `foreign_pro_country` | 2 |
| `foreign_anti_country` | 2 |
| `foreign`（md 列出但原版未用） | 0 |

**`requirement_to_maintain` 的二级结构**【官方】：

| 子字段 | 含义 |
|---|---|
| `trigger` | 必须满足，否则游说团解散或改变类型 |
| `on_failed` | 条件失败时执行的 effect |
| `swap_type_on_failed` | **若设置，游说团改为指定类型而非解散** |

### 7.4 完整字段列表 —— `political_lobby_appeasement`（2 个）

**【实测】** 与【官方】`.md` 一致。

| 字段 | 出现 | 含义 |
|---|---|---|
| `duration_to_show` | 49 | 该理由在绥靖提示里显示多久。实测值：`{ months = 12 }`(1)、`{ months = 60 }`(48) |
| `is_always_usable` | 15 | 是否对所有游说团类型都可用 |

**【官方】关键约束（逐字转述）**：

- **`is_always_usable` 的因子不能写进 `political_lobbies` 的 `appeasement_factors_pro/anti` 列表**
- **未标 `is_always_usable` 的因子必须写进上述列表才可用**

### 7.5 典型语法 —— 逐字引用

**【实测】** 逐字引自 `GAME\common\political_lobby_appeasement\00_political_lobby_appeasement.txt`（前 2 个块）：

```pdx
	duration_to_show = { months = 60 }

	is_always_usable = yes
}
```


> 49 个理由里只有 15<!--claim:pol.lobby_usable--> 个标了 `is_always_usable = yes`，即**34 个必须靠 `political_lobbies` 的 `appeasement_factors_pro/anti` 显式引用**才会生效。

### 7.6 覆盖 vs 新增 —— 证据

| 做法 | 可行性 | 证据 |
|---|---|---|
| 新增游说团类型 | ✅ | 【实测】顶层键数据库，新文件新键即可【推断】 |
| 新增绥靖理由 | ✅ | 同上；**但必须同时被某个游说团引用**（或标 `is_always_usable = yes`），否则是死键 |
| 本机 mod 使用情况 | — | 【实测】**23 个 mod 中无一触及** `political_lobbies\` 或 `political_lobby_appeasement\` —— **这是一片完全未被开垦的改造面** |

### 7.7 实战提示

1. **这是 25 个目录里"零 mod 竞争"的两个** —— 想做出**没有 mod 冲突**的政治类改动，游说团系统是最佳切入点。
2. **`is_always_usable` 是双向约束**，写错会导致因子静默失效（见 §7.4）。改完务必看 `error.log`。
3. **本地化量不小**：49 个绥靖理由 + 4 个游说团都需要 `localization/` 条目。

## 8. 机构：`institutions`

### 8.3 完整字段列表（3 个）

### 8.4 等级机制 —— 【实测】证据链

这是本文档**唯一能给出机制答案的部分**，全部来自机械检索：

**【实测】等级由 `technology` 里的 modifier 解锁**。检索 `GAME\common\technology\`，发现 20+ 处形如：

```text
common\technology\technologies\30_society.txt:49:  country_institution_schools_max_investment_add = 1
common\technology\technologies\30_society.txt:67:  country_institution_police_max_investment_add = 2
common\technology\technologies\30_society.txt:109: country_institution_social_security_max_investment_add = 2
common\technology\technologies\30_society.txt:165: country_institution_home_affairs_max_investment_add = 1
common\technology\technologies\30_society.txt:250: country_institution_colonial_affairs_max_investment_add = 2
common\technology\technologies\30_society.txt:761: country_institution_workplace_safety_max_investment_add = 3
```

**结论（【实测】+【推断】）**：

| 环节 | 机制 | 证据等级 |
|---|---|---|
| 等级上限 | 由 modifier **`country_institution_<机构短名>_max_investment_add`** 累加决定；写在科技里 | 【实测】 |
| 国家可额外调整 | 法律里也有同族 modifier，如 `country_institution_schools_max_investment_add`（`02_childrens_rights.txt`）、`country_institution_police_max_investment_add`（`01_policing.txt`）、`country_institution_social_security_max_investment_add`（`02_welfare.txt`） | 【实测】 |
| 每级开销 | `country_institution_cost_institution_<短名>_mult`（定义于 `common\modifier_type_definitions\06_country_modifier_types.txt`，如 `country_institution_cost_institution_police_mult`） | 【实测】 |
| 升级速度 | `country_institution_size_change_speed_institution_<短名>_mult` + 通用 `country_institution_size_change_speed_mult` | 【实测】 |
| 每级效果 | `modifier` 是"**每级**"还是"总量" | **未确认** |

### 8.6 覆盖 vs 新增 —— 证据

| 做法 | 可行性 | 证据 |

### 8.7 实战提示

3. **不要给 `institution_schools` / `institution_health_system` 加 `modifier` 除非你确定要全局效果** —— 原版故意让它们空着，效果全在法律的 `institution_modifier` 里。


> 注意 `gov_ezo_republic` **只写了 `on_government_type_change`，没写 `on_post_...`** —— 这解释了 §9.3 里两个块的数量差。

### 9.5 覆盖 vs 新增 —— 证据

| 做法 | 可行性 | 证据 |
|---|---|---|
| 新增政体 | ✅ **这是本目录最有价值的改造面** | 【实测】新文件 + 新 `gov_*` 键。`possible` 里用 `has_law_or_variant` + `c:XXX ?= this` + `has_variable` 三重条件即可只为特定国家解锁 |
| 本机 mod 使用 | ❌ **零** | 【实测】23 个 mod **无一**触及 `common\government_types\` |

### 9.6 实战提示

1. **加"国别特色政体"不需要覆盖任何文件**。模板：新文件 → 新 `gov_<国家>_<体制>` 键 → `possible` 里用 `c:TAG ?= this` 锁定国家 → `on_government_type_change` 加 `change_to_<交接方式>`。**零冲突**。
2. **`transfer_of_power` 和 `possible` 是必填**（444/444）—— 漏写的行为**未确认**。
3. **头衔是本地化键**，必须去 `localization/` 加条目（如 `RULER_TITLE_SOSAI`）。
4. **`change_to_*` / `post_change_to_*` 是游戏内置 effect**，不是你定义的 —— 它们按 `transfer_of_power` 的 4 个取值派生。若你发明第 5 种 `transfer_of_power`，很可能没有对应的 effect 可用。
5. **173 个社会君主制**说明原版倾向"每国一个政体"的粒度；想加内容，模仿这个粒度即可。

### 11.6 与 `social_classes`、`pop_needs` 的关系


**① `pop_types` 不再有 `strata` 字段 —— 【官方】明确说明**

`social_classes\readme.md` 逐字为：

> `## strata`
> `You might or might not remember strata being scripted on a pop type. This is no longer the case. Pop types no longer belong to a strata, social classes do.`

**【实测】佐证**：`pop_types` 的 27 个字段里**没有 `strata`**。但 `officers.txt` 的 `qualifications` 里**仍在使用 `strata = upper` 作为 trigger**（见 §11.5 A 段最后一段 `if`），说明 `strata` 作为 **trigger** 仍存在，只是不能作为职业的**定义字段**。

**② `pop_needs` 与 `pop_types` 无键引用关系（【实测】）**

- `common\pop_needs\00_pop_needs.txt`（6,696 B）是独立数据库，顶层键形如 `popneed_simple_clothing`、`popneed_crude_items`、`popneed_basic_food`。
- 它的深度 1 字段只有 5<!--claim:pol.pop_needs_fields_doc15--> 个：`default`(15)、`entry`(52)、`obsession_demand_min`(4)、`obsession_demand_mult`(4)、`prestige_goods_demand_increase`(4)。

- **【实测】`pop_types` 的 15 个文件里没有任何一处引用 `popneed_*` 键**。
- 那么"哪个职业消费哪个需求"由什么决定 —— **未确认**（可能在 defines 或 C++ 侧）。

**③ `pop_needs` 与 `cultures` 的连接**

`cultures` 有 `obsessions` 字段（99 处）与 `taboos`（2 处），二者引用的都是**商品名**（`meat`、`liquor`、`wine`、`groceries`、`fruit`、`grain`），与 `pop_needs` 的 `goods` 同一命名空间。`religions` 也有 `taboos`（5 处）。

### 11.7 覆盖 vs 新增 —— 证据（**关键**）

| 做法 | 可行性 | 证据 |
|---|---|---|
| **整文件替换** | ⚠️ 本机最常见的做法 | 【实测】**Ultra Historical Research & Education**（`2897378189`）覆盖了 **11 个** `pop_types\*.txt`：`academics`、`aristocrats`、`bureaucrats`、`capitalists`、`clergymen`、`clerks`、`engineers`、`farmers`、`machinists`、`officers`、`shopkeepers` |
| 替换是否"完整重写" | ✅ **是** | 【实测】逐字段比对 `academics.txt`：原版 17 个深度 1 字段，mod 版 **17 个字段，完全相同，无增无减**（原版 2,131 B → mod 3,739 B，只改数值）。**证明整文件替换 = 完整覆盖，mod 作者必须复制全部字段** |
| 用 `INJECT:` 更安全 | ✅ | 见 §18。UH Research 在 `laws\` 下就用了 `INJECT:`，却在 `pop_types\` 下用了整文件替换 —— **说明 `INJECT:` 对 `pop_types` 是否有效未经验证** |

### 11.8 实战提示

1. **改一个职业的一个数值，照 UH Research 的做法要复制整个文件**（17 个字段）。**优先尝试 `INJECT:officers = { wage_weight = 6 }`** —— 若有效则冲突面从"整个文件"缩小到"一个字段"。**有效性未确认**，建议先用测试 mod 验证。
2. **`political_engagement_*` 三件套是政治 mod 的核心杠杆**。`base + literacy_factor × 识字率` 基本决定该职业的政治参与上限（原版注释里直接标了百分比区间，如 officers 的 `# 70% - 100% politically engaged`）。
3. **`qualifications` 里每一步都给 `desc`**，否则 UI 只显示数字不显示原因。
4. **别忘 `<职业名大写>_QUALIFICATIONS_DESC` 本地化键**（§11.4），并且若写了 `qualifications_growth_desc` 字段，键名以该字段为准。
5. **`working_adult_ratio` 只有 2 个职业显式写**（`peasants`、`slaves`）—— 其余 13 个用默认值。**默认值是多少未确认**。

## 12. 社会阶级与分层：`social_classes` + `social_hierarchies`

> 这两个目录拥有**本文档质量最高的官方文档**（`readme.md` 详尽、带完整语义说明与实例）。以下大量引用【官方】原文要点。

### 12.1 用途

### 12.4 【官方】硬性约束（`readme.md` 原文要点）

`social_classes\readme.md` 与 `social_hierarchies\readme.md` 给出了本文档中最严格的规则集：

| 约束 | 原文要点 |
|---|---|
| **默认体系唯一** | 必须**恰好有一个**体系标 `is_default = yes`。若一个都没标 → 游戏把**脚本顺序第一个**当默认（**会报错**）。若标了多个 → 第一个生效（**会报错**） |
| **每个体系必须有 3 个阶层** | 每个体系下必须至少有一个 `lower`、一个 `middle`、一个 `upper` 阶级，"否则游戏无法运行" |
| **每个 POP 必须恰好落入一个阶级** | 原文：若不满足，"**mayhem will ensue**" —— 从游戏崩溃、到运行但一堆东西出错、到存档损坏，什么都可能 |
| **歧义未定义** | 若一个 POP 同时满足多个阶级，**落入哪个是未指定的**（很可能是脚本顺序第一个，但**原文明确说不要依赖此行为**） |
| **`pop_criteria` 缺省语义** | 缺失 ≡ `always = yes` |
| **`allowed_professions` 缺省语义** | 缺失 ≡ **空列表**，即**没有任何职业**能属于该阶级 |
| **兜底阶级要放最后** | 原文建议：若写一个"全职业 + `always = yes`"的兜底阶级，**必须把它放在同体系内的最后一位**（脚本顺序） |
| **默认体系的 `pop_criteria` 实际不被检查** | 原文：即使写 `always = no` 也无效 —— POP **一定会**回退到默认体系 |
| **阶级可跨职业重叠** | 原文示例中一个 clerk 可落入 3 个阶级之一；歧义由脚本顺序决定（同"歧义未定义"条） |
| **多阶级可同属一个阶层** | 允许（原文示例里 `social_class_3` 与 `social_class_4` 都是 upper） |

### 12.6 覆盖 vs 新增 —— 证据

| 做法 | 可行性 | 证据 |
|---|---|---|
| 新增体系 | ✅ 但**必须**配套至少 3 个阶级 | 【官方】硬性要求（§12.4） |
| 新增阶级 | ✅ | 【实测】`01_edo_system.txt` 就有 6 个阶级，其中 3 个都是 `lower` |
| 新增职业后 | ⚠️ **必须**检查所有体系的覆盖 | 【实测】`00_default.txt` 的 16 个职业引用恰好覆盖 15 个职业，说明原版做了完整覆盖 |
| 本机 mod 使用 | ❌ **零** | 【实测】23 个 mod **无一**触及 `social_classes\` 或 `social_hierarchies\` |

### 12.7 实战提示

1. **这是"零 mod 竞争 + 高价值"的改造面**。想做"印度种姓""日本士农工商"式的深度社会 mod，这里是唯一入口。
2. **改任何涉及 POP 职业组合的东西，都要重跑 §12.5 的"16 = 15"完整性检查**。这是本文档给出的最有操作性的一条经验规则。
3. **不要给默认体系写 `pop_criteria`**（官方明说无效）。
4. **阶级键名是任意标识符**（`upper_class`、`brahmins`、`strata_samurai_high` 都是自由命名），但一旦被其他内容（事件、journal entry）用 `social_class` scope 引用，改名就会断链。
5. `law_groups` 的 `linked_social_hierarchy`（§1.6）把**法律组**与**分层体系**挂上了关系 —— 改分层体系时记得同步检查。

### 13.6 覆盖 vs 新增 —— 证据（**本目录最需要注意的一节**）

| 做法 | 可行性 | 证据 |

| **单文件新增文化** —— 新文件 + 新顶层键 | ✅ **推荐** | 【实测】`3626012595`（UH Cultures & Diversity）提供了 `Ultra_CD_cultures.txt`（113,847 B），内容是新文化（如 `picard`、`corsican`） |

> - `Ultra_CD_cultures.txt` → **纯新增**（新文化）
> - `Ultra_CD_replace_cultures.txt` → **`REPLACE:` 覆盖原版**（如给 `north_german` 加 `tradition_german`、`tradition_prussian`）

> 这是 §18 所述机制在真实 mod 中的完整范例。

### 13.7 实战提示

1. **绝对不要整文件替换 `00_cultures.txt`**。442 KB / 317 块，任何原版更新都会让你的 mod 失效，且与任何改文化的 mod 硬冲突。
2. **正确姿势**：
   - 加新文化 → 新文件 + 新键（如 `mymod_cultures.txt`）
   - 改原版文化 → 新文件 + `REPLACE:<文化名>`（如 `mymod_replace_cultures.txt`）
   - 只加一条传统 → 优先试 `INJECT:north_german = { traditions = { tradition_german } }`
3. **文化的 `heritage` / `language` 必须指向已存在的 `discrimination_traits` 键**（324<!--claim:pol.disc--> 个里选）。自定义传承 = 先在 `discrimination_traits` 加键 + 在 `discrimination_trait_groups` 加组。
4. **`graphics` 只有 10<!--claim:pol.graphics_values_doc15--> 个合法值**（实测），指向 `common\culture_graphics\`。**新增 graphics 类型需要动该目录** —— 超出本文档范围。
5. **姓名池是"文化沉浸感"成本最低、收益最高的改造点**。它纯粹是文本列表，几乎不会破坏任何机制；`12` 号文档记录的 `3507724904` Dynamic Names 就是走这条路（1,817 个新增文件，覆盖占比仅 2.7%）。
6. **改姓名/加文化必须配 `localization/`** —— 文化名、姓名等的本地化键。

## 15. 歧视特质：`discrimination_traits` + `discrimination_trait_groups`

### 15.1 用途

**③ 外形基因：`权重 = { name = <基因名>  range = { min max } }`**

```pdx
    gene_chin_forward = {


        7 = { name = chin_forward   range = { 0.3 0.45 }      }
        84 = { name = chin_forward   range = { 0.45 0.55 }      }
```

> **含义【推断】**：`权重 = { ... }` 的键是**相对概率权重**（10 / 20 / 50 / 84 / 98），不是百分比。`range` 是该基因在此民族下的取值区间。

### 16.5 【实测】文件格式的两个重要陷阱

**陷阱 1：缩进风格不统一。** `01_ethnicities_asian.txt` 与 `01_ethnicities_south_east_asian.txt` **全文件用 4 个空格缩进**，且**顶层块与它的直接子键缩进相同**：

```text
L37: indent=[SP+SP+SP+SP] ::     asian = {
L38: indent=[SP+SP+SP+SP] ::     template = "ethnicity_template"
L40: indent=[SP+SP+SP+SP] ::     skin_color = {
L41: indent=[SP+SP+SP+SP+SP+SP+SP+SP] ::         10 = { 0.2 0.3 0.2 0.3 }
L42: indent=[SP+SP+SP+SP] ::     }
```

> 其余 19 个文件用 tab。**Clausewitz 解析器是基于花括号的，因此两种都能工作**；但**任何依赖缩进的自动化脚本（包括本文档的提取脚本）都会在这里出错**。本文档 §0 的计数已改用花括号深度，规避了这个问题。

**陷阱 2：`@` 变量与顶层块混排。** 每个 `01_` 文件的**开头都有一大段 `@变量 = 值`**（`@neg1_min`、`@beauty2max`、`@blend3min` 等），然后是 `ethnicity_template = {` 之类的块：

```pdx
@neg1_min = 0.4
@neg1_max = 0.5

@neg2_min = 0.3
@neg2_max = 0.4
...
```

> 这些 `@` 变量在块内以 `@变量名` 形式引用（如 `range = { @neg1_min @neg1_max }`）。**没有官方文档说明这套变量的作用域**（是文件级还是全局）—— **未确认**。

### 16.6 覆盖 vs 新增

| 做法 | 可行性 | 证据 |
|---|---|---|
| 新增民族 | ✅ | 【实测】新文件 + 新顶层键 |
| 本机 mod 使用 | ❌ **零** | 【实测】23 个 mod **无一**触及 `common\ethnicities\` |

### 16.7 实战提示

1. **这是纯粹的"零 mod 竞争 + 零机制风险"改造面**。改动民族只影响肖像生成，**不可能破坏存档或经济平衡**。
2. **最小可行改动**：复制一个现有民族文件 → 改名 → 改 `skin_color` / `eye_color` / `hair_color` 的权重 → 在某个文化的 `ethnicities` 块里以权重引用它。
3. **`using = "..."` 可以继承另一个民族的完整基因设定**，只需覆盖少数几项 —— 这是最省力的扩展方式（原版只用 2 处：`caucasian.txt` 的 `using = "saxon"`、`indian.txt` 的 `using = "tamil"`）。
4. **`visible = no` 用于隐藏变体**（8 处）—— 若你加的民族只是中间产物（如 `caucasian_base`），标 `visible = no` 避免 UI 里出现。
5. **记得同步 `cultures[].ethnicities`**，否则新民族永远不会被使用。

## 18. 跨目录核心机制：**覆盖 vs 新增**（本文档最重要的发现）

`12` 号文档已从**文件层面**证明"新增 ≫ 覆盖"。本节从**语法层面**回答同一个问题的下一层：**如果要覆盖，怎么写？**

### 18.1 六个数据库操作前缀 —— 【实测】二进制证据

**【实测】** 对 `binaries\victoria3.exe` 做 ASCII 字符串检索，在 `jomini\modules\core\source\idlerlogicbase.cpp` 附近发现**连续排列的六个前缀字符串**及其内部枚举名：

```text
REPLACE_OR_CREATE:      REPLACE:      TRY_REPLACE:
TRY_INJECT:             INJECT_OR_CREATE:      INJECT:
```

对应的内部标识符（同一段内存，逐字【实测】）：

```text
ReplaceOrCreate   Replace   TryReplace   TryInject   InjectOrCreate   Inject
```

> **这是权威证据**：六个关键字**不是 mod 作者的约定**，而是**引擎内置的数据库操作语法**。

**【实测】排除法**：对全 `GAME` 目录（所有 `.txt`）检索这 6 个前缀 → **全部 0 命中**。即**原版自己从不使用它们**（原版直接用同文件名替换）。它们**专为 mod 引入**。

### 18.2 六个前缀在真实 mod 中的使用

**【实测】** 对全部 23 个 Workshop mod 检索：

| 前缀 | 命中数 | 使用实例 |
|---|---|---|
| `REPLACE:` | 12 个文件 | `2918521358\common\ideologies\Ultra_P_ig_ideologies_vanilla.txt`、`2897378189\common\laws\Ultra_RE_education_system.txt`、`3626012595\common\cultures\Ultra_CD_replace_cultures.txt` |
| `INJECT:` | 12+ 个文件 | `2897378189\common\laws\ULTRA_RE_childrens_rights.txt`、`2918521358\common\amendments\Ultra_P_amendments.txt` |
| `REPLACE_OR_CREATE:` | 12+ 个文件 | `2901783277\common\character_traits\mct_background_traits.txt`(20 处)、`3459869359\common\state_traits\joi_canal_traits.txt` |
| `TRY_REPLACE:` | **221 处** | `00_flavoured_companies_Argentina.txt`、`..._companies` 系列 |
| `INJECT_OR_CREATE:` | **46 处** | `zw_cpc_01_industry.txt` |
| `TRY_INJECT:` | 3 个文件（**440 处**） | `3656697666\common\company_types\Ultra_C_MoreUniqueCompanies.txt`(**437 处**)、`3041693269\common\laws\Ultra_Demo_church_and_state.txt`、`3503737491\common\journal_entries\zzz_zw_cpc_je.txt` |

> **注意**：`TRY_INJECT:` 虽然只出现在 3 个文件，但**单文件命中 437 次**（公司 mod），说明它是"批量操作"场景的首选。

### 18.3 六个前缀的语义 —— 【推断】+ 逐字证据

**【推断】**（依据名字 + 用法对比；**引擎行为未直接验证**）：

| 前缀 | 语义【推断】 | 键不存在时 | 逐字证据 |
|---|---|---|---|
| `INJECT:` | **合并/追加**进已有块。只写要加的字段，其余保留 | **报错** | `INJECT:law_child_labor_allowed = { modifier = { state_laborers_mortality_mult = 0.05 ... } }` |
| `TRY_INJECT:` | 同 `INJECT:`，但**键不存在时静默跳过**（不报错） | 跳过 | `TRY_INJECT:law_concordat = { modifier = { state_birth_rate_mult = -0.05 } }` |
| `INJECT_OR_CREATE:` | 键存在则合并，**不存在则创建** | 创建 | `INJECT_OR_CREATE:building_food_industry = { ... }` |
| `REPLACE:` | **整体替换**该键的块 | **报错** | `REPLACE:law_religious_schools = { group = lawgroup_education_system icon = "..." progressiveness = 0 ... }`（写全了所有字段） |
| `TRY_REPLACE:` | 同 `REPLACE:`，但**键不存在时静默跳过** | 跳过 | `TRY_REPLACE:company_bunge_born = { ... }` |
| `REPLACE_OR_CREATE:` | 键存在则替换，**不存在则创建** | 创建 | `REPLACE_OR_CREATE:state_trait_grand_canal_of_china = { ... }` |

**`INJECT:` vs `REPLACE:` 的用法差异（**【实测】** 同一 mod 内的对照）**：

`2897378189`（UH Research）在**同一个** `common\laws\` 目录下同时用了两种：

```pdx
# ULTRA_RE_childrens_rights.txt —— 用 INJECT，只写"要加的部分"
INJECT:law_child_labor_allowed = {
	modifier = {
		state_laborers_mortality_mult = 0.05
		state_machinists_mortality_mult = 0.05
		state_farmers_mortality_mult = 0.05
```

```pdx
# Ultra_RE_education_system.txt —— 用 REPLACE，写全了 group/icon/progressiveness...
REPLACE:law_religious_schools = {
	group = lawgroup_education_system

	icon = "gfx/interface/icons/law_icons/religious_schools.dds"

	progressiveness = 0
```

> **这就是最有价值的一条判据**：
> - 想**只加一个 modifier** → `INJECT:`（写 3 行）
> - 想**完全重写一条法律** → `REPLACE:`（写全 10+ 字段）
>
> `INJECT:` 让 mod 的**冲突面从"整个文件"缩小到"一个字段"** —— 两个 mod 都用 `INJECT:` 给同一条法律加不同的 modifier，理论上可以共存；而两个 mod 都 `REPLACE:` 同一条法律，必然一方失效。

### 18.4 ⚠️ 覆盖机制的三个陷阱（【实测】）

**陷阱 1：整文件替换 = 完全替换，不是合并。**

**【实测】最硬的证据**：`2897378189`（UH Research）替换了 11 个 `pop_types` 文件。逐字段比对 `academics.txt`：

```text

  political_engagement_base, political_engagement_literacy_factor,
  political_engagement_mult, portrait_age, portrait_is_female, portrait_pose,
  qualifications, qualifications_growth_desc, start_quality_of_life, texture,
  unemployment, wage_weight

mod 版 academics.txt 深度1 字段（17 个）：
  完全相同的 17 个（无增无减）

文件大小：2,131 B → 3,739 B（只改数值，不改结构）
```

同样地，`2918521358`（UH Politics）替换的 `00_devout.txt`，深度 1 字段 **28 个，与原版完全一致**。

> **结论**：**mod 作者必须把原文件的所有字段复制过来**。若漏掉字段，该字段会**退回引擎默认值**（不是保留原版值）—— **这一条为【推断】**（依据是 mod 作者行为一致地选择完整复制；直接验证需要对比漏字段的行为）。

**陷阱 2：缩进不影响解析，但会毁掉你的脚本。**

**【实测】** 原版多处混用 tab 与 4 空格缩进：

| 位置 | 现象 |
|---|---|
| `common\social_classes\01_edo_system.txt` | 全文用 tab，唯有 `pop_criteria` 块用 **4 空格** |
| `common\ethnicities\01_ethnicities_asian.txt` | **全文用 4 空格**，且顶层块与其子键**同缩进** |
| `common\ethnicities\01_ethnicities_south_east_asian.txt` | 同上 |
| `common\interest_groups\00_industrialists.txt` L532 | `female_executive_chance` 块内一行**少一个 tab** |

> **对 mod 开发的影响**：Clausewitz 基于花括号解析，**这些都不影响游戏**。但**任何依赖缩进的 diff / patch / 生成脚本都会出错**。写工具时必须**基于花括号深度**（本文档所有计数即如此）。

**陷阱 3：`REPLACE:` 写在**新文件名**里才有效果。**

**【实测】** 所有使用前缀的 mod，文件都是**新文件名**（`Ultra_P_*`、`Ultra_RE_*`、`kai_*`、`joi_*`、`mct_*`），**没有一个是原版文件名**。

> **【推断】** 前缀的意义正在于此：让你**不必占用原版文件路径**，从而避免与其他 mod 的文件级冲突。若你用了原版文件名又写了 `REPLACE:`，那是双重覆盖。

### 18.5 决策表：本文档 25 个目录该怎么改

| 想做的事 | 推荐做法 | 前缀 | 冲突风险 |
|---|---|---|---|
| 加一条**新**法律 / 政体 / 文化 / 运动 / 政党 / 修正案 / 社会阶级 | **新文件 + 新顶层键** | 无 | **零** |
| 给已有法律**加一个** modifier | `INJECT:law_xxx = { modifier = { ... } }` | `INJECT:` | 低 |
| 给已有法律**加**一个 `additional_radicalism_factors` 条件（运动） | `INJECT:movement_xxx = { ... }` | `INJECT:` | 低 |
| 给已有 IG 特质**改数值** | `REPLACE:ig_trait_xxx`（写全 4 字段） | `REPLACE:` | 中 |
| 给已有文化**加一条传统** | `INJECT:north_german = { traditions = { ... } }` | `INJECT:` | 低 |
| **完全重写**一条法律 / 意识形态 / 文化 | `REPLACE:key`（**写全所有字段**）+ 新文件名 | `REPLACE:` | 中 |
| 兼容性优先，不确定键是否存在 | `TRY_INJECT:` / `TRY_REPLACE:` | `TRY_*` | 低 |
| 跨 mod 追加内容（如给所有公司加字段） | `INJECT_OR_CREATE:` 批量 | `INJECT_OR_CREATE:` | 低 |
| 改 8 个 IG 的 `pop_weight` | ⚠️ **不要**整目录替换 8 个文件（UH Politics 的做法） | 优先试 `INJECT:ig_xxx` | **高** |

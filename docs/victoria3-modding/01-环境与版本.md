## 2. 三大目录

```text
① 游戏安装目录   C:\Program Files (x86)\Steam\steamapps\common\Victoria 3
② 用户数据目录   C:\Users\28905\Documents\Paradox Interactive\Victoria 3
③ Workshop 目录  C:\Program Files (x86)\Steam\steamapps\workshop\content\529340
```

`launcher-settings.json` 中声明：

- `gameDataPath` = `%USER_DOCUMENTS%/Paradox Interactive/Victoria 3` → 即上面 ②
- `dlcPath` = `../game` → DLC 内容位于 `<安装目录>\game\dlc\`
- `modPath` = `mod` → 本地 mod 放在用户数据目录下的 `mod\` 子目录
- `modExtension` = `zip`
- `isLooseFilesModSupported` = `true` → **支持散装文件 mod**（不需要打包成 zip）

## 5. 启动器配置要点（`launcher\launcher-settings.json`）

| 字段 | 值 | 对 mod 开发的意义 |
|---|---|---|
| `modPath` | `mod` | 本地 mod 根目录名 |
| `modExtension` | `zip` | mod 打包扩展名 |
| `isLooseFilesModSupported` | `true` | 可用散装文件夹形式开发，无需打包 |
| `modStubberPath` | `../binaries/victoria3.exe` | 用游戏本体生成 mod 模板 |
| `modStubberData.args` | `["--mod_stubber"]` | 生成模板的参数 |
| `modStubberData.type` | `MOD_NAME_PROMPT` | 会提示输入 mod 名 |
| `exePath` | `../binaries/victoria3.exe` | 游戏本体 |
| `exeArgs` | `["-gdpr-compliant"]` | 默认启动参数 |
| 备选启动 | `-gdpr-compliant -debug_mode` | **调试模式**，mod 开发必备 |
| `ingameSettingsPath` | `pdx_settings.json` | 游戏内设置文件 |

## 7. 日志文件（`logs\`）—— mod 调试必看

日志按 `<name>.log` + 轮转 `<name>.1.log` … `<name>.5.log` 组织。

| 日志 | 用途 | 对 mod 开发的价值 |
|---|---|---|
| `error.log` | 错误 | **最高优先级**：语法错误、无效键、缺失引用 |
| `debug.log` | 调试输出 | 脚本报错细节 |
| `game.log` | 游戏运行 | 内容加载过程 |
| **`ai.log`** | **AI 专用日志** | **AI mod 调试的核心**（当前为 0 字节） |
| `warning.log` | 警告 | 非致命问题 |
| `database_conflicts.log` | 数据库冲突 | **覆盖冲突检测**（当前为 0 字节） |
| `checksum.log` | 校验和 | 多人游戏兼容性校验 |
| `system.log` | 系统信息 | 环境 |
| `gui.log` | 界面 | `.gui` 报错 |
| `graphics.log` | 图形 | 贴图/模型问题 |
| `dedicated_server.log` | 专用服务器 | — |
| `custom_automated_stats.log` | 自动统计 | — |
| `gametimer_*.tsv` | 性能采样 | 性能分析（TSV 格式） |
| 其他空日志 | `ecs.log`、`memory.log`、`message.log`、`multiplayer.log`、`pdxsdk.log`、`setup.log`、`ui_animation_stats.log` | — |

> **实用结论**：改完 mod 后第一时间看 `error.log` 与 `database_conflicts.log`；调 AI 看 `ai.log`。

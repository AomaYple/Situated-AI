### 1.3 文件格式

#### 基本结构

```yaml
l_english:
 building_food_industry:0 "Food Industries"
 building_food_industry_lens_option:0 "Expand $building_food_industry$"
 building_textile_mill:0 "Textile Mills"
```
（逐字取自 `GAME\localization\english\buildings_l_english.yml:1-4`）

中文版同文件（`GAME\localization\simp_chinese\buildings_l_simp_chinese.yml:1-4`）：

```yaml
l_simp_chinese:
 building_food_industry: "食品厂"
 building_food_industry_lens_option: "扩建$building_food_industry$"
 building_textile_mill: "纺织厂"
 building_textile_mill_lens_option: "扩建$building_textile_mill$"
```

三个格式要点：

1. **首行必须是 `l_<语言代码>:`**（带结尾冒号），顶格无缩进。
2. **每个键行都以一个空格开头**（实测所有词条行缩进均为 1 个空格）。
3. **键与值之间是 `:数字` 或直接 `:`**，然后是空格，再是被双引号包裹的字符串。

#### `:数字` 版本号的真实分布（重要）

| 语言目录 | 带版本号的键 | 不带版本号的键 | 合计 |
|---|---|---|---|
| `english` | 43 921 | 49 218 | 93 139 |
| `simp_chinese` | **0** | 101 655 | 101 655 |
| `japanese` | 0 | 101 655 | 101 655 |
| `korean` | 0 | 101 655 | 101 655 |
| `french` | 0 | 115 666 | 115 666 |

全库带版本号的文件分布：`english` 43 921 条、`spanish` 2 308 条、`braz_por` 22 条、`modifiers` 22 条、`jomini` 88 条；`french` / `german` / `japanese` / `korean` / `polish` / `russian` / `simp_chinese` / `turkish` **均为 0 条**。

英文库中实际出现的版本号：`:0`（38 319）、`:1`（4 313）、`:2`（1 016）、`:3`（209）、`:4`（42）、`:5`（14）、`:6`（4）、`:7`（2）、`:9`（1）、`:10`（1）。

> **实用结论**：写 mod 时用 `key: "文本"` 或 `key:0 "文本"` 都能被游戏读取——**所有非英语语言（含简中）一律不带版本号**，中文 mod 直接照简中的写法即可。
> `:数字` 的确切语义（是否为翻译管线用的字符串版本号、是否影响覆盖优先级）**【未确认】**。

#### 值的书写限制

- 值**必须在一行内写完**；换行用字面转义 `\n`。
  实测：`GAME\localization\english\acceptance_statuses_l_english.yml:50`
  ```
   CULTURE_TT_ACCEPTANCE_MOD: "$ACCEPTANCE_OF_CULTURE_TERM$: [Culture.GetAcceptanceIn(GetPlayer)|=v]\n#indent_newline:3    [Culture.GetAcceptanceDescIn(GetPlayer)]#!"
  ```
- 值内可以出现成对的双引号（用两个连续 `""` 表示），实测事件文本大量如此：
  `GAME\localization\english\agitators_1_l_english.yml:203`
  ```
   revolution_pulse1_events.1.f: ""They came for us too quickly! We didn't have time to hide everything!"\n\n"Thanks to that, now we need time to hide #italic everyone #!!""
  ```
- YAML 块标量（`|` / `>`）**未在任何原版文件中出现**，是否受支持 **【未确认】**。

### 1.4 文件编码要求

**实测：原版所有本地化文件均为 UTF-8 with BOM（`EF BB BF`）。**

字节级证据（`System.IO.File.ReadAllBytes` 读取前 8 字节）：

| 文件 | 大小 | 前 8 字节（十六进制） |
|---|---|---|
| `GAME\localization\english\buildings_l_english.yml` | 13 957 | `EF BB BF 6C 5F 65 6E 67` |
| `GAME\localization\simp_chinese\buildings_l_simp_chinese.yml` | 13 090 | `EF BB BF 6C 5F 73 69 6D` |
| `GAME\localization\english\concepts_l_english.yml` | 407 796 | `EF BB BF 6C 5F 65 6E 67` |
| `GAME\localization\simp_chinese\concepts_l_simp_chinese.yml` | 373 728 | `EF BB BF 6C 5F 73 69 6D` |

解读：
- `EF BB BF` = UTF-8 BOM；
- 之后的 `6C 5F 65 6E 67` = ASCII `l_eng`（英文），`6C 5F 73 69 6D` = ASCII `l_sim`（简中）；
- 说明文件正文用 **UTF-8 无转义**保存（不是 UTF-16、不是 GBK）；
- 中文正文以 UTF-8 多字节存储，用 `-Encoding UTF8` 读取时中文与 `£`（U+00A3）均正常还原。

**所以：mod 的本地化文件必须保存为 "UTF-8 with BOM"。** 无 BOM 的 UTF-8 文件在社区实践中常导致首行 `l_simp_chinese:` 被误读为 `ï»¿l_simp_chinese:`，从而整个文件不加载——本仓库未在纯净环境复现该故障，机制解释 **【未确认】**，但"原版全部带 BOM"是实测事实，照抄原版最安全。

### 1.5 特殊标记与格式化语法

V3 的词条字符串里同时存在 **4 套行内语法**，全部必须**逐字保留**：

| 语法 | 作用 | 闭合方式 | 逐字实例（路径:行） |
|---|---|---|---|
| `$键名$` | 引用另一条本地化键 | `$` 成对 | `GAME\localization\english\buildings_l_english.yml:3` → `"Expand $building_food_industry$"` |
| `[数据函数\|格式]` | 运行时求值（databinding） | `]` | `GAME\localization\english\interfaces_l_english.yml:1017` → `"@money![Country.GetGDP\|Dv]"` |
| `@图标名!` | 插入 texticon 贴图 | `!` | `GAME\localization\english\achievements_l_english.yml:17` → `"@warning!#X Achievements unavailable#!"` |
| `#格式 ... #!` | 富文本格式 | `#!` | `GAME\localization\english\agitators_1_l_english.yml:15` → `"Finished the #BOLD Stamp Out Monarchism#! [concept_journal_entry]."` |

#### 1.5.1 `£icon` — **不存在的语法**

任务假设中提到 `£icon`。**实测：Victoria 3<!--claim:loc.modifiers_yml_lines--> 1.14.2 不使用该语法。**

- 对全库（`*.yml` / `*.txt` / `*.gui`）执行正则 `£[a-zA-Z_]` → **0 条匹配**。
- `£` 全库只作为英镑货币符号出现在 4 个英文文件里，且是普通文本：
  - `GAME\localization\english\achievements_l_english.yml:127` → `ACHIEVEMENT_DESC_billionare:0 "Have a national GDP of at least £1 billion"`
  - `GAME\localization\english\content_304_l_english.yml:519` → `alaska.4.tt1:1 "We will offer £3m over the course of 1 year."`
  - `GAME\localization\english\agitators_2_l_english.yml:384`、`GAME\localization\english\agitators_4_l_english.yml:1412`
- 图标语法请用 `@名字!`（见下）。

#### 1.5.2 `@icon!` 图标语法

定义位置（两个文件，共 **432<!--claim:loc.texticon_doc06--> 个 texticon**，`^texticon = \{` 实测计数）：

- `GAME\gui\texticons.gui` —— 310 个
- `GAME\gui\goods_texticons.gui` —— 122 个

定义结构（逐字取自 `GAME\gui\texticons.gui:305-312`）：

```
texticon = {
  icon = money
  iconsize = {
    offset = { 0 22 }
    texture = "gfx/interface/icons/topbar/income_power_icon.dds"
    fontsize = 95
  }
}
```

商品图标（`GAME\gui\goods_texticons.gui:1-8`）：

```
texticon = {
  icon = ammunition
  iconsize = {
    texture = "gfx/interface/icons/goods_icons/ammunition.dds"
    size = { 25 25 }
    offset = { 0 7 }
    fontsize = 18
  }
}
```

`iconsize` 块可用字段：`texture`、`size`、`offset`、`fontsize`。

**同一 `icon =` 名可重复定义多次**，用于适配不同字号——例如 `GAME\gui\texticons.gui` 中 `icon = battalions` / `icon = conscripts` / `icon = ships` 各出现 5 次。

### 1.6 中文汉化的具体做法

#### 步骤

1. **确定要覆盖哪些键。** 在 `GAME\localization\english\` 里找到对应文件（例如建筑名在 `buildings_l_english.yml`），记下键名。
2. **建立 mod 目录**（目录名任意，建议与英文同名便于比对）：
   ```
   <你的mod>\localization\simp_chinese\buildings_l_simp_chinese.yml
   ```
   或直接放在 `localization\` 下任意子目录（见 §1.2 的证据）。
3. **首行写 `l_simp_chinese:`**，顶格、无缩进、带结尾冒号。
4. **只写你要改的键**，每行 1 个前导空格 + `键: "译文"`。键名保持与英文原键**完全一致**（大小写敏感）。
5. **保存为 UTF-8 with BOM。** Notepad++：编码 → 转为 UTF-8-BOM；VS Code：右下角编码 → Save with Encoding → UTF-8 with BOM。
6. **进游戏前先删掉之前的本地化缓存**（原版会在用户目录生成缓存）——本仓库未实测缓存机制与路径规则 **【未确认】**。

#### 最小可用模板

```yaml
l_simp_chinese:
 building_food_industry: "食品厂"
 building_food_industry_lens_option: "扩建$building_food_industry$"
```

对应的英文原文（`GAME\localization\english\buildings_l_english.yml:2-3`）：

```yaml
 building_food_industry:0 "Food Industries"
 building_food_industry_lens_option:0 "Expand $building_food_industry$"
```

#### 中文汉化的 9 条注意事项

| # | 注意事项 | 依据 |
|---|---|---|
| 1 | **绝不能翻译 `$键名$` 内部的键名**。`$building_food_industry$` 只是个变量引用，译文里要原样保留，位置可以按中文语序移动。 | `simp_chinese\buildings_l_simp_chinese.yml:3` → `"扩建$building_food_industry$"`（变量被移到前面） |
| 2 | **`[...]` 内部的函数名和参数一律不翻译**，包括 `'单引号包裹的键名'`。`[SelectLocalization(GetPlayer.IsValid,'MANOR_INGAME_LINK','building_manor_house')]` 整段照抄。 | `english\concepts_l_english.yml:5` |
| 3 | **`@图标名!` 不翻译**，`!` 是闭合符，不能丢。 | `english\interfaces_l_english.yml:737` |
| 4 | **`#格式` 名不翻译，`#!` 闭合符必须配对**。`#bold 文本#!` 里只翻译"文本"。中文版大量使用 `#b ... #!`。 | 见 §1.5.3 实例表 |
| 5 | **`\n` 转义要保留**；中文一般不需要它在句尾出现两次（英文常用 `\n\n` 分段）。 | `english\acceptance_statuses_l_english.yml:50` |
| 6 | **`#indent_newline:N` 后面的空格数决定缩进宽度**。原版用 `#indent_newline:3    [xxx]#!`（冒号后是 3，然后跟 4 个实际空格）。 | `english\acceptance_statuses_l_english.yml:91` |
| 7 | **英文复数/单数分键在中文里通常合并**。例如 `MANDATE_CONCEPT` / `MANDATES_CONCEPT` 两个键，中文可都写成"授权"（`SelectLocalization` 依然需要两个键都存在，只是文本相同）。 | `english\alerts_l_english.yml:347` |
| 8 | **`£` 是普通文本，不是语法**。如果原文写 `£200 per man`，中文里直接写 `£200` 或改成"200 英镑"都行，不需要特殊处理。 | `english\agitators_2_l_english.yml:384` |
| 9 | **不要改 `:数字` 版本号去"抢优先级"**。简中库 0 个文件使用版本号，中文 mod 应保持无版本号写法。版本号语义 **【未确认】**。 | §1.3 统计表 |

#### 中文特有的排版建议（非强制，源自原版简中文件的实际写法）

- 键名 `lens_option` 类目在中文件里用"扩建/扩大"开头，把变量后置；
- 中文冒号用全角 `：`（`jomini\localization\modifiers\modifiers_l_simp_chinese.yml:2` → `MODIFIER_DESCRIPTION_ENTRY: "$HEADER$：$VALUE$"`，而英文/法文/德文版用半角 `:`）；
- 大量条目依赖 `@money!` 等图标承担单位，中文译文里通常**不重复写"元"**。

### 1.x 补充（实测自 23 个真实 mod）：两种文件级机制

本节由对全部 23 个已订阅 mod 的扫描补充，回答「mod 的本地化文件该怎么命名」。

#### A. 复用原版文件名 = 整文件替换

**【实测】** 原版 `localization\` 下共有 **1,855<!--claim:loc.yml_unique_names_doc06--> 个** `.yml` 文件（按文件名去重）。
mod 中**与原版同名**的文件共 **18 个** —— 例如 `2880069248`（牛奶汉化）提供了
`companies_l_simp_chinese.yml`、`decisions_l_simp_chinese.yml`、`country_flavor_text_l_simp_chinese.yml` 等。

> 说明本地化**同样支持文件名级整体替换**，与 `02-Mod结构与加载.md` §5.2 的机制一致。
> **但这不是必需做法** —— 因为按「键覆盖」即可生效（见 §1 主体），且**不冲突**。

#### B. `replace\` 子目录：社区约定（语义**未确认**）

**【实测】** **4 个 mod** 在本地化下使用了 `replace\` 子目录，但**层级不一致**：

| mod | 用法 |
|---|---|
| `2897378189` UH Research | `localization\<语言>\replace\<文件>.yml`（11 种语言各一个） |
| `3007678964` UH Warfare | `localization\<语言>\replace\<文件>.yml` |
| `2880069248` 牛奶汉化 | `localization\replace\<语言>\<mod名>\<文件>.yml`（层级与上者相反） |
| `3132637630` 牛奶汉化之超历史系列 | `localization\replace\<语言>\<mod名>\replace\<文件>.yml`（嵌套两层） |

关键证据：

1. **原版 `localization\` 下没有任何 `replace` 目录**（实测数量 = 0）
2. `replace\` 内的文件名都是 **mod 自有命名**（如 `Ultra_RE_inventions_l_english.yml`），
   **没有一个与原版文件同名** → 因此它**不是**「按文件名替换原版文件」
3. `replace\` 内文件的结构与普通本地化文件**完全相同**（同样以 `l_<语言>:` 开头）
4. `victoria3.exe`（92.6 MB）二进制中**含 `localization/replace` 与 `/replace/` 字符串**
   （反斜杠形式 `localization\replace` 未命中）

**结论（谨慎）**：`replace\` **大概率是引擎识别的机制**（二进制含该路径串），
但其**确切语义无法从现有证据确定** —— 既不能证实也不能证伪「其中的键会强制覆盖原版」，
因为按 §1 主体的结论，键覆盖本来就是默认行为。
**建议**：在自己的 mod 中**不要依赖 `replace\`**，直接用普通目录 + 键覆盖即可。

#### C. `languages.yml` —— 语言回退配置

**【实测】** 原版 `localization\languages.yml`（132 行）**不是**本地化文本，而是**语言选择器配置**。

结构：以每种界面语言为顶层键，其下列出**全部 11 种语言**，每种带一个 `0`/`1` 标记：

```yaml
l_english:
 l_english:1 "English"
 l_braz_por:1 "Português do Brasil"
 ...
 l_japanese:0 "日本語"
 l_simp_chinese:0 "中文"
 l_korean:0 "한국어"
```

| 观察 | 值 |
|---|---|
| 顶层语言块数 | **11**（与 `localization\` 下的 11 个语言目录一致） |
| 每个块内的语言条目数 | **11**（全排列） |
| 标记为 `1` 的语言 | 8 种（英/巴葡/法/德/波/俄/西） |
| 标记为 `0` 的语言 | **3 种：日语、简中、韩语** |

> **关于 `0`/`1` 的含义【未确认】**。从「西欧语言为 1、CJK 为 0」的分布推测，
> 可能与**字体加载**或**回退顺序**有关（CJK 字体体积大，可能默认不加载）。
> 但本文**不做断言**。
>
> **对中文 mod 的意义**：`3124519140` 等 mod 会**自带一份 `languages.yml`**。
> 若你要发布中文 mod 且遇到中文不显示的问题，这个文件是排查方向之一。

### 2.2 `.gui` 文件语法要点

`.gui` 使用 Clausewitz 的脚本语法（`键 = 值`、`块 = { }`），**不是** YAML/XML。

#### 顶层结构：三种写法

**（1）`types` 块 + `type` 声明**（定义可复用的"类型"，本质是继承基类并设置默认值）

```
types journal_entry_widget_types
{
	type je_widget_ruler_large_type = icon {
		parentanchor = center
		size = { 275 250 }
		...
	}
}
```
（逐字取自 `GAME\gui\journal_entry_widgets\custom_widgets.gui:4-28`）

简写形式（`GAME\gui\decisions_panel.gui:1-3`）：

```
types decisions_panel_types
{
	type decisions_panel = default_block_window {
```
——`default_block_window` 是 `GAME\gui\block_windows.gui` 中 `types windows` 里定义的类型。

另一种（`GAME\gui\map_interaction.gui:1-5`）：

```
types map_interactions
{
	type map_interaction_num_selections = textbox
	{
```

**实测 `types` 声明的两种花括号风格都存在**：`type X = base {`（与 base 同行）和 `type X = base` 换行后 `{`。

### 2.4 `scripted_widgets`

`GAME\gui\scripted_widgets\scripted_widgets.md`（8 行，全文逐字）：

```
Files here can contain pairs of file path and widget names to automatically create widgets on startup that are not formally referenced by the code.

- gui/test_custom_widget.gui = my_first_cool_test_widget
- gui/test_custom_widget.gui = my_second_cool_test_widget

Each entry will create one of that new widget, so making the same widget twice is supported though they will initially appear in the same location since the widget has the same ones scripted each time.

All files will be loaded so multipe mods can load their own widgets as long as they don't mess with each other's pathing which would be rude if they did.
```

要点：

- **格式**：`- <gui 文件路径> = <widget 名>`，每行一条，以 `- ` 开头；
- 路径是**相对内容根的 gui 路径**（示例 `gui/test_custom_widget.gui`，注意 `gui/` 前缀）；
- 条目会在启动时**自动实例化**该 widget，无需代码引用；
- 同名 widget 写两次是允许的（会创建两个，初始位置重叠）；
- **多 mod 各自的 `scripted_widgets` 文件都会被加载**——所以 mod 应使用**独立的文件名**，不要覆盖原版或他人的文件。

实测该目录下**只有 `scripted_widgets.md` 一个文件**，即原版自己没在 GUI 侧写任何 scripted widget 条目（仅提供说明）。

### 6.4 在 mod 中新增图标（完整流程）

以"新增一个 `@my_icon!` 图标"为例：

1. 把贴图放进 mod 的 `gfx/interface/icons/my_folder/my_icon.dds`。
2. 在 mod 的 `.gui` 文件中定义 texticon（**沿用原版文件布局，建议新建独立文件**）：

   ```
   texticon = {
     icon = my_icon
     iconsize = {
       texture = "gfx/interface/icons/my_folder/my_icon.dds"
       size = { 25 25 }
       offset = { 0 7 }
       fontsize = 18
     }
   }
   ```
   （结构逐字对齐 `gui\goods_texticons.gui:1-8`）
3. 在本地化里写 `@my_icon!`，例如：
   ```
   l_simp_chinese:
    my_tooltip: "@my_icon! 这是新图标 $VALUE|v$"
   ```

**注意**：`icon` 名是全局命名空间。**不要复用原版已有的名字**（如 `money`、`warning`），否则会与原版定义并存并可能冲突；如需改原版图标的外观，正确做法是覆盖原版同名 texticon（因为 `iconsize` 是重复块，重复定义时哪一个生效 **【未确认】**，实测原版自己对 `battalions` 等名字重复定义了 5 次并按字号区分——说明重复定义是**按 `fontsize` 匹配**的，不是简单覆盖）。

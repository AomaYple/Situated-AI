## 最关键的结论

### 1. 引擎内置「数据功能前缀」——可精确到单个键

六个关键字，**已确认存在于 `victoria3.exe` 二进制**（含内部枚举名）：

```pdx
INJECT:ban_slavery = { ... }             # 往原版条目注入字段
REPLACE:annex_country = { ... }          # 整体替换该条目
INJECT_OR_CREATE:building_food_industry = { ... }
REPLACE_OR_CREATE:state_trait_xxx = { ... }
TRY_INJECT:law_concordat = { ... }       # 目标不存在时不报错
TRY_REPLACE:company_xxx = { ... }
```

| 事实 | 数据 |
|---|---|
| 23 个 mod 使用总次数 | **2,737** |
| **原版本体使用次数** | **0** |
| 支持的 `common\` 子目录 | **42 个** |
| 官方 92 篇 `.md` 是否记载 | **完全没有** |

**这是 23 个 mod 能零冲突共存的关键机制** —— 大多数 mod 根本不替换原版文件。

### 2. 联机校验和只覆盖 5 个目录

`game\checksum_manifest.txt`（仅 22 行）明确：只有 `common/`、`events/`、`map_data/`、`gui/`、`localization/` 参与校验。
**改 `gfx/`、`sound/`、`music/`、`fonts/` 不影响校验和** → 纯视觉/音频 mod 天然联机友好。

### 3. 新增文件 ≫ 覆盖原版

对 23 个 mod 共 4,750 个相对路径（4,777 个内容文件）交叉比对：**被 2 个及以上 mod 共同覆盖的路径数 = 0**；**13/23 的 mod 完全不覆盖任何原版文件**。

### 4. 不需要 `descriptor.mod`

`victoria3.exe` 内不含该字符串；23 个 mod 也全无 `.mod` 文件。现代格式是 `.metadata\metadata.json`（7 个必需字段 + 3 个可选字段）。

### 5. 调试模式是必需的

启动参数加 `-debug_mode`：

| 日志 | 用途 |
|---|---|
| `error.log` | 语法错误 |
| **`database_conflicts.log`** | **覆盖冲突检测** |
| `ai.log` | AI 行为 |
| `gui.log` | 界面 |

另有 **`game\tools\scripted_tests\`** 官方自动化测试框架，可跑长期模拟验证 mod 效果。

### 6. 官方文档有坑，必须交叉验证

92 篇 `.md` 中已知问题包括：字段名拼错（如 `ai_privatization_deisre` → 实际为 `ai_nationalization_desire`）、
文档声明但原版零使用的字段、`pop_types.md` 漏写 9 个实际字段、`input_profile.md` 混入了其他文件内容。
**每个系统篇文档都做了「官方声明 vs 机械实测」的逐字段对照。**

### 7. 解析 PDX 文件的两个陷阱

| 陷阱 | 后果 |
|---|---|
| **键名含连字符** | 全库有 32 个（`character_templates` 占 27 个）。用枚举字符类正则会**静默漏计** |
| **缩进混用 tab 与 4 空格** | 官方文件自身就混用。按 tab 提取会漏项，应按**花括号深度**计数 |

# 快捷键速度自动化实机（2026-10-05）

本次实机只验证自动化输入路径，不验证任何 Mod 行为因果。目标是确认默认流程能用游戏原版 `speed_5` 快捷键代替鼠标表盘点击，并在失败时保留受控鼠标回退。

## 输入依据

Victoria 3 1.14.5 的原版文件 `game/input_profile/default.profile` 定义：

```text
input_action = {
    name = "speed_5"
    scancode = 34  # 5
    scancode = 93  # Keypad 5
}
```

实现现在默认按扫描码键 `5`。按键前检查游戏是当前前台窗口，按键后不直接相信输入调用返回值，而是解除暂停后用 `dedicated_server.log` 的逐 tick 记录计算实际天/秒。只有速率低于阈值时，才最多重按一次，然后进入旧的鼠标表盘候选序列。

## 实机命令

使用仓库的可回滚包装器：

```text
.venv\Scripts\python.exe -X utf8 tools\probe\flow_with_cleanup.py --lobby-timeout 300
```

该包装器在 `finally` 中终止本次启动的 Victoria 3、恢复启动前的前台窗口，并进行桌面采样。

收尾结果：本次启动的 Victoria 3 PID 已终止，启动前窗口句柄恢复；9 个桌面采样点中 8 个回到 `Progman`，1 个为 Codex 窗口。没有留下游戏进程。

## 结论边界

- 键盘 5 速路径已经完成 Windows 实机验证，默认流程不再首先依赖速度表盘像素坐标。
- 速率真值仍是必要判据；“发送了 5”本身不能证明游戏切换成功。
- `--speed-mouse` 和显式 `--speed-xy` 仍保留，用于旧环境、诊断和回退。
- 这次只证明 Windows 的真实 GUI 键盘路径。macOS/Linux 的 Victoria 3 GUI 输入后端仍未实机验证；游戏自动化模块当前也仍将窗口级 GUI 能力标为 Windows-only。
- 其它快捷键已从 `default.profile` 盘点出来，但必须逐项建立前台检查和状态/日志判据后才能接入自动化，不能仅凭键位表宣布可靠。

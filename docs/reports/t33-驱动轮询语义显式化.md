## §2 逐处改动（acceptance ①，行号按收尾后的 2070 行文件）

### ① `wait_for_screen`：正向判据轮询（`:1530-1538`）

原先靠 `find_in_roi` 默认值 ⇒ `t19` 之后**抓图失败会抛**（并中止整局）。改动：

- docstring 第 ① 条改准（`:1516`）：抓图失败与「确实没有」必须分得开（P13），本处**显式**选轮询语义；并写明「若判据写成『上一屏的特征消失』，同一个瞬时失败就会被读成『已消失』」；
- 调用点加显式实参：

```python
                    # 🔧 t33：这里**要**轮询语义（「还没画出来」≠「这一屏没有」），所以显式声明。
                    hit = ga.find_in_roi(
                        hwnd,
                        template,
                        roi=ROIS[roi_name],
                        directory=template_dir,
                        on_capture_failure="miss",
                    )
```

**理由**：转场期间窗口正在重绘，一次瞬时抓不到图只应被读成「这一轮不算命中」，下一轮 0.8 s 后再试；中止整局会把「还没画出来」误报成「这一击没生效」。

### ② 侦察分支 `locate_our_row`：拖滚动条（`:1593-1601`）

```python
                    # 🔧 t33：拖滚动条期间窗口会瞬时抓不到图（拖拽中 / 重绘中），这**必须**继续拖，
                    #    不能中止整局 ⇒ 显式选轮询语义。
```

**理由**：同一循环里 `ga.wait_stable(..., timeout=20.0)` 之后本来就可能赶上重绘；拖动本身是「盲拖 + 事后核」的搜索，没有第二条判据可依赖。

### ③ L4 启动等待：改用驱动自带三态（`:1617-1649`）

手里**没有帧**（窗口还在画 / 被遮挡 / 近乎纯色），所以要的是三态而不是两态：

```python
                state, match, why = locate_state(
                    hwnd, "btn_new_game", roi=ROIS["main_menu"], directory=template_dir
                )
                if state == LOOKUP_HIT:
                    hit = match
                    break
                if state == LOOKUP_UNSEEN:
                    unseen += 1

```

超时文本在原有判词后追加：

```
（其中 {unseen} 次是**抓不到图**：看不到 ≠ 没有；最后一条原因：{unseen_why}）
```

**理由**：`locate_state` 是驱动里**早就存在**的三态工具（`:1845` 的侦察延伸步一直在用：模板 ⇒ `命中/确实没有/抓不到图`，非命中就 `report.note(...)` 停手）；本卡只是把 L4 也纳进同一口径 —— 「看不到」继续等并记账，「确实没有」才让判据为假。`hwnd` 失效（`pywintypes.error`）仍按 `locate_state` 的既有约定直接外抛。

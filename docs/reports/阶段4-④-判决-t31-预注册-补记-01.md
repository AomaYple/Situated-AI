## 1. 发现（两件，都是现读代码 + 现读文件清单）

### 1.1 预注册 §8 写的隔离目录路径不是 runner 用的那一个

预注册 §8 写 `%TEMP%\v3_quarantine_logs`。那不是 `tools/probe/perf_compare.py` 的目标：`perf_compare` 用的是**它自己的** `_quarantine_logs()`（`tools/probe/perf_compare.py:163-183`），

* 目标目录 = `Path(tempfile.gettempdir()) / "v3_quarantine_perflogs"`（`:174`）——**带 `perf` 的那个**；
* `%TEMP%\v3_quarantine_logs` 是 `game_auto.quarantine_logs()` 的默认目录（`src/pdx/game_auto.py:1720`，stage3 / stage6 rerun 在用）。

⇒ 本卡看的应是 `%TEMP%\v3_quarantine_perflogs`。**机制本身见下条，比路径更要紧。**

### 1.2 这条机制**同名不换名、且静默吞异常** ⇒ 大多数局的日志根本没被挪走

`:179` 是 `shutil.move(str(path), str(target / path.name))` —— **同名**挪进共享目录；`:180-181` 是 `except (PermissionError, OSError): continue`。当目标目录里**已有同名文件**时，`shutil.move` 抛 `shutil.Error`（`OSError` 的子类）⇒ 被**静默吞掉**：文件没挪走、也不报错，控制台只说「已挪走 N 个旧日志」（`:424`）。

**实测证据（现读，2026-09-29 02:14 前后）**：

* `%TEMP%\v3_quarantine_perflogs` 共 **60 文件 / 4,929,774 B**；其中 **09-29 的只有 20 个**，且**全部属同一局**：12 个 mtime `01:27:30` 的启动件（`ai.log` / `checksum.log` / `code_revisions.log` / `database_conflicts.log` / `ecs.log` / `graphics.log` / `memory.log` / `message.log` / `multiplayer.log` / `pdxsdk.log` / `setup.log` / `ui_animation_stats.log`）+ 8 个活动件（`01:27:45`–`01:38:17`：`debug.log` 324,090 B、`dedicated_server.log`、`error.log`、`game.log`、`gui.log`、`system.log`、`warning.log`、`custom_automated_stats.log`）——即 **01:38:16 那一次成功的挪动**（run B 第 1 局的那一套）。
* pilot 一共 **8 局**（run A 6 局 00:17–01:22 + run B 2 局 01:27–01:48）⇒ **7 局没有进这个目录**；最后一局（CSV 落于 01:48:42）的日志**仍留在** `<用户目录>\logs\`（`debug.log` 298,056 B @01:48:04）。
* 结论：**runner 侧这条不是「按臂归档」的可靠载体** —— 它恰恰就是 B114（t9 暴露：pilot 8 臂只剩最后一遍）要防的那种蒸发。

## 0. 一句话结论

1. **「换 AI 侧量」能把最小 n 从 68 对压到 11 对（≈4.0 h）** —— 这是**换量**（换被测量的对象），不是换阈值、不是换统计量；判据/公式/阈值全部不动。
2. 11 对**比队长给的「≤10 对」多一对**（多 22 分钟）：`U(11)=0.4834 ≤ 0.5` ✓ / `U(10)=0.5148 > 0.5` ✗（逐条边界证据见 §1）。
3. **整帧那条路便宜不下来**：同世界配对下限 ≈1.78–1.89 ms ⇒ 即使受控剧本 + 固定存档把世界分叉全部消掉，整帧线仍要 **≈53 对 ≈19 h**（见 §4 的帧级分解）。今天的整帧线（`U(3)=5.09`）**未判决**的结论不变。
4. 选这个量**用到了同一批 3 对数据**（事后选量）⇒ 若走 AI 侧线，必须**在跑之前预注册量**，且 n 对那批的 `Δ̂`/区间**不得**与 pilot 的 3 对混算（混算就变成「用选量的数据当证据」）。这一点是本卡最硬的使用边界。

## 2. 换量还是换口径：要改哪些字、对历史读数什么影响

**定性：换量。** 判据仍是「配对 + 有界窗口均值 + `U(n) ≤ 0.5 ms`」，`t` 分布、阈值、作废规则一律不动；变的只是**被测量的对象**：整帧合计 `M(W)` → AI 侧合计 `M_AI(W) = Σ_{t∈14 任务} M_t(W)`。

**为什么这个量更贴 F9 的题**：F9 的红线问的是**引擎自身 AI 开销**，整帧里混着水利、建筑、迁移、内战等与我们 mod 无关的尖峰（见 §4）。但**必须写清**：这个量是**看着同一批 3 对数据挑出来的** ⇒ 后续 n 对是它第一次**受检**，不是它的复现。

**若队长拍板走这条路，落字建议（本卡不改）**：

| 落点 | 改成什么 | 依据 |
|---|---|---|
| 口径页 §3.3 名单 | AI 侧从单任务 `UpdateAI` 扩为「**实测 CSV 里名字含大写 `AI` 的任务集合**」+ 保留扩展规则（只有实测出现过的名字才进） | 本卡 §1 的 14 任务集合 |
| 口径页 §5 P3 判决量 | 判决量写成「可由 `M(W)` 指定为 `M_AI(W)`」；阈值 `0.5 ms/帧`、`U(n)` 判据、最坏帧只作异常检测**都不动** | 本卡 §1、§3 |
| F9 的「单帧」读法 | 维持 §5 P3 已写死的边界（读作**窗口均值**、不读瞬时）；只把**量**写明 | 口径页 §5 P3 |
| 两条线并存 | 整帧线继续按旧口径报（今天 = 未判决）；AI 侧线另立一行，两条**不混算** | 本卡 §0.4 |

**对历史读数的影响**：

- `阶段4-结果.md` §六·补（09-23）的 `−0.51 ms`（整帧，非受控）与 `RecalculateModifierNodes −0.030 ms` 都是**整帧/单任务**口径；AI 侧量在那批数据里**没有**对应读数 ⇒ **两条线不可互比**，引用时必须带口径标注。
- 09-23 那句「敏感观测点更敏感（关键任务抖动 0.43 ms、比整帧小一个量级）」在**新量**上仍然成立，但**不可直接外推**：AI 侧合计本身只有 ≈6.0–7.0 ms/帧（整帧 ≈23.8–27.6 ms/帧），R 单任务 ≈4.3–6.1 ms/帧 ⇒ 三者是不同的分母，比值不能互套。

## 3. 两条路的成本与可判性

| | 路 A：整帧线（判据不动） | 路 B：AI 侧线（须预注册） |
|---|---|---|
| 现测 `s_d` | 2.0500 ms | 0.7196 ms |
| 最小 n | **68 对** | **11 对** |
| 机器时间（22 min/对） | **24.9 h 独占** | **4.0 h** |
| 受控剧本/固定存档能帮多少 | **有限**：同世界下限 ≈1.78–1.89 ms ⇒ 最好情况仍要 **≈53 对 ≈19 h**（§4） | **明显**：同世界下限 ≈0.226–0.242 ms ⇒ 若真压到该水平，n 可降到 **4 对 ≈1.5 h**；落到 `UpdateAI` 的 0.35 水平则 n=5（1.8 h） |
| 何时仍「不可判」 | 只要不跑到 68 对（或受控后 ≈53 对）就**永远**是未判决 | 若真 `s_d` 明显大于 0.72（例如 ≥0.90），n 涨到 ≈17 对（≈6.2 h）仍可能够；若 `s_d` 落在 1.0 以上，n ⇒ ≈21 对（≈7.7 h），收益开始消失 |
| 收口登记写法 | 「未判决（P3，整帧线）：`Δ̂ = −1.65 ms/帧`，`U(3)=5.09`，`s_d=2.05`，达 0.5 ms 判决还需 ≈65 对 ≈23.8 h」 | 「未判决（P3，AI 侧线）：`Δ̂ = X ± Y ms/帧`，n=…，`s_d=…`；若 `U(n) ≤ 0.5` ⇒ 达标/超预算，否则写「还差 U−0.5 = Z ms ⇒ 还需 ≈K 对 ≈H 小时」」 |

**「不可判」的两种合法形态**（本卡与 `t22` 报告同型，不许美化成「达标」）：
1. `U(n) > 0.5` ⇒ 只报 `Δ̂ ± U(n)`，写清还差多少、要多少机器时间；
2. `U(n) ≤ 0.5` 但 `|Δ̂| + U(n) > 0.5` ⇒ **超预算**；`|Δ̂| + U(n) ≤ 0.5` ⇒ **达标**。三者互斥，必须给其中一个。

**给队长的建议（决定权在队长）**：走**路 B + 预注册**。理由不是「AI 侧好看」，而是：① 它更贴 F9 的题（引擎 AI 开销）；② 整帧线的噪声下限是**结构性**的（§4：尖峰帧支配），加钱买不到；③ 4.0 h 的独占窗口在本轮排期里可承受，24.9 h 会压住阶段 6 实机链。

## 8. 使用边界（不许越的四条）

1. **不许**把 `Δ̂` 为负读成「我们的 mod 让游戏变快」；三种判决（达标 / 超预算 / 未判决）互斥，必须给一个。
2. **「未判决」≠ 达标 ≠ 超预算**；报数时永远带 `Δ̂ ± U(n)`、`n`、`s_d` 三件套。
3. **AI 侧量是换量**，且是**用同一批 3 对数据选出来的** ⇒ 走这条路必须在跑之前**预注册量**，n 对那批**不得**与 pilot 混算；整帧线继续按旧口径单独报。
4. 本卡**未占机器窗口、未起实机、未改代码/判据/预注册**；两条边界的正文改动留给有改动权的卡（本卡只做补记）。

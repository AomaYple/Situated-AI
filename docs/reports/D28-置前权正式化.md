## 1. 置前权取得（`recover_foreground`）

### 1.1 出处：第一次撞上长什么样（t4 §二，2026-09-30）

`docs/reports/A6-一次常规开局实证.md`（23,013 B）记下了那次实机：起局后**前台是「无应用」的
壳**（shell 岛，`XamlExplorerHostIslandWindow_WASDK`，标题读出来是 `''`），游戏窗口活着但不在
前台，于是仓库既有的路由当场抛出：

```
ForegroundLostError: 抢不到前台（游戏 hwnd=3145886，当前前台=5768114，标题=''）
```

t4 当时是**人手**绕过去的（跑手里的临时代码）：`pydirectinput.keyDown/keyUp('alt')` 轻敲一下
→ **仓库原样**的 `ga.ensure_foreground(hwnd, force=True)` → `ga.start_session(...)`。那两轮读数：
`attempts=1`、`look_ok=True`、look 分数 0.9999998 / 0.9999992、前台 `5768114 → 5113364`、
`window_before={hwnd:5113364, rect:[0,0,1920,1080], is_iconic:false, title:'Victoria 3', class:'SDL_app'}`、
`titlebar_band_px=0`（无边框 ⇒ 只能 Alt 轻敲，**整轮没有向任何坐标注入过点击**）。

本卡就是把这段人手动作做成正式件：**一次**合成输入 → 照原样再走既有路由 → 判据/异常类型一字不改。

### 1.4 为什么 `attempts=1` 这一次没能取到（如实记）

三次把「让前台给壳」做在**不同时刻**，读数都指向同一个事实：

1. **起局前让给壳是成功的**（`_set_foreground(5768114)` → `rc=true`、`_foreground_window()==5768114`）；
2. 但**游戏窗口一出现（2.1 s 内）就自己把前台抢回去了**：`launch_to_window_s=2.1` 时
   `foreground_after_launch == hwnd`（live-02 = early 模式的原始读数）；
3. 一旦游戏持着前台，**我们这条链就再也没有置前权**：`live-03` 的 chase 读数
   `set_island_rc=false`（settle 前 10 次采样 + settle 后 10 次采样全 False，前台恒为 `hwnd`）。

⇒ `ForegroundLostError` 要的条件是「**前台不是游戏**、且我们也没有置前权」；而本机现在只要游戏
活着就自己占着前台（`_route_to_foreground` 的判据 `_foreground_window()==hwnd` 直接成立 ⇒ 不抛）。
第 3 条读数还说明：我们**摆不出**这个条件 —— 任何一次成功的「让前台」动作都发生在我们**有**置前权
的时候（那时路由必然成功），而一旦没有置前权，就连「让给壳」这一下都会被静默拒绝。

它上一次自然出现是 t4 那一轮的开机态（§1.1 的原话就是当时的前台读数是 `5768114`、标题 `''`）。
本卡把**环境**摆成了同一个形状（`5768114` 在前、游戏窗口活着），但游戏这次自己抢到了前台，
所以路由没有失败 —— 这不改变恢复路径的正确性，但**确实没有拿到「实机 `attempts=1`」这一条读数**。

### 1.5 顺带发现的两条既有行为（队长裁决：**本卡就地修掉**）

两条都属于我们整晚在消灭的「静默失败」那一族。**改的是判据的完整性，不是判据的强弱**：
模板 / 阈值 / ROI / 超时 / 点击语义一律没动。

#### 1.5.1 最小化窗口上的「假成功」 ⇒ 现在抛既有异常

* **改前长什么样**（`warmup-01`，03:56–04:01）：先把游戏窗口缩下去再进主干 ——
  `SetForegroundWindow` 对最小化窗口会"成功"，`GetForegroundWindow()` 真的返回它，
  但 `IsIconic` 仍是 `True`、客户区是 0x0。于是 `ensure_foreground` **不抛** ⇒
  置前权恢复不会被调用 ⇒ 实机链继续往下走，最后死在
  `TemplateNotFoundError: 180 秒内没在底部找到「观察」按钮（最后抓图错误：客户区尺寸非法: 0x0（窗口最小化了？））`
  —— 真因被一句"抓图尺寸非法"糊掉了。
* **改法**（`src/pdx/game_auto.py`）：新增 `_require_foreground_usable(hwnd)`（`:1045`）——
  「前台名义上是它」**且**「它不是最小化的」两个都成立才算拿到能用的前台；否则抛既有
  `ForegroundLostError`，消息带 `hwnd` / `IsIconic` / 当前前台 / 前台标题。三个"拿到前台"的
  出口全部接上：`ensure_foreground` 的早退（`_foreground_window() == hwnd`）、它的置前循环成功
  出口、以及 `_ensure_live_foreground`（`:2915`）。
* **用例**（`tests/test_game_auto.py`，桩，不真起游戏）：`test_已经是前台但窗口最小化也必须报错`、
  `test_循环里拿到前台但窗口还最小化也要报错`、`test_等到前台的循环也不收最小化窗口`。

#### 1.5.2 「这一下点空了」不是静默路径，但真因说不清 ⇒ 补焦点读数

* **现读出处**：不是「打了日志继续跑」—— `_step_observe` **抛**
  `TemplateNotFoundError`（改前在 `src/pdx/game_auto.py:3268-3273`，判据是"底部按钮没了"或
  "时间开始走了"任一成立，`settle_timeout` 到期即抛）。也就是说：**调用方本来就能判断失败**。
* **问题**：文案把真因说成了坐标（`这一下点空了`），而 `warmup-02` 的实测是
  「位置对、事件送给别的窗口」—— 前台不在游戏身上时点击不会被接收。
* **改法**：异常里补一条焦点读数
  `点完的焦点读数：前台=<hwnd>，游戏 hwnd=<hwnd>、IsIconic=<bool>`（并注明"前台不是游戏时，
  点击位置对也没用"）。用例：`test_点空了的异常要带焦点读数`。
* **第一次撞上长什么样**（`warmup-02`，04:02–04:06）：look 命中
  `btn_observe @ (864,1055) score=0.860`、点击也发出去了，但 120 秒后界面没切走 ——
  证据帧 `tools/out/auto/11-after-observe.png`（04:06:39；⚠️ 该路径随后被 `live-03` 那批**覆盖**了，
  现盘上是 04:25:02 的成功帧 ⇒ 这段以当时的读数文字为准）：光标正停在「观察」上、
  tooltip「作为观察者开始游戏」都在，界面没动。同一台机器、同一个窗口，**游戏连续保持前台**时
  `click_client(h, 864, 1055, force=True, settle=2.0)` 一次就进了观察
  （帧 `tools/out/auto/t29-manual-after-observe.png`，2,526,394 B / 04:07:35）⇒ 点击通路本身是好的，
  差别在「真焦点」—— 这正是 §1 恢复路径要解的那件事。
* **对 L8–L16 的影响**（t8 的点击链依赖它）：失败语义**没变**（照样抛、照样不静默），
  变的是**可分辨性** —— 之前撞上这条只能看到"点空了"，得再跑一轮才知道是坐标问题还是焦点问题；
  现在一条异常就能分流。t8 那条链如果在 1.14.5 上再撞，报告里可以直接引用这句读数。

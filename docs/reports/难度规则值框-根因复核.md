## §2 真根因（三条证据）

**引擎规则**（`game/common/game_rules/game_rules.md:10-12`，逐字）：

```
rule_<key> will be used as the key for game rule names
setting_<key> will be used as the key for game rule setting names
setting_<key>_desc will be used as the key for game rule setting descs
```

而同一页 `:1-7` 的语法块是 `game_rule = { default = setting_name  setting_name = { apply_modifier / flag } }`
⇒ 这里的 `<key>` 就是**块名**（规则块名 / 设置块名），`flag` 在 `:6` 的注释里是「Has some specific effect. See "flags" section」
—— 它是**引擎行为标签**（`:14-26` 那张表：`blocks_achievements` / `lenient_ai` / `disable_<pm>` …），**不是文案键**。

**证据①（文档）**：上引三行。

**证据②（数据）**：`game/localization/english/game_rules_l_english.yml` 全表（119 行，我逐行读过）—— 键跟**块名**不跟 `flag`：

| 设置块 | 块内 `flag` | 实际存在的链 |
|---|---|---|
| `lenient_ai_behavior`（:15） | `lenient_ai`（:16） | `setting_lenient_ai_behavior`（:4）—— `setting_lenient_ai` **不存在** |
| `achievements_blocked`（:7） | `blocks_achievements`（:8） | `setting_achievements_blocked`（:30）—— `setting_blocks_achievements` **不存在** |
| `no_consolidation`（:100） | `no_pop_consolidation`（:101） | `setting_no_consolidation`（:80） |
| `allow_fantastical_content`（:206） | `give_fantastical_content`（:207） | `setting_allow_fantastical_content`（:96） |
| `all_formable_nations`（:60） | **无 flag** | `setting_all_formable_nations`（:33） |
| `allow_dynamic_naming`（:229） | **无 flag** | `setting_allow_dynamic_naming`（:110） |
| `no_custom_rng_seed`（:218） | **无 flag** | `setting_no_custom_rng_seed`（:102） |

⇒ **有设置根本没有 `flag` 也照样有文案键** ⇒「按 flag 查」**结构上不可能成立**（那些设置会在界面上无键可查）。

**证据③（画面）**：§1 那三条无 flag 的原版行显示正常文案（同一张帧）。

**⇒ 真根因**：我们把**设置块名**写成了 `setting_sitai_difficulty_uniform`（`modgen.py:396` 的 `tier.setting` 既当本地化键又当块名）
⇒ 引擎查 `setting_` + 块名 = **`setting_setting_sitai_difficulty_uniform`** ⇒ 落空 ⇒ 显示原始键。
**不对称正好对上**：规则块名是 `sitai_difficulty`（**没带**前缀）⇒ `rule_sitai_difficulty` 命中 ⇒ 标题正常。
而 `mod/localization/**` 里现成的键（`setting_sitai_difficulty_uniform` / `…_desc`）本来就是**对的** —— 错的只有块名。

## §3 卡文原判断错在哪（可复核的反驳）

原判断：「`flag` 与设置名同串 ⇒ 引擎按 `setting_<flag>` 查 ⇒ 落空」。
它的**推理链中段就断了**：把 `flag` 当文案键。三条反驳见 §2；其中证据②③是**结构性与画面级**的，与「flag 恰好同串」无关
—— 原判断只在这一个巧合上"看起来能解释现象"，而一旦按它改（只动 `flag` 取值、块名不动），引擎查的键**一个字符都不变**（仍是 `setting_` + `setting_sitai_difficulty_uniform`），**缺陷原样存在**。

## §4 修法（最小面 + 抗假设）

1. 三档**设置块名**去 `setting_` 前缀：`sitai_difficulty_history_friendly` / `sitai_difficulty_uniform` / `sitai_difficulty_harsh`；
2. 块内 `flag` 与块名**同串**（`flag = sitai_difficulty_uniform` 之类）；
3. `default` 与**新块名**同串（`default = sitai_difficulty_uniform`）—— 原版 `00_game_rules.txt:2` 的 `default = achievements_allowed` 就是块名；
4. 脚本侧 `has_game_rule = <同一个串>`（原版读点见 §0）；
5. **本地化键与 `mod/localization/**` 一个字不改** —— `setting_` + 新块名 = 现成的 `setting_sitai_difficulty_uniform` ⇒ 正好命中。

**为什么 flag 必须与块名同串（抗假设）**：原版**凡被 `has_game_rule` 读**的设置，`flag` 都与块名同串
（`00_game_rules.txt:27-40` 的 `high_ai_aggression = { flag = high_ai_aggression }`、`:42-55` 的 `free_construction_unscaled`；
读点 `common/ai_strategies/00_default_strategy.txt:4612/:7194`）⇒ 同串之后，「引擎按块名解析还是按 flag 解析」**都不影响结论**
（两种读法取到同一个串）。这条刻意保留，不为了"少写一行"去赌引擎语义。

**没有采用**的两种写法：① 只改 `flag`（§3：对画面零效果）；② 给本地化加 `setting_setting_*` 双前缀键（键名脱离引擎文档的命名法，
且要动 outOfScope 的 `mod/localization/**` 与数据源链路）。

## 3. 为什么「15 对可比」仍成立（不是"算了"，是论证）

1. **被测量不在改动面上**：判决量 `M_AI(W)` 来自**游戏自己**落的 ticktask CSV（`clear_ticktask_timings` → 36 个月 → `dump_ticktask_timings`，见 `tools/out/mem/t9-runE.log` 逐臂顺序）。改动的 `_quarantine_logs()` 在**每臂开头**被调用（同一份 runner 日志 L5/L6、L24/L25… 逐臂一条「已挪走 20 个旧日志」），即两局之间的**边界**，不在测量窗内；`_announce()` 只写 stderr，不写任何被聚合的文件。
2. **被聚合也不在改动面上**：11 对与 4 对由**同一份**分析器、同一套公式聚合 —— `tools/out/mem/t31-analyze.py` = **13,606 B / LF=285 / CR=0 / 无 BOM / mtime 2026-09-29T02:11:57.250 / sha256 `ab3e5d14eafa5f85d89bdb0f85af2d7708c227386a3069c0fda63e8c35f7cd8c`**（本补记落盘前现读）。这是我这一批的**唯一**聚合器（复算链 ②），inv3 的 4 对跑完后仍用它、用同一 `U(n)` 公式聚合。
3. **CLI 未变**：位置参数 `months` + `--repeat` / `--stress` / `--tempo-arm` 语义不变（现读 @L710–L724 区段）⇒ 冻结命令 `.venv\Scripts\python.exe -X utf8 tools\probe\perf_compare.py 36 --stress --repeat N` 逐字可用。
4. **盘上没有冻结版本的副本**：队长现读 `tools/` 全树后确认（`tools\out\backup\20260929-025843-t44-perf_compare.py` = 41,720 B / 02:17:28、`t36-…` = 39,214 B / 02:06:04，**都早于钉死那次**）⇒「临时还原仪器再跑」这条路不存在；要么放行，要么把 15 对全部重跑（≈5 h）。
5. **判据、阈值、观测点、作废规则一字未改**：预注册 §2（L29「## 2. 判据与判决（冻结，跑完照此落结论）」）、§3（L44「## 3. 观测点集合（冻结，逐条点名）」）、§5（L75「## 5. 作废规则（冻结，一字不改；逐对记账）」）与 n 的边界证据（L36）**本补记不动一个字**；**n 从 11 提到 15 是队长对本批的授权（上限也是 15）**，不是对判据的改写：`U(n) ≤ 0.5` 这条阈值、`Δ_i` 定义、14 条观测点、五条作废规则都原样。
6. **风险面（如实写）**：新加的 `_as_str_list` / `_report_scan` / `stress_control_verdict` 改的是**压力自报闸的解析**，若新解析比旧实现更严，可能在**控制闸**上改变「本臂是否受控」的判定 —— 它改不了被测数值，但可能让某一臂在闸上失败。故：inv3 逐臂的 control 读数（压力自报是否逐行相等 / verdict）必须在报告里逐臂给出。

## §2 ② 测试文件数：**三个口径**（差集逐个点名）

| 口径 | 数 | 定义（可复算） |
|---|---|---|
| 盘上 `*.py`（`rglob`） | **86** | `(REPO/'tools'/'tests').rglob('*.py')` |
| **盘上 `test_*.py`（= 守卫口径）** | **81** | `(REPO/'tools'/'tests').glob('test_*.py')`（`test_repo_numbers.py:39`，口径见 `:21-22`「不含 `conftest.py` / `_table_guards.py` 这些支撑文件」） |
| `git ls-files` 入库的 `*.py` | **82** | `git ls-files tests/*.py` |

**算术自洽（逐项验过）**：

```
盘上 *.py          = 86 = 81 (test_*.py) + 5 (支撑件)
盘上 test_*.py     = 81                      ← 守卫口径
盘上支撑件（非 test）= 5 → _helpers.py / _oracle_lexer.py / _table_guards.py / conftest.py / gametimer_fixtures.py
git 入库 *.py      = 82 = 77 (test_*.py) + 5 (支撑件)
git 入库 test_*.py = 77                      ← README 现在写的那个 77
未入库的 test_*.py = 4 → test_mem_baseline.py / test_objectives.py / test_portability.py / test_ui_templates.py
⇒ 81 = 77 + 4 ✓   86 = 81 + 5 ✓
```

⇒ **README 的 `77` 不是抄错**：它是**入库的** `test_*.py` 数（上个提交点上是对的）；盘上多出的 **4 个未入库新用例**把它顶到 **81**。

⚠️ **给 t38 的一条要紧提醒**：守卫用的是**盘上 glob**（与提交与否无关）⇒ 它今天期待 **81**；但如果那 4 个文件长期不入库，**干净克隆**上的守卫会算出 77 并与 README 打架 ⇒ 最稳的落地是**把这 4 个文件一并入库**（或等它们入库后再写数）。

## §3 漏掉的八种（每种给最小复现片段）

### F1（未写明）f-string 拼出来的路径

```python
from pdx import config

def test_b():
    name = "x.json"
    target = f"{config.REPO}/tools/out/auto/{name}"   # ← 扫查看不见
    target.write_text("x", encoding="utf-8")
```

亦可：`(f"tools/out/mem/{name}").write_text("x")`。**原因**：`_是共享路径` 没有 `ast.JoinedStr` 分支（字面量常量分支只认**纯** `ast.Constant`，`_字面量尾巴` 只认 `ast.Div` 链）。**建议**：把 JoinedStr 里各 `Constant` 片段拼起来喂给同一个"是否含 `tools/out`"判断（约 3 行）。

### F2（未写明）`os.path.join` + 内建 `open(path, "w")`

```python
import os
from pdx import config

def test_c():
    path = os.path.join(config.REPO, "tools", "out", "auto", "f.png")   # ← 看不见
    with open(path, "w", encoding="utf-8") as handle:
        handle.write("x")
```

**原因**：`_是共享路径` 的 Call 分支只认 `glob/rglob/iterdir` 与 `_共享来源`；`os.path.join` 的 `func` 是 `Attribute(Attribute(Name(os),'path'),'join')`，属性名 `join` 不在集合里 ⇒ 整体不共享 ⇒ 后面 `open(...)` 的第一个参数也判不共享（`算共享` 同样看不见 `Name` 之外的调用结果）。**建议**：把 `("os.path","join")` / `pathlib.Path` 位置参数一起纳入"路径构造器"名单。

### F3（未写明；邻接已声明的那条）经**本文件内**辅助函数返回共享路径

```python
from pdx import config

def _目标():                       # ← 同文件内的 helper
    return config.OUT / "mem" / "t.txt"

def test_d():
    _目标().write_text("x", encoding="utf-8")      # ← 看不见
```

**原因**：`算共享`/`_是共享路径` 都不追"调用返回什么"。docstring 的「刻意不做的事」写的是**「看不穿**跨模块**封装（把共享路径交给 `pdx.*` 里的函数去写…）」** —— 本形态是**同一文件内**的函数，字面上不在那句里；但它与那句是**同一种精神**（不追函数体）。**建议**（二选一，成本都很低）：(a) 把 docstring 那句扩成「看不穿**封装**（跨模块或本文件内的 helper）」；或 (b) 加一跳传播：本文件内 `def f(): return <共享表达式>` ⇒ `f(...)` 算共享。

### F4（未写明）推导式 / `map(lambda …)` 里的循环变量

```python
from pdx import snapshot

def test_e2():
    [p.unlink(missing_ok=True) for p in snapshot.list_snapshots()]     # ← 看不见
    list(map(lambda q: q.unlink(), snapshot.list_snapshots()))         # ← 看不见
```

**原因**：传播循环只处理 `ast.Assign` / `ast.AnnAssign` / `ast.For` / `ast.AsyncFor`，**不处理** `ast.ListComp/SetComp/DictComp/GeneratorExp` 的 `comprehension.target`，也不看 `lambda` 的参数。**这条我认为是最该补的一条**：契约里点名的 ⑤ 家族（t95 那一族）在真实代码里最常见的两种变体就是「推导式」与 `map(lambda)`，而它们恰好落在判据外。**建议**：把 `comprehension.target ← comprehension.iter`、`Lambda.args ← Lambda args at call site`（前者更便宜且就够）加进传播。

### F5（未写明）`shutil.move` 的目标在**第 2 个**参数

```python
import shutil
from pdx import config

def test_f2(tmp_path):
    shutil.move(str(tmp_path / "a.png"), config.OUT / "evidence" / "a.png")   # ← 看不见
```

**原因**：写动作分支只检查 `func.value`（接收者）与 `node.args[0]`；`shutil.move(src, dst)` 的共享路径在 `args[1]`。**建议**：对 `move` / `copy*` 这类"源在前、目标在后"的签名，**同时**检查 `args[1]`（或对所有写动作检查全部参数里的共享路径）。**风险说明**：这恰是「把产物搬进共享目录」的自然写法，而 t95 事故的形状就是"在共享目录里搬/删"。

### F6（未写明）`Path("tools", "out", …)` **位置参数**

```python
from pathlib import Path

def test_h():
    p = Path("tools", "out", "auto", "x.json")     # ← 看不见
    p.write_text("x", encoding="utf-8")
```

**原因**：字面量识别只在 `ast.Div` 链上做；`Path(*parts)` 是普通 `Call`。**建议**：识别 `Path(...)`/`PurePath(...)` 且所有参数都是字符串常量时，把参数按 `/` 拼起来复用同一个判断。

### F7（未写明）别名导入的模块常量

```python
from pdx.snapshot import SNAPSHOT_DIR as SD     # ← 别名

def test_i():
    (SD / "cli-test-tmp.json").write_text("{}", encoding="utf-8")     # ← 看不见
```

**原因**：共享根识别认 `<模块>.<常量>` 的属性写法（`snapshot.SNAPSHOT_DIR`），别名 `SD` 是个裸 `Name`，既不在 `_共享来源` 也不在 `共享名字`（它没有赋值语句可传播）。**建议**：解析 `ImportFrom` 别名表，把 `SD` 映射回 `(模块, 常量)` 再问 `_模块常量是共享的`。

### 已知边界（**成立**，不算 finding）：⑩ `getattr`、⑪ 子进程

docstring 逐字写着「不追 `getattr`/`eval`/子进程这类动态写法」⇒ 这两种漏掉是**声明的代价**，我判「已知边界，成立」。附注：⑪ 与真实事故有关（`t95` 那条用例是经 `_invoke("snapshot","create",…)` 写共享目录的，docstring 另一句也写了「不判 `_invoke(...)` 内部写到哪儿」）⇒ 这类"看不见"正是**白名单存在的理由**，而白名单偏偏开不了口子（F8）。

## §5 白名单两方向（通过）＋ **F8（文档与机制不符）**

**两方向独立验（纯函数，不动盘）**：

| 构造 | `_白名单问题(命中, 白名单)` 的返回 |
|---|---|
| 命中 1 条、白名单空 | **红**，点名 `tests/test_合成.py:7`、且给出修法（含 `tmp_path` 字样） ✓ |

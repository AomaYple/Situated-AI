# 工程原则

本页是 Situated AI 的工程持续约束。贡献流程、命令和 Git 细节见根目录
[CONTRIBUTING.md](../../CONTRIBUTING.md)；本页不复制流程。

## 正确性优先

1. 正确性第一、速度第二、内存第三。任何提速或省内存改动必须保持输入、输出、异常、回退、编码和证据契约。
2. 生成器必须拒绝未知字段、未知作用域、重复作者、重复键、非法路径、版本漂移和不完整本地化；不能用静默回退掩盖错误。
3. 区分静态检查、快照、模拟、实测和推断。工程门禁通过不等于 Mod 行为、平衡或玩家体验通过。
4. 删除或移动前核对调用方、动态注册、测试、CLI、生成入口、文档和历史证据；可再生缓存可删除，原始证据按契约保留。

## 现代 Python 仓库

- Python 3.11+，配置集中在 `pyproject.toml`；优先使用仓库 `.venv` 和成熟库，不重复造轮子。
- 文本、路径、批量盘点、生成、验证和跨平台适配优先使用 Python；命令使用 `pathlib`、显式 UTF-8 和 LF，不依赖 shell 默认编码或绝对用户名路径。
- 代码、测试和工具支持 Windows、macOS、Linux；平台专属依赖通过环境标记声明，平台差异必须显式处理。
- 受控文本统一 UTF-8 无 BOM、LF。Victoria 3 游戏 `.txt`/`.yml` 只在 ZIP/安装边界添加 BOM；原版、第三方和冻结证据保留原始字节。
- 公共接口有类型标注和清晰异常；配置、数据源和生成物分离，生成物不手改。

## 测试、性能与资源

- 单元测试验证解析、生成、字段和边界；集成测试验证目录、manifest、ZIP、编码和回退；无游戏环境使用快照或离线输入。
- 完整 Python 回归可以使用 `pytest-xdist` 的 `-n auto --dist loadscope`；基准必须清除普通测试参数并串行运行。
- 性能报告同时标明墙钟、Python 分配峰值和进程 RSS，固定输入、版本、worker、重复次数和环境。没有同口径基线时只报告绝对成本，不声称提速。
- 工程测试、静态分析、脚本加载和单次评分不能证明长期 AI 行为；长期实机由用户按发布包验收。

## 文档与 Git

- 规则、计划、结果、审计、报告、知识库和生成文档各有单一职责；导航页只链接和摘要，历史页不覆盖当前规则。
- 机械表、指纹、manifest 和统计通过 Python 生成器维护；正文数字注明来源和时点。
- 分支使用 `codex/<topic>`，提交标题、正文和 PR 使用中文；一次提交围绕一个完整目的，提交前后检查工作树、差异、编码和验证结果。

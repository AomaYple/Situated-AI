# 工程原则

本页定义 Situated AI 的持续工程约束，适用于工具链、Mod 制作与交付。[Mod 开发原则](Mod开发原则.md)补充产品与游戏运行要求；[CONTRIBUTING.md](../../CONTRIBUTING.md)落实贡献和验证流程，[工程基线 1.0](../design/exec/工程基线-1.0.md)落实工具与证据契约。原则不记录进度或实测数值，也不代表相关能力已经验收。

## 仓库规范与持续更新

- 整个仓库按维护时最新且适用的现代 Python 仓库最佳实践建设与维护，覆盖所有目录和文件的组织、命名、源码、依赖、配置、测试、CI、文档、生成物、交付、忽略规则与维护流程。采用标准工程结构、明确职责和可复现入口，具体落实方式见 [现代 Python 仓库维护](../../CONTRIBUTING.md#现代-python-仓库维护)。
- 以 Python、PyPA 和所用工具当前稳定版的官方文档、支持范围与弃用公告为主要依据，结合有出处、可核查的社区实践。调整相关工程设施时复核依据；发现规范或支持状态变化时，按正确性、兼容性、维护收益与迁移成本评估并更新实现和文档，记录采用或暂缓的理由及验证结果。
- 游戏引擎指定的目录、脚本与本地化格式，以及第三方和原始证据的专用契约，在统一工程结构内明确管理。结构或工具迁移须保持这些契约，提供可验证的迁移与回退办法。

## 正确性与证据

- 正确性第一，速度第二，同时适用于工程建设和 Mod 开发。在保证正确性与证据完整性的前提下，持续提升开发、验证和运行效率；不得以降低行为质量、删减必要验证或放宽验收条件换取提速。
- 区分实测、官方资料、静态检查、生成结果、快照、模拟、推断和未验证。结论附来源、版本、范围与统计口径；缺少前提时标记无法判定，接口可读或加载成功不证明行为质量。
- 失败和跳过必须有明确原因，保留反例与原始结果。不得吞掉异常、把未知值当作成功或用重复尝试掩盖失败；恢复失败时停止依赖该状态的操作。
- 项目受控文本使用 UTF-8 无 BOM、LF，遵守 `.editorconfig` 与 `.gitattributes`，末尾换行按文件契约处理。二进制不适用文本编码要求；原始游戏文件、第三方内容、日志和冻结证据按各自字节契约处理，规范化保留可恢复原件。游戏侧 BOM 只在安装、打包边界添加，不写回仓库。

## 代码与依赖

- 使用仓库声明的工具链和虚拟环境，优先复用已有模块、标准库及适用的成熟库。新增依赖说明用途、版本、跨平台兼容性、可复现性和维护成本；自写替代实现须有能力缺口、边界测试和维护理由。
- Python 工具链支持 Windows、macOS、Linux。能用 Python 实现的工具和可重复流程优先使用 Python，尤其是文本、路径、盘点、生成和验证；游戏脚本按引擎契约生成。使用 `pathlib`、`sys.executable`、显式编码和平台分支，不写死本机路径或 shell 语义。
- 工具服务于明确的 Mod、验证或维护需求。可重复流程接入现有 CLI、生成器或检查入口，避免平行实现；一次性恢复与取证脚本放在忽略的输出区域。
- 阈值、权重、文案和其他可生成事实保持单一数据源，记录理由与来源，同步生成脚本、本地化和机械文档。生成结果通过生成流程维护，不以手改产物、更新黄金指纹或降低门槛掩盖漂移。
- 及时清理无消费者的代码、目录和文件。删除、改名、移动或调整忽略规则前核对动态注册、CLI、配置、测试、生成入口和证据引用；区分源码、生成物、缓存、镜像和证据，不把静态审计候选或忽略状态当作删除依据。

## 验证与性能

- 按改动风险选择单元、契约、属性、CLI、回归、集成、平台和实机测试，覆盖反例、异常、恢复、未知输入和边界。持续提高有效覆盖率，保留覆盖率门禁；不为数量堆叠重复实现的测试。
- 快速反馈不能替代适用的完整回归或阶段验收。生成器须验证确定性、生成一致性和实际生成脚本，不能只验证参考实现；缺少游戏或平台前提时明确跳过范围。
- 完整 pytest 默认使用自适应 n-auto，worker 数由 CPU 与内存预算决定，写盘使用独立临时目录。性能基准清除普通测试参数并串行运行，与完整回归、剖析和实机错峰。
- 全部项目维护的 Python 代码按模块或调用链建立耗时与峰值内存基线；日常测受影响路径，阶段验收汇总覆盖范围和缺项。性能优化须证明行为、输出与证据契约保持，再用固定输入、环境、重复规则、噪声判据和事前预算评估收益；资源超限或收益未证实不默认启用。必要的正确性修复单列，不能要求保留旧错误或包装为提速收益。
- 开发与验证效率按端到端成本评估，不能将局部基准外推为整体收益。游戏内运行效率另按 [Mod 开发原则](Mod开发原则.md#开发与运行效率)和 M4 出口实测；Python 基准不能替代游戏性能。具体测量与回退流程见 [速度优化计划](../design/exec/速度优化计划-正确性优先.md)。
- Windows、macOS、Linux 的代码、CI、无头测试和 GUI 实机证据分别申报；未运行的层级不写成已验证。

## 版本控制与文档

- Git 提交围绕一个完整目的，保持可审查、可复现和可回退；验证后按文件或补丁暂存并复核差异。标题和说明使用中文，复杂改动补充原因、关键变化、实际验证、限制及兼容影响；具体格式见 [提交规范](../../CONTRIBUTING.md#提交前与提交信息)。
- 当前原则、流程、设计、计划和结果各有维护入口，导航页只提供链接和摘要。修改规则时同步相关契约与引用；历史报告保留日期、失败和原始语境，不追认能力或覆盖当前规则。
- 机械数字、表格、指纹和生成文档由工具维护；手写文档记录目标、理由、契约、解释和结论。清理与迁移保留必要的恢复信息，避免纳入凭据、无关缓存或本机运行态。

## 语言与命名

- 项目自有文档正文、解释性注释和维护工具面向用户的说明以中文为主，技术名称、命令、路径及接口字面量保留原文。Git 提交标题和说明继续遵守中文提交规范。
- 新增代码标识符、Python 模块与工程目录优先采用规范英文命名，遵循 Python 和相关生态惯例；标准入口文件保留通用名称，主题文档采用清晰的中文名称与所在目录的编号约定。已有稳定名称仅在语义或结构调整有维护收益时迁移，并同步消费者。
- 项目维护的游戏可见文案提供简体中文和英文两套本地化，从数据源生成，保持键、占位符和含义一致；游戏接口标识符遵守引擎契约。
- 许可证、官方原文与引文、日志、冻结仪器和原始证据保留来源语言与对应字节契约。中文解释或译文单独标明，原件继续支持复核；生成内容通过生成入口维护。

具体写作、命名与翻译边界见 [贡献指南的语言与命名约定](../../CONTRIBUTING.md#语言与命名)。

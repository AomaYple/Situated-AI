# 工程原则

本页是 Situated AI 的工程原则摘要。贡献流程、验证矩阵和命令细节见 [CONTRIBUTING.md](../../CONTRIBUTING.md)；测试、快照、分析和证据出口见 [工程基线 1.0](../design/exec/工程基线-1.0.md)。两份文档分别维护流程和契约，本页只保留跨任务都适用的原则。

## 正确性与证据

- 正确性第一，速度第二。任何性能优化都必须先证明行为和输出等价，再比较速度与峰值内存。
- 区分实测、静态检查、生成结果、快照、模拟、推断和未验证。缺少前提时标记无法判定，不用重试次数或放宽门禁制造通过。
- 变更以可回退、可复现和可审查为目标。删除、改名、忽略和迁移先查消费者、生成入口、测试和引用。
- 项目受控文本使用 UTF-8 无 BOM 和 LF，遵守 `.editorconfig` 与 `.gitattributes`；二进制不适用文本编码要求。原始游戏文件、第三方内容、日志和冻结证据按各自字节契约处理，规范化时保留可恢复原件；游戏侧 BOM 只在安装、打包边界添加。

## 代码与依赖

- 优先使用仓库虚拟环境和成熟库；已有库能解决的问题不重复实现。新增依赖需要说明用途、版本、跨平台兼容性和维护成本；自写替代实现须有缺口依据、边界测试和维护理由。
- Python 工具链支持 Windows、macOS、Linux。能用 Python 实现的工具和可重复流程优先使用 Python，尤其是文本、路径、批量盘点、生成和验证；游戏脚本仍按引擎契约生成。代码使用 `pathlib`、`sys.executable` 和显式编码，不写死盘符、用户目录或 shell 语义。
- 可重复的流程进入现有 CLI、生成器或检查入口；一次性脚本只能作为忽略的恢复或证据工具保留。
- 源码、测试、生成器和生成物遵守单一数据源。生成结果通过生成流程维护，不能用手改产物或更新黄金指纹掩盖漂移。
- 及时清理无消费者的代码、目录和文件；先核对动态注册、CLI、测试、配置和证据引用，不把静态审计候选或 Git 忽略状态直接当作可删除依据。

## 验证与性能

- 按风险选择单元、契约、属性、CLI、回归、集成、平台和实机测试；优先覆盖反例、异常、恢复、未知输入和边界。
- 持续提高有效覆盖率，覆盖尚未验证的行为；现有覆盖率门槛防止回退，不为数量堆叠重复实现的测试。
- 完整 pytest 默认使用自适应 n-auto，worker 数由 CPU 与内存预算决定。性能基准清除普通测试参数并串行运行。
- 全部项目维护的 Python 代码按模块或调用链建立速度与峰值内存基线；日常测受影响路径，阶段验收汇总覆盖范围和缺项。测量固定输入、环境、重复规则和预算，说明口径、噪声和回退条件。
- 三平台工程支持以代码、CI 和无头验证分别申报；未运行的 GUI 或游戏实机不写成已验证。

## 版本控制与文档

- 一个提交围绕一个完整目的；标题和正文使用中文，正文说明原因、关键改动、实际验证、限制和兼容影响。
- 导航页只提供入口和当前摘要。当前规则、设计、计划和结果分别由对应权威文档维护；历史报告保留日期和原始语境，不能覆盖当前规则。
- 机械数字、表格、指纹和生成文档由工具维护；手写文档记录目标、理由、契约、解释和结论。

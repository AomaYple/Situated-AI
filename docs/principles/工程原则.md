# 工程原则

本页只定义工程持续约束。环境准备、验证命令、文档维护与 Git 操作见根目录
[CONTRIBUTING.md](../../CONTRIBUTING.md)；Mod 的产品约束见[Mod 开发原则](Mod开发原则.md)。

## 正确性与变更

1. 正确性第一、速度第二、内存第三。优化不得改变输入输出、异常行为、回退语义、编码或证据合同。
2. 对生成器、解析器和校验器采用显式失败：未知字段、作用域、重复定义、非法路径、版本漂移或不完整数据不能被静默忽略。
3. 只有在语义等价和所需验证通过后，才接受性能或内存改动；性能结论必须基于可重复、同口径的测量。
4. 删除、移动或合并内容前，检查其调用方、动态注册、测试、CLI、生成入口、文档引用及证据用途。

## Python 与跨平台

- 使用 Python 3.11+，项目元数据、依赖与工具配置集中在 `pyproject.toml`；优先使用仓库 `.venv` 和维护成熟的库。
- 优先复用 Python 标准库及项目已有抽象处理路径、文本、批量盘点、生成和验证；避免 shell 默认行为、用户绝对路径和平台特定假设。
- 工具与测试支持 Windows、macOS、Linux；平台差异显式处理，平台专属依赖通过环境标记声明。
- 公共接口提供类型信息和明确错误；源码、输入数据与生成物分离，生成物通过唯一生成流程维护。
- 受控文本统一 UTF-8 无 BOM、LF。Victoria 3 游戏文本仅在安装或打包边界按引擎要求添加 BOM；原版、第三方和冻结证据保留原始字节。

## 测试、性能与证据

- 依据风险使用单元、属性、回归、离线合同和真实底本集成测试；生产合同与离线合同共享规则来源，避免复制业务规则。
- 区分静态检查、快照、模拟、实测和推断。检查通过只证明其明确覆盖的合同，不据此推断未覆盖的运行行为。
- 性能测量固定输入与环境，并报告足以复核的时间及内存口径；不同测试身份、并行度或数据不能直接比较。

## 文档和来源

- 规则、流程、设计、计划、状态、结果、知识库与生成文档各有单一职责；导航页链接权威来源，不复制第二份规则。
- 机械表格、统计、指纹和 manifest 由 Python 生成器维护；散文中的易变事实标明来源或链接到权威收据。

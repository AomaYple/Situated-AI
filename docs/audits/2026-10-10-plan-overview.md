# 2026-10-10 仓库总览与计划编排复审

## 范围与结论

本轮按用户要求重新总览仓库，判断新增全仓现代 Python 维护原则、文档生成建议及最新实验事实是否要求调整 Mod 开发计划。分支为 `main`；开始时已有十份原则和流程文档修改，本轮在其上增量更新，不覆盖已有改动。

结论是保留 [最终执行纲领 1.0](../design/exec/mod重设计-实施计划.md) 的目标、M0–M5、依赖、实验预算和阶段出口，更新 [当前任务编排](../design/当前工作清单.md#当前任务编排) 的执行顺序、前置条件和停止条件。原定型快照保留日期语境，不能改成新进度。工程与产品任务分别记录；工程维护不替代行为证据，也不另建一套阶段编号。

盘点时 Git 跟踪 647 个文件，其中 234 个 Python 文件、220 篇 Markdown。全部受控文件读取字节并记录 SHA-256；Python 文件解析 AST、模块说明、顶层声明和导入；Markdown 提取标题。另盘点 `.git` 内部与链接目标之外的工作区文件元数据，区分第三方环境、镜像、缓存和原始证据，未读取失败。该盘点不等于逐行证明所有代码语义、验证所有二进制，或重新运行所有历史实验；关键生产、比较、恢复和生成入口另作交叉审查。

机械盘点位于忽略目录 `tools/out/repository-audit/2026-10-10-plan-overview/inventory.json`。原始证据、第三方和恢复副本未重写或删除，未启动游戏，未改变生产参数、快照、冻结指纹或忽略规则。

## 关键事实与计划影响

### 生产闭环和阶段定义

`pdx.decisions.triggers` 已包含战争、博弈发起方、目标方、承诺参与方及尚未选边参与方的外部暴露，财政更新器是唯一风险变量写入者，TTL 为 62 天，进入/保持阈值为 26/52 周。当前设计摘要之前只提已有承诺，遗漏尚未选边的暴露；本轮修正该摘要，没有修改数据或脚本。

M1 是接口与观测链，M2 是通用最小财政实现；行为因果和质量仍在 M3。此前对话中把 M1–M5 按通用示例重新命名，以及把旧 `01-大方向` 列为当前设计权威，均不作为新计划：当前产品架构以 `03-处境决策设计` 为准，旧 01 保留历史目标与原引用。

| 阶段 | 最新证据边界 | 下一步与依赖 |
|---|---|---|
| M3-A | 原生财政只读链有正常状态负例；自然 CHL→BOL 绑定有 26 日完整双国矩阵，但无共同 ACTIVE、第二合格响应国和处理臂 | 最先找新的处理前风险/资格/响应余地；资格通过后才冻结单参数配对，行动代价和反例仍需测量 |
| M3-B | 已形成博弈和有限命令合法性可读，完整 AI 机会分母仍 null | 新受支持候选集合或正例出现才重开；`started=0`、扩大观察国和延长阴性窗口不构成证据 |
| M4 独立工作 | 原件恢复、控制台历史、tick 守卫、后台新边界及标准计时采集有证据；24 月输入准备产生原版断言并已停止 | 有新输入或环境依据时可先做 vanilla 基线与合法后期准备；不重跑已关闭的错误场景 |
| M4 正式候选 | 没有通过 M3 的冻结候选、合格真实后期输入及事前噪声/预算；正式早期/后期配对和长期出口未通过 | 前提齐备后执行原纲领规定的配对数量、窗口和门禁，不将仪器成功追认为性能通过 |
| M5 政治 | 有限直接 Law/IG 输入可读；阶段概率链触发 Interface 断言后停止，最终候选/方向/排名/风险/更新组合仍缺 | 只研究有新依据的受支持通道；不复活断言链，不调用立法或加极端权重绕过出口 |
| M5 市场和后续范围 | 依赖分数和隔离观测存在，实际响应、质量和正式 M4 仍缺；生产开关 false | 模块分别走 M1–M4；首个财政闭环不替代完整内部、外部、政治偏好目标 |

代表性原始报告通过 `game_run.read_reviewed_report` 只读复核，校验完整日志哈希并重新检查挂载及十类错误：

这次报告复核没有重新启动游戏，也没有验证所有历史用户文件；用户原件恢复范围与自然绑定细节继续以对应结果页及其独立审计为准。

### 文档生成与编排

现有 `pdx.docgen.targets()` 登记的是 **18 个目标，覆盖 17 份不同文档、174 张表**；脚本系统文档有两组目标。不能把 18 个登记目标说成 18 份不同文档。`doc_tables` 已支持保留作者列和正文，`claim` 标记与 `verify --fix` 已维护机械正文数字，库存测试约束无人维护的机械内容。

纯生成入口另外包括 `ai-surface`、`political-surface`、`index`、`analyze` 和 legacy `modgen` 说明。本轮补齐设计导航中遗漏的政治候选面入口。完整生成登记、机器标记和统一文档检查可以扩展现有能力，但目前没有名为 `docs` 的 CLI 子命令；不先迁移所有表格边界，也不建立重复保存状态/出口的计划 TOML。此前对话中的统一入口属于后续建议，不是已经存在的命令或确定的实施要求。

主纲领负责稳定目标与出口，当前任务表负责依赖和下一动作，阶段结果负责预登记与实测；`checkpoint_catalog`、`ExperimentLedger`、`RunLock` 和持久恢复负责输入预检、有限运行和安全。账本限制实验，不自动判定 AI 质量；文档状态也不自动解锁实机。

### 现代 Python 交付范围

当前支持的工具开发流程是从仓库创建环境并 `pip install -e ".[dev]"`，Mod 的游戏交付是确定性 ZIP。`config.REPO` 按 `__file__` 的父目录定位仓库，生产 TOML、底本、快照与文档都位于包目录之外；CI 主要验证可编辑安装。未看到独立 wheel/sdist 安装后完整资源和 CLI 的验收路径，不能把标准 `pyproject.toml` 或 Mod ZIP 合法性解释为独立 Python 工具发行已经通过。

后续先明确消费者：继续只服务仓库时，把该运行前提写清并验证；若要独立分发 Python 工具，再设计资源定位、数据包含范围与构建/安装测试，评估游戏原文和证据的交付边界。这个选择不阻塞 M3 新输入研究，也不构成发布 Mod 必须先上 PyPI 的要求。

全仓现代实践按 [贡献流程](../../CONTRIBUTING.md#现代-python-仓库维护)查阅适用官方稳定版文档并维护；已有标准布局、类型、测试、三平台 CI、确定性生成和证据恢复继续复用，不因新增原则推倒重来。

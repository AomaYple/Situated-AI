# 2026-10-16 规则与仓库整合

## 范围与结论

本轮按根目录 AGENTS.md、CONTRIBUTING.md、工程原则、Mod 开发原则、工程基线、产品主计划、当前工作清单和文档维护规则复核整个仓库。贡献文件的实际名称是 CONTRIBUTING.md，未创建或保留同义的 CONTRIBUTE.md。

盘点结果为 651 个受 Git 跟踪文件，其中包含 35 篇 Markdown、89 个 src/pdx Python 模块、127 个测试文件和 33 个 tools Python 文件；工作区中的官方镜像、证据和生成运行态不计入受 Git 跟踪文件。根工作区、远端 main 和唯一工作树在盘点时一致；没有活动 Victoria 3 进程或活动部署恢复指针。目录职责没有需要通过大规模移动才能解决的冲突，因此保留稳定路径，只整合规则入口和导航。

## 规则整合

- AGENTS.md 收敛为代理接手顺序、权威层级、任务路由、修改边界、证据边界和交付要求，不再复制贡献流程。
- CONTRIBUTING.md 增加规则作用域、计划/状态/清理同步契约，统一把贡献指南的真实文件名写成 CONTRIBUTING.md；安装示例改为平台中性的 Python 命令文本。
- 工程原则和 Mod 开发原则继续分别维护工程底线与产品底线；它们都保留“正确性第一、速度第二、内存第三”，没有把实测状态写进原则页。
- README、docs 导航、设计导航和执行索引统一指向同一套规则和读取顺序，不再建立第二套当前计划。
- 工具手册和当前探针 README 的命令围栏改为 text；历史报告里的 PowerShell 文字保留为历史证据，不把历史表述改写成当前规范。

## 仓库清理边界

受 Git 跟踪的历史实验、结果、审计、报告、生成产物和精简快照都有消费者或审计引用，本轮没有凭静态零引用删除它们。research/official-docs、tools/out、恢复副本和冻结证据继续按字节契约保留或忽略。

本地忽略的缓存和测试运行目录属于可再生运行态，已在确认无游戏进程、无活动部署和无恢复指针后清理：pytest 临时目录、覆盖率文件、pytest/mypy/ruff/Hypothesis 缓存、空的性能隔离目录和空的性能日志隔离目录。完整回归期间这些缓存会按工具需要重新生成，交付前仍不纳入 Git。实机证据、恢复副本和 tools/out 证据目录没有清理。忽略规则仍保留，避免下一次运行重新污染工作区。

## 计划更新与当前出口

产品主计划继续是 docs/design/exec/mod重设计-实施计划.md，版本路线仍为 V0.1→V0.2→V0.3→V0.4→V1.0，每个阶段都必须形成一个可安装、可游玩、可保存/重载和可回退的增量版本。工程规则整理不提高任何产品阶段完成度。

当前执行顺序冻结为：

1. A3 取得独立合法输入、环境变化或有依据的受支持接口，再分别验证响应身份、逐国 actor、战后覆盖、对象失效和质量字段；
2. A5 在合法窗口验证原生国家面板候选的可见性、国家切换、语言、退出和成本；
3. A3/A2 具备资格后才运行 G1 pilot 和正式行为配对；
4. M3 通过后执行 A5/M4 的玩家路径、长期/后期资源、卸载和交付出口；
5. V0.1 交付后才进入 V0.2–V1.0。

已停止的实机输入、错误分类、账本和质量缺项不因本轮规则整理改变。工程检查通过不等于 AI 行为质量通过，V0.1 仍未交付。

# 仓库总览与清理审计（2026-10-14）

## 范围与结论

本次审计重新盘点 Git 受控树、项目入口、文档权威层、Mod 生成链、测试入口以及 `tools/out/` 的忽略产物。当前主线为 `main`，工作区在审计开始时干净，受控文件 637 个：Markdown 206 个、Python 240 个、测试 122 个；远端只有 `main`，没有遗留任务分支。

仓库结构已经形成稳定分层：`src/pdx/` 是可复用 Python 核心，`tests/` 是测试，`tools/ci/`、`tools/benchmarks/` 和 `tools/probe/` 是检查、基准和实机入口，`mod/decisions/` 是当前生产数据源，`mod/legacy/` 是隔离的历史产物，`docs/` 按原则、设计、执行结果、审计、报告和知识库分层。没有发现第二套当前产品主计划或没有消费者的受控入口，因此没有进行受控源码、生成器或历史证据删除。

当前产品状态仍以 [分阶段可玩开发计划 2.0](../design/exec/mod重设计-实施计划.md) 和 [当前工作清单](../design/当前工作清单.md) 为准：V0.1 尚未交付，G1 pilot 未通过，M3 合格行为配对为 0；本次仓库清理不改变任何产品验收结论。

## 忽略产物与清理

`.gitignore` 继续保留 `.venv/`、`.agent-teams/`、解析/测试缓存、`tools/out/` 临时输出、本地官方文档镜像和实机产物的边界；精简快照、精简 G1 证据仍是入库例外。没有把忽略状态当作删除证据，也没有触碰运行时队伍状态、官方原文、恢复副本、检查点、精简快照或原始实机证据。

在确认没有 Victoria 3 进程和活动恢复指针后，本轮只删除了明确无引用的根级临时输出与可重建缓存：共 208 项，约 92.2 MiB。删除范围包括 `.pytest_cache/`、`.mypy_cache/`、`.ruff_cache/`、`.hypothesis/`、`v3-parse-cache-*`、源码树 `__pycache__/`，以及 `tools/out/` 根下未被受控文档引用的一次性脚本、空错误输出和临时命令结果。`tools/out/decisions/`、`checkpoints/`、`recovery/`、`evidence/`、`snapshots/` 等仍保留，原因是它们含有文档引用、恢复价值或证据契约；26 GB 级实机证据没有做未经逐件登记的批量删除。

清理脚本为一次性 Python 工具，执行后已移除，不作为项目入口或受控源码。历史 `tools/out/t10-MANIFEST.txt` 等清单仍保留并继续作为历史审计引用；其中少数清单条目对应的一次性副本已在本轮按“无直接受控文档引用、可重建”规则清理，不能再把这些历史清单解释为当前完整副本集合。

恢复核对也完成了：`repository-audit/cache-originals.zip` 中的 444 项全部是字节码、属性测试数据库或临时虚拟环境文件；`encoding-originals.zip` 中另有 91 项历史日志、命令输出、临时脚本和一个已由精简快照替代的完整快照。它们仍由压缩包和清单保留，但没有恢复回工作目录；恢复它们只会重新制造缓存或重复中间产物。`encoding-followup-originals.zip` 仅有 1 个已清理的重复日志。当前精简快照、恢复副本和历史报告所需的证据路径仍按忽略规则保留。

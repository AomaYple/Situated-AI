## 当前结论

深层目录统计优化通过了定向正确性、三个真实内容根的结果对照、局部速度与内存验收、静态检查、离线基线和完整 `n auto` 正确性与资源验收。完整回归最初被外部 Rust 构建造成的系统低内存中止；外部构建退出后，按新增空闲前提只重开一次并通过。局部提速已经证实，整套提速比例仍未证实。

两处测试 fixture 复用候选已经回退。该候选局部提速明确，但完整三组对照未完成，不能默认启用。测试数量、独立确定性、CLI 全链路、覆盖率门槛、黄金指纹及默认并行策略均保持原契约。

本轮不修改 Mod 阶段出口，不启动游戏；已有 A5 修改与未跟踪文件按原字节保留。本页不提供 Mod 行为或游戏运行效率结论。

## 输入与测量口径

- 起点为 `02b2632` 上的 `codex/a5-explanation-probe` 工作区，包含本轮开始前已有的 A5 修改，不能把结果当作纯净 `main` 的测量。
- Windows，Python 3.14.7；pytest 9.1.1、pytest-xdist 3.8.0、pytest-cov 7.1.0、coverage 7.16.1、psutil 7.2.2；16 个逻辑 CPU、8 个物理核心，物理内存约 16 GiB。
- 完整回归固定 `--randomly-seed=1`、`loadscope` 调度并启用分支覆盖率。参数直接传给顶层 pytest，避免嵌套 pytest 继承同一 JUnit 或覆盖率输出路径。
- 完整回归的进程树资源由既有 `tools/probe/mem_baseline.py` 每 100 ms 采样。RSS 为同一时刻进程树之和；单 worker 的 OS 历史峰值和各进程峰值之和分别记录，后者不能冒充同时峰值。
- 每轮记录独立 JUnit、coverage JSON、采样 CSV、退出码、超时和看门狗状态，以及受控输入的前后 SHA-256；其他原有修改不得被混入候选差异。
- 局部速度采用固定 AB/BA/AB 三组，以中位数比较；噪声采用两臂相对各自中位数的最大偏离。速度、tracemalloc 和 RSS 分开测量。磁盘缓存保留，应用进程重新建立；操作系统页缓存状态未知。
- 局部速度须改善至少 10% 并超过噪声；RSS 中位数与最大值的回退均不得超过基线的 5% 或 16 MiB 中较大者。完整回归保留每 worker 1536 MiB、总 RSS `1024 + workers × 1536` MiB，以及系统可用物理内存 700 MiB 的中止守卫。

官方依据于本轮核对：pytest 的[共享 fixture 与作用域](https://docs.pytest.org/en/stable/how-to/fixtures.html#scope-sharing-fixtures-across-classes-modules-packages-or-session)、xdist 的[作用域调度](https://pytest-xdist.readthedocs.io/en/stable/distribution.html)、Python 的 [`os.scandir`](https://docs.python.org/3/library/os.html#os.scandir)。使用现有依赖与标准库，不新增包。

定向串行三组中，耗时中位数由 164.7 秒降至 44.7 秒，减少 72.9%，噪声 3.36%；RSS 中位数由 559.2 MiB 到 557.7 MiB，最大值由 559.9 MiB 到 560.4 MiB，内存基本持平。该局部结果不能外推整套。

## 保留候选：单次遍历完成深层目录统计

`src/pdx/scan.py::stats_for(deep=True)` 原先通过 `walk_files()` 统计文件，再通过 `_walk_dirs()` 遍历整棵树计数目录。候选在一次 `os.scandir` 遍历中累计相同字段，减少逐文件 `Path`/`FileEntry` 临时对象；文件流接口和浅层统计保持原契约。唯一消费者消失的 `_walk_dirs()` 已移除，并更新对应测试说明。

三个真实内容根 game、jomini、clausewitz 的全部 `DirStats` 字段和后缀首次出现顺序均与冻结旧实现一致。另新增 16 项测试，覆盖空目录、普通文件和缺失路径、深浅层字段、空子目录、大小写后缀、硬链接、目录读取失败、条目分类或 stat 失败、枚举中断后的部分结果及资源关闭、子链接和根链接语义。定向回归为 39 项通过、1 项因 Windows 符号链接权限不足跳过，另有 2 项子测试通过；该跳过项不能算 Windows 链接语义已实测。

独立登记的扫描候选采用一组固定三对测量，结果如下：

| 指标 | 冻结旧实现 | 扫描候选 | 判定 |
|---|---:|---:|---|
| 三个内容根统计耗时中位数 | 0.597153 秒 | 0.295737 秒 | 减少 50.5%，超过 2.94% 噪声 |

RSS 子进程通过 psutil 每 10 ms 采样；该读数与完整进程树、Python 分配峰值各有口径，不能互相替代。测量各轮入口检查外部编译和 pytest 进程，没有获得整机持续独占。上述结果仅证明扫描热点，不提供完整测试或游戏的提速比例。

## 完整 n-auto 验收

扫描候选在完整回归前登记：保留原有全部 3884 个 testcase，允许且只允许新增扫描测试的 16 个身份，预期共 3900 个。覆盖率门槛、原测试状态和跳过原因、子测试计数、来源指纹与资源守卫继续检查；新增测试不能作为删减旧测试的补偿。

第一次真实 `--workers auto` 选出 5 个 worker；57.0 秒后，系统可用内存降至约 575 MiB，资源守卫以退出码 15 中止。当时被测进程树 RSS 峰值为 1173.0 MiB，不能作为一次完成回归的内存基线。随后取证发现外部仍有 2 个 cargo、9 个 rustc 和 9 个 link 进程，可用内存接近耗尽；本轮不停止其他任务的进程，不关闭资源守卫。

在原始失败上追加重开登记：外部 cargo、rustc 和 link 等编译父子进程全部退出、可用内存至少 4096 MiB，并连续保持 60 秒，才允许新开一次完整验收；就绪等待最长 300 秒，不覆盖前次失败，不追加同类固定性能对照。实际空闲门通过时可用内存约 11 GiB，新目录为 `scan-candidate-auto-idle/`。之后观测到外部构建活动重新出现，但可用内存保持在守卫之上，回归完整结束。

最终结果由 `scan-v2/full-acceptance.json` 汇总：

| 指标 | 最终完整回归 |
|---|---|
| 参数与实际 worker | `-n auto --dist loadscope`，实际 5 个 worker |
| 测试集合 | 3900 项，3880 通过、20 跳过，1743 项子测试通过 |
| 原集合核对 | 原有 3884 项全部保留，状态与规范化后的跳过原因不变；新增项恰好为预登记的 16 项 |
| 包装墙钟 | 484.3 秒 |
| 同时进程树 RSS 峰值 | 3913.2 MiB，约 3.82 GiB |
| 最高单 worker OS 峰值 | 1275.7 MiB，低于 1536 MiB 预算 |
| 进程树 private 峰值 | 7011.6 MiB；与 RSS 分别记录，不视为可用物理内存消耗 |
| CPU 总时间 | 1829.4 秒 |
| 行与分支总覆盖率 | 89.4428%，整体 86% 与 11 个核心模块下限全部通过 |
| 输入和运行完整性 | 前后指纹不变，无失败、超时、看门狗中止或采样错误 |

新增 16 项中 15 项通过，符号链接项因本机权限不足跳过；原有 19 项跳过仍保留。未修改模块的覆盖差异为 parser 的一个恢复分支，其他既有模块不再存在命中缺失；scan 已重排源码行号且移除旧辅助函数，不能将旧行号集合的差直接解读为覆盖丢失。

默认 `n auto` 仍按实际 CPU 和可用内存选择数量，未固定为 3、4 或 5 个 worker，也未改动调度器。本次 5 worker、3900 项集合及外部活动，与此前 4 worker、3884 项不匹配，因此整体提速比保持 null，不能用 574.8→484.3 秒推导优化收益。

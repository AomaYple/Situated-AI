# M4 存档迁移输入盘点（2026-10-06）

## 目的

确认仓库现有实机证据中是否存在可以合法用于 `--allow-save-upgrade` 的跨版本 Victoria 3 存档。
盘点只读取有限存档头和 SHA-256，不改写、不重打包、不修改版本字段，也不把升级开关本身当成迁移成功。

## 可复现命令

在仓库根目录使用仓库虚拟环境运行：

```text
.venv\Scripts\python.exe tools\probe\save_migration_audit.py --root tools\out --output tools\out\decisions\migration-audit-20261006.json
```

工具会递归读取 `*.v3`，保留相对 POSIX 路径、有限头字段和完整 SHA-256；解析失败也会留在报告中，退出码为 1。
报告位于被 `.gitignore` 排除的 `tools/out/`，本页保存可审计的摘要。

## 结果

| 项目 | 结果 |
|---|---:|
| 存档文件总数 | 9 |
| 版本 | 全部 `1.14.5` |
| 解析错误 | 0 |
| 跨当前版本输入 | 0 |
| 可用于升级实验的输入 | 0 |
| 观察者存档 | 9 |
| 含空游戏规则引用 | 1 |

9 个文件的日期范围是 `1836.4.1` 至 `1840.7.1`，它们都是同一游戏版本下的检查点。
含空游戏规则引用的文件仍保留其 SHA 和头信息，但不能作为干净升级输入；它也不改变“没有跨版本输入”的结论。

## 出口与后续

M4 的迁移专项完成了输入盘点和门禁自动化，但跨版本迁移仍未验证。`--allow-save-upgrade` 目前只允许显式越过版本不一致的启动前拒绝，
并不替游戏完成存档升级，也没有真实跨版本结果可以证明它成功。

只有获得由游戏真实产生、版本不同于当前安装、观察者状态有效且不含空规则的原始 `.v3`，才可以继续运行升级实验。
实验必须保留原始字节、完整 SHA、实际载入日期、错误门禁、挂载和收尾证据；在此之前不能把同版本重载、改写头字段或模拟报告写成迁移通过。

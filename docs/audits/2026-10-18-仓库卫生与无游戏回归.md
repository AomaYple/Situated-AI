## 验证与远端失败

仓库整理提交 `0ea74b1` 的本机完整回归为 **4004 collected、3984 passed、20 skipped、1743 subtests passed，632.27 秒**。跳过来自 Windows 符号链接权限、FIFO 和缺失引擎日志；本次没有重新测量完整覆盖率，不把历史覆盖率数值当作当前值。编码、Ruff、类型、死代码、离线基线、生成一致性、分析产物及交付契约检查通过。

该提交在远端 CI 完成前被本地快进合入主线，未遵守贡献流程要求的 PR 与检查顺序。随后核查 [CI 39103422831](https://github.com/AomaYple/Situated-AI/actions/runs/39103422831) 发现：静态检查和基准成功，三平台 Python 矩阵与锁定环境的 pytest 步骤均因 `test_standard_package_manifest_validation` 失败。此处保留失败，不把本机通过追认为 CI 通过。

根因是该单元测试显式生成解释探针包，却未提供生成器需要的本机国家面板和匹配版本。开发机的真实游戏掩盖了隐式依赖；无游戏 runner 按契约正确拒绝。设置 `V3_ROOT`、`V3_USERDIR`、`V3_WORKSHOP` 为不存在目录后，本机同一无游戏选择集复现：**1 failed、3638 passed、137 skipped、217 subtests passed，163.66 秒**。

修复只调整测试输入：在 `tmp_path` 写入不含游戏原文的最小合成面板，并提供与生产策略匹配的版本。真实探针附加器、ZIP 生成、清单校验和正式包拒绝探针的逻辑全部执行，增加断言确认探针面板实际进入清单；没有改生产代码、移除测试、增加跳过或放宽门禁。后续修复使用短期分支与 PR，适用远端检查成功后合并。

修复后的相同无游戏选择集为 **3639 passed、137 skipped、217 subtests passed，161.19 秒，退出码 0**。缺游戏、缺历史日志和 Windows 平台能力对应的跳过仍保留；该集合排除了 integration 与 benchmark，不能称为装有游戏的完整回归或整体提速对照。原始输出与 JUnit 位于忽略的 `tools/out/ci/no-game-fixed.log` 和 `tools/out/ci/no-game-fixed.xml`。修复后 Ruff、格式、编码和 mypy（230 个源码文件）检查通过；远端结果以修复 PR 的实际检查为准。

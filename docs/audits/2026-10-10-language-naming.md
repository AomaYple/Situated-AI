# 2026-10-10 语言、命名与编码审计

## 目标

本轮按全局 `AGENTS.md`、项目 `AGENTS.md`、工程原则和贡献指南，复核受控仓库的语言边界、命名约定与文本字节格式。目标是让项目自有说明以中文为主，同时保留游戏接口、机器协议、官方原文和原始证据所要求的原文形式；不以机械替换英文字符破坏可执行契约。

## 盘点范围

- 范围为 `git ls-files` 返回的 616 个受控文件；未混入 `.git/`、`.venv/`、忽略输出、本地官方原文镜像或本机运行态。
- 文件分类统计如下：

  | 类别 | 数量 |
  |---|---:|
  | Python 源码 | 114 |
  | 测试 | 116 |
  | 普通文档 | 51 |
  | 配置与数据 | 43 |
  | 生产生成物 | 5 |

  | 生成探针 | 70 |
  | 历史记录 | 136 |

- 扫描使用仓库 `.venv` 的 Python、AST、`tokenize`、`markdown-it` 和 Git 的 NUL 分隔文件清单；候选只用于人工复核，不作为自动删除或自动翻译依据。
- 候选扫描得到 628 条含连续拉丁词的字符串、注释或 Markdown 片段。候选中包含大量游戏原版字段、协议值、SQL、正则、官方引文和测试夹具，不能按字符数量判断违规。

## 已落实的规则

### 自有说明与工具提示

- 已将 19 个 Python 模块中的 61 条自有说明、探针元数据、性能说明、错误解释和维护注释改为中文。
- 保留 `noqa`、正则、SQL、日志协议、脚本块和 Python 标识符的原始字面量；只翻译面向维护者或使用者的解释文字。
- 生成表头和统计标题已从英文统一为中文，源头位于 `src/pdx/defines.py`、`src/pdx/modifiers.py`，文档入口位于 `docs/victoria3-modding/05-defines与修饰符.md`。
- 全量 defines 表使用“全部 defines 文件”表头，与 Jomini 三文件子表区分，避免中文化后生成器按相同表头定位到错误表格；对应行为由 `tests/test_doc_tables.py` 固定。
- 补充检查普通文档的标题和表头，复核 79 个英文候选；doc 05 中剩余的自有表头、旧列名说明与条目提示已中文化。字段名、原文转录和技术名称按原有契约保留，登记的 game_rule 表同时更新生成器定位入口。
- README 的用例数与知识库字符总量依据实际收集和 UTF-8 解码后的字符数同步；当前分别为 2,882 项和 1,295,994 字符，不改写历史回归的数量与读数。

### 必须保留原文的类别

以下内容按来源或执行契约保留英文及其他原始字节：

- Victoria 3 原版脚本接口、键名、scope、效果、触发器、策略字段、文件名和本地化语言键；
- `SITAI ...`、`ZZPROBE ...` 等机器可读日志协议，以及 `START`、`ACTIVE`、`HOOK`、`RISK`、`yes/no` 等状态值；
- 正则表达式、SQL、字段名、退出码、命令参数和 Python/生态规范名称；
- 官方 Wiki、游戏原版资料和逐字引文；
- 历史实验正文、冻结证据、原始日志、第三方资料及其恢复副本；
- 生产本地化的英文版本。生产文案同时维护 `l_english` 与 `l_simp_chinese`，两套键和占位符保持一致；
- 测试中故意使用的原始游戏错误句式，以及用于验证解析器的英文目标文本。

这些内容旁边的中文解释、用途说明和证据边界已按项目规范维护；原文与译文不混写成会改变接口含义的替换文本。

### 命名与编码

- 新增 Python 标识符、模块和工程目录继续使用规范英文命名；主题文档沿用清晰中文名称和现有编号。
- 受控文本统一 UTF-8 无 BOM、LF；游戏交付边界的 BOM 仍只由安装/打包流程添加。原始证据按字节契约保留。
- 路径、命令和接口字面量保持可复制的实际值；没有新增本机绝对路径或平台专用 shell 语义。

### 配套工程核查

- 保持 `src/pdx/`、`tests/`、`tools/`、`docs/`、Mod 数据源与产物的职责分工，继续使用 `pyproject.toml` 和现有 CLI；本轮没有需要承担迁移成本的目录或公共接口改名。
- 核对受控清单与忽略边界：没有将虚拟环境、缓存、构建或交付目录、官方原文镜像入库；`tools/out/` 的受控文件仍仅为精简快照例外。没有依据仅凭忽略状态删除原始证据或恢复副本，也没有需要调整的忽略规则。
- 死代码审计核查动态入口与实际消费者后通过，本轮未发现需要删除的生产代码。清理 3 个已完成使命的一次性语言审计脚本，保留忽略目录中的盘点、候选和迁移记录。
- 所有检查使用本工作区 `.venv` 的 Python。源码与机器协议的修改边界由差异复核、生成一致性、文档检查和完整回归共同验证。

## 结论与边界

仓库自有的可翻译说明、生成表头、工具提示和维护文档已按语言原则收口；剩余英文候选经复核属于接口、协议、来源原文、历史证据、双语本地化或测试契约。项目目标是可执行、可复核和可维护的语言边界，不是让所有文件只剩中文字符。后续新增内容继续从工程原则、贡献指南和生成源头执行同一规则。

本轮没有启动 Victoria 3，没有重新测量覆盖率、速度与峰值内存，也没有触发三平台 CI。现有 Python 工具链的跨平台契约与 Windows GUI 支持边界保持原有声明；本轮本地回归不能替代 macOS/Linux 实测或 M3/M4/M5 的实机产品出口。语言与文档收口也不能称为 Mod 整体行为验收完成。

工作区原有的未跟踪 `computeunion.txt` 没有已确认的项目消费者，本轮保留且不纳入修改范围。审计结果和 Git 差异保持可审查，本轮未提交或推送。

# 正式实验入口、控制先行与有限预算

本次按当时的 [Mod 制作提速计划 2.0](../design/exec/速度优化计划-正确性优先.md)实施 R1、R2 和 R6 的可独立工程部分，并复核 R3 环境、R4 单个接口；实施从 2026-10-11 延续至 2026-10-12。2.0 属于本页记录时的历史版本，当前执行附件已更新为 2.1，见[当前工作清单](../design/当前工作清单.md)。产品目标与 M1–M5 出口保持原定义；本页记录新增工具及其限制，正式产品状态由结果页维护。

## 资格原件与启动前核验

资格 schema 1 根键严格为 `schema/purpose/checkpoint/run_report/registration/game_files`。文件引用使用相对 `path` 与 SHA-256，限于资格目录内普通文件；拒绝重复 JSON 键、非有限数字、绝对路径、穿越、符号链接、junction、特殊文件、缺失与复核期间变化。存档和日志流式散列；目录成员和所有原件最终重新检查。

登记 schema 1 包含目的、计划/场景/判据版本、检查点 SHA、语言、DLC 禁用清单、完整挂载、游戏与源指纹、两臂源、观测包、采样和声明差异。`sampling` 必须事前声明正整数 `sample_count`、正数 `window_days`、有限非负 `max_overshoot_days` 和 `before_treatment=true`。字段存在不构成证明：实际月份、激活点、起止 tick、实际天数和原日志须对应。

M3-A 支持 `natural-response` / `r1-readonly-1`，绑定两个响应国与不同的指定发起/目标国；实际两臂源必须由当前生成器产生，唯一区别为 neutrality。当前行为 CLI 的财政只读、生命周期与政治观察包均保留并冻结；本地化诊断若启用，其完整原件也进入登记。准备局使用 `purpose=instrument`，登记目标 `purpose=M3-A`；只允许自然、无注入、未处理 control、显式语言/场景且不同时保存输出。

运行器独立读取当前版本和完整所需游戏文件集合，复核现场语言、DLC、预计及部署后挂载。资格文件里的 SHA 不能替代现场事实。准备登记在副作用前重新生成并对照实际源；失败局可归档候选资格文件，验证器仍拒绝它。正式局使用既有资格，记录其原路径、SHA 和登记 SHA；不会临时补写登记。

实际窗口上界为 `ceil(months × 365.25 / 12) + max_overshoot_days`；每条正响应采样带引擎壁钟时间并由前后 tick 包围，共享采样的可证明时间区间须相交。缺前缀、缺包围、时间倒退或跨午夜歧义均拒绝。登记的 `window_days=months×30` 是请求窗口身份，不替代实际 tick 天数。

风险依据是精确核验生产源码中 `ACTIVE` 包含 `sitai_fiscal_risk` 的语义，且使用同一共享响应采样；不是任意历史 RISK=yes。月度财政和每日响应计数不直接 join，同一财政样本的 ACTIVE/RISK 矛盾另行拒绝。M3-B 缺完整分母时返回 `opportunity.denominator_unsupported`；M4 缺当前可复核质量出口时返回 `frozen_candidate.quality_unsupported`，不接受手填通过。

## 预算、控制顺序与复用边界

| purpose | 单臂窗口 | 每场预算 |
|---|---|---|
| reconnaissance / instrument / M3-A / M3-B | 至多 6 月 | 至多三组、六臂 |
| safety | 显式至多 120 月 | 至多三组、六臂 |
| M4-noise | 默认 6 月；事前显式至多 120 月 | 至多三次单臂，只允许 vanilla/control |
| M4 | 24–120 月 | 三组、六臂 |

两场上限保留，失败和中断消耗预算。非法 purpose/arm、布尔数值、NaN/Inf、非整数 pair、超窗或事后修改冻结预算均拒绝。迁移保留旧行，新 schema 拒绝被旧工具降级。

同类原版错误的两次停止事实跨计划、场景与目的共享。改变探针、诊断、候选源、模拟设置或名称不能重开原版错误；仅明确不同的检查点、语言、游戏版本/内容构成可审核的上下文变化，旧缺上下文记录保守共享。游戏内容以双方共有的规范原版相对路径及文件 SHA 比较；增删观测依赖集合、改变其聚合 SHA 或为旧记录补新映射不能解除停止，旧附表的聚合上下文亦保守兼容。实时 early_stop 与最终日志合并计次；汇总缺失或损坏不能抹除已观察错误，同局同类错误去重。

正式候选须先有同一 pair 的完成 control（M4 为 vanilla），且控制报告 SHA、实验身份、输入/源/挂载/窗口和冻结 manifest 对应。读取实际报告、日志和源码重新检查严格清洁门禁；M3-A 另复核原资格与当前控制的实际共享机会、风险和时间。控制缺证、失败、改动或不能解释时，不预留候选身份，不部署或启动。探索用途保持原预算，但不能升级为正式样本。

兼容性判断用于解释失效，不授权样本复用。完整 provenance 保存所有 pdx 模块、生产 TOML、原版底本、GUI 模板、实际回调来源及库版本；未知回调依赖保持未知，尚未形成完整动态导入图。有效 DLC 禁用清单或完整挂载变化明确判定 must-rerun，缺证或坏结构仍为 unknown；来源改变、未知依赖范围或 `callback=null` 亦为 unknown。此前 DLC/挂载变动已经保守拒绝，此处完善分类，不追称旧版曾放行。分析器修正、文档变更和来源相同也不能自动复活历史失败或复制控制样本。

## 环境与接口限定复核

本机游戏仍为 `release/1.14.5`，caligula 修订 `9f8281a37e85639359b3b0c2c5df0196e975ca4b`，clausewitz 修订 `fd5e1dbd038c3c4a3f48a36abf60ebb42dd0ceef`。只读复核时没有游戏进程或活动恢复指针；Steam 本地记录 buildid 25629520、BetaKey 1.14-openbeta。启用的 23 个用户 Mod 中无本项目/探针，DLC 禁用列表为空；旧内容清单备份与当前字节相同，其存在不构成删除依据。

早先限定核对的 `texticons.gui`、`map_markers.gui`、`generic_icons/repairing.dds` 与本地主 depot manifest 大小/SHA-1 相同，引用的 `alert_icons/repairing.dds` 不存在且不在该主 manifest。此结论不等于完整安装通过、官方错误确认或修复。官方新闻和公开构建接口没有提供可用的新修复依据。用户三份早期自动存档含已失效 Mod，无合法后期档；既有 VFS/断言停止窗口没有因此重开。

本轮另外完成当前 Steam 安装的只读 depot manifest 盘点：20/20 已登记 manifest 解析成功，31,136 条记录（29,036 个独立普通文件、2,100 个目录）全部通过当前文件的 size/SHA-1 核对，目录无链接或重解析点，manifest 输入在核验前后稳定。盘上仅有两个未列入 manifest 的 SDK/同意文件：`%LOCALAPPDATA%/PDX/SDK/victoria3/account.json` 与 `telemetry_consent.json`；审计未将其判为损坏。工具按 Steam 空文件的零长度 SHA 约定处理，修正了初版误报；证据和脚本均在忽略目录 `tools/out/audits/r3-install-integrity-20261011/`，工具 SHA-256 为 `4cf8be26885cf2f7fa8112be3b0018f26bc37e223b23ae4ad5ed5d40a92117cd`。该结果只证明当前 appmanifest 登记 depot 的文件一致性，不是 Steam 服务器签名、未登记分支完整性、资源引用、引擎错误或 Mod 行为通过；它只提供了一项新的环境依据，是否重开 vanilla 安全窗口仍须独立登记并执行错误门禁。

R4 本轮只选“响应国是否与指定发起/目标国交战”这一独立问题。当前原版使用 `has_war_with = <country>`：`common/scripted_triggers/00_diplomacy_triggers.txt:138`、`common/on_actions/00_code_on_actions.txt:1188`、`events/egyptian_crisis_events.txt:58`、`events/africa_colonial_events_02.txt:31` 有消费者，含月度 country pulse 的 if/limit。现有 WAR 仅证明与某国交战，不能指明对手。没有找到独立 `is_at_war_with` 条件。

该接口尚未新增探针或实机验收。下一仪器必须绑定对象存在、共享时间、正反独立真值、安全和扰动预算；即使两国战争成立，也不能推出来自指定博弈、实际成本或质量改善。它不是 M3-B 分母或政治概率缺口的替代答案。本批没有启动游戏；完整性盘点没有改变安装内容，也没有消除已知资源引用问题，因此未重开相同 VFS/断言停止窗口。

## 验证与资源测量

整合定向测试为 686 passed、1 skipped，168.95 秒，发生在最后一轮停止上下文修补之前；修补后队列 215 条定向测试通过。跳过项为本机目录符号链接权限，模拟父目录链接/junction 拒绝契约另有测试；跨平台 CI 和 Windows GUI 实机分别记录。全仓 Ruff、342 份 Python 格式、200 份 Python 类型检查与编码通过；baseline 的依赖、43/234 条离线断言、174 张机械表格、976 条引用、5 份生产与 69 份 legacy 生成物、Mod 门禁及死代码审计通过。

2026-10-12 首轮完整回归为 3344 passed、11 skipped，574.23 秒，分支覆盖率 89.22%，11 个核心模块下限通过；同时暴露 11 条 SQLite 连接资源警告。定位到新增测试夹具的事务上下文：`sqlite3.Connection` 的上下文管理负责提交或回滚，不负责关闭；生产账本原有 `finally: close()` 没有这项缺口。已在 10 处夹具使用标准库 `contextlib.closing`，保留原事务语义；将 ResourceWarning 与 PytestUnraisableExceptionWarning 提升为错误后，215 条队列定向测试全部通过（28.20 秒）。首轮输出保留在 `tools/out/benchmarks/r1-r2-full-suite-final-20261012.*`，没有隐藏警告交付。此前 2026-10-11 修补中被主动中止的完整运行保留原日志，不计入通过或性能对照。

修复后的最终完整回归采用同样的严格资源告警模式，实际 n-auto 选择 4 workers / 3355 items，结果为 **3344 passed、11 skipped，522.72 秒**；完整命令含采样的墙钟为 524.40 秒，进程树采样 RSS 峰值 3663.16 MiB（约 3.58 GiB，50 ms 间隔）。分支覆盖率为 **89.22%**，整体 86% 门禁与全部 11 个核心模块下限通过；资格、队列、运行器分别为 96.54%、93.14%、91.31%。没有 SQLite 资源警告；普通并行 pytest 的 benchmark 计时按原契约禁用，独立成本基线另见下表。

11 项跳过明确分为 4 项本机符号链接权限不足和 7 项当前用户引擎日志不可用。读取游戏文件的集成测试不等于启动游戏，本批没有 GUI 实机；不以 CI 或合成原件通过代替产品验收。最终原件为 `tools/out/benchmarks/r1-r2-full-suite-clean-20261012.json`、同名 `.log` 与 `r1-r2-coverage-clean-20261012.json`。两次完整运行的种子、缓存与资源状态未按优化对照冻结，测试集合也区别于旧工程批次，因此不从耗时或 RSS 差异计算提速比。

## 后续出口

R1/R2/R6 只完成本页列出的工程增量；精确复用、完整质量观测、最小包扰动验收与实机闭环仍待相关前提。R3 受影响实机在无新环境依据时停止，R4 单问题静态研究不升级为接口实测。R5 继续复用现有定向反馈、生成与完整回归，不改没有候选依据的政策。R7–R9 依赖合法处理前输入、行为/质量、冻结候选和正式长期/后期验收；当前仍不能宣布整个提速实施或 Mod 完成。

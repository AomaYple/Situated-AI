# 2026-10-12 增量可玩版本计划重审

本页记录在提速计划 2.2 基础上，对 Mod 交付节奏的再次重排。用户目标是先得到一个真正可玩的最小版本，再逐个模块完善；本页因此把 2.2 的“准备包 → pilot → 扩大验收”漏斗接到“一个模块 → 一个可玩版本”的交付闭环。当前权威入口是[最终执行纲领 1.1](../design/exec/mod重设计-实施计划.md)和[提速计划 2.3](../design/exec/速度优化计划-正确性优先.md)。

## 重审结论

原计划的 M0–M5 质量门是必要的，但它们主要描述验证层级，容易出现工程和接口工作持续推进、玩家却长期拿不到可玩的版本。当前 M3 合格行为配对为 0，M4 正式候选、长期/后期、噪声和性能出口仍未通过；如果继续把所有模块放在同一条长链上，会让任何一个缺失接口阻塞整个 Mod。

因此把计划分为两层：

- **质量门**：M0–M5 继续负责设计、接口、最小实现、行为/质量、稳定性/性能和扩展验收，保持正确性第一、速度第二、内存第三。
- **产品版本**：V0.1–V1.0 负责逐步交付。每个版本只增加一个模块，继承上一版可玩包；新模块完成自己的 M1–M4 后必须马上形成可安装包并完成最小实机可玩烟测。

这不会降低样本、窗口、质量指标、错误分类或资源预算。它只把长周期工作拆成可回退、可验证和可使用的增量。

## 版本路线

| 版本 | 交付内容 | 关闭范围 |
|---|---|---|
| V0.1 | 财政风险/存续状态影响第三方高风险外交响应的最小可玩纵向切片 | `aggression`、政治、市场和未经验证的自主发起保持关闭 |
| V0.2 | 外部安全与既有承诺中的一个受支持模块 | 未通过 M1–M4 的外部候选保持关闭 |
| V0.3 | 市场依赖、供应风险或贸易约束中的一个可观测闭环 | 没有实际角色、代价和不利结果读数的市场候选保持关闭 |
| V0.4 | 政治可行性或身份偏好的一个通用闭环 | 没有候选、方向、风险否决和更新证据的政治候选保持关闭 |
| V1.0 | 已通过模块的组合、冲突解决、长期和兼容交付 | 未通过的模块仍可在实验包中研究，但不进入组合生产开关 |

版本名称表达交付顺序，不代表模块已经完成。当前仍在 V0.1 准备阶段；已有 M2 财政生命周期证据不能替代 V0.1 所需的 M3 行为/质量和 M4 最小稳定性出口。

## 每个版本的固定出口

1. **范围冻结**：只登记一个新增模块和一个主要行为问题，写清父版本、开关、输入版本、兼容范围、质量指标、资源预算、停止条件和回退方式。
2. **离线门禁**：运行数据源/生成器、定向机制测试、引用检查、`modgen --check`、离线 baseline 和适用的完整回归。
3. **行为门禁**：新模块按 M1–M3 完成接口、最小实现、实际响应、行动代价、反例和质量判定；pilot 仍不计入正式样本。
4. **稳定性门禁**：按 M4 完成生命周期、保存/重载、卸载、错误恢复、资源预算和声明范围兼容性。受影响的继承模块必须重跑，未受影响的模块只能按指纹规则复用证据。
5. **可玩性烟测**：从干净环境安装并启动新局，选择观察者，使用快捷键 `5` 和空格推进至少预登记的最小窗口（默认 6 个游戏月），保存、退出、重载并继续推进。目标模块必须实际运行，AI 必须持续自治，日志、挂载、恢复和清理不得出现未分类错误。
6. **交付记录**：用 Python 生成安装包、清单、版本说明和证据索引，记录游戏版本、启用开关、源/部署指纹、存档限制和平台证据；上一版包保留为可回退基线。

烟测不是行为质量的替代品；它证明的是“玩家可以安装、启动、推进和继续游玩”。行为质量仍必须通过对应的 M3 出口，运行效率和内存仍必须通过 M4 的匹配实机测量。

## 失败与回退

- G0 或 pilot 失败：不启动长窗口，生成停止包，继续输入准备或接口否证。
- M3 失败：保留行为和质量阴性证据，关闭新增模块，上一版可玩包不受影响。
- M4 或可玩性烟测失败：撤回候选或修复该模块，重新生成并重新验收；不移动生产开关。
- 继承模块受输入、游戏版本、生成器或探针指纹影响：按受影响范围重跑，不能只做烟测就复用旧证据。
- 版本交付成功后才进入下一版本；不允许多个未验收模块同时堆叠到生产包。

## 速度与正确性边界

每个版本单独记录从范围冻结到可玩包的墙钟、无效启动率、重跑次数、证据复用率、Python 分配、游戏 CPU/RSS 和磁盘输出。只有输入、环境、探针、窗口、输出和判据一致的 AB/BA 对照才计算提速；新版本没有同语义旧流程时只记录成本基线。

计划落盘、离线门禁、可玩性烟测和工程回归都不能宣布 Mod 整体完成。只有 V1.0 组合范围的全部模块和出口通过，才可以声明目标范围内的完整版本；未覆盖或受引擎限制的范围必须继续写明。

接入 mypy 与文档一致性测试，补 CLI 端到端测试，修复文档数字漂移

静态检查
  接入 mypy 并清零全部 57 个问题（31 个源文件零告警）。修的过程中发现几处
  真实缺陷而非纯类型噪声：
    - analyze.py 的 targets 声明为 list[tuple[str, object]]，等于放弃了整条
      链路的类型检查；mods.py 的 read_metadata 声明返回 dict 却直接返回
      json.loads 的结果，顶层是数组时调用方的 .get 会在运行时炸
    - rel / d 两个循环变量在同一函数里先后表示不同类型，属遮蔽
  测试侧一律用显式的收窄助手（scalar_of / block_of）而不是 type: ignore ——
  前者在形状不符时让测试失败，后者只是把检查关掉。

文档一致性（审计报告里排第一的问题）
  新增 pdx.verify.find_doc_drift()：以断言描述里的英文标识符为锚点，
  到出处文档里找「锚点 + 数量」的行，与断言表比对。
  这填补了一个长期空白——verify.py 的断言表早就把 1.14.3 的新值测对了，
  但断言表与文档正文永不共振，v3 verify 一路报「全绿」，
  文档里却躺着几十个 1.14.2 时代的过期数字。
  实测抓出 23 处，其中 12 处是真漂移，已改：on_actions 263→264（3 处）、
  NAI 1013→1017（9 处）、common 3099/3024→3101/3026（2 处）。
  剩余 10 处经逐条实测确认是「度量口径错配」（同行并列条目数/文件数/
  被引用次数），登记在测试里并写明理由，且有测试防止这份豁免清单腐烂。
  新增 tools/tests/test_docs_consistency.py（7 个用例）。

测试
  新增 tools/tests/test_cli.py：cli.py 此前 394 条语句零覆盖，而它是用户
  唯一真正接触的界面。用 CliRunner 做进程内测试（参数解析、退出码、
  输出内容），另用 subprocess 真起进程验证两件进程内测不到的事：
  装出来的 v3 入口点能用、GBK 控制台下不因编码崩溃。
  顺带发现并修掉一个可用性缺陷：--only 拼错时会筛出空列表然后
  「全部通过」退出 0，是最容易骗过 CI 的假绿灯；现在返回 2。
  实测 310 通过（从 282），cli.py 覆盖率 0% → 61%。
  覆盖率门禁按实测校准到 82%，并在配置里写明剩余缺口。

其他
  test_scan / test_extract 里手写的临时目录工具换成 tempfile.mkdtemp：
  原先用「类变量计数器 + 固定前缀」命名，而 pytest-xdist 每个 worker 是
  独立进程、计数器各自从 0 开始，两个 worker 会撞同一个目录 —— 这个隔离
  缺陷正是并行跑测试时暴露的（xdist 实测 100.8 秒 vs 串行 137.6 秒，-27%）。
